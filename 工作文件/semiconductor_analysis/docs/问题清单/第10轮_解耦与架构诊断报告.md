## 详细发现

### 架构违规TOP5

#### 🔴 P0-10-1: `profiling.py` 930行单函数 `_p2_agg` — 极端SRP违规

- **位置**: `product_lifecycle/profiling.py:196-1130`
- **规模**: 930行（全文件1,125行中的83%）
- **功能混装**:
  - 产品指标计算（销售额、毛利率、增长率、ASP等）
  - 5因子风险评分组合
  - 数据质量标记生成
  - 九宫格画像分类
  - 策略建议文本生成
  - 产品策略概要
  - 结果DataFrame组装
- **影响**: 无法单元测试、无法并行化、修改一处需通读900行
- **建议**: 拆分为8-12个聚焦函数，按职责分组（计算/评分/分类/策略）

#### 🔴 P0-10-2: `build_silver_layer` 两份重复实现

- **两处实现**:
  - `customer_analysis/silver.py:27-91`（91行）— 规范实现
  - `product_lifecycle/run.py:128-184`（57行）— 独立副本
- **差异**: 产品侧版本使用 `load_config_from_dict()`，但逻辑步骤完全相同（read→clean→aggregate→write CSV）
- **风险**: 修改清洗逻辑需同步两处，现已不一致（产品侧缺少某些列传播）
- **建议**: 产品侧 `run.py` 删除自建版本，导入 `customer_analysis.silver.build_silver_layer`

#### 🟡 P1-10-1: 两套RFM评分系统

| 系统 | 文件 | 因子 | 标签 | 范围 |
|------|------|------|------|------|
| v2.8 (产品报告) | `shared/customer_analysis.py:12` | R/F/M (3因子) | 5客户类型+流失 | 1-5求和 |
| v2.9 (客户分析) | `customer_analysis/models.py:18` | R/F/M/π (4因子) | S/A/B/C 4级 | 加权0-100 |
| **影响** | 同一客户在两处可能得到不同分群结果 | | | |

- **建议**: 统一为v2.9的4因子模型，v2.8使用适配器

#### 🟡 P1-10-2: `dimensions.py` 14个包装函数

- **文件**: `customer_analysis/dimensions.py`（144行）
- **模式**: 14个函数全部是 `shared/pricing.py` 的薄包装
  ```python
  def calc_purchase_interval(df, cust_col="客户编号", date_col="发货日期", ...):
      return _calc_purchase_interval(df, cust_col, date_col, ...)
  ```
- **增加价值**: 提供默认参数值
- **替代**: 将默认参数移至 `shared/pricing.py`，删除包装层
- **建议**: 精简为直接导入或折叠到pricing.py

#### 🟡 P1-10-3: `run_profiling()` 15个参数

- **位置**: `product_lifecycle/profiling.py:20-30`
- **签名**: `def run_profiling(thr, prod_month, ... [13 more] ...)`
- **建议**: 使用配置对象或 `dataclass` 封装参数
