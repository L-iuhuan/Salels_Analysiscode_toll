# 客户分析映射修复 — 修改记录

> 日期：2026-06-12
> 目标：将分析维度从"代理商/直供名称"切换为"终端客户简称"，并修复所有关联的属性映射链

---

## 一、背景

原系统的"客户编号"映射自 ERP 的"代理商/直供名称"列（311 个唯一值），分析粒度为代理商级别。业务需要下沉到终端客户维度，改由"终端客户简称"列（3,851 个唯一值）作为客户标识。

切换后，原有的客户属性映射链（客户信息表 → CRM 主数据 → 交易数据回退）全部失效，导致渠道类型、客户等级、客户层级、所属区域等字段大面积"未知"。

---

### 3.3 `run_all.py` — stage_silver() 构建 cust_info

**修改位置**：`stage_silver()` 函数，约第 160-195 行

**逻辑**：
1. 原代码尝试读取 Excel 的"客户信息表" sheet → 该 sheet 不存在
2. 原代码回退为所有字段设"未知"
3. 新代码在回退分支中，从 ERP 列直接提取客户属性构建 `cust_info` DataFrame：
   - 渠道类型：`raw.groupby("客户编号")["销售模式"].first()` → 映射为 代理/直供
   - 客户类别：`raw.groupby("客户编号")["客户类别"].first()`
   - 客户等级：从客户类别推导（KA/AA→A, KM→B, MM→C）
4. `cust_info` 随函数返回，传递到 `stage_customer()` → `run_customer()` → `calc_customer_portrait()`

**关键设计决定**：cust_info 在聚合前提取，但不 merge 到 raw（避免干扰 `monthly_aggregate_double_pass` 的聚合列）。

**同时移除**：旧的 `raw_for_channel` 列保留逻辑（`_channel_cols = ["代理商/直供名称", ...]`），因为渠道推导不再需要这些列。

**附带修复**：`find_source_data()` 添加 `~$` 临时文件过滤：
```python
xlsx_files = [f for f in os.listdir(DATA_DIR) if f.endswith(".xlsx") and not f.startswith("~$")]
```

**修改点 3**：raw_data 列选择从旧字段改为新字段

**修改点 4**：两条路径均添加 cust_info 构建逻辑

skip_silver 和非 skip 路径中，从 raw_data 提取 per-customer 属性：
- 渠道类型：`groupby("客户编号")["销售模式"].first().map({"经销":"代理","直销":"直供"})`
- 客户类别：`groupby("客户编号")["终端客户名称_客户类别"].first()`
- 客户等级：从客户类别推导

**修改点 5**：用 cust_info merge 替换旧的渠道推导循环

```python
# 之前：对每个"未知"渠道客户调用 _derive_channel()
still_unknown = customer_df["渠道类型"].isna() | (customer_df["渠道类型"] == "未知")
if still_unknown.any() and raw_data is not None:
    for idx in customer_df.index[still_unknown]:
        cid = customer_df.loc[idx, "客户编号"]
        ch = _derive_channel(cid, raw_data)
        ...

# 之后：直接从 cust_info_data merge 渠道+类别+等级
if cust_info_data is not None and len(cust_info_data) > 0:
    customer_df = customer_df.merge(cust_info_data[["客户编号", "客户类别"]], ...)
    customer_df = customer_df.merge(cust_info_data[["客户编号", "客户等级"]], ...)
    customer_df.loc[mask, "渠道类型"] = customer_df.loc[mask, "客户编号"].map(cust_channel)
```

### 3.5 `customer_analysis/portrait.py` — 客户全景画像

**修改点 1**：`_derive_channel()` 支持两种模式

```python
def _derive_channel(cid, raw_data):
    cd = CHANNEL_DERIVE

    # 新增：模式1 — source_col + mapping（直接列映射）
    source_col = cd.get("source_col")
    if source_col and source_col in raw_data.columns:
        mapping = cd.get("mapping", {})
        row_match = raw_data[raw_data["客户编号"] == cid]
        if len(row_match) > 0:
            val = row_match[source_col].iloc[0]
            return mapping.get(str(val), cd.get("default", "未知"))
        return cd.get("default", "未知")

    # 模式2（保留）：buyer_col/end_cust_col 匹配计数
    ...
```

### 3.7 `analysis/pricing/pricing_customer.py` — 品类接受度 NaN 处理

**修改位置**：`calc_category_acceptance()` 函数，约第 195 行

```python
# 之前
dominant = category_share.loc[
    category_share.groupby(cust_col)["占比"].idxmax()
].reset_index(drop=True)

# 之后
category_share_valid = category_share.dropna(subset=[category_col])
idx_max = category_share_valid.groupby(cust_col)["占比"].idxmax().dropna()
dominant = category_share_valid.loc[idx_max].reset_index(drop=True)
```

**根因**：部分产品的"产品一级分类"为空（NaN），导致 `idxmax()` 返回 NaN 索引，`.loc[NaN]` 抛出 KeyError。终端客户数量（3,851）远超代理商（310），放大了此边界情况。
