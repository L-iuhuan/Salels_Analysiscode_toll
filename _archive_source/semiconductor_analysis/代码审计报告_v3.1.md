# v3.1 代码对齐审计报告

> **审计目标**：检查所有代码、配置、文档是否与 v3.1 校准测试结论一致，不一致则规划修改方案。

## 校准结论（基准）

| 项目 | 结论 |
|------|------|
| 因子模型 | **4因子**: F1f(赚钱能力趋势) + F5(自比健康度) + F4(增速衰减) + c6(大客户订货变化) |
| 权重 | **F1f=0.368, F5=0.316, F4=0.211, c6=0.105** (F3已移除) |
| 阈值 | **[50, 60, 75]** → 低/中/高/极高 |
| c6缺失策略 | **zero_fill** (填0) |
| F1f计算 | **近6月**毛利额(销量×毛利率)的**最小二乘斜率**，方向修正为"负=高风险" |
| F4连续下降 | 基础分 + 连续下降月数 × **10分/月** (上限100) |
| 标签定义 | 未来6个月连续3个月落入九宫格"衰退期/夕阳/隐性衰退" |
| 新品豁免 | 月龄<6月或历史数据<3月 → "新品观察"，不参与评分 |
| AUC-ROC | **0.7844** |

## 一、生产代码审计

### 1. 🔴 关键：F1f 计算逻辑不一致

| 项 | 当前代码 (`profiling.py:747-765`) | v3.1 要求 | 严重程度 |
|---|-------------------------------|-----------|---------|
| 测量对象 | **毛利率** (margin ratio) 斜率 | **毛利额** (qty × margin) 斜率 | **严重** |
| 窗口长度 | **12个月** | **6个月** | **严重** |
| 计算方法 | 最小二乘斜率 (polyfit) ✅ | 最小二乘斜率 | ✅ |
| 方向处理 | 负斜率→高风险 (通过 risk_slope) | 负斜率→高风险 | ✅ |

**影响**：
- 当前计算的是"毛利率趋势"，不是"赚钱能力趋势"
- 毛利率可能上升（降价促销导致销量暴增，固定成本摊薄），但毛利额可能下降——两者信号相反
- 12个月窗口太长，衰退信号会被历史拉平，响应变慢

**修改建议**：
- `profiling.py:747-765`：从"近12月毛利率序列"改为"近6月毛利额序列"
- 新增 `calc_gp_slope_6m()` 函数或修改现有逻辑
- 公式：`月毛利额 = 月销量 × 月毛利率` → 取最近 6 个月 → `polyfit(x, y, 1)[0]` → `-斜率/均值` 归一化

### 2. 🔴 关键：F4 连续下降加成未生效

| 项 | 当前代码 | v3.1 要求 |
|---|---------|-----------|

| 加成应用 | **未应用** — `risk_decay()` 无 bonus 参数 | 基础分 + 连续月数 × 10/月 |

**影响**：
- 连续下降月数算出来了，但没有用上，F4 信号比预期弱

**修改建议**：

- `profiling.py` 调用 `risk_decay()` 处传入 `连续下降月数`
