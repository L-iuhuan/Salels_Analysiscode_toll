## 4. 重点逻辑偏差详细分析

### 4.1 RFM-π分位排名不稳定（P1）

**问题**：`models.py:63` 使用 `sub[col].rank(method="first")` 对 `pd.qcut()` 输入。这意味着：
- 两客户相同"距上次采购天数=30天" → 先出现的行得rank=1、后出现的rank=2
- qcut划分五分位时，rank=1和rank=2可能被分入不同bin
- 如果DataFrame因数据加载顺序/并行处理变化 → 同值客户获得不同RFM等级

**业务影响**：客户评级S/A/B/C的稳定性取决于DataFrame行顺序，这是**不可接受的**。

**修复方向**：改为 `rank(method="dense")`（同值同排名，无间隔），然后对dense_rank用qcut。当并列值过多导致qcut失败时，使用简单分箱回退。

### 4.2 Min-Max归一化漂移（P1）

**问题**：`scoring.py:45-55` 的 Min-Max 归一化是**相对归一化**：
```python
norm = (s - s.min()) / (s.max() - s.min()) * 100
```
这意味着：
- 本月100个客户中，收入最高的得100分，最低的得0分
- 下月新增一个超级大客户后，老客户第1名不再是100分
- 评分在不同时间点**不可比**
- 客户从"B级"变成"C级"不是因为自己变差了，而是因为他人变好了

**业务影响**：无法做客户评分的月度趋势对比（客户评分下降可能是他人进步所致）。影响客户生命周期管理中的"客户升级/降级"判断。

**修复方向**：采用固定基准分布（每年校准一次），或将Min-Max改为百分位归一化（相对位置稳定）。

### 4.3 不完整月检测缺失（P2）

**问题**：`product_lifecycle/run.py:260-275` 实现了完整的不完整月检测逻辑（检查最新月份最大日期<25日），但 `customer_analysis/silver.py:58-61` 和 `run_all.py` 中无此检查。

**业务影响**：如果客户分析在月未关账时运行（如4月25日），会将不完整的月份包含在"近12月"窗口内，导致营收指标偏低的系统性偏差。

**修复方向**：将不完整月检测提升到共享清洗层（monthly_aggregate_double_pass），让所有下游模块统一受保护。

### 4.4 产品vs客户分析时间覆盖不一致（P3）

**问题**：第1轮发现客户分析 start_date=2024-01-01 过滤了48个月数据。产品分析用2020-01-01（正确）。这导致：
- 产品分析看到76个月完整历史
- 客户分析仅看到28个月（2024-01 ~ 2026-04）
- growth_window_months=12 要求下，客户增长对比只能用2024-01 vs 2025-01（仅1个对比点）

**业务影响**：客户增长率计算的稳定性差（对比窗口窄），早期客户行为模式完全丢失。

**修复方向**：统一将start_date改为2020-01-01（与产品分析一致），或在注释中明确说明"客户分析仅关注近2年活跃客户"并重新校准评分阈值。
