## 1. 实证诊断：因子评分函数的结构性问题

### 1.1 F4（增速衰减）— 严重逆转

对13,536条前瞻标签数据的分析发现 **F4的评分与预测力严重不匹配**:

| F4得分 | 预测含义 | 实际衰退率 | 样本量 | 诊断 |
|:------:|:--------:|:---------:|:-----:|:----|
| 10 (safe) | 增长加速 | **2.2%** | 3,092 | ✅ 正确 |
| 30 (slight) | 轻度衰减 | **15.0%** | 3,188 | ✅ 可接受 |
| 50 (moderate) | 中等衰减 | **36.2%** | 2,620 | ✅ 正确 |
| 60 | 连续下降加成 | **54.2%** | 179 | ✅ 正确 |
| **70 (high)** | **严重衰减** | **8.9%** | **2,983** | ❌ **完全逆转** |
| 80 (severe) | 极严重 | **30.1%** | 1,474 | ⚠️ 偏低 |

**根因**: F4=70 的 scoring 逻辑存在 bug:

```python
# risk_decay() 中的正常分支：
elif decay_val < t_high:  # decay < -10pp (严重衰减)
    return 70
```

但实际落入此分支的产品, 其 yoy_change 分布如下:
- yoy_change > 0.5（高增长）且 decay < -10pp → 2.3% 实际衰退率, 被错误评为70分
- yoy_change > 0（增长）且 decay < -10pp → 2-5% 实际衰退率, 被错误评为70分

也就是说: **一个高增长产品即使增速衰减10pp以上, 实际衰退概率仍然极低(2.3%)**, 但当前模型给了70分(高风险)。这是F4误报的最大来源。

**影响范围**: ~2,983条样本评分虚高, 贡献约500个FP。

### 1.2 F5（自比健康度）— 顶部逆转

| F5得分 | 自比健康度范围 | 实际衰退率 | 样本量 | 诊断 |
|:------:|:-------------:|:---------:|:-----:|:----|
| 10 | ≥ 70% | **11.3%** | 9,620 | ✅ 正确 |
| 40 | 50-70% | **27.1%** | 2,247 | ✅ 正确 |
| **70** | **30-50%** | **37.0%** | **825** | ✅ 正确 |
| **90** | **< 30%** | **35.3%** | **844** | ❌ **逆转** |

**根因**: 自比健康度<30%的产品通常是"长期低毛利产品"(非短期恶化), 其衰退率反而略低于30-50%的"正在恶化"产品。惩罚这些产品为90分是过度的。

### 1.3 F1f（毛利率斜率）— 冗余分档

| F1f得分 | 斜率范围 | 实际衰退率 | 样本量 | 诊断 |
|:-------:|:--------:|:---------:|:-----:|:----|
| 10 | ≥ 0% | **13.0%** | 6,335 | ✅ |
| 20 | -0.3~0% | **15.7%** | 1,471 | ⚠️ 与50分无差异 |
| 50 | -0.8~-0.3% | **15.7%** | 2,376 | ⚠️ 与20分完全相同 |
| 80 | < -0.8% | **26.1%** | 3,354 | ✅ |

20分和50分实际衰退率完全相同(15.7%), 分档无意义。可以合并。

### 1.4 根因汇总

| 问题 | 影响范围 | FP贡献占比 | 修复难度 |
|:----|:-------:|:---------:|:--------:|
| F4 70分将高增长+增速衰减评为高风险 | ~2,983行 | ~40% | 中 |
| F5 90分过度惩罚长期低毛利产品 | ~844行 | ~15% | 低 |
| F1f 20/50分档无效 | ~3,847行 | ~5% | 低 |
| 权重配置不当(F1f过高,F5过低) | 全量 | ~10% | 低 |
| c6未加入导致缺少独立信号 | 全量 | ~5% | 中 |
| **合计可改善** | — | **~75% FP** | — |

## 2. 总体设计思路

### 2.1 核心理念

```
误报率高的根本原因不是"模型不好", 而是"评分函数不对"。
AUC=0.7269 是区分能力, 但评分函数将区分能力映射为了错误的分数。
```

**三个独立的优化层**, 递进执行:

```
Layer 1: 因子评分函数优化
   每个因子的内部阈值和得分映射
   目标: 确保每个因子内部单调、区分有效
   
Layer 2: 因子权重优化
   因子之间的权重分配
   目标: 最大化AUC, 最小化FP
   
Layer 3: 风险阈值校准
   低/中/高/极高 的分界点
   目标: 精度-覆盖率平衡
```

### 2.2 优化评估指标

| 指标 | 当前值 | 目标值(Phase后) | 用途 |
|:----|:-----:|:--------------:|:-----|
| AUC-ROC | 0.7269 | > 0.76 | 整体判别力 |
| Precision (高+极高) | 39.9% | > 50% | 预警可信度 |
| Recall (高+极高) | 15.0% | > 20% | 覆盖率 |
| F1 Score | 0.218 | > 0.30 | 综合 |
| 严格单调性 | ✅ | ✅ | 评分排序 |
| 极高占比 | 1.5% | 3-8% | 业务可操作性 |

## 3. Phase 1: 因子评分函数优化

### 3.1 F4 评分函数重写

**问题**: 当前`risk_decay()`的70分分支将高增长+高衰减误判为高风险。

**解决方案**: 用**实际衰退率热力图**作为评分映射依据, 替换经验阈值。

#### 方案: 基于数据驱动的F4评分

通过实证分析, 衰退率在yoy_change × decay_pp联合空间中的实际分布为:

```
             decay < -10    -10 ≤ decay ≤ 0    decay > 0
yoy > 0.5         2.3%           ~4%             ~11%    ← 均低风险
0 < yoy ≤ 0.5     4.5%          ~12%            ~20%    ← 中低风险
-0.1 < yoy ≤ 0    11.2%         ~29%            ~31%    ← 中风险
yoy ≤ -0.1       34.4%          52%              55%    ← 高风险
```

建议评分方案:

| 条件 | 得分 | 逻辑依据 |
|:----|:----:|:---------|
| yoy > 0.5 (高增长) | 保守: 10, 激进: 10~30 | 增长可容忍自然减速 |
| 0 < yoy ≤ 0.5 且 decay ≤ -10 | 20 | 增长中的正常波动 |
| 0 < yoy ≤ 0.5 且 decay > 0 | 30~50 | 增长+加速=过热信号 |
| yoy ≤ -0.1 且 decay ≤ -10 | 60 | 萎缩且加速恶化 |
| yoy ≤ -0.1 且 decay > 0 | 70~80 | 萎缩但开始恢复(实为假象) |
| **连续下降加成** | **上限50, 而非无限制** | 避免过度惩罚 |

#### 新的 risk_decay 评分矩阵（数据驱动版）

```python
DECAY_SCORE_MATRIX = {
    # (yoy_group, decay_group) -> score
    ("high_growth",   "accelerating") : 10,   # 高增长+加速
    ("high_growth",   "stable")       : 10,   # 高增长+稳定
    ("high_growth",   "decelerating") : 20,   # 高增长+减速(过热)
    ("growing",       "accelerating") : 30,   # 增长+加速
    ("growing",       "stable")       : 40,   # 增长+稳定
    ("growing",       "decelerating") : 50,   # 增长+减速
    ("flat",          "accelerating") : 50,   # 持平+加速
    ("flat",          "stable")       : 60,   # 持平+稳定
    ("flat",          "decelerating") : 70,   # 持平+减速
    ("shrinking",     "accelerating") : 70,   # 萎缩+加速(仍在改善)
    ("shrinking",     "stable")       : 80,   # 萎缩+稳定(真正恶化)
    ("shrinking",     "decelerating") : 80,   # 萎缩+减速(严重恶化)
}
```

连续下降加成: 每月+5分, 上限+25分(原为每月+10分, 无上限)。

### 3.2 F5 评分函数优化

**问题**: 自比健康度<30%(90分)的衰退率(35.3%)反而低于30-50%(70分)的衰退率(37.0%)。

**原因**: <30%的产品往往是"历史毛利率一直很低"而非"毛利率正在恶化"。

**解决方案**: 合并70分和90分, 或调整90分为80分:

```python
def risk_self_health_v2(health_pct, thr, history_months=None):
    """v2: 修复顶部逆转."""
    if pd.isna(health_pct):
        return 50
    
    pct = health_pct * 100
    # 数据驱动优化阈值
    if pct >= 70:     return 10    # 11.3% decline
    elif pct >= 50:   return 40    # 27.1% decline
    elif pct >= 30:   return 70    # 37.0% decline (highest risk!)
    else:             return 70    # 35.3% decline — COLLAPSED TO 70!
    
    # 可选: tenure-based moderation
    # if history_months and history_months > 24 and pct < 30:
    #     return 60  # 长期低毛利产品额外降级
```

### 3.3 F1f 评分函数优化

**问题**: 20分和50分无差异(均15.7%), 分档冗余。

**解决方案**: 合并不必要的分档, 或引入加速度(二阶导)区分:

```python
def risk_slope_v2(slope_ratio, thr, slope_accel=None, zero_profit=False):
    """v2: 合并冗余分档, 加入加速度."""
    if zero_profit:
        return 80

    # 数据驱动优化: 实际将4档降为3档
    if slope_ratio >= 0:           return 10     # 13.0% decline
    elif slope_ratio >= -0.008:    return 50     # 15.7% decline (合并20+50)
    else:                          return 80     # 26.1% decline
    
    # 可选: 加速度调节（当斜率已见底, 即加速度>0时降级）
    # if slope_accel is not None and slope_accel > 0 and slope_ratio < -0.008:
    #     return 50  # 斜率虽负但已见底 → 降级
```

### 3.4 c6 评分函数

**当前**: `score = 50 - order_qty_change * 40` 的线性映射。

**问题**: c6的预测力集中在负值端(萎缩), 正值端(增长)区分力弱。

**优化方向**: 改用桶状映射, 匹配c6的非线性特性:

```python
def risk_c6_v2(c6_raw):
    if pd.isna(c6_raw):
        return 0  # zero_fill, 权重再分配
    
    # 数据驱动分桶
    if c6_raw <= -0.5:     return 95   # 严重萎缩 (45.2% decline)
    elif c6_raw <= -0.2:   return 75   # 明显萎缩 (21.3%)
    elif c6_raw <= 0:      return 50   # 微跌 (17.4%)
    else:                  return 20   # 持平/增长 (14.5-15.4% — 几乎无差异)
```

### 3.5 Phase 1 验收标准

| 检查项 | 方法 | 通过标准 |
|:-------|:----|:--------|
| 各因子单调性 | 分桶衰退率检查 | 每个因子内部严格单调 |
| F4 70分逆转修复 | 重新计算F4各桶衰退率 | min decline(70) > max decline(50) |
| F5 90分逆转修复 | 重新计算F5各桶 | 90分衰退率 ≥ 70分 |
| F1f 分档冗余修复 | 重新计算F1f各桶 | 相邻档位衰退率差>2pp |
| 因子-标签相关性 | Point-biserial r | 每个因子与标签r绝对值提升 |

## 4. Phase 2: 权重自动网格搜索

### 4.1 搜索空间

**三因子 (F1f, F4, F5)**:
- 步长: 0.025
- 范围: 每个因子 [0.10, 0.70], sum=1.0
- 组合数: ~276 (整数解 x+y+z=40 with x,y,z≥4)

**四因子 (F1f, F4, F5, c6)**:
- 步长: 0.05
- 范围: 每个因子 [0.05, 0.60], sum=1.0
- 组合数: ~969

合计: ~1,245 种权重组合。

### 4.2 评估函数

对每种权重组合, 计算:

```python
def evaluate_weights(w_f1f, w_f4, w_f5, w_c6=0):
    # 1. 计算复合评分 (用Phase 1优化后的因子评分)
    scores = w_f1f * f1f_score + w_f4 * f4_score + w_f5 * f5_score
    if w_c6 > 0:
        scores += w_c6 * c6_score
    
    # 2. 计算指标
    auc = roc_auc_score(y_true, scores)
    
    # 3. 对T_current和X_h60e63两个阈值方案计算precision/recall
    for thr_scheme in [T_current, X_h60e63]:
        pred = pd.cut(scores, bins=thr_scheme, labels=[0,1,2,3])
        high_extreme = pred >= 2
        precision = precision_score(y_true, high_extreme)
        recall = recall_score(y_true, high_extreme)
        f1 = f1_score(y_true, high_extreme)
    
    # 4. 单调性检查
    monotonic = check_monotonicity(scores, y_true)
    
    return {
        'auc': auc,
        'precision_tc': precision_tc,
        'recall_tc': recall_tc,
        'f1_tc': f1_tc,
        'precision_x60': precision_x60,
        'recall_x60': recall_x60,
        'f1_x60': f1_x60,
        'monotonic': monotonic,
    }
```

### 4.3 Pareto 前沿识别

对所有~1,245种组合, 计算AUC-Precision Pareto前沿:

```
Pareto最优 = 不存在另一个权重组合同时满足:
  - AUC更高(或相等)
  - Precision更高(或相等)
  - 至少一项严格更高
```

筛选策略:
1. 剔除不满足 monotonic = True 的组合
2. 剔除 Precision < 40% 的组合
3. 在剩余组合中找 Pareto 前沿
4. 从Pareto前沿中选择综合F1最高的组合

### 4.4 运行时间估算

| 步骤 | 样本量 | 组合数 | 单次耗时 | 总耗时 |
|:----|:-----:|:-----:|:--------:|:-----:|
| 评分计算+指标 | 13,536 | 1,245 | ~10ms | ~12s |
| Pareto分析 | — | <100(前沿) | — | <1s |

**合计**: <30秒, 可以在一次pytest或脚本运行中完成。

### 4.5 Phase 2 验收标准

| 检查项 | 通过标准 |
|:-------|:--------|
| AUC vs 当前 | AUC ≥ 0.73 (三因子) / ≥ 0.74 (四因子) |
| Precision vs 当前 | ≥ 45% (提升5pp+) |
| 权重结果可解释 | 每个因子权重>0.10, 无极端分配 |
| 覆盖最优区域 | Pareto前沿至少5个候选方案 |

## 5. Phase 3: 阈值协同校准

### 5.1 方法

**输入**: Phase 2 选出的 Top-3 权重方案  
**搜索空间**: 

| 阈值 | 当前值 | 搜索范围 | 步长 |
|:----|:------:|:--------:|:----:|
| 低风险上界 | 50 | [30, 60] | 5 |
| 中风险上界 | 60 | [50, 70] | 5 |
| 高风险上界 | 75 | [55, 80] | 2 |

**约束条件**:
- low < mid < high (严格递增)  
- low ≥ 30 (避免低风险失去意义)
- high ≥ mid + 5 (确保中风险有宽度)

**组合数**: ~7×5×13 ≈ 455 种阈值组合。

### 5.2 评估标准

按优先级:

1. **极高衰退率 ≥ 40%** — 极高分组中至少40%实际衰退
2. **极高占比 3-8%** — 极高分组覆盖3-8%产品
3. **严格单调性** — 低<中<高<极高衰退率严格递增
4. **低风险占比 > 50%** — 多数产品归入低风险
5. **Precision最大化** — 在上述约束下最大化高+极高precision

### 5.3 运行时间

~455 种阈值 × Top-3 权重 ≈ 1,365 次评估, 每次 ~10ms → ~14秒。

### 5.4 Phase 3 验收标准

| 检查项 | 通过标准 |
|:-------|:--------|
| 极高衰退率 | > 40% |
| 极高占比 | 3-8% (比当前1.5%大幅改善) |
| Precision (高+极高) | > 45% |
| Recall (高+极高) | > 15% (从当前回升) |

## 6. Phase 4: 时间序列交叉验证

### 6.1 背景

前瞻标签的正例率随时间波动剧烈:

| 时间段 | 平均正例率 | 业务背景 |
|:------|:---------:|:---------|
| 2020-07 ~ 2021-06 | 5.6% | 疫情后复苏 |
| 2022-07 ~ 2023-06 | 27.7% | 需求高峰+库存调整 |
| 2024-01 ~ 2025-06 | 15.6% | 市场回归理性 |

用全量数据优化可能导致模型对 "高峰时期" 过拟合。

### 6.2 时间序列CV方案

```
训练: 2020-07 ~ 2024-06  (4年, ~10,000条)
验证: 2024-07 ~ 2025-11  (1.5年, ~4,000条)
```

滚动窗口验证:

```
Fold 1: train 2020-07~2023-12, test 2024-01~2024-06
Fold 2: train 2020-07~2024-06, test 2024-07~2024-12
Fold 3: train 2020-07~2024-12, test 2025-01~2025-06
Fold 4: train 2020-07~2025-06, test 2025-07~2025-11
```

评估指标: 取4个Fold的均值, 同时检查各Fold之间的一致性(标准差)。

**验收标准**: 
- 各Fold的AUC差异 < 0.03（时间稳定性）
- 各Fold的Precision差异 < 10pp（业务稳定性）
- Hold-out验证集性能不低于训练集的90%（无严重过拟合）

```
  ┌──────────────┐
  │ Phase 3:     │ ← 对Top-3权重方案搜索阈值
  │ Threshold    │    输出最优阈值方案
  └──────┬──────┘
         │
         ▼
  ┌──────────────┐
  │ Phase 4:     │ ← 时间序列CV验证最终方案
  │ TimeSeriesCV│    输出验证报告
  └──────┬──────┘
         │
         ▼
  ┌──────────────┐
  │   Report     │ ← 优选出最终方案
  └──────────────┘
```

### 7.3 关键设计决定

1. **Phase 1在Phase 2之前**: 如果先优化权重再修改评分函数, 评分函数变化会使权重优化失效。必须先修复因子评分函数本身的问题。

2. **Phase 3在Phase 2之后**: 阈值取决于评分分布, 评分分布取决于权重。阈值必须在权重确定后校准。

3. **Phase 4在最后**: 交叉验证是对最终方案的整体评估, 不是搜索过程的一部分。

4. **不引入外部优化库**: 网格搜索(而非贝叶斯优化)在这个规模下已经足够快, 且结果可解释性更好。
