## 1. 系统架构

### 1.1 顶层设计

```
data/*.xlsx ──→ [共享清洗管道] ──→ Silver 层 (CSV) ──→ Gold 层 (CSV) ──→ Excel 报告
                     │                      │
                     │            ┌── customer_monthly
                     │            ├── product_monthly
                     │            └── customer_x_product
                     │
            ┌────────┴──────────────────────┐
            │                                │
    product_lifecycle/               customer_analysis/
    (产品生命周期分析)               (客户销售分析)
            │                                │
            └────────┬───────────────┬────────┘
                     │               │
               cross_reference/    src/ (B2B v2)
```

**三个主要管道阶段**：

| 阶段 | 模块 | 输出 | 说明 |
|------|------|------|------|
| Silver | `shared/data_cleaning.py` | 3 张月度聚合 CSV | 一次清洗，两系统复用 |
| Gold (产品) | `product_lifecycle/run.py` | `gold_product_portrait.csv` + Excel 报告 | 40+ 产品指标 |
| Gold (客户) | `customer_analysis/run_pipeline.py` | 8+ 张 Gold CSV + Excel 报告 | 60+ 客户指标 |

### 1.2 入口点

| 文件 | 功能 | 典型用法 |
|------|------|----------|
| `run_all.py` | 统一运行入口，支持分阶段执行 | `python run_all.py --stage silver,customer` |
| `run_product.py` | 仅运行产品生命周期 | `python run_product.py` |
| `run_customer.py` | 仅运行客户分析 | `python run_customer.py` |

所有独立运行模块在文件顶部使用以下路径注入模式（**必须从项目根目录运行**）：

```python
# 文件: run_all.py (第 34-36 行)
PROJECT_ROOT = os.path.abspath(os.path.dirname(__file__))
if PROJECT_ROOT not in sys.path:
    sys.path.insert(0, PROJECT_ROOT)
```

> ⚠️ **重要**：始终从项目根目录执行脚本。`sys.path.insert(0, PROJECT_ROOT)` 模式在所有模块中都有，但 `cd` 到子目录后执行会破坏查找。

#### `customer_analysis/scoring.py`（311 行）

**职责**：5 维度评分卡（v2.0）。

评分体系：
- **综合价值分**: 5 维度加权 → S/A/B/C
- **机会评级**: 增长动能 × 0.6 + 战略潜力 × 0.4
- **风险评级**: (100-稳定关系) × 0.7 + (100-效率运营) × 0.3
- **双轴矩阵**: 价值贡献 × 增长动能 → 明星/金牛/培育/瘦狗

**⚠️ 已知问题** — `_minmax_norm()` 第 47 行使用 `s.fillna(0)` 将缺失值替换为 0 后再做 Min-Max 归一化。这会导致缺失值参与极值计算，扭曲归一化分布。应用 `fillna(0)` 仅在归一化之后，或在归一化前单独处理缺失值。

```python
# 文件: customer_analysis/scoring.py (第 45-55 行，问题代码)
def _minmax_norm(s: pd.Series, reverse: bool = False) -> pd.Series:
    s = s.fillna(0)  # ← 问题：缺失值填充0后参与归一化
    # ...
    if s.max() > s.min():
        norm = (s - s.min()) / (s.max() - s.min()) * 100
```

### 6.5 新列自动兼容

系统对新列是**自动容错**的：
- `read_excel_auto()` 读取所有列（`data_cleaning.py:23`）

因此添加新 ERP 列到数据文件不需要修改代码，只需：
1. 将新列名加入 `ERP_COL_MAP`

| `iterrows()` | 28 处 | `for _, row in df.iterrows():` | `apply()`、向量化操作、列表推导 |
| 逐行 for 循环 | 34 处 | `for i in range(len(df)):` | `groupby().agg()`、`transform()` |
| 无索引 merge | 43 处 | `df1.merge(df2, on="key")` | `df2.set_index("key")` 后 `df1.join()` |
| `groupby().apply()` | 11 处 | `df.groupby("x").apply(f)` | `groupby().agg()`（C 级别优化） |

### 7.2 性能瓶颈分布

| 瓶颈 | 原因 | 预估优化收益 |
|------|------|-------------|
| `profiling.py` 主循环 | 930 行非向量化逐产品循环 | 5-10x（向量化后） |
| `monthly_aggregate_double_pass()` 重复调用 | 产品分析和客户分析各聚合一 | 2x（缓存复用） |
| CSV 整文件加载 | 286MB → ~800MB 峰值内存 | 50%+ 内存（分块读取） |
| 无索引 merge | 43 处 O(n²) 运算 | 变量，平均 2-5x |

### 7.3 优化优先级

1. **P0**: 分解 `profiling.py` 主循环（930 行 → 8-12 向量化函数）—— 最大收益
2. **P1**: 统一 Silver 构建 —— 消除重复聚合，可能节省 ~30 秒/次运行
3. **P1**: 为频繁出现 merge 字段（`客户编号`, `产品品种`, `_月`）建立索引
4. **P2**: 关键路径 `iterrows()` → 向量化替换
5. **P3**: CSV 分块读取（`pd.read_csv(chunksize=...)`）—— 内存优化

### 7.4 当前并行化

**唯一并行区域**：
