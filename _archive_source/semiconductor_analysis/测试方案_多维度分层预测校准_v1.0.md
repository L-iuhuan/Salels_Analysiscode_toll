## 0. 总纲

### 0.1 核心目标

**将全局销售额WAPE从当前基线压低至 < 10%（最优目标）/ < 15%（可接受目标），且保证所有产品线的预测值可追溯、分层自洽。**

### 0.2 测试哲学

```
不做复杂系统 → 做校准实验
不找终极方案 → 找最优组合
不假设因子有效 → 逐轮回测验证
```

**Prometheus视角（前瞻）：** 每轮实验前问"如果这轮失败了，可能的原因是什么？"，设计对照实验消除混淆变量。

**Oracle视角（洞察）：** 每轮实验后问"这个结果意味着什么？哪些因子真的在起作用？"，只保留统计显著的因子进入下一轮。

### 0.3 实验设计原则

| 原则 | 含义 |
|---|---|
| **单一变量** | 每轮只改变一个维度，其余锁定 |
| **对照基线** | 每个实验必须有对应的基线对照组 |
| **统计显著性** | 提升必须有p值或Bootstrap验证 |
| **可复现性** | 种子固定、数据版本锁定、配置可追溯 |
| **提前注册** | 每轮开始前声明假设和成功标准 |

### 0.4 全局评价指标

| 指标 | 公式 | 权重 | 说明 |
|---|---|---|---|
| 全局销售额WAPE | Σ\|预测-实际\| / Σ\|实际\| | 50% | 主指标 |
| 全局销售额MAPE | mean(\|预测-实际\|/max(\|实际\|,ε)) | 15% | 截尾辅助 |
| 全局销售额Bias | Σ(预测-实际) / Σ实际 | 10% | 系统性偏差 |
| 全局销量WAPE | 同上 | 10% | 辅助 |
| 全局毛利额WAPE | 同上 | 10% | 辅助 |
| 全局毛利率MAE | mean(\|预测毛利率-实际毛利率\|) | 5% | 辅助 |

**综合评分 = 0.50×销售额WAPE + 0.15×销售额MAPE + 0.10×\|Bias\| + 0.10×销量WAPE + 0.10×毛利额WAPE + 0.05×毛利率MAE**

## Phase 1: 单一维度增强

每轮只改变一个变量，其余锁定为基线。

### 实验 1.1: 间歇性需求预测方法扩充

**假设：** 对C类产品线（当前WAPE > 30%），用专业的间歇性需求预测方法（Croston变体、ADIDA、TSB）替代现有简单方法，可以显著降低WAPE。

**方法：**

| 新增方法 | 来源 | 变体数 | 适用层级 |
|---|---|---|---|
| CrostonOptimized | statsforecast | 1 (自动优化α) | 产品线/产品 |
| Croston SBA | statsforecast | 3 (α=0.1/0.3/0.5) | 产品线/产品 |
| Croston SBJ | statsforecast | 1 | 产品线/产品 |
| TSB | statsforecast | 3 (α,β组合) | 产品线/产品 |
| ADIDA | statsforecast | 3 (agg_size=2/3/4) | 产品线/产品 |
| IMAPA | statsforecast | 2 (mean/median) | 产品线/产品 |
| Zero-inflated baseline | 自实现 | 1 (零值概率×非零均值) | 产品线 |

**总计新增 ~14种方法。**

**实验设计：**

| 组 | 产品线 | 方法池 | 预期 |
|---|---|---|---|
| 实验组 | C类6条（无刷/MLED/电源模组/未分类/其他） | 14种间歇性方法 + 原基线方法 | WAPE下降 |
| 对照组 | C类6条 | 仅原基线方法 | 不变 |
| 保持组 | A类/B类 | 原方法锁死 | 不变 |

**注意：** A/B类产品线方法锁死（用现有选中的最优方法），避免混淆。

**成功标准：**
- 任一C类产品线WAPE下降 ≥ 5个百分点 → 实验成功
- 所有C类产品线WAPE平均下降 ≥ 3个百分点 → 强力证据
- 如果仅部分产品线下降 → 记录差异性，做按条件启用策略

**预期结果：**
- 无刷直流电机驱动（47.2% WAPE）→ 可能降到 25-35%
- 电源模组（97.7% WAPE）→ 可能降到 50-70%（极稀疏，难大幅改善）
- 未分类（93.7% WAPE）→ 数据本身混乱，改善有限

**风险：** 间歇性方法对极短序列（< 6个有效桶）无效。如果某C类产品线有效桶数 < 4，则标记为"不可预测"，跳过本实验。

### 实验 1.2: 移动平均窗口自适应优化

**假设：** 现有系统固定窗口（如12桶），但不同产品线的最优窗口不同。通过回测自动选择每产品线的最优窗口，可以降低WAPE。

**方法：**
对每条产品线，遍历窗口 [3, 4, 6]（季度桶），对每种窗口重新回测，选择综合评分最低的窗口。

**粒度：** 产品线级（17条）和产品级（新增，之前仅有产品线级窗口选择）。

**实验设计：**

| 组 | 方法池 | 窗口 | 层级 |
|---|---|---|---|
| 实验组-产品线 | 基线方法 | 自适应 | 产品线 |
| 实验组-产品 | 基线方法+产品级变体 | 自适应 | 产品→汇总 |
| 对照组 | 基线方法 | 固定12 | 产品线 |

**成功标准：**
- 自适应窗口组的全局WAPE ≥ 对照组 → 实验失败（窗口优化有提升）
- 产品级自适应优于产品线级自适应 → 窗口粒度越细越好

**预期结果：** C类产品线可能需要更短窗口（数据少），A类可能需要更长窗口（数据丰富）。

### 实验 1.3: 产品生命周期因子初次校准——权重扫参

**假设：** 产品生命周期因子（风险等级、画像、营收-毛利判断）对预测准确性有区分力，但直接映射（"衰退期→用衰减模型"）可能过拟合。应作为加权修正项使用。

**方法：** 不做直接映射。而是：
1. 对每条产品线×季度桶，计算聚合的"生命周期健康度指标"：
   - `健康度_score` = (健康扩张+现金牛+成长型产品销售额占比) - (衰退期+夕阳+清仓产品销售额占比)
   - `风险调整系数` = 1 - (极高风险+高风险产品销售额占比 × 折扣因子)
   - `方向信号` = 减速产品销售额占比 vs 加速产品销售额占比
2. 将上述3个连续值作为**预测修正项**乘到基线预测上：
   ```
   修正后预测 = 基线预测 × (1 + α×健康度_score + β×风险调整系数 + γ×方向信号)
   ```
3. 通过网格搜索 α, β, γ ∈ [-0.5, 0.5]，步长0.05，找到使回测WAPE最小的参数组合。

**关键约束：修正项只调整幅度，不改变方向。**

**实验设计：**

| 组 | 预测基础 | 修正 | 对比 |
|---|---|---|---|
| 实验组 | 基线方法（锁定） | 生命周期因子修正 | 全局WAPE |
| 对照组 | 基线方法（锁定） | 无修正 | 全局WAPE |

**成功标准：**
- 如果全局WAPE下降 ≥ 1个百分点 → 生命周期因子有预测价值，继续深化（Phase 2）
- 如果全局WAPE下降 < 0.5个百分点 → 因子价值有限，改为仅用于置信度标记
- 如果全局WAPE上升 → 因子在本轮不可用，排除

**预期：** α/β/γ 最优值很可能不是0（即因子有信息量），但可能只在部分产品线上有用。记录每条产品线的独立最优参数。

### 实验 1.4: 新品/老品分层预测初探

**假设：** 新品（首次出货 < 12个月）和老品（出货 > 24个月）的预测行为模式不同，分开预测再汇总优于混在一起预测。

**方法：**
1. 读入 `gold_product_portrait.csv` 的 `当前画像` + `是否已达6K` 字段
2. 将每个产品线内的产品分为：
   - 新品：当前画像 = "新品观察" 或 未达6K
   - 老品：其余
3. 对老品部分用基线方法预测（数据稳定），对新品部分用：
   - 最近3桶均值 + 增长趋势方向（不预测绝对值，预测方向）
   - 同类老品早期历史曲线的类比（从同品类、同客户群的老品中找相似的早期轨迹）
4. 两组合并后与基线对比

**实验设计：**

| 组 | 老品方法 | 新品方法 | 对比指标 |
|---|---|---|---|
| 实验组 | 基线锁死 | 类比+方向 | 全局WAPE |
| 对照组 | 基线锁死 | 同基线方法 | 全局WAPE |

**成功标准：**
- 实验组WAPE ≤ 对照组 → 分层有效
- 新品部分WAPE改善 ≥ 5个百分点 → 方法论有效
- 如果无效 → 记录为"新品分层在该数据集上无显著收益"

**预期：** 新品预测几乎不可能高精度（120个新品观察中很多是真正的0历史新品），但方向预测（涨/跌/平）准确率可达60-70%。

## Phase 2: 多维组合与调和

---

### 实验 2.1: 分层调和——单产品线验证

**假设：** 在单个产品线上，用 hierarchicalforecast 对产品线级预测和产品级预测进行调和，使两个层级自洽，且调和后的汇总WAPE优于任一单层。

**方法：**
1. 选1条数据最好、结构最完整的产品线作为试点（推荐：充电与控制电源管理，当前WAPE 10%）
2. 构建该产品线的层级结构：
   ```
   产品线(顶层)
     ├── 产品品类A
     │    ├── 产品1
     │    └── 产品2
     └── 产品品类B
          └── 产品3
   ```
3. 利用 `hierarchicalforecast` 库：
   - 底层层独立预测 → 基预测
   - 逐层调和：BottomUp / TopDown(forecast_proportions) / MiddleOut / MinTrace(wls) / MinTrace(ols)
4. 记录每种调和策略的回测WAPE与基线的对比

**实验设计：**

| 组 | 基预测 | 调和策略 | 对比指标 |
|---|---|---|---|
| 实验组 | 产品+产品品类+产品线独立预测 | BottomUp→汇总 | 产品线级WAPE |
| 实验组 | 同上 | TopDown→分配 | 产品线级WAPE |
| 实验组 | 同上 | MinTrace(wls) | 产品线级WAPE |
| 对照组 | 产品线级直接预测（基线锁死） | 无 | 产品线级WAPE |

**成功标准：**
- 调和后产品线级WAPE < 基线产品线级WAPE → 调和有效
- 调和后层级自洽（底层级之和 = 高层级，误差 < 1%）→ 一致性达标

**注意：** 如果 MinTrace 要求协方差矩阵估计失败（样本太少），回退到 WLS。

### 实验 2.2: 分层调和——全产品线扩展

**前提：** 实验 2.1 成功。

**方法：** 将调和扩展到全部17条产品线，构建完整层级树：
```
全局总量
├── 产品线1 (A类) → 品类 → 产品
├── 产品线2 (A类) → 品类 → 产品
├── ...
└── 产品线17 (C类) → 产品（跳过品类，因为C类品类维度稀疏）
```

**结合 Phase 1 结论：**
- A类产品线：底层用最优方法（可能已包含间歇性方法）
- C类产品线：底层用间歇性方法或保守基线
- 调和层：自动选择最佳调和策略

**成功标准：**
- 调和后全局WAPE < 基线全局WAPE
- 调和后全局Bias绝对值 < 5%
- 无产品线因调和而显著恶化（WAPE上升 < 2pp）

### 实验 2.3: 产品生命周期因子深化——向量化因子

**前提：** 实验 1.3 成功（α/β/γ显著非零）。

**方法：** 从简单加权修正升级为向量化因子：
1. 对每条产品线，为每个季度桶生成一个特征向量：
   ```
   [健康扩张占比, 现金牛占比, 成长型占比, 衰退期占比, 夕阳产品占比,
    新品占比, 极高风险占比, 高风险占比, 低风险占比,
    加权平均风险评分, 加权平均毛利率, 加权平均毛利率趋势,
    加权平均客户集中度, 减速产品占比, 加速产品占比,
    管理层摘要_投入区占比, 管理层摘要_退出区占比]
   ```
2. 将该特征向量作为 Ridge回归 的额外特征（附加在时间趋势特征之上）
3. 回测验证：带生命周期特征的Ridge vs 不带生命周期特征的Ridge

**实验设计：**

| 组 | 特征集 | 模型 | 对比 |
|---|---|---|---|
| 实验组 | 时间特征+生命周期向量化特征 | Ridge回归 | 全局WAPE |
| 对照组 | 仅时间特征 | Ridge回归 | 全局WAPE |

**成功标准：**
- 实验组WAPE < 对照组 → 生命周期向量化有增量信息
- 如果改善 < 0.5pp → 向量化无显著增益，保留Phase 1的简单修正即可

**风险：** Ridge回归在12个数据点（季度桶）上可能过拟合。如果回测折数不足，改为只保留Top-3重要特征（通过Lasso自动选）。

### 实验 2.4: 可诊断性预评分——A/B/C自动分级 【降级为探索性附录】

> **⚠️ Oracle审查结论: 12个数据点上tsfresh特征提取+分类器训练不可行。降级为探索性分析，不纳入正式Gate决策路径。**
> 本实验保留为方案设计参考，执行优先级低。

**假设：** 可以用 tsfresh 提取的特征 + 现有回测WAPE 训练一个分类器，自动判断一条新产品线/产品序列属于A/B/C哪类可预测性等级。

**方法：**
1. 对每条产品线的季度桶销售额时序提取 tsfresh 特征（如：自相关系数、熵、线性趋势R²、季节强度、转折点数等）
2. 用现有16条产品线的WAPE作为标签（A: WAPE<20%, B: WAPE 20-40%, C: WAPE>40%）
3. 训练一个简单的规则/决策树分类器
4. 交叉验证（16条留一法）

**实验设计：**

| 步骤 | 操作 |
|---|---|
| 特征提取 | tsfresh 对每条产品线时序提取30+特征 |
| 特征筛选 | 与WAPE的相关性分析，保留Top-10 |
| 分类器 | 决策树（max_depth=3，可解释） |
| 验证 | Leave-One-Out，16折 |

**成功标准：**
- 分类准确率 ≥ 75%（12/16正确）
- 没有将C类误判为A类（假阴性比假阳性更危险）
- 特征重要性Top-3有业务可解释性

**产出：** 一个 `predictability_classifier` 函数/模型，可用于后续新数据自动分级。

## Phase 3: 组合优化与动态选择

---

### 实验 3.1: 集成策略扫参——Ensemble组合

**假设：** 多种预测方法的加权组合优于任何单一方法（Ensembe原理）。

**方法：** 对每条产品线：
1. 取回测中Top-N方法（N=3/5/7）
2. 组合方式：
   - 简单平均
   - 误差倒数加权
   - 排名倒数加权
   - 基于生命周期状态的动态选择（衰退期时给衰减方法更高权重）

**实验设计：**

| 组 | N | 组合方式 | 对比 |
|---|---|---|---|
| 对照组 | 1 | 最优单一方法（基线） | 基线WAPE |
| 实验组 | 3/5/7 | 3种组合方式 | 对比WAPE |

**成功标准：**
- 任一组合的全局WAPE < 基线最优单一方法WAPE → 集成有效
- 全局WAPE下降 ≥ 1pp → 强力证据

**预期：** 对B/C类产品线，集成效果可能更明显（单一方法误差大，集成平滑）。对A类可能改善有限（最优方法已经很准）。

---

### 实验 3.2: A/B/C分界阈值自动搜索

**假设：** 当前的A/WAPE<20%, B/20-40%, C/>40% 分界是启发式的。通过对比2-3组业务合理的阈值组合，确认最优分界。

**方法：**
对比3组阈值（当前默认值 ±20% 偏移）:
1. 默认: θ₁=18%, θ₂=35% (当前Oracle建议值)
2. 宽松: θ₁=22%, θ₂=40% (更多A类)
3. 严格: θ₁=15%, θ₂=30% (更多C类)

对每组计算全局综合评分，选择最优。

**成功标准：**
- 最优组的综合评分不差于默认组
- 分组有业务可解释性

---

### 实验 3.3: 跨层级策略自动选择

**假设：** 不同产品线的"最优预测粒度"不同——有的应该先预测产品再汇总（bottom-up），有的应该直接预测产品线（top-down），有的应该预测产品×客户再汇总。

**方法：**
对每条产品线自动在以下3种策略中选择最优：
1. **产品→汇总（bottom-up）：** 先预测每个产品，再按产品线汇总
2. **产品线直接（top-down）：** 直接预测产品线总量
3. **产品×客户→汇总（bottom-up granular）：** 先预测产品×客户组合，再汇总

选择准则：回测WAPE最低的策略即为该产品线的最优策略。

**结合 Phase 1-2 结论：** 策略选择 + 生命周期修正 + 调和，形成完整的预测链。

**成功标准：**
- 每条产品线都有明确的策略推荐
- 全局WAPE ≤ 基线全局WAPE

| 策略选择有效 | 无产品线因自动选择而恶化 | 纳入框架 |

## Phase 4: 综合验证与交付

### 实验 4.1: 滚动窗口稳健性验证

**假设：** 之前所有实验的回测都是固定折次。用滚动窗口验证（每次只移动1个验证桶）可以更严格地测试方法的泛化能力。

**方法：**
1. 对最终选择的最优配置（方法池+分层+调和+集成+修正）
2. 用10折滚动窗口回测：每次训练窗口向前滚动1个季度桶
3. 记录每折的WAPE及其方差
4. 对比基线的滚动窗口WAPE方差

**成功标准：**
- 滚动窗口平均WAPE ≤ 固定折次平均WAPE（不能差太多）
- WAPE方差 ≤ 基线WAPE方差（更稳定）
- 无折次出现极端恶化（WAPE翻倍）

### 实验 4.2: 消融实验——量化每个因子的贡献

**假设：** 最终方案是多个增强的叠加，需要量化每个增强的独立贡献。

**方法：** 从最终方案出发，每次移除一个组件（递增消融）：

| 消融步骤 | 移除内容 | 指标变化 |
|---|---|---|
| 全量 | （无） | 基线 |
| -调和 | 移除分层调和 | ΔWAPE |
| -集成 | 移除集成策略 | ΔWAPE |
| -生命周期 | 移除生命周期修正 | ΔWAPE |
| -间歇性 | 移除间歇性方法 | ΔWAPE |
| -窗口优化 | 移除自适应窗口 | ΔWAPE |
| 裸基线 | 仅剩原始552方法 | 原始基线 |

**成功标准：**
- 每个组件的移除导致WAPE上升 → 该组件有效
- 量化每个组件的贡献度（ΔWAPE），用于报告和后续决策

**预期：** 间歇性方法对C类线贡献最大，调和对A类线贡献最大，生命周期因子可能贡献较小但稳健。

### F.3 连续耦合链路分析

#### 链路1: 1.2窗口选择 → 全部后续实验
```
1.2选出"最优窗口=6"
    ↓
2.1/2.2/2.3/3.1/3.2/3.3都用窗口=6
    ↓
如果窗口=6是噪声选出来的 → 全链污染
```
**防污染：** 1.2后报告3折窗口一致性。若3折都选同一个窗口→可靠；若不一致→弃用自适应，统一用默认窗口。

#### 链路2: 1.3生命周期因子 → 2.3向量化
```
1.3发现α=0.15（p=0.07，边界显著）
    ↓
2.3投入时间做18维向量化
    ↓
2.3发现改善2pp（但在另一个时间窗口消失）
    ↓
3.1集成包含了这个向量化 → 在Phase 4消融中表现为"正贡献"
```
**防污染：** 1.3后必须做留出验证（用1个桶做holdout，不在扫参中看到），只有holdout上也改善才进入2.3。

#### 链路3: 提前淘汰导致的幸存者偏差
```
2.1失败 → Gate阻断 → 进入Phase 3时没有调和组件
3.1集成时只包含了没有调和的方法
4.3最终验收时"集成最优"——但这个"最优"是在调和没被尝试的前提下
```
**防污染：** Gate阻断 ≠ 永久放弃。Gate不通过时，记录为"本轮数据不支持"，在Phase 4最终验证时可以将被阻断的方法作为额外对比重新加入。

---

### F.4 v1.2新增3个硬保护

#### 保护1: Gate的统计加固
原Gate规则"改善 ≥ 3%"太弱。修改为：
> 改善的均值 - 1.5×标准差 ≥ 3%，且3折中至少2折改善

含义：不仅均值改善，而且改善足够稳定（方差不太大），且不是单一折拉动的。

#### 保护2: 关键实验的Holdout验证
以下实验在参数选择后，必须做额外一轮holdout验证（训练9桶→验证3桶，或训练10桶→验证2桶，从未在扫参中见到）：
- 1.2（窗口选择）
- 1.3（生命周期权重）
- 3.1（集成N和组合方式）

Holdout WAPE ≤ 训练WAPE × 1.5 → 通过（即holdout恶化不超过50%，可接受）。

#### 保护3: C类产品线诚实标记
Phase 0后对以下产品线永久标记为"低置信度预测"：
- 有效桶数 < 6 → 仅用朴素基线，不参与方法筛选
- 有效桶数 < 4 → 标记为"数据不足以支撑任何统计预测"，输出专家判断区间

这样C类线的劣质预测不会通过调和/集成污染A类线的结果。

---

### F.5 修正后的实验序列与耦合阻断点

```
Phase 0: 基线 + 朴素参照 + 预筛选 + C类诚实标记
    ↓ Gate 0
Phase 1: 1.1间歇性 → 1.2窗口(含HOLDOUT) → 1.3生命周期(含HOLDOUT) → 1.4新品分层
    ↓ Gate 1 (含统计加固)
    ↓ [分步消融: 记录各组件贡献]
Phase 2: 2.1单线调和 → [若通过] 2.2全产品线调和 → [仅若1.3通过] 2.3向量化
    ↓ Gate 2 (含统计加固)
    ↓ [分步消融]
Phase 3: 3.1集成(含HOLDOUT) → 3.2阈值 → 3.3跨层级策略
    ↓ Gate 3 (含统计加固)
    ↓ [分步消融]
Phase 4: 4.1扩展验证 → 4.2全局消融(含被Gate阻断方法的重新加入) → 4.3最终验收
```

### F.6 一句话诚实结论

**这个方案不会给你一个"奇迹方法"让WAPE从97%降到10%。它会做的事情是：(1)把A类产品线从10-15%打磨到8-12% (2)确认哪些C类线本质不可预测并诚实标记 (3)建立一个可复现的、可配置的、比当前系统更稳健的预测框架。如果你要的是第3个，方案可行；如果你要第1个，方案不可行。**

### H.3 Pipeline核心类设计

```python
class ForecastPipeline:
    """
    可配置的多维度分层预测Pipeline。
    
    使用方式:
        pipeline = ForecastPipeline("forecast_config.yaml")
        result = pipeline.run()
    """
    
    def __init__(self, config_path: str):
        self.config = self._load_config(config_path)
        self.data = None
        self.dimensions = {}
        self.forecasts = {}
        self.backtest_results = {}
        self.validation_report = {}
    
    def run(self) -> ForecastResult:
        """
        主执行流程:
        1. load_data()          → 加载+清洗+字段映射
        2. build_buckets()      → 构建时间桶(月/季/年)
        3. aggregate()          → 按配置维度聚合
        4. for each dimension:
             diagnose()         → 可诊断性评分
             select_methods()   → 为每条序列选最优方法
             backtest()         → 回测验证
        5. reconcile()          → 跨维度调和(如果启用)
        6. validate()           → 验证+生成报告
        7. export()             → 输出CSV/Excel/HTML
        """
    
    def set_dimensions(self, dimensions: list[str]):
        """
        配置要预测的维度。可单独运行任意组合:
        - ["product_line"]            → 仅产品线
        - ["product_category"]        → 仅产品品类
        - ["product"]                 → 仅产品SKU
        - ["customer_tier"]           → 仅客户分层
        - ["product_line", "product"] → 产品线+产品(含调和)
        """
    
    def set_time_granularity(self, granularity: str, periods: int):
        """
        时间粒度配置:
        - granularity: "monthly" / "quarterly" / "yearly"
        - periods: 历史期数 + 预测期数
        示例: set_time_granularity("quarterly", history=12, forecast=4)
               set_time_granularity("monthly", history=36, forecast=6)
        """
    
    def diagnose(self, dimension: str) -> DiagnosticReport:
        """
        可诊断性报告:
        - 每条序列的A/B/C等级
        - 推荐方法族
        - 置信度评估
        - 风险提示
        """
    
    def forecast(self, dimension: str) -> pd.DataFrame:
        """
        单维度预测输出。
        返回DataFrame包含: 维度值 × 时间桶 × 预测值/置信区间/方法/评分
        """
```

#### I.6.3 Orchestrator伪代码

```python
class ExperimentOrchestrator:
    """自动化实验递进编排器"""
    
    def __init__(self, sequence_yaml: str):
        self.sequence = load_sequence(sequence_yaml)
        self.master_log = MasterLog()
    
    def run_all(self):
        for exp_def in self.sequence:
            # 1. 检查依赖
            if not self._dependencies_met(exp_def):
                print(f"[SKIP] {exp_def.id}: 依赖未满足")
                continue
            
            # 2. 执行实验
            print(f"[RUN] {exp_def.id}: {exp_def.name}")
            result = self._run_experiment(exp_def)
            
            # 3. Gate检查
            gate_result = self._evaluate_gate(exp_def, result)
            
            # 4. 处理结果
            if gate_result.passed:
                print(f"[PASS] {exp_def.id}: Gate通过")
                self.master_log.record(exp_def.id, "passed", result)
            else:
                print(f"[FAIL] {exp_def.id}: Gate不通过")
                self.master_log.record(exp_def.id, "failed", result)
                
                if exp_def.on_fail == "abort":
                    print("[ABORT] 终止全部实验")
                    break
                elif exp_def.on_fail == "diagnose":
                    diagnosis = self._run_diagnosis(exp_def, result)
                    self.master_log.record_diagnosis(exp_def.id, diagnosis)
                elif exp_def.on_fail == "continue":
                    print("[CONTINUE] 记录后继续")
                elif exp_def.on_fail == "report":
                    pass  # 最终实验无论怎样都生成报告
            
            # 5. 分步消融(每个Phase末尾)
            if self._is_phase_boundary(exp_def):
                self._run_ablation(exp_def.phase)
        
        # 6. 生成最终推荐
        self._generate_final_recommendations()
```
