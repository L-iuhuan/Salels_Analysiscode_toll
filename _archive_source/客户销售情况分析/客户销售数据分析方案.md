# 客户销售数据分析方案文档

## 1 项目概述

### 1.1 背景

某 Fabless 半导体设计企业，拥有两条核心产品线，采用**直销 + 渠道代理**双模式运营。客户通过订单下达需求并完成发货，回款按**月度对账金额分 1-3 笔支付**。

当前已有销售明细数据规模约 30 万+行（一笔订单一行产品品种的线条粒度），涵盖金额、成本、毛利信息，存储于单个电子表格文件的多张工作表中。尚未建立系统化、可定期执行的客户数据分析体系。

另有一产品生命周期评估系统（v2.8）已投产运行，基于同一套销售数据，以产品品种为分析粒度输出九宫格画像和6因子风险评分。客户分析系统应与其共享数据清洗层，并做交叉引用。

### 1.2 目标

| 目标编号 | 目标描述 | 优先级 |
|---------|---------|--------|
| G1 | 基于渠道模式（直销/代理）分别构建客户分层评分模型 | P0 |
| G2 | 建立客户经营势能评估矩阵（规模/增长/盈利/稳定性） | P0 |
| G3 | 分析客户回款健康度，预警信用风险 | P0 |
| G4 | 建立产品结构迁移和价格治理分析体系 | P1 |
| G5 | 监控品种（SKU）生命周期，识别集中度风险和替代机会 | P1 |
| G6 | 追踪新品导入后的爬坡表现，形成可复用的完整追踪框架 | P1 |
| G7 | 归因销售人员贡献，识别组织依赖风险 | P1 |
| G8 | 实现渠道路径穿透，发现价差和渠道冲突 | P1 |
| G9 | 整合机会/风险评分，输出每月可执行的动作清单 | P1 |
| G10 | 建立客户→产品的下钻导航能力，从客户视角穿透到产品细节 | P1 |
| G11 | 构建准实时KPI通道，满足管理层日常监控需求 | P1 |
| G12 | 输出BI工具无关的规范化数据模型，支持后续可视化接入 | P1 |

### 1.3 非目标

以下事项不在本次方案范围内，记录为已知局限：

- 不涉及终端渠道库存数据采集（代理商sell-through）——当前无此数据，结论将标注基于出货端数据
- 不涉及设计导入（Design-In）跟踪——如未来CRM补充该数据后可扩展
- 不涉及产品代次/代际生命周期自动标注——当前无代次信息，采用首次销售日期作为代理变量
- 不涉及ERP实时接口开发——准实时通道基于T+1或更优的数据同步方式，具体取决于ERP接口能力
- 不涉及BI工具的选型、部署和行级权限配置——数据层做好标准化输出，BI接入阶段另行实施

### 1.4 与产品生命周期评估系统的关系

两套系统基于**同一销售数据源**，但分析粒度和受众不同：

| 维度 | 产品生命周期系统（现有） | 客户分析系统（本方案） |
|------|------------------------|----------------------|
| 分析粒度 | 每行 = 一个产品品种 | 每行 = 一个客户 |
| 核心框架 | 九宫格（销量动能×盈利健康）+ 6因子风险评分 | RFM-π + 10维经营画像 + 信用评分 |
| 受众 | 产品线管理团队 | 销售团队、财务团队、管理层 |
| 已有客户功能 | 基础RFM分群、客户集中度因子 | 完整的客户分层、回款分析、渠道分析、销售归因 |
| 成熟度 | v2.8已投产 | 本方案实施后交付 |

**不合并**（主键不同、受众不同、迭代节奏不同），但**通过共享数据层和交叉引用字段建立连接**：

- 共享数据清洗层：Winsorization、负销量过滤、月聚合等逻辑统一，维护一次两系统共用
- 交叉引用：客户分析引用产品画像（计算客户的产品组合健康度），产品分析引用客户分层（计算产品的客户群健康度）

## 2 数据需求

### 2.1 源数据要求

所有数据位于一个电子表格文件 (.xlsx) 中，按以下工作表组织：

| 客户编号 | 客户唯一标识 | 非空，无重复映射 |
| 客户名称 | 客户全称 | 用于核对 |
| 渠道类型 | 直销/代理 | 必须明确归类 |
| 订单编号 | 订单号 | 用于按订单去重统计频次 |
| 产品品种 | 具体料号 | 非空 |
| 产品一级分类 | 产品线 | 推荐提供（如缺失则分析受限） |

### 2.2 数据质量校验红线

以下问题必须在分析前确认并处理：

| 问题类型 | 影响范围 | 处理方式 |
|---------|---------|----------|
| 客户编号空值或重复 | 所有客户级汇总失真 | 建立统一客户主数据映射 |
| 渠道类型（直销/代理）归类不准确 | 分层模型系统性偏差 | 逐客户确认归类准确性 |
| 金额/数量负数未标明含义 | 可能是退货/冲销/折扣未区分 | 确认负数含义并标注 |
| 对账回款表的应收金额与销售明细汇总不一致 | 回款分析不匹配 | 核查差异原因 |
| 回款日期早于对账月最后一日 | 逻辑异常 | 标记为待核实记录 |
| 单价与金额/数量逻辑不一致 | 平均数口径失真 | 按加权口径重算 ASP |
| 销售负责人字段含产品类目文本 | 销售归属分析失真 | 清洗并回退至备用字段 |

### 2.3 特殊数据处理策略

**样品单识别**：当前无明确样品单标记。采用统计法初步识别——按「客户 × 产品品种」分组的单价均值和标准差，标记低于均值减两倍标准差的订单为候选异常单，输出清单供人工核验确认阈值。

**产品生命周期替代方案**：因缺少产品代次信息，采用每个品种的首次销售日期和末次销售日期推断生命周期阶段——首次出现距今不足12个月标记为「导入期」，近6个月销量较前6个月下降超过50%标记为「衰退期」，其余为「成熟期」。

**与产品生命周期系统的清洗逻辑统一**：共享以下清洗规则（已在产品系统中验证）：
- 负销量过滤：发货数量为负的记录视为退货/红冲，剔除
- 毛利率 Winsorization：钳制范围 [-50%, 75%]，在行级处理后再做月度汇总
- 最低数据要求：历史不足3个月的产品仅记录不参与分析

## 3 分析框架

### 3.1 核心设计原则

1. **渠道类型是分层变量，不是属性变量**。直销客户和代理客户分别建立评分模型，两者不混合评分。

2. **回款健康度是 B2B 信用风险评估的锚点**。所有评分中纳入回款维度，利润再高的客户若回款差则风险等级下调。

3. **每个结论标记数据约束**。缺少的字段和无法执行的维度在输出中明确标注，避免误导。

4. **输出以行动为导向**。最终产出不仅是图表，而是推演出「谁该跟进、跟进什么、优先级多高、截止何时」的动作清单。

5. **分析周期分层**。月度批量分析（客户分层、产品画像等深度计算）与准实时KPI通道（每日销售汇总）解耦，互不阻塞。

6. **BI 工具无关**。所有计算在 Python 层完成，输出为规范化的表格数据，BI 工具只做可视化展示和下钻配置。

### 3.2 维度体系总览

分析分为 **8 个核心分析维度 + 2 个顶层评分层**：

```
核心分析层（维度 01-08）：
  01 客户经营势能    —— 规模、增长、稳定性的三向判断
  02 毛利三因子拆解   —— 毛利变化归因于数量/价格/成本
  03 价格治理         —— 加权 ASP 趋势、品种价格偏离度、价格带分布
  04 产品结构迁移     —— 产品各级分类的收入占比变化
  05 品种生命周期     —— 集中度监控、品种状态机（新增/消失/放量/衰退）
  06 新品导入爬坡     —— 新品渗透率 + 月度复购 Cohort 追踪
  07 销售人员归因     —— 人效、客户份额、归属变更异常
  08 渠道路径穿透     —— 客户-代理-终端的交易网络和路径价差

顶层评分层（维度 09-10）：
  09 机会/风险评分    —— 综合各维度产生可执行的动作清单
  10 回款信用评分     —— DSO、逾期率、回款模式的客户健康度判定
```

### 3.3 维度详细设计

#### 维度 01：客户经营势能

**核心指标**：月度收入、毛利额、毛利率、加权 ASP、发货数量。

**趋势判断**：
- 月度环比（MoM）、年度同比（YoY）、滚动 3 个月趋势
- 连续增长/下滑月数
- 各渠道客户在总盘中的收入占比与毛利占比变化

**可视化输出**：四象限矩阵（收入增长率 × 毛利率，气泡大小 = 毛利额），将客户分为高增长高毛利、高增长低毛利、下滑高毛利、下滑低毛利四类。

---

#### 维度 02：毛利三因子拆解

**核心逻辑**：将客户月度毛利额的变化拆分为三个独立因子的贡献。

```
Δ毛利 ≈ Δ数量 × 期初单位毛利 + Δ销售单价 × 期末数量 - Δ单位成本 × 期末数量
```

**三因子的业务含义**：

| 因子 | 正向贡献意味着 | 负向贡献意味着 |
|------|--------------|---------------|
| 数量因子 | 客户采购量在扩大 | 需求量缩减或份额流失 |
| 价格因子 | 产品结构升级或提价成功 | 降价竞争或结构降级 |
| 成本因子 | 成本控制或规模效应显现 | 成本上升（晶圆/封测涨价或良率下降） |

**执行层级**：按 客户 → 产品一级分类 → 产品品种 三层做因子瀑布图。

---

#### 维度 03：价格治理

**核心指标**：
- 加权 ASP（金额/数量），区分客户整体 ASP 和各产品线 ASP
- 品种价格偏离度 = 客户 × 品种 ASP − 全体客户同品种中位 ASP
- 价格带分布：各品种按价格区间分档，观察低价品种收入占比变化

**业务判断规则**：

| 现象 | 可能的业务含义 |
|------|--------------|
| ASP 下滑但产品结构未变 | 客户议价压力或竞争降价 |
| ASP 下滑且低价品种占比上升 | 客户进入成本优化阶段 |
| ASP 上升但收入下降 | 高端品种未形成放量，结构升级未转化为规模 |
| 同一品种在不同客户间价格差过大 | 报价纪律问题或渠道定价失控 |

---

#### 维度 04：产品结构迁移

**核心指标**：
- 各产品线收入/毛利/毛利率占比的月度变化
- 结构贡献 = `Δ占比 × 产品线毛利率差异`（判断高毛利线是否被低毛利线稀释）

**分析方法**：
- 堆叠面积图展示每个客户的产品结构变化
- 月度热力图标记突然新增或消失的产品线
- 按渠道类型（直销/代理）分别汇总展示

**关联引用**：此维度的分析结果可通过下钻导航，穿透到具体产品的生命周期画像。

---

#### 维度 05：品种生命周期

**品种状态机**：对每个「客户-品种」组合标记月度状态

| 状态 | 判定规则 |
|------|---------|
| 新增 | 该品种在该客户首次出现于当月 |
| 持续 | 上月和当月均有发货 |
| 消失 | 上月有、当月无发货 |
| 复活 | 消失至少 1 个月后再次出现 |
| 放量 | 当月数量较上月增长超过 100% |
| 衰退 | 连续 3 个月数量下降且当月下降超过 30% |

**集中度指标**：Top N 品种收入占客户总收入比重。集中度过高（Top 3 > 70%）意味着客户依赖少数品种，替代风险大。

**关联引用**：每个客户-品种组合可携带产品生命周期画像标签（来自产品分析系统），在客户视图中直接看到"该客户在采的衰退期产品有哪些"。

---

#### 维度 06：新品导入爬坡

**核心指标**：
- 新品渗透率 = 新品收入 / 客户总收入
- 新品品种渗透率 = 该客户在采的新品品种数 / 全部新品品种数
- 新品复购率 = 首次导入后 3 个月内仍有发货的客户-品种组合数 / 首次导入组合数

**爬坡跟踪（Cohort 表）**：

```
建立客户-品种首次发货月的 Cohort 分组
追踪每组在 M0（首月）、M1、M2、...、M6 的复购情况
区分三类结果：
  - 成功爬坡：M0 后有持续 ≥3 个月的稳定发货
  - 导入后沉默：M0 后 2 个月内无后续发货
  - 持续放量：M0 后逐月增长
```

---

#### 维度 07：销售人员归因

> **注**：此维度存在数据依赖——需要销售负责人字段完整且准确。若该字段大量缺失或内容异常则跳过此维度并标注。

**核心指标**：
- 销售人员月度收入、毛利、活跃客户数、活跃品种数
- 销售人员在每个客户中的收入贡献份额
- 销售人效 = 销售毛利 / 活跃客户数（或活跃品种数）

**异常清洗**：检查销售负责人字段是否存在非人名文本（如产品类目名称），若存在则回退至备用字段，输出异常明细。

---

#### 维度 08：渠道路径穿透

> **注**：此维度适用于代理渠道的客户分析。直销渠道客户此维度不适用。

**分析内容**：
- 构建 客户名称 → 终端客户 → 代理商名称 的三级交易网络
- 同一终端客户通过不同代理商采购时：比较路径之间的 ASP 和毛利率差异
- 代理渠道集中度：Top N 代理商收入占比

**业务信号**：

| 发现 | 可能的问题 |
|------|-----------|
| 代理商切换后毛利率显著下降 | 渠道定价或返利机制需要检讨 |
| 同一终端客户多路径成交 | 需要统一客户价格策略，避免价差套利 |
| 渠道过度集中于单一代理商 | 单一渠道依赖性风险 |

---

#### 维度 09：机会/风险评分（顶层输出）

**机会评分构成**：

| 要素 | 权重 |
|------|------|
| 收入规模（近12个月） | 25% |
| 收入增长趋势（MoM/YoY） | 20% |
| 毛利质量（毛利率 × 稳定度） | 20% |
| 新品渗透率 | 15% |
| 产品线广度 | 10% |
| 回款健康度 | 10% |

**风险评分构成**：

| 要素 | 权重 |
|------|------|
| 连续下滑月数（收入/毛利） | 25% |
| ASP 跌幅（同比） | 20% |
| 毛利率跌幅（同比） | 20% |
| 品种集中度（Top 3 占比） | 15% |
| 回款逾期趋势 | 10% |
| 关键品种消失/衰退 | 10% |

**输出形式**：Top 10 机会客户列表、Top 10 风险客户列表，每条附带「核心判断 + 三条建议动作 + 负责人员」。

---

#### 维度 10：回款信用评分（顶层输出）

**核心指标**：

| 指标 | 公式 |
|------|------|
| 月度 DSO | 月末应收余额 / 近 3 个月日均销售额 |
| 回款效率 | 当月回款金额 / 当月到期应回款金额 |
| 逾期率 | 期末逾期金额 / 期末应收总额（逾期定义：超过对账日+约定账期未付） |
| 回款模式 | 该客户常用回款笔数（1笔/2笔/3笔）及变化趋势 |

**评分规则**：

| 等级 | 判定条件 | 策略 |
|------|---------|------|
| A 级 | DSO < 45 天，无逾期记录 | 正常信用政策 |
| B 级 | DSO 45-60 天，偶有逾期但快速结清 | 常规监控 |
| C 级 | DSO 60-90 天，经常逾期 | 缩短账期谈判，加强催收 |
| D 级 | DSO > 90 天或存在坏账记录 | 冻结信用，转为款到发货 |

### 3.4 与产品生命周期系统的交叉引用

#### 客户分析 → 引用产品画像

在客户分析输出中，增加以下字段（由产品生命周期系统的输出计算）：

```
每个客户：
  - 产品组合健康度：客户采购产品中各生命周期画像的占比（%）
  - 高风险产品占比：客户采购产品中，风险等级为高/极高的产品占比
  - 衰退品金额占比：客户采购产品中，处于衰退期的产品金额占比
  - 平均产品风险得分：客户采购产品的6因子风险评分加权均值
  - 主要画像品种数：每个生命周期画像标签下，客户在采的品种数

业务价值：
  如果一个客户大量采购"预警增长"和"衰退期"产品，
  该客户未来的采购量大概率会下降，应提前布局替代方案。
```

#### 产品分析 → 引用客户分层

在产品生命周期系统的输出中（如需扩展），增加以下字段：

```
每个产品品种：
  - 客户群健康度：该产品客户中，各客户分层的占比（%）
  - 信用风险客户占比：该产品客户中，信用C/D级客户占比
  - 流失预警客户占比：该产品客户中，处于流失预警状态的客户占比
  - 直销/代理比例：该产品通过直销和代理渠道的销售额占比

业务价值：
  如果一个产品的客户集中在信用差或流失预警的客户群，
  该产品的未来销量预测需要打折扣。
```

#### 客户→产品下钻路径

新增桥接数据表 `gold_customer_x_product`，用于在BI工具中实现从客户视图穿透到产品详情的导航路径：

### 3.5 已知假设与局限

| 编号 | 假设/局限 | 影响说明 |
|------|----------|----------|
| A1 | 所有订单视为实际销售（含可能的样品单） | 无样品单标记，增设异常订单比例作为控制变量 |
| A2 | 客户编号已清洗，无重复映射 | 如有集团多子账户情况需在阶段一确认 |
| A3 | 渠道类型（直销/代理）归准确认 | 混营型客户的归类原则需业务确认 |
| A4 | 产品缺少代次信息 | 生命周期分析采用首次销售日期代理，精度有限 |
| A5 | 渠道出货数据可近似反映终端需求 | 此假设在代理客户端可能不成立（存在备货/去库存波动） |
| A6 | 销售人员字段需清洗 | 如有异常值需在阶段一输出清洗清单 |
| A7 | 回款可精确匹配对账期 | 基于现有数据结构（按月对账单笔记录），此假设成立 |
| A8 | 准实时通道的ERP数据源可用 | 如ERP不支持日常导出则退回月度单次导入模式 |
| A9 | 产品生命周期系统的输出可被客户分析读取 | 需约定输出文件格式和存放路径 |

### 4.2 双通道刷新策略

| 通道 | 刷新频率 | 包含的数据 | 依赖关系 |
|------|---------|-----------|----------|
| 准实时KPI通道 | T+1（可升级到小时级） | 销售额、数量、订单数、Top排名 | 独立，仅依赖ERP原始数据 |
| 月度分析通道 | 月度全量 | 客户分层、产品画像、回款信用、机会/风险评分 | 产品分析和客户分析可并行运行，交叉引用在两者完成后进行 |

**为什么采用双通道而非单一刷新节奏**：
- 深度分析指标（客户分层、产品画像）需要12个月的数据窗口来计算增长率、健康度等——今天算和月初算结果一致，不需要每日刷新
- 管理层关注的核心KPI（今日销售额、本周累计）只需要基础汇总，不依赖深度分析——可以高频刷新
- 两个通道互不阻塞：KPI通道数据准实时更新，不影响月度分析的计算节奏

## 7 优缺点与风险评估

### 7.1 优势

| 优势 | 说明 |
|------|------|
| 行业适配 | 针对半导体设计行业的直销/代理双渠道、月度对账、双产品线特点定制 |
| 维度全面 | 覆盖经营、毛利、定价、产品、品种、新品、销售、渠道、信用、交叉10个层面 |
| 准实时能力 | 双通道架构满足管理层日常监控和深度分析的差异化需求 |
| BI工具无关 | 计算在Python层完成，Gold层为规范化表格，任何BI工具可直接消费 |
| 客户→产品下钻 | 桥接表支持从客户视图穿透到产品详情，打通两个分析域 |
| 与产品系统协作 | 共享清洗层 + 交叉引用字段，避免数据口径冲突 |
| 参数可配 | 所有阈值集中在config.py，无需改主程序逻辑即可调整分析结果 |
| 渐进交付 | 四阶段均有独立产出物，每个阶段可验收后再推进 |

### 7.2 劣势

| 劣势 | 说明 | 缓解方案 |
|------|------|----------|
| 架构复杂度提升 | 从单一批处理变为双层架构+交叉引用 | 准实时KPI通道代码仅150行，独立运行不干扰主管道 |
| BI配置工作转移 | 下钻路径、定时刷新、角色视图需在BI工具中配置 | Gold层数据做好后，BI配置是一次性的工作 |
| 双数据源时效冲突 | KPI实时数据与月度分析数据同时展示时可能混淆 | 严格的数据时效标注规范（见4.4节） |
| 产品系统依赖 | 交叉引用需要产品分析先行完成 | 可在产品分析未就绪时跳过此部分，不影响其他维度 |
| ERP接口不确定性 | 准实时通道依赖ERP的导出能力 | 如ERP不支持日更，则退回到全部月度单次导入模式 |

### 7.3 风险矩阵

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| 数据质量不达标（客户编号混乱、金额异常） | 中 | 高 | 阶段一即为质量检查，不达标先行治理 |
| 客户总数过少导致分层无统计意义（如 < 30） | 中 | 中 | 改为规则驱动分层 |
| 样品单占比大（> 20%） | 低 | 高 | 两版对照分析后判断影响 |
| 渠道类型存在大量模糊归类 | 中 | 高 | 必须逐一确认后进入分析 |
| 产品系统输出格式/时间不固定 | 中 | 高 | 交叉引用采用文件存在性检测，不存在则跳过并输出提示 |
| 销售负责人字段大面积缺失或异常 | 中 | 中 | 跳过维度07并标注 |
| ERP不支持日常数据导出（准实时通道受阻） | 中 | 中 | 退回月度单次导入模式，KPI通道降级为月度KPI |
| BI工具对跨事实表下钻支持有限 | 低 | 中 | 将产品摘要字段合并到gold_customer_x_product单表中实现下钻 |
| 分析结果与业务经验冲突 | 中 | 中 | 工具参考，最终由业务判断 |
| 缺乏新品标记字段 | 中 | 高 | 维度06无法执行，标注为因数据缺失受限 |

## 8 运行环境

### 8.1 硬件

- 操作系统：Windows / macOS / Linux
- 内存：≥ 4 GB
- 磁盘：≥ 1 GB 可用空间（含Gold层输出、历史数据归档）

### 8.2 软件与依赖

```
Python 3.9 或更高版本
所需库：
  pandas ≥ 2.0
  numpy ≥ 1.24
  openpyxl ≥ 3.1
  plotly ≥ 5.18
  scipy ≥ 1.11
  scikit-learn ≥ 1.3（可选，用于回款模式聚类）
```

### 8.3 安装命令

```bash
pip install pandas numpy openpyxl plotly scipy scikit-learn
```

### 8.4 系统定时任务配置

**准实时KPI通道**需配置定时任务（以下任选其一）：
- Windows：任务计划程序，每日指定时间执行 `python run_kpi_daily.py`
- Linux：crontab，例如 `0 8,14,18 * * * cd /path/to/customer_analysis && python run_kpi_daily.py`
- BI工具内置调度：如果BI支持直接连接ERP数据库，可由BI工具按计划刷新

**月度分析通道**建议手动触发或每月固定日期（如财务结账后第2个工作日）执行：
```bash
python run_pipeline.py
```
