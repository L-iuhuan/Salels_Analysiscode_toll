## 1. 当前问题

### 1.1 业务痛点

| 问题 | 表现 |
|------|------|
| 客户分层凭感觉 | 无法量化回答"这个客户值多少钱"，客户评级依赖销售员主观判断 |
| 只看销售额 | 销售额高但利润低、回款慢、集中度过高的客户被统一对待 |
| 反应滞后 | 客户流失后才开始补救，没有提前预警机制 |
| 管理粗放 | 大客户小客户统一管理，缺乏差异化服务策略 |
| 缺乏价格治理 | 同一产品不同客户价格差异大而不自知，利润被隐性侵蚀 |
| 新品导入无跟踪 | 新品卖给谁了、爬坡进展如何，没有系统化的追踪框架 |

### 1.2 方案目标

1. **标准化评分**：每个客户自动获得RFM-π综合评分和S/A/B/C分层
2. **风险预警**：提前识别采购中断、集中度风险、ASP侵蚀
3. **机会识别**：发现高增长潜力客户和新品渗透机会
4. **行动导向**：输出可执行的动作清单，告诉销售团队"谁该跟、跟什么"
5. **价格治理**：系统化监控客户价格偏离度，识别提价/降价空间
6. **新品追踪**：建立新品导入后的Cohort追踪框架，评估爬坡效果

## 2. 数据源与口径说明

### 2.1 数据范围

| 项目 | 说明 |
|------|------|
| 数据源 | ERP销售出货明细表（订单行级数据） |
| 可选关联表 | 客户信息表（渠道类型、客户等级、区域、业务负责人） |
| 时间跨度 | 建议 ≥ 24个月（支撑同比计算） |
| 关键字段 | 产品品种、发货日期、发货数量、金额、利润、客户编号 |
| 辅助字段 | 渠道类型、客户等级、所属区域、业务负责人、产品一级分类 |

### 2.2 分析粒度

**分析基本单元：客户（每客户一行）**

| 层级 | 用途 |
|------|------|
| 客户 | **核心分析单元**，每个客户一行全景画像 |
| 客户 × 产品 | 下钻桥梁表，用于BI穿透和品种状态分析 |
| 客户 × 月份 | 月度聚合中间表，用于趋势计算 |

### 2.3 时间窗口定义

每次分析取数据截止月为基准，**按月刷新快照**：

| 窗口 | 定义 | 用途 |
|------|------|------|
| 近12月 | 数据截止月前推12个月 | 当前状态判断 |
| 前12月 | 近12月再前推12个月 | 增长率计算的分母期 |
| 全历史 | 客户首次交易至截止月 | 历史参照计算 |
| 近3月/近6月 | 截止月前推3/6个月 | 短期趋势判断 |

### 2.4 数据清洗规则

#### 与产品生命周期系统共享

本系统与产品生命周期评估系统共用同一套数据清洗逻辑，维护一次两系统共用：

| 规则 | 处理方式 | 用途 |
|------|---------|------|
| **负销量过滤** | 发货数量 < 0 的记录直接剔除（退货/红冲） | 避免退货造成的比率失真 |
| **毛利率Winsorization** | 钳制范围 [-50%, 75%]，在行级处理后再做月汇总 | 限制极端成本录入错误，保留真实业务亏损 |
| **最低数据要求** | 历史不足3个月的客户仅记录不参与完整评分 | 避免小样本导致的评分失真 |

#### 客户信息表合并

源数据如包含"客户信息表"Sheet，自动合并以下字段：

| 字段 | 说明 |
|------|------|
| 渠道类型 | 直销/代理（作为分层变量，不混合评分） |
| 客户等级 | S/A/B/C 或 KA/AA/KM/MM（来自业务标记） |
| 所属区域 | 地理区域 |
| 业务负责人 | 对应的销售/客户经理 |

> **注**：渠道类型是分层变量不是属性变量。直销客户和代理客户分别建立评分模型，两者不混合评分。如源数据无客户信息表，渠道类型默认标记为"未知"。

## 5. 核心分析框架：RFM-π + 机会/风险评分

### 5.1 框架原理

放弃传统的一维综合得分法，改用**三维评分体系**：

1. **RFM-π基线评分**：回答"这个客户值多少分"
2. **机会评分**：回答"这个客户还有多大增长空间"
3. **风险评分**：回答"这个客户有多大概率会流失或恶化"

三者从不同角度评估客户价值，互相补充但不互相替代。

### 5.2 评分层次

```
                        ┌─────────────────────┐
                        │  顶层：S/A/B/C分层     │
                        │  RFM-π综合分映射      │
                        └──────────┬──────────┘
                                   │
            ┌──────────────────────┼──────────────────────┐
            ▼                      ▼                      ▼
    ┌──────────────┐     ┌────────────────┐     ┌──────────────┐
    │ RFM-π评分    │     │  机会评分        │     │  风险评分     │
    ├──────────────┤     ├────────────────┤     ├──────────────┤
    │ R(近度) 30%  │     │ 规模(近12月)25% │     │ 连续下滑 30% │
    │ F(频次) 20%  │     │ 增长动量 25%    │     │ ASP跌幅 20%  │
    │ M(金额) 30%  │     │ 毛利率 20%      │     │ 毛利率跌幅20% │
    │ π(新品) 20%  │     │ 新品渗透 15%    │     │ 集中度 15%   │
    │              │     │ 品种广度 15%    │     │ 中断预警 15% │
    └──────────────┘     └────────────────┘     └──────────────┘
```

### 5.3 渠道隔离原则

直销客户和代理客户**分开评分、分别分层**。原因：

- 直销客户多为终端厂商，采购量大、SKU集中、毛利高
- 代理客户为渠道分销商，采购量分散、SKU多、毛利低
- 混合评分会导致代理客户全面低于直销客户，分层失去意义

> **当前实现**：RFM-π评分使用 `pd.qcut` 五分位法，渠道类型为信息字段不直接参与评分权重。分层时可按渠道类型分别解读。

## 6. 模块功能详解

### 6.1 客户全景画像（10维）

每个客户输出一张全景画像，涵盖10个维度、60+指标：

| 维度 | 核心指标 | 计算方式 |
|------|---------|---------|
| **基本信息** | 渠道类型、客户等级、所属区域、业务负责人 | 从客户信息表合并 |
| **经营势能** | 近12月收入/毛利/毛利率、前12月收入、增长率 | 近12月 vs 前12月月均法 |
| **趋势判断** | 连续增长月数、连续下滑月数 | 近12月逐月比较 |
| **产品覆盖** | 品种总数、Top3集中度、品种集中度Top3占比 | 客户×产品聚合 |
| **产品线分布** | 产品线数、主导产品线及占比、产品线HHI | 按产品一级分类汇总 |
| **采购健康** | 常规平均采购间隔、距上次采购天数、采购中断预警 | 计算函数（见7.6） |
| **价格治理** | 加权ASP、ASP跌幅%、低价/中价/高价品种收入占比 | 价格函数（见7.5） |
| **品类接受度** | 主导品类及占比、品类机会标签 | 品类接受度函数 |
| **SKU生命周期** | 主要SKU阶段（客户采购最多的SKU所处阶段） | SKU状态机函数 |
| **新品渗透** | 新品采购额、新品品种数、新品采购占比、是否采购新品 | Cohort追踪函数 |

### 6.2 RFM-π评分模型

#### 设计理念

传统RFM模型（R=最近购买、F=频次、M=金额）适用于B2C场景，B2B芯片行业需要调整：

- **R（近度）**：距上次采购天数，越小越好
- **F（频次）**：常规平均采购间隔，间隔越小频率越高
- **M（金额）**：近12月毛利总额，越大越好
- **π（新品渗透）**：新品采购占比，越高代表客户接受新品能力越强

> **为什么用"毛利"替代"营收"作为M维度？** B2B芯片行业中，营收高不一定价值高——大量采购低毛利产品的大客户可能实际贡献有限。毛利更真实反映客户对公司的利润贡献。

#### 评分方法

每个维度使用五分位法（`pd.qcut`）打分1-5分：

| 维度 | 方向 | 5分 | 4分 | 3分 | 2分 | 1分 |
|------|------|-----|-----|-----|-----|-----|
| R（距上次采购天数） | 反向 | 最近20% | 次近20% | 中间20% | 次远20% | 最远20% |
| F（平均采购间隔） | 反向 | 最短20% | 次短20% | 中间20% | 次长20% | 最长20% |
| M（近12月毛利） | 正向 | 最高20% | 次高20% | 中间20% | 次低20% | 最低20% |
| π（新品采购占比） | 正向 | 最高20% | 次高20% | 中间20% | 次低20% | 最低20% |

#### 权重配置（默认）

| 维度 | 权重 | 理由 |
|------|------|------|
| R（近度） | **30%** | B2B客户黏性强，最近购买是活跃度的最直接信号 |
| F（频次） | 20% | B2B采购频次比B2C低，权重适中 |
| M（金额） | **30%** | 毛利贡献是B2B客户价值的核心衡量 |
| π（新品） | 20% | 新品渗透反映客户成长性和技术接受度 |

#### 分层标准

| 综合分范围 | 层级 | 含义 |
|-----------|------|------|
| ≥ 4.0 | **S级** | 核心价值客户 |
| 3.5 ~ 4.0 | **A级** | 高价值客户 |
| 2.5 ~ 3.5 | **B级** | 中等价值客户 |
| < 2.5 | **C级** | 待提升客户 |

### 6.3 机会评分模型

#### 设计理念

机会评分回答"这个客户还有多大增长空间"。机会维度越高，越值得投入资源。

#### 评分因子

| 因子 | 权重 | 数据来源 | 业务含义 |
|------|------|---------|---------|
| **收入规模** | 25% | 近12月收入 | 规模大的客户有更大的再开发基础 |
| **增长动量** | 25% | 增长动量信号 | 高增长客户值得继续投入 |
| **毛利率** | 20% | 近12月毛利率 | 高毛利意味着盈利能力强 |
| **新品渗透率** | 15% | 新品采购占比 | 接受新品的客户有增长潜力 |
| **品种广度** | 15% | 在采品种数 | SKU覆盖广意味着合作深度 |

#### 评分方法

每个因子使用Min-Max归一化转为0-100分，按权重加权求和：

```
机会分 = 规模分×25% + 增长分×25% + 毛利率分×20% + 新品分×15% + 广度分×15%
```

#### 分级标准

| 机会分 | 机会等级 | 建议策略 |
|-------|---------|---------|
| ≥ 80 | 极高 | 重点投入，配备专属资源 |
| 60 ~ 80 | 高 | 适度投入，定期跟进 |
| 40 ~ 60 | 中 | 标准维护 |
| < 40 | 低 | 被动响应 |

### 6.4 风险评分模型

#### 设计理念

风险评分回答"这个客户有多大概率会流失或恶化"。风险越高，越需要提前干预。

#### 评分因子

| 因子 | 权重 | 数据来源 | 业务含义 |
|------|------|---------|---------|
| **连续下滑月数** | 30% | 近12月收入逐月比较 | 持续下滑是最大风险信号 |
| **ASP跌幅** | 20% | 客户ASP vs 全市场ASP | ASP持续下跌意味着议价能力弱化 |
| **毛利率跌幅** | 20% | 当前毛利率 vs 前12月毛利率 | 毛利率下降意味着盈利恶化 |
| **品种集中度** | 15% | Top5集中度 ≥ 70% 标记 | 过度依赖少数SKU，替代风险大 |
| **采购中断预警** | 15% | 距上次采购 > 1.5倍常规间隔 | 采购中断是流失的前兆 |

#### 评分方法

每个因子使用Min-Max归一化转为0-100分，按权重加权求和：

```
风险分 = 下滑月数分×30% + ASP跌幅分×20% + 毛利率跌幅分×20% + 集中度分×15% + 中断预警分×15%
```

#### 分级标准

| 风险分 | 风险等级 | 行动频率 |
|-------|---------|---------|
| ≥ 80 | 极高 | 立即联系，周度跟踪 |
| 60 ~ 80 | 高 | 双周跟踪，加入预警清单 |
| 30 ~ 60 | 中 | 月度跟踪 |
| < 30 | 低 | 季度跟踪 |

### 6.5 价格治理体系

#### 6.5.1 加权ASP计算

```
客户加权ASP = 客户近12月总金额 ÷ 客户近12月总数量
全市场ASP   = 全市场近12月总金额 ÷ 全市场近12月总数量
ASP跌幅%    = (客户ASP - 全市场ASP) ÷ 全市场ASP × 100
```

#### 6.5.2 价格带分布

对每个客户采购的产品按单价分三档：

| 价格带 | 定义 | 业务含义 |
|--------|------|---------|
| 低价品种 | 单价低于全市场中位价 | 可能为低端产品或促销品 |
| 中价品种 | 单价在全市场中位价±30%内 | 主流价格区间 |
| 高价品种 | 单价高于全市场中位价×1.3 | 高端产品或溢价产品 |

输出各价格带的收入占比，观察客户是否向低价产品迁移。

#### 6.5.3 跨客户价格离散度

对每个产品，计算不同客户间单价的变异系数（CV）：

| CV范围 | 判断 | 业务含义 |
|--------|------|---------|
| CV < 0.15 | 价格统一 | 报价纪律良好 |
| 0.15 ~ 0.30 | 轻微偏离 | 可按客户体量差异定价 |
| CV ≥ 0.30 | 价格混乱 | 报价缺乏纪律，需审计 |

#### 6.5.4 提价机会识别

判断客户×产品组合是否具备提价空间：

- 条件1：该客户的实际成交价 < 全市场中位价 × 0.90
- 条件2：该客户采购量不超过该产品总销量的30%
- 条件3：该客户持续交易 ≥ 6个月

满足全部条件则标记为"有提价空间"。

#### 6.5.5 降价策略试算

对处于成熟期/衰退期的产品，按多档降价幅度模拟：

| 参数 | 默认值 |
|------|-------|
| 降价档位 | 3%、5%、8%、10% |
| 弹性系数 | −1.0（固定默认值） |
| 盈亏平衡缓冲 | 目标销量 ≥ 盈亏平衡销量 × 1.2 |
| 总毛利增长目标 | ≥ 10% |
| 新毛利率底线 | ≥ 公司整体毛利率 × 0.80 |

### 6.6 采购健康度分析

#### 6.6.1 常规平均采购间隔

```
有效月份 = 总月份 - 前N个月（新品观察期）
常规平均采购间隔 = 有效月份 ÷ 有效采购次数
```

- 剔除新品观察期（默认前6个月），防止爬坡期短间隔拉偏均值
- 仅统计有发货的月份（连续零采购月份不计数）

#### 6.6.2 采购中断预警

```
预警阈值 = 常规平均采购间隔 × 1.5（默认倍率）
距上次采购天数 > 预警阈值 → 触发"采购中断预警"
```

| 距上次采购天数 | 状态 |
|--------------|------|
| > 90天 | 疑似流失 |
| > 180天 | 高危流失 |

#### 6.6.3 产品集中度

```
Top5集中度 = 前5大产品采购额 ÷ 总采购额
强依赖标记：Top5集中度 ≥ 70%
```

#### 6.6.4 品类接受度

```
主导品类占比 = 最大品类采购额 ÷ 总采购额
品类机会标签：客户未采购某品类但同类客户普遍采购时标记
```

### 6.7 SKU生命周期状态机

对每个产品品种，计算其在全市场层面的生命周期阶段：

| 阶段 | 判定规则 |
|------|---------|
| **导入期** | 首次销售距今 ≤ 12个月（`new_product_max_months`），且累计销售金额 ≥ 1000 |

## 7. 指标计算公式全集

### 7.1 基础指标

#### 7.1.1 近12月收入

$$
\text{近12月收入} = \sum_{\text{近12月}} \text{金额}
$$

#### 7.1.2 近12月毛利率

$$
\text{近12月毛利率} = \frac{\displaystyle\sum_{\text{近12月}} \text{Winsorized利润}}{\displaystyle\sum_{\text{近12月}} \text{金额}} \times 100\%
$$

利润列使用Winsorization处理后的值（钳制[-50%, 75%]），毛利率为滚动合计值而非单月平均。

#### 7.1.3 收入增长率（月均法）

$$
\text{近12月月均收入} = \frac{\text{近12月总收入}}{\text{近12月有收入的月数}}
$$

$$
\text{前12月月均收入} = \frac{\text{前12月总收入}}{\text{前12月有收入的月数}}
$$

$$
\text{收入增长率} = \frac{\text{近12月月均收入} - \text{前12月月均收入}}{\text{前12月月均收入}}
$$

**月均法的必要性**：部分客户在某个窗口内只有部分月份有交易数据（如新客户在前12月窗口只有5个月数据）。直接总量比会低估增长率。月均法消除窗口月份数不一致的影响。

**窗口自动缩短**：如果前12月窗口完全无数据，增长率计为0。

#### 7.1.4 加权ASP

$$
\text{ASP}_\text{加权} = \frac{\text{近12月总收入}}{\text{近12月总数量}}
$$

#### 7.1.5 ASP跌幅（vs全市场）

$$
\text{ASP跌幅\%} = \frac{\text{客户ASP} - \text{全市场ASP}}{\text{全市场ASP}} \times 100
$$

全市场ASP为所有客户×产品近12月的加权平均ASP。

#### 7.1.6 毛利率跌幅

$$
\text{毛利率跌幅\%} = \frac{\text{当前毛利率} - \text{前12月毛利率}}{\text{前12月毛利率}} \times 100
$$

### 7.2 RFM-π评分指标

#### 7.2.1 R得分（近度）

使用`pd.qcut`将客户的距上次采购天数排5等份（标签1-5），小值高分（反向计分）。

#### 7.2.2 F得分（频次）

使用`pd.qcut`将客户的常规平均采购间隔排5等份（标签1-5），小值高分（反向计分）。

#### 7.2.3 M得分（金额）

使用`pd.qcut`将客户的近12月毛利排5等份（标签1-5），大值高分（正向计分）。

#### 7.2.4 π得分（新品渗透）

使用`pd.qcut`将客户的新品采购占比排5等份（标签1-5），大值高分（正向计分）。

#### 7.2.5 RFM-π综合分

$$
\text{RFMπ综合分} = \text{R得分} \times 30\% + \text{F得分} \times 20\% + \text{M得分} \times 30\% + \text{π得分} \times 20\%
$$

### 7.3 机会评分指标

#### 7.3.1 增长动量

来自`calc_opportunity_signals`函数，综合收入增长率和增长趋势的信号值。

#### 7.3.2 机会分

$$
\text{机会分} = \sum (\text{因子}_i \text{归一化得分} \times \text{权重}_i)
$$

各因子Min-Max归一化：$\text{归一化得分} = \frac{x - x_{\min}}{x_{\max} - x_{\min}} \times 100$

权重默认值：规模25%、增长25%、毛利率20%、新品渗透15%、品种广度15%。

### 7.4 风险评分指标

#### 7.4.1 连续下滑月数

近12个月中，收入逐月下降的连续月数最大值。

#### 7.4.2 风险分

$$
\text{风险分} = \sum (\text{因子}_i \text{归一化得分} \times \text{权重}_i)
$$

各因子Min-Max归一化（同机会评分）。

权重默认值：连续下滑30%、ASP跌幅20%、毛利率跌幅20%、品种集中度15%、采购中断预警15%。

### 7.5 价格治理指标

#### 7.5.1 价格偏离度

$$
\text{价格偏离度} = \frac{\text{客户×品种成交价} - \text{全市场中位价}}{\text{全市场中位价}} \times 100
$$

#### 7.5.2 价格带分布

以全市场中位价为基准分三档：

$$
\text{价格带}_i \text{收入占比} = \frac{\text{价格带}_i \text{收入}}{\text{客户总收入}}
$$

其中价格带_i ∈ {低价 (< 中位价), 中价 (中位价±30%), 高价 (> 中位价×1.3)}

#### 7.5.3 价格离散度(CV)

$$
\text{CV} = \frac{\text{各客户间单价的样本标准差}}{\text{各客户间单价的均值}}
$$

### 7.6 采购健康指标

#### 7.6.1 常规平均采购间隔

$$
\text{有效月数} = \max(\text{总月数} - \text{新品期月数}, 1)
$$

$$
\text{常规平均采购间隔} = \frac{\text{有效月数}}{\text{有效采购次数}}
$$

#### 7.6.2 产品集中度(Top N)

$$
\text{Top5集中度} = \frac{\sum_{i=1}^{5} \text{前5大品种采购额}}{\text{总采购额}}
$$

### 7.7 SKU生命周期判定

#### 7.7.1 导入期

```python
首次销售距今 <= new_product_max_months（默认12）
且 累计销售金额 >= new_product_min_volume（默认1000）
```

#### 7.7.2 爬坡期

```python
近3月发货数量环比增长率 >= 爬坡期环比阈值（默认0.15）
```

#### 7.7.3 成熟期

```python
近6月发货数量在 均值 ± 成熟期标准差倍数（默认1.5）× std 的范围内
```

#### 7.7.4 衰退期

```python
连续3月发货数量低于 均线 × (1 - 衰退期跌幅阈值（默认0.15）)
```

### 7.8 Cohort新品追踪指标

#### 7.8.1 新品采购占比

$$
\text{新品采购占比} = \frac{\text{新品采购总额}}{\text{客户总采购额}}
$$

#### 7.8.2 新品品种渗透率

$$
\text{新品品种渗透率} = \frac{\text{客户在采的新品品种数}}{\text{全部新品品种数}}
$$

| `margin_decline` | 20% | 毛利率跌幅% |
| `concentration` | 15% | 强依赖标记 |
| `churn_warning` | 15% | 采购中断预警 |

> 原方案中回款信用评分权重（机会10% + 风险10%）因数据未就绪已吸收至其他维度。机会评分：增长吸收5%+广度吸收5%；风险评分：下滑月数吸收10%。

### 11.3 关键判断逻辑

#### 增长率计算逻辑

```python
if 前12月有效月数 >= 2 and 前12月总收入 > 0:
    增长率 = (近12月月均 - 前12月月均) / 前12月月均
else:
    增长率 = 0  # 窗口不足或零收入
```

#### 采购中断预警逻辑

```python
预警阈值 = 常规平均采购间隔 × 1.5
if 距上次采购天数 > 预警阈值:
    标记"采购中断预警"
```

#### 强依赖标记逻辑

```python
Top5集中度 = Top5品种采购额 / 总采购额
if Top5集中度 >= 0.70:
    标记"强依赖"
```

#### 新品判定逻辑

新品判定采用**优先级机制**：

1. **ERP标记优先**：如果源数据包含"是否新品"字段（ERP提供），则直接使用该标记。
   - 产品在近12个月内如有任一行标记为"是"，即判定为新品品种。
   - ERP标记由业务端定期维护（通常在约12个月后清除标记），比系统自动判定更准确。

2. **系统自动回退**：如果源数据无"是否新品"字段，使用自动计算：
   ```python
   if 首次销售距今 <= 12个月 and 累计销售额 >= 1000:
       标记为"新品品种"
   ```

> **历史变更**：原方案仅使用系统自动判定（首次销售日≤12月+金额≥1000）。v2.10 改为以ERP"是否新品"字段为优先、自动计算为回退的双轨制，确保两系统（产品生命周期 + 客户分析）共用统一的判定标准。

## 12. 隐患与不足

### 12.1 数据层面的隐患

| 隐患 | 影响 | 缓解措施 |
|------|------|---------|
| 客户编号混乱（一客多号/多客一号） | 客户级汇总失真 | 建议建立统一客户主数据映射 |
| 渠道类型归类不准 | 导致分层偏差 | 需业务逐一确认归类准确性 |
| 业务负责人字段含非人名文本 | 销售归因无法执行 | 当前已跳过此维度 |
| 回款数据未就绪 | 无法分析DSO和信用风险 | 权重已吸收至其他维度 |
| 产品分类缺失或混乱 | 品类接受度分析受限 | 基于产品一级分类做兜底 |

### 12.2 模型层面的隐患

| 隐患 | 说明 |
|------|------|
| 评分依赖客户间相对排序 | RFM-π使用五分位法，客户数过少（< 30）时分层无统计意义 |
| 机会/风险评分的截断问题 | Min-Max归一化对极端值敏感，单客户极端值会挤压其余客户的区分度 |
| 无法区分"主动收缩"和"被动流失" | 连续下滑可能是客户主动优化供应链，也可能是被竞争对手替代 |
| 新品定义依赖时间窗口 | 12个月窗口为固定值，品类差异大时可能不适用 |

### 12.3 功能层面的局限

| 局限 | 说明 | 规划 |
|------|------|------|
| 无回款信用评分 | 因数据未就绪，回款维度未纳入评分 | 待对账回款表就绪后恢复 |
| 无销售归因 | 销售负责人字段质量不可控 | 待字段清洗完成后实施 |
| 无渠道穿透 | 缺少代理商/终端客户数据 | 待数据补充后实施 |
| 无购物篮分析 | 交叉销售推荐未实现 | 规划功能（详见附录） |
| 无工作日调整 | 分析基于自然月，未消除月份天数差异 | 规划功能（详见附录） |

```
[Phase 1] 加载 → 清洗 → Silver层 → 保存中间件(pickle)
[Phase 2] 加载中间件 → 功能验证 → 保存诊断CSV
[Phase 3] 读取诊断数据 → 生成可视化图表 → 输出测试报告
```

- **Phase 1** 仅执行一次（~200s），中间件存为 `.pkl` 供后续阶段快速复现
- **Phase 2-3** 可在调整参数后快速重跑（跳过数据加载）

### 15.3 测试用例模板

每个批次定义6~8项 `[TEST A-F]` 功能验证，覆盖：

| 测试类型 | 验证内容 | 判定标准 |
|---------|---------|---------|
| 列存在性 | 断言某列是否在DataFrame中 | `assert col in df.columns` |
| 值分布 | 统计关键字段的分布比例是否合理 | ±20% 容忍区间 |
| 对比验证 | 新旧逻辑的结果差异(如ERP vs 自动) | 记录差异但不拦截 |
| 边界场景 | NaN填充、空数据集、极值截断 | 不抛异常 |
| 耗时 | 各阶段执行时间 | 记录作为性能基线 |

### 15.4 可视化产出

每次测试自动生成5张图表，用于业务校验：

| 图表 | 用途 | 生成代码 |
|------|------|---------|
| 01_产品画像分布 | 检查新品观察/成长期/衰退期比例是否合理 | `portrait['当前画像'].value_counts()` → barh |
| 02_客户生命周期饼图 | 检查流失期/爬坡期/导入期占比 | `stages['客户生命周期'].value_counts()` → pie |
| 03_新品渗透分析 | 检查新品采购占比分布 + 渗透率 | `cohort['新品采购占比']` → hist + pie |
| 04_月度新品趋势 | 监控新品标记随时间的变化 | `prod_monthly` 按_月聚合 → bar+line |
| 05_新旧逻辑对比* | 验证变更影响范围（仅批次A首次执行） | ERP vs自动计算 → 分组柱图 |

> *05号图表仅在首次切换逻辑时生成，后续批次不重复输出。

### 15.6 回退策略

若批次变更测试不通过：
1. **代码回退**: `git revert` 回退变更文件
2. **参数回退**: `settings.py` 中还原配置参数
3. **数据清理**: 删除 `output/test_diag/` 重新测试
4. **快速验证**: 因中间件存在，Phase 2-3 仅需 ~30s
