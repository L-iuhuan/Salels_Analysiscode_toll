# 风险模型改造方案 v2.8→v2.9

## 一、问题背景

v2.8 使用 6 因子加权评分模型（毛利率斜率、客户集中度、CV、增速衰减、历史对照、ASP趋势），经实际 681 款产品数据验证，发现以下系统性偏差：

| 问题 | 表现 | 严重程度 |
|------|------|---------|
| 隐性衰退被低估 | 隐性衰退组均分 28.7（全场最低），64.6% 被打为低风险 | 致命 — 与事实完全相反 |
| 成长期被高估 | 成长期均分 42.6，高于隐性衰退和健康扩张 | 严重 — 增长型产品被误判 |
| 增速衰减惩罚自然减速 | 成长期 F4=52.5，隐性衰退 F4=24.3 — 衰减因子反向区分 | 严重 — 因子方向性错误 |
| 客户集中度反向相关 | 因子2 与生命周期阶段呈逆相关（隐性衰退集中度最低） | 严重 — 信号噪音 |
| 分布太集中 | 63.4% 挤在中风险，风险区分度不足 | 中等 |

## 二、调整后的因子分布

### 5 因子模型（含 CV）

| 序号 | 因子名称 | 权重 | 功能 | 说明 |
|------|---------|------|------|------|
| F1 | 毛利率趋势斜率 | 20% | 检测利润率侵蚀速度 | 不变，阈值不变。含CV时从0.25等比缩至0.20 |
| F3 | 订货波动性(CV) | 10% | 检测订单波动风险 | **阈值放宽**（0.3→0.5/0.7→1.0/1.0→1.5），成长期不会因高CV被过度罚分 |
| F4 | 增速衰减 | 20% | 检测增长势头恶化 | **内部算法升级**为增长率感知 v4，config 名称不变。含CV时从0.25等比缩至0.20 |
| F5 | 自比健康度(SH) | 35% | 检测盈利水位 | **新增**，健康度越低风险越高（30%→90分，50%→70分，70%→40分，>70%→10分） |
| F6 | ASP趋势 | 15% | 检测价格战风险 | 不变，阈值不变。含CV时从0.20等比缩至0.15 |

**原 F2（客户集中度）** 和 **原 F5（同类历史对照）** 被移除。

```python
def risk_self_health(health_pct, thr):
    """自比健康度 → 风险得分：健康度越低风险越高
    注意：health_pct 可能为小数(0~1)或百分比(0~100)，函数自动判别。"""
    if pd.isna(health_pct):
        return int(thr.get("健康度_默认分值", 50))
    pct = health_pct * 100 if health_pct < 2 else health_pct  # 兼容小数
    low  = float(thr.get("健康度_低分阈值%", 70))
    mid  = float(thr.get("健康度_中分阈值%", 50))
    high = float(thr.get("健康度_高分阈值%", 30))
    if pct >= low:
        return 10
    elif pct >= mid:
        return 40
    elif pct >= high:
        return 70
    else:
        return 90
```

#### D6. `risk_decay` → `risk_decay_v4`（第947-968行）
名称保持 `risk_decay`，但内部逻辑改为增长率感知版本：

```python
def risk_decay(decay_val, yoy_change, thr):
    """因子4：增速衰减 → 风险得分（v2.9: 增长率感知版本）
    
    核心逻辑：同样的衰减值，在不同增长率下含义完全不同。
    - 增长率 > 50%（快速正增长）：自然减速 → 低风险（≤15pp=10分, >15pp=30分）
    - 增长率 ≤ -10%（已萎缩）：衰减值已不是主信号 → 偏高-高风险
    - 正常区间：使用原阈值逻辑
    """
    t_yoy  = float(thr.get("衰减_同比下降高分线", -0.10))
    t_high = float(thr.get("衰减_高分阈值(pp)", -10))
    t_mid  = float(thr.get("衰减_中分阈值(pp)", 0))
    default = int(thr.get("衰减_默认分值", 20))
    
    if pd.isna(decay_val):
        return default
    
    # 增长率感知分支
    if yoy_change is not None and yoy_change > 50:
        # 快速正增长：自然减速，低风险
        if decay_val <= t_mid:
            return 10
        elif decay_val <= t_high:
            return 30
        else:
            return 50
    elif yoy_change is not None and yoy_change <= -10:
        # 已负增长：衰减值不是主信号
        if decay_val <= 0:
            return 80
        elif decay_val <= t_mid:
            return 70
        elif decay_val <= t_high:
            return 60
        else:
            return 50
    else:
        # 正常区间：原阈值逻辑
        if yoy_change is not None and yoy_change < t_yoy:
            return 80
        elif decay_val < t_high:
            return 70
        elif decay_val < t_mid:
            return 50
        else:
            return default
```

## 四、修改原因

### 为什么移除客户集中度（F2）
- 与生命周期阶段呈逆相关：衰退期集中度最高(0.64)，隐性衰退最低(0.51)
- 逆向选择：客户集中度低的企业更容易被误判为低风险
- 与SH相关度 r=0.36，贡献信息量有限

### 为什么移除同类历史对照（F5）
- 49% 产品标记 HL（历史参照不足），默认分50，相当于噪音注入
- 与生命周期阶段相关度低，区分能力弱
- 权重仅5%，边际贡献小

### 为什么新增自比健康度（SH）
- 与生命周期阶段**最相关**的单一指标：隐性衰退 SH=12.5%→80分，成长期 SH=89.5%→10分
- 与F1斜率正交（r=0.065），提供独立的风险视角
- 作为"水位线"因子，捕获盈利水平的绝对恶化程度
- 对隐性衰退特别有效：这是原模型中最大的漏洞

### 为什么增速衰减升级为增长率感知
- 原问题：成长期（yoy=+89.5%）自然衰减27.8pp被判85分，隐性衰退（yoy=+12.5%）微改善-1.2pp被判10分 — 完全反直觉
- 核心修正：高增长率下的衰减是自然现象，不应惩罚；已负增长的产品，衰减值意义不同

### 为什么改阈值 30/60/80 → 25/50/75
- 新模型下总分分布更分散，隐性衰退中位数~55，原 30/60/80 会导致隐性衰退集中在中风险
- 25/50/75 确保：隐性衰退→高风险，成长期→低风险，分布呈金字塔形
