## 详细发现

### P0-5-1: `scoring.py` MinMax归一化前 `fillna(0)` 扭曲分布

- **文件**: `customer_analysis/scoring.py:47,49`
- **机制**: 第47行`df[col] = df[col].fillna(0)` → 第49行`(x - x.min()) / (x.max() - x.min())`
- **问题链**: 对某一评分因子，若某客户该字段缺失→填0→参与MinMax计算→若0恰好是全局最小值→该客户得0分；若所有缺失客户被填0→0值数量膨胀→MinMax的分母受噪声影响→整个评分分布偏置
- **业务影响**: 缺失数据越多的客户，评分越偏向50分中位数（前轮发现的`_minmax_norm`特性），产生"数据越少评分越中庸"的悖论——系统对无数据客户反而给出看似合理的中间分
- **归因**: B（代码逻辑偏差）— 应标记缺失而非填0参与归一化

### P1-5-1: 假阳性输出 — `scoring.py` 全0客户得分50

- **文件**: `customer_analysis/scoring.py:47-49`（同上路径延伸）
- **机制**: 若某客户对所有因子均缺失→`fillna(0)`后全部填充0→MinMax(0, 0)时为常数序列→`_minmax_norm`回退到全50分（第3轮已确认）→下游评分合并后该客户依然得到看似合理的50分
- **业务表现**: 一个没有任何数据的客户，最终评分50/100 → "看起来正常，实际全为回退"
- **诊断特征**: 评分50均匀分布且`std=0`的客户集群——应在管道中标记并隔离
- **归因**: B（代码逻辑偏差）+ A（数据不足）

### P1-5-2: `九宫格`假阳性 — F42缺失字段→"确认退市"

- **文件**: `product_lifecycle/nine_grid.py:42`（第2轮已报F42）
- **机制**: 缺失字段→`fillna(0)`→衰退风险=0(低风险)/市场规模=0(无市场)→9宫格判定为空值处理→退市建议→`decline_product_flag(True)`和`确认退市策略概要`
- **业务表现**: 一个因数据缺失无法评分的产品，被系统标记为"确认退市"。业务方看到这个标签会认为分析模型做出了有依据的判断，实际是fallback链路的终点
- **归因**: B（代码逻辑偏差）— 缺失应传播为NaN而不是0→退市

### P1-5-3: 仅有产品画像有质量标记，其他20个Gold文件全无

- **文件**: `output/gold/` 全部21个CSV
- **仅有**: `gold_product_portrait.csv` 有 `数据质量标记` 字段（8种标记码：全满分默认值_评分稳定性不足_无实际出库量_价格数据缺失_参数校准异常_样本量不足等）
- **占比**: 56%产品"全部可靠"（无标记）、24%有质量标记、20%完全NaN
- **缺失**: `gold_customer_portrait.csv` 没有质量标记、`gold_customer_score.csv` 没有、`gold_customer_trend*.csv` 全部没有、`gold_product_strategy.csv` 没有、`gold_portfolio*.csv` 全部没有
- **业务风险**: 下游BI看板/报表消费这些数据时，无法区分"这是可靠计算结果"和"这是fillna回退值"。一旦某个客户或产品的字段大部分是回退拼凑的，看板上看起来与其他数据无异
- **归因**: C（设计缺失）— 全管道缺失数据血统(data lineage)追踪

### P1-5-4: `silver层`数据无缓存标记/过期检测

- **文件**: `run_all.py` stage_silver（AGENTS.md已记录）
- **机制**: `SKIP_SILVER_IF_EXISTS=True` → 仅检查文件是否存在，不检查文件年龄/内容哈希/配置版本
- **风险**: 修改`ERP_COL_MAP`、清洗逻辑或新增字段后，silver层缓存静默使用旧数据→gold层输出不一致→无任何告警
- **对比**: test/pickle缓存有`--force`参数，silver层无对应机制
- **归因**: C（配置/体验缺陷）— 应增加缓存过期检测或版本校验

### P2-5-1: 客户生命周期阶段置信度缺失

- **文件**: `customer_analysis/models.py`
- **机制**: 44.4%客户被归为"流失期"，但无任何置信度指标说明"这是基于多少数据做出的判断"
- **风险**: 如果一个客户仅有1条出库记录（存在），也被归入某个生命周期阶段，结论与有3年数据的客户无从区分
- **归因**: A（数据不足）+ C（设计缺失）

### P2-5-2: `低量品标记`被下游静默忽略

- **文件**: `product_lifecycle/profiling.py` → `nine_grid.py`
- **机制**: profiling.py正确标记了低量品（筛选特征），但nine_grid.py的F42中并未特判低量品标记使其跳过策略生成→低量品依然进入产品矩阵和退市决策流程
- **业务影响**: 低量品（数据不足以做可靠分析）被当作正常产品产出策略建议
- **归因**: B（逻辑漏洞）— 低量品标记仅在profiling阶段可用，未传播到下游消耗方

## 假阳性输出清单 (False Positive Output Registry)

以下输出路径在"看起来正常"的外表下隐藏了fallback：

| 输出类型 | Fallback链 | 外表 | 真相 | 检测方法 |
|----------|-----------|------|------|----------|
| 客户评分50分 | fillna(0)→MinMax常数→全50 | 正常中等评分 | 无数据客户 | 检查std=0的评分 |
| 产品评分>100 | 分母错误→分数量出 | 高分产品 | 公式溢出 | 裁切或检查>100记录 |
| 确认退市 | 缺失→0→退市判定 | 有依据的决策 | NaN→回退 | 检查原始数据充足度 |
| 生命周期阶段 | 单条记录→也分阶段 | 有阶段标签 | 无数据支撑 | 检查客户记录数<=N |
| 行业评级 | 未知客户→默认 | 正常评级分布 | 40.3%未知 | 检查未知占比 |

## 修复建议

### 立即修复（P0，阻塞型）
1. **`scoring.py:47-49`**: 缺失客户因子不参与MinMax归一化；归一化后标记缺失率高于50%的客户为"低置信度"
2. **`scoring.py:_minmax_norm`**: 输入NaN或常数序列时返回NaN而非全50

### 短期修复（P1，高影响）
3. **全管道质量标记**: 为所有Gold CSV增加至少一个`数据质量`或`置信度`列。第一阶段仅在产出层增加标记，不改变计算逻辑
4. **九宫格NaN链路**: 缺失字段→NaN传播→最终显示"数据不足"而非伪决策
5. **`nine_grid.py`低量品特判**: 读取`低量品标记`并在策略生成前过滤

### 中期改进（P2，架构性）
6. **Silver层缓存校验**: 增加`silver_version.txt`或`settings.py`哈希，版本不匹配时强制重跑
