## Step 0: 认知对齐 — 当前状态确认

### 0.1 项目目标

从ERP导出的出货明细Excel，经过清洗→聚合→分析→评分，输出客户全景画像、评分评级、定价建议，最终形成19张Gold表CSV和Excel报告。

### 0.2 数据管道现状

```
ERP Excel (所有的出货明细5.9.xlsx, 337,525行)
  ↓ read_excel_auto + rename_erp_columns + filter_negative_qty + winsorize_margins
Silver层 (3张聚合表 + 行级数据)
  ├── customer_monthly (8,612行, 每客户×月)
  ├── product_monthly (21,453行, 每产品×月)
  └── customer_x_product (94,609行, 每客户×产品×月)
  ↓
客户分析管道 (run_pipeline.py)
  ├── calc_customer_portrait() → 客户全景 (310客户, 60+指标)
  ├── calc_customer_tier() → 客户层级 (CRM→未分类)
  ├── score_rfm_pi() → RFM-π评分 (渠道隔离)
  ├── score_opportunity() → 机会评分 (Min-Max归一化)
  ├── score_risk() → 风险评分 (Min-Max归一化)
  ├── calc_composite_scores() → 5维度评分卡 (综合/机会/风险评级+双轴矩阵)
  ├── classfiy_customer_journey_stage() → 7阶段旅程 (B2B v2)
  ├── batch_calc_volatility() → 采购波动性 (B2B v2)
  ├── batch_estimate_true_profit() → 估算真实利润 (B2B v2)
  ├── generate_gold_tables() → 19张Gold表
  └── generate_reports() → Excel报告
  ↓
Gold层 (19张CSV → BI工具就绪)
```

## 3. 代码内重要问题

### 3.1 🔴 `models.py` 硬编码阈值 — 导致旧评分体系失效

**问题**: `models.py` 中的 `score_opportunity()` 和 `score_risk()` 使用硬编码分级阈值:

```python
# models.py:score_opportunity  (line 158-167)
def _tier(score):
    if score >= 80: return "极高"
    elif score >= 60: return "高"
    elif score >= 40: return "中"
    else: return "低"

# models.py:score_risk  (line 213-221)
def _tier(score):
    if score >= 80: return "极高"
    elif score >= 60: return "高"
    elif score >= 30: return "中"
    else: return "低"
```

**业务影响**:
- 机会评分: 当前数据分布下，机会分P90≈36, P99≈58 → ≥80**完全不可达** → 全部客户= "低"
- 风险评分: 当前数据分布下，风险分中位≈43 → ≥60约前10% → 90%集中在"中"
- 两个评分在Gold输出中存在但**几乎无区分力**
- 与5维度评分卡中的机会/风险评级**重复且不一致**

**建议**:
- 方案A(推荐): 将这两个函数的阈值移到 `settings.py` 或用 Min-Max 后再百分位截断
- 方案B: 如果5维度评分卡已覆盖用例，可直接从Gold输出中移除旧评分

### 3.2 🟡 `scoring.py` 机会/风险评级与 `models.py` 独立运行

**问题**: Gold层输出中同时包含:
- `机会分/机会等级` (来自 `models.py`, Min-Max, 硬编码阈值)
- `机会评级分/机会评级` (来自 `scoring.py`, 混合权重, settings配置阈值)
- `风险分/风险等级` (来自 `models.py`, Min-Max, 硬编码阈值)
- `风险评级分/风险评级` (来自 `scoring.py`, 混合权重, settings配置阈值)

**业务影响**: 四列名称相近但含义不同，输出到Excel后容易混淆。且旧版评分几乎无用。

**建议**: 
1. 在Gold输出中为两套评分加明确前缀(如"旧_机会等级" vs "机会评级")
2. 或仅输出新版5维度评分卡的评级

### 3.3 🟡 `run_all.py` 和 `silver.py` 存在两套Silver构建逻辑

**问题**: 
- `silver.py:build_silver_layer()` — 被 `run_pipeline.py` 直接调用
- `run_all.py:stage_silver()` — 有独立实现，但缺少 `silver.py` 中的部分逻辑(如行级数据保存)

**业务影响**: 两套逻辑曾因产品线列传递不一致导致Fix #23。虽已修复但架构脆弱。

**建议**: 长期应合并为单一入口。短期在stage_silver()中增加更多断言检查。

### 3.4 🟢 `shared/pricing.py` 中函数参数默认值与settings不一致风险

**问题**: 多个函数在 `shared/pricing.py` 中有硬编码默认值，而 `dimensions.py` 包装层又从settings读取覆盖。当直接调用 `shared/pricing.py` 函数(跳过dimensions.py)时，使用硬编码默认值。

**实例**: `calc_category_acceptance()` 的 `dominant_threshold=0.60`, `opportunity_threshold=0.20` 不在settings.py中。

**影响**: 低风险 — 因为所有调用都通过 `dimensions.py` 包装层。
