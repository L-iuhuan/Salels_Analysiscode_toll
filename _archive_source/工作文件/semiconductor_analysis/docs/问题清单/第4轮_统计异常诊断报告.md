## 二、P0：衰退风险评分计算错误

### 【P0】衰退风险得分最大值250，突破0-100可能范围

- **严重性**: 极高
- **归因**: B（代码逻辑偏差）
- **影响**: 28个产品 (3.5%)，全部属于"衰退期"且被标记为"极高风险"

**证据**:
```
衰退风险得分: min=10, max=250, mean=42.3
>100 产品: 28个 (110〜250)
分布:
  0-20: 103 (16.3%)
  20-40: 260 (41.1%)
  40-60: 132 (20.9%)
  60-80: 108 (17.1%)
  80-100: 2 (0.3%)
  >100: 28 (4.4%)
```

**根因**: `product_lifecycle/profiling.py:1037`

```python
# Line 1007-1015: 权重重归一化
w = [w1, w3, w4, w_sh, w6]
reliable = [slope_reliable, cv_reliable, decay_reliable, sh_reliable, asp6_reliable]
for idx in range(5):
    if not reliable[idx]:
        w[idx] = 0.0       # 不可靠因子权重置0

sum_w = sum(w)              # sum_w = 旧权重和(≤1.0)
if sum_w > 0:
    w = [wi / sum_w for wi in w]  # w被改写为重归一化后的权重(和为1.0)

# ... 正常计算 total = s1*w[0] + s3*w[1] + ...  (最大值100) ✓

# Line 1028-1038: 衰退期最低分保护（出bug的地方）
if 当前画像 == "衰退期" and (毛利率≤0 or 销量≤0):
    non_sh_weight = w[0] + w[1] + w[2] + w[4]   # w是重归一化后的
    non_sh_score = (s1*w[0] + s3*w[1] + s4*w[2] + s6*w[4]) / non_sh_weight
    if non_sh_score < exit_min_risk:            # exit_min_risk=50
        total = (50 * non_sh_weight + s_sh * w[3]) / sum_w   # ← BUG: 除以旧sum_w
```

**问题**: `sum_w` 是重归一化**前**的权重和（有因子被置0后<1.0），但 `w[0]..w[4]` 已经是重归一化**后**的（和为1.0）。公式比例不匹配：
- 当1个因子不可靠：sum_w=0.85 → 理论最大≈117
- 当2个因子不可靠：sum_w=0.65 → 理论最大≈154
- 当3个因子不可靠：sum_w=0.35 → 理论最大≈250（实际观测到的最大值）

**修复**: 将 `sum_w` 替换为 `1.0`（或等价地用 `sum(w)` 重新计算）

```python
# 修正后:
total = exit_min_risk * non_sh_weight + s_sh * w[3]  # 分子已正确，无需除以sum_w
```

**影响链**: 28个产品的衰退风险得分虚高 → 等级误标为"极高风险"（本应为"极高风险"或"高风险"尚不确定）→ 策略建议偏离 → 产品组合决策偏误

## 三、P1：关键发现

### 1. 增速方向列缺失率50.9% 【A-数据不足】

| 列名 | 缺失率 | 非空 | 
|------|:------:|:----:|
| 增速方向 | **50.9%** | 390/794 |
| 增速变化(pp) | **50.9%** | 390/794 |
| 前12月增长率% | **50.9%** | 390/794 |

超半数产品无法判断增速方向。这404个产品恰好是那些缺少前12月数据（新品、过早）或销量为0的产品。虽然技术上属于"数据不足"，但缺失率过高影响下游判断——"增速方向"列实际只有一半的产品有价值。

### 2. 客户稳定性等级几乎无区分度 【B-代码逻辑偏差】

| 等级 | 客户数 | 占比 |
|------|:------:|:----:|
| **高波动** | **303** | **97.7%** |
| 中等稳定 | 7 | 2.3% |

97.7%的客户被标记为"高波动"——这个指标实际上没有信息量。可能是阈值设置过严，或者全体客户本身的购买行为确实不稳定。无论哪种情况，该指标当前无决策价值。

### 3. 40.3%的客户评级为"未知" 【B-代码逻辑偏差】

| 等级 | 客户数 | 占比 |
|------|:------:|:----:|
| C | 146 | 47.1% |
| **未知** | **125** | **40.3%** |
| A | 33 | 10.6% |
| B | 6 | 1.9% |

超过4成客户无法评级。"未知"客户可能是数据不足、新客户、或评分阈值之外的客户。需要明确"未知"的定义和降级路径。

## 四、P2：数据分布异常

### 4. "潜力产品"中32%处于明显衰退期 【A-数据不足/B-算法】

"潜力产品"类中包含93个"明显衰退"产品（占全部"潜力产品"的32%）。"潜力"与"明显衰退"在中文语义上矛盾。可能原因：
- 产品发展阶段标注来自ERP（不可修改），而生命周期阶段来自算法判断
- 两套分类体系对同一产品的判断冲突

### 5. 近期峰值毛利率缺失率59.8% 【A-数据不足】

475/794个产品无法追溯毛利率历史峰值。该列用于计算"自比健康度"——若缺失则无法计算此指标（退化为无收益分项）。

### 6. 公司权重值%(公司权重值%)为常量35.41% 【C-配置/体验】

该列标准差为0（所有产品值35.41%），表明它是一个占位符常量而非实际业务权重。如果这一列本应反映各产品对公司营收的贡献权重，则当前实现方式使该指标无意义。

### 7. 客户生命周期中"流失期"占44.5% 【A-数据不足】

| 客户生命周期阶段 | 客户数 | 占比 |
|:----:|:------:|:----:|
| 流失期 | 138 | 44.5% |
| 沉默期 | 68 | 21.9% |
| 增长期 | 59 | 19.0% |
| 活跃期 | 18 | 5.8% |
| 培育期 | 15 | 4.8% |
| 衰退期 | 12 | 3.9% |

近一半客户在流失期，结合"高波动"比例97.7%，说明客户关系管理面临严峻挑战——但这也可能是B2B业务特征（客户企业本身周期长，采购频次低）。

### 8. 客户收入分布极端右偏

| 指标 | 值 |
|------|------|
| 近12月收入均值 | 244.4万 |
| 近12月收入中位数 | **1.28万** |
| 相差倍数 | **190倍** |
| 最大值 | 4861.5万 |
| 最小值 | 0 |

均值远大于中位数说明少数大客户主导营收。但中位数仅1.28万引发疑问——超半数客户的年收入不到1.3万，这部分客户的商业价值值得单独审视。

### 9. 品种集中度Top3均值75%，中位数80%

说明绝大多数客户只采购少数品种——B2B分销的典型特征，但也意味着客户流失风险高（对少数品种的依赖性强）。

## 七、交叉验证发现

### LTV vs 复购率

未找到直接的"LTV"列。近12月收入 vs 订单次数的相关性=**0.52**（中度正相关）。高收入客户确实贡献更多订单，但相关性不够强——部分高收入客户可能是单品高单价而非高频复购。

### 风险评分 vs 毛利率

衰退风险得分与当前毛利率的相关系数待算（受数据缺失影响）。但从生命周期×风险等级交叉表看：
- 衰退期产品中：40%极高风险 + 29%高风险 = 69%中高风险 ✓合理
- 成长期产品中：0.8%高风险 ✓合理
- 明显衰退产品中：75.5%高风险 ✓合理

整体阶段×风险对应关系**合理**，排除bug影响后的评分应该具有区分度。
