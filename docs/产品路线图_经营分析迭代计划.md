### 2.2 调整方案

**A. 名词统一表**（写进 faces.yaml 头注，全文按此执行）：

| 统一用词 | 淘汰/并存词 | 说明 |
|---|---|---|
| 销售员 | 业务员 | 全文统一"销售员" |
| 环比 / 同比 | 月环比 / 与去年同期比 | 保持标准词 |
| 下四分位（P25） | P25 裸用 | 首次出现写"下四分位（P25）"，后文可用 P25 |
| 前25%低收入的活跃客户 | （对"微量活跃"的解释重写） | 口语化替代分位术语 |
| 上一个统计期 | 上期 | "上期均价"→"上一期均价"更完整，公式内保留"上期" |

**B. 符号规范**：
- Δ → 改文字："量贡献 = 销量变化 × 上期均价"（首次），公式简写保留在 ❓弹层详注里
- ≈ → "约等于（不严格相等，交叉项未摊分）"或直接删符号改陈述句
- ≥/≤/±/× 保留（通用数学符号，无阅读障碍）
- 百分比权重串 "35%+10%+10%…" → 改表格式或分号分项："绝对贡献35%、客户维系10%、品类拓展10%、…"（顿号替代加号，阅读节奏更好）

**C. 长句拆分**：R面策展、D面九维两条 100+ 字 koujing 改为编号短句（口径条本身支持多行）；权重类内容移入 ❓弹层详注（详注是"想深究的人"看的，正文只留"九维加权评分，50分为团队均值"）。

**D. 指代具象化**：热力图文案"行/列"改为"纵轴方向（每行一个客户）/横轴方向（每列一个销售员）"。

## 三、#14 observed=True 方案（事项2）

**现状**：`processing/analysis/pricing/pricing_actions.py:44` 的 `groupby([客户,产品])` 在 categorical dtype 下默认 `observed=False`，展开 263万 幽灵叉积行（NaN/0 值），批次⑦用"可提价标记"过滤到 505 有效行止血。

**改法**：groupby 加 `observed=True`（只算实际发生过的组合）。与 505 行过滤是两层不同机制（observed 治幽灵行；可提价标记是业务筛选），改后两者叠加，结果行数不变（505），但源头不再产生 263万 行中间数据。

**收益**：提价机会 CSV 从 170MB 级降到 KB 级；该阶段计算与 IO 变快；口径正名（"提价机会=实际组合中满足提价条件的"）。

**验证**：改后跑全链 → 提价机会 CSV 行数仍=505 且逐格一致（与现有效子集对拍）→ golden_diff 中"提价机会"10 处已登记漂移应消失或变化 → 更新登记/冻结新基线 → pytest 93/93。

**风险与回退**：低。若 groupby dtype 非 categorical 则无行为变化（幂等）；回退=去掉参数。

**工作量**：1 小时（含验证）。

## 六、C面数据迁移方案（事项5，探查已完成）

**结论**（exp-4 文件:行号级取证）：产品报告 Excel 是纯序列化终点，无独有计算；C 面消费的全部数据（快照/历史_t-N 列/数据月份/数据不足数）均可从 `product_lifecycle/run.py` 内存对象直接落 gold CSV。

**方案（4 处改动）**：
1. `processing/product_lifecycle/run.py` L510 后追加：`hist_sheet_df` 落 `gold_product_portrait_history.csv` + meta（data_month/insuff_count/hist_intervals）落 `gold_product_portrait_meta.json`

## 七、⭐⑨ chartDefaults 统一层说明（用户问"具体做什么、带来什么提升"）

**现状问题**：template.html 里约 **75 处 fontSize**（7/8/9/10/11/12/13/14 散布各图 setOption）、**35 处 grid**（left 45~110、top 15~55 各写各的）、splitLine 颜色两套（#F1F5F9 / #E2E8F0）、轴名 nameGap 十几种值。每新增/修改一个图表都要手抄一遍参数，改全局风格要 touch 几十处。

**做什么**：建 `TABS.chart.LAYOUTS`（按图型 3-4 种预设：柱图/折线/散点/热力图）+ `TABS.chart.TYPOGRAPHY`（轴标签11/数值标签10/图例11/轴名11 四档）+ splitLine/配色统一走 chart token；存量约 40 个 setOption 逐批迁移到预设。

**带来什么提升**：
1. **一致性**：字号/边距/网格线全网真统一（现在只是"看起来差不多"）
2. **维护成本**：改一处全局生效；新图表不再抄参数（新增图工作量 -50%）
3. **防回归**：轴名裁切类 bug（本轮 r4 修的那种）从结构上杜绝——预设里 nameGap/containLabel 已调好
4. **为换肤铺路**：将来若做暗色模式，token 层一处切换

**代价**：2-3 人日专项 + 全图表回归验证（截图对拍）。**建议**：下次集中改图表时顺带启动，或单独排一天半。
