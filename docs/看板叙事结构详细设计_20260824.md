## 2. 叙事线详细设计

### 2.1 新叙事线

**A 总览 → R 风险与行动 → B 客户 → C 产品 → D 销售 → E 月度作战 → F H1 专项**

这条线的逻辑是：先看大局 → 再看这个月要处理什么风险 → 下钻到客户 → 下钻到产品 → 下钻到销售 → 最后看月度执行细节 → H1 专项按需出现。

### 2.2 每面叙事定位

#### A 面「总览决策」

- **主题**：当月经营大局。
- **回答的业务问题**：公司这个月整体经营得怎么样？收入、毛利、ASP、KA/AA 贡献是否在预期区间？
- **主要读者**：管理层、销售负责人。
- **与下游 R 面的衔接**：看完 A 面后，管理层会问"有没有异常需要我马上处理？"R 面直接回答这个问题。

#### R 面「风险与行动」（新合并面）

- **主题**：当月风险信号 + 待办事项 + 各面口径说明。
- **回答的业务问题**：这个月有哪些客户/产品/销售异常？谁负责跟进？状态是什么？每个面该怎么看？
- **主要读者**：管理层、销售运营、客户经理。
- **与上游 A 面的衔接**：承接 A 面总览中发现的异常（如毛利率下降、KA 收入下滑），列出具体风险信号。
- **与下游 B 面的衔接**：风险清单中的客户级事项，点击客户名可直接跳转到 B 面下钻详情。

#### B 面「客户 360」

- **主题**：以客户为轴心的下钻分析。
- **回答的业务问题**：这个客户最近怎么样？在买什么？有没有风险？
- **主要读者**：客户经理、销售。
- **与上游 R 面的衔接**：R 面列出风险客户后，B 面提供下钻能力。
- **与下游 C 面的衔接**：客户采购的产品出现风险时，跳转到 C 面看产品生命周期。

#### C 面「产品生命周期」

- **主题**：以 SKU 为轴心的生命周期与风险分析。
- **回答的业务问题**：哪些产品在成长、哪些在衰退、哪些高风险？该怎么处理？
- **主要读者**：产品管理、销售。
- **与上游 B 面的衔接**：B 面发现某客户采购的产品异常，C 面展示该产品在全市场的表现。
- **与下游 D 面的衔接**：产品问题最终需要销售执行，D 面展示销售员的客户覆盖和品类能力。

#### D 面「销售能力」

- **主题**：以销售员/部门为轴心的能力与业绩评估。
- **回答的业务问题**：哪个销售员/部门能力强、哪个弱？客户覆盖和品类热度如何？
- **主要读者**：销售管理、HR。
- **与上游 C 面的衔接**：C 面发现某品类/产品需要重点关注，D 面看哪些销售员在该品类上最强。
- **与下游 E 面的衔接**：D 面看长期能力，E 面看月度执行结果。

#### E 面「月度作战雷达」

- **主题**：月度级次的执行作战视图。
- **回答的业务问题**：这个月客户/产品/销售的异动是什么？首次导入、量利拆解、销售贡献如何？
- **主要读者**：销售一线、运营。
- **与上游 D 面的衔接**：D 面看能力，E 面看当月实际作战结果。
- **与下游 F 面的衔接**：E 面的月度数据累计后，F 面做半年度复盘。

#### F 面「H1 汇总」

- **主题**：上半年经营复盘专项（按需更新）。
- **回答的业务问题**：上半年整体经营结果如何？产品线/品类/部门/客户/新品各维度对比怎样？
- **主要读者**：管理层、财务。
- **与上游 E 面的衔接**：E 面是月度作战，F 面是半年累计。
- **开关控制**：通过 `faces.yaml` 的 `cadence` 和 `visible` 控制是否生成和展示。

### 2.3 叙事线变更说明

- **新增 R 面**：插在 A 面之后，作为"总览→行动"的桥梁。
- **B/C/D/E 顺序不变**：避免大面积用户习惯迁移。
- **F 面仍在最后**：作为专项复盘，按需出现。

### 3.2 上部：当月风险与异常摘要

- **跟进中**：已分配负责人，正在处理。
- **已关闭**：已处理完成或确认无需处理。

#### 3.3.2 行动清单字段

| 字段 | 类型 | 说明 |
|---|---|---|
| ID | 字符串 | 稳定 ID，格式 `{source}:{customer}:{signature}:{data_month}` |
| 标题 | 字符串 | 一句话描述，如「某某科技负毛利产品 4 个，月损失 117.2 万」 |
| 来源 | 字符串 | 异常日志 / 负毛利分析 / 客户组合健康度 |
| 客户 | 字符串 | 客户名称 |
| 风险等级 | 字符串 | 高 / 中 / 低 |
| 创建月份 | 字符串 | 如 2026-06 |
| 状态 | 枚举 | 待处理 / 跟进中 / 已关闭 |
| 负责人 | 字符串 | 可编辑 |
| 备注 | 文本 | 可编辑 |
| 建议动作 | 文本 | 来自源表 |
| 触发值 | 数值 | 如损失金额 |
| 关联面 | 字符串 | B / C / D / E，点击跳转 |

### 3.7 跨月结转规则

1. **保留未关闭项**：状态为「待处理」或「跟进中」的事项，跨月保留。
2. **更新触发值**：若同一事项当月仍在触发，更新 `trigger_value`、`suggested_action`、描述，保留业务填写的状态/负责人/备注。
3. **自动关闭**：连续 3 个月未触发且状态为「待处理」的事项，自动转为「已关闭」（阈值可配置）。
4. **业务手动关闭**：状态为「已关闭」的事项不再自动重新打开。

## 4. faces.yaml 注册表 schema 定稿

### 4.1 文件位置

`sales_analytics_platform/dashboard/faces.yaml`

### 4.2 字段定义

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 面标识，如 A/B/C/D/E/F/R。决定 tab 顺序和数据变量前缀。 |
| `name` | string | 是 | 面显示名称。 |
| `theme` | string | 是 | 面主题一句话定义。 |
| `enabled` | bool | 是 | 是否启用。`false` 时生成期完全跳过该面计算，模板不渲染 tab。 |
| `cadence` | string | 是 | 更新节奏：`monthly`（每月）、`quarterly`（每季）、`half_year`（半年）、`on_demand`（按需）。 |
| `visible` | bool | 否 | 是否在 tab 栏展示。`false` 时计算照常进行，但 tab 隐藏或显示占位提示。默认 `true`。 |
| `owner` | string | 否 | 负责该面的业务方或数据团队。 |
| `icon` | string | 否 | Font Awesome 图标类名，如 `fa-chart-pie`。 |
| `description` | string | 否 | 面级简短描述。 |
| `compute_stage` | string | 否 | 关联 `generate_dashboard.py` 中的进度阶段，用于日志和调试。 |
| `sections` | list | 否 | 该面下各区块的口径说明。 |
| `sections[].title` | string | 是（sections 内） | 区块名称。 |
| `sections[].definition` | string | 否 | 区块定义。 |
| `sections[].source` | string | 否 | 数据来源文件。 |
| `sections[].koujing` | string | 否 | 关键口径说明。 |
| `sections[].usage` | string | 否 | 使用建议。 |
| `sections[].update_note` | string | 否 | 更新节奏说明。 |

### 4.3 特殊字段说明

#### `enabled` vs `visible`

- `enabled=false`：彻底关闭。不计算、不注入数据、不渲染 tab。用于长期废弃或季节性面。
- `visible=false`：隐藏展示。计算照常进行，数据仍注入，但 tab 不显示或显示"本季度未更新"占位。用于 F 面 H1 专项在 non-H1 月份的轻量处理。

#### `cadence`

生成器根据当前数据月份判断该面是否参与本月生成：

| cadence | 生成条件 | 示例 |
|---|---|---|
| `monthly` | 每月都生成 | A/B/C/D/E/R |
| `quarterly` | 季度末月份生成（3/6/9/12 月） | 未来季度复盘面 |
| `half_year` | 6 月和 12 月生成，或 H1/H2 数据完整后 | F 面 |
| `on_demand` | 由人工在配置中手动开启 | 临时专项面 |

## 5. 插拔与更新节奏机制

### 5.1 总体原则

- **生成期决定**：在 `generate_dashboard.py` 读取 `faces.yaml` 后，决定每个面是否参与计算、是否注入数据。
- **模板最小改动**：模板仍保留 A~F 的固定结构，新增 R 面通过独立测试页先行验证。
- **进度协议不动**：现有 `[STAGE]/[n/m]` 打印语句保留原格式；新增 R 面的进度打印追加到最后一个阶段内部或新增阶段末尾，不破坏 Tauri 壳解析。

### 5.2 生成期挂点设计

| KPI | L776-815 | `[2/5] YTD KPI...` | A 面顶部 |

#### 挂点 1：加载阶段后读取 faces.yaml（L648 附近）

在加载基础数据之后、进入 KPI 计算之前，读取 `faces.yaml`：

```python
# 建议在 L648 之后、L776 之前新增
import yaml
_faces_path = os.path.join(os.path.dirname(__file__), "faces.yaml")
with open(_faces_path, "r", encoding="utf-8") as f:
    FACES = yaml.safe_load(f).get("faces", {})

# 判断各面是否启用
def face_enabled(face_id):
    cfg = FACES.get(face_id, {})
    if not cfg.get("enabled", True):
        return False
    cadence = cfg.get("cadence", "monthly")
    if cadence == "monthly":
        return True
    elif cadence == "quarterly":
        return _latest_m in (3, 6, 9, 12)
    elif cadence == "half_year":
        return _latest_m in (6, 12)
    elif cadence == "on_demand":
        return cfg.get("on_demand_active", False)
    return True
```

#### 挂点 4：模板 tab 栏动态生成（L2420-2472）

当前模板 tab 栏是硬编码在 `template.html:249-262`。生成器可以在替换阶段注入启用面列表，前端 JS 根据列表渲染 tab 按钮。

建议做法：

1. 生成器注入 `ENABLED_FACES = ['A','R','B','C','D','E']` 和 `VISIBLE_FACES = ['A','R','B','C','D','E']`。
2. 前端 JS 在页面加载时读取这两个变量，动态生成 `.tab-bar` 中的按钮。
3. 对 `visible=false` 的面（如 F 在 non-H1 月份），若 `enabled=true`，则不生成 tab 按钮；或在 tab 顺序末尾生成一个灰色占位按钮。

### 5.3 禁用面在模板上的两种呈现

#### 方案 A：隐藏 tab（推荐用于长期禁用）

- `enabled=false` 的面：不生成 tab 按钮，不渲染 tab-content。
- 用户看不到该面，页面更清爽。

#### 方案 B："本季度未更新"占位（推荐用于 F 面按需）

- `enabled=true` 但 `visible=false` 的面：在 tab 顺序末尾显示一个灰色不可点击按钮，tooltip 显示"H1 专项·本季度未更新"。
- 优点：用户知道有这个面，只是当前没数据；避免"面是不是被删了"的困惑。
- 缺点：tab 栏多了一个灰色项。

**F 面建议**：默认采用方案 B，即 non-H1 月份显示灰色占位；若用户选择方案 A，则把 `visible=false` 改为 `enabled=false`。

### 5.4 缓存兼容性

`preagg.json` 缓存机制（L560-646）：

- 当前缓存键包含 `dashboard_code` 和 `template` 等的 sha256。
- 如果 `faces.yaml` 修改导致启用面变化，建议把 `faces.yaml` 内容也纳入指纹计算，确保缓存失效。
- 或者，在缓存命中路径中（L575-646）也读取 `faces.yaml` 并重新判断启用面，禁用面的数据从缓存中排除。

**推荐**：把 `faces.yaml` 纳入指纹，简单可靠。

### 6.2 独立测试页产出方式

## 7. 三个面的示例口径文案

> 文案风格：朴素业务语言，不营销。用户审后推广到全面。

### 7.1 A 面「总览决策」

**这面看什么**

快速了解公司当月经营大局：赚了多少钱、毛利怎么样、ASP 是涨是跌、KA/AA 大客户贡献多少、整体趋势是向上还是向下。

**关键口径**

- **YTD 收入/毛利**：从本年 1 月到最新数据月的累计值。收入是 RMB 未税金额，毛利是利润列，毛利率 = 毛利 / 收入 × 100%。
- **ASP**：平均售价 = 收入 / 发货数量。ASP 下降通常意味着产品均价走低或低价产品占比上升。
- **KA+AA**：客户层级里包含 "KA" 或 "AA" 的客户，是公司最核心的大客户群。KA+AA 收入占比反映公司业务质量。
- **K 类客户数**：客户层级为 KA、AA、KM、MM 的客户数量分布。
- **KA 客户经营势能矩阵**：横轴是 YTD 同比收入增长率，纵轴是毛利率。右上角客户"增长快+毛利高"，左下角客户"下滑+毛利低"。

**怎么用**

1. 先看顶部 7 张 KPI 卡：收入同比、毛利率同比、ASP 环比是核心。
2. 再看月度成本/毛利趋势：判断近几个月是收入驱动还是毛利承压。
3. 最后看 KA/AA 客户列表：找收入或毛利率异常的客户，点击客户名跳到 B 面下钻。

**更新节奏**

每月随最新 ERP 数据刷新。数据截至右上角标注的月份。

---

### 7.2 R 面「风险与行动」

**这面看什么**

这个月有哪些客户、产品、销售出现异常？哪些事需要跟进？谁负责？处理到哪一步了？看不懂其他面的时候，来这里查口径。

**关键口径**

- **异常日志**：系统自动识别的客户级异常，比如营收大幅下滑、连续多月下滑、层级变化等。
- **负毛利分析**：客户采购的产品里，有哪些卖出去是亏本的（负毛利），以及每月损失金额。
- **风险等级**：高 / 中 / 低。高等级事项建议当月必须处理。
- **行动清单状态**：
  - 待处理：系统刚生成，还没分配人。
  - 跟进中：已分配负责人，正在处理。
  - 已关闭：已处理完成或确认无需处理。
- **跨月结转**：未关闭的事项会带到下个月，直到处理完成或连续 3 个月未再触发。

**怎么用**

1. 上部「风险摘要」：快速扫本月有多少异常、损失金额多大、哪些客户/产品高风险。
2. 中部「行动清单」：给每项分配负责人、写备注、改状态。状态变更后需要下载 `action_items.json` 提交。
3. 下部「口径说明」：点对应面，看该面定义和用法。

**更新节奏**

风险摘要每月随 gold 表刷新；行动清单状态跨月持久，由业务维护。

### 7.3 B 面「客户 360」

**这面看什么**

聚焦单个客户，回答"这个客户最近怎么样、在买什么、有没有风险"。

**关键口径**

- **客户列表**：来自 `output/gold/客户全景.csv`，包含层级、活跃状态、风险等级等属性。支持按层级、活跃状态、风险等级筛选。
- **近 25 个月趋势**：该客户每月的收入、利润、数量，用于看长期走势。
- **品类/品种 Top5**：该客户近 12 个月采购金额最高的品类和型号。
- **新品明细**：来自 `silver_cleaned_rows.csv`，标记为新品的产品在该客户中的采购情况。
- **活跃状态**：基于客户全景表判定，包括活跃、微量活跃、非活跃。

**怎么用**

1. 左侧列表找到目标客户（可用搜索/筛选）。
2. 点击客户名，右侧显示该客户近 25 个月趋势、财务汇总、品类构成、Top 品种。
3. 如果发现风险等级高或收入下滑，回到 R 面行动清单建立跟进事项。

**更新节奏**

每月刷新。
