## 2. 叙事线详细设计

### 2.1 新叙事线

**总览 → 风险与行动 → 客户 360 → 产品生命周期 → 销售能力 → 月度作战雷达 → 半年度专项**

逻辑：先看大局 → 再看本月要处理的风险 → 下钻客户 → 下钻产品 → 下钻销售 → 月度执行细节 → 半年度专项按需出现。

### 2.2 面名对照（内部 id 仅用于开发，不进 UI）

| 中文面名 | 内部 id | 原字母面代称 |
|---|---|---|
| 总览决策 | A | 原 A 面 |
| 风险与行动 | R | 新增 |
| 客户 360 | B | 原 B 面 |
| 产品生命周期 | C | 原 C 面 |
| 销售能力 | D | 原 D 面 |
| 月度作战雷达 | E | 原 E 面 |
| 半年度专项 | F | 原 F 面/H1 汇总 |

### 2.3 每面叙事定位

#### 总览决策

- **主题**：经营总览（总体 + 常用维度速览）。
- **回答的业务问题**：公司这个月整体经营得怎么样？各常用维度摘要表现如何？哪里异常需要下钻？
- **主要读者**：管理层、销售负责人。
- **设计原则**：速览不下沉，明细引专面。
- **与下游衔接**：总览面摘要卡中的异常信号，在风险与行动面展开为具体行动项。

| 面 | 回答的业务问题 | 主要读者 | 上下游衔接 |
|---|---|---|---|
| 风险与行动 | 本月哪些客户/产品/销售异常？谁跟进？状态？ | 管理层、销售运营 | 承接总览异常信号；客户级事项跳转客户 360 |
| 客户 360 | 这个客户最近怎样？买什么？有风险？ | 客户经理、销售 | 风险与行动面风险客户下钻；产品风险跳转产品生命周期 |
| 产品生命周期 | 哪些产品在成长/衰退/高风险？ | 产品管理、销售 | 客户面产品异常的全市场视角；问题产品对应到销售能力 |
| 销售能力 | 哪个销售员/部门强？客户覆盖和品类热度？ | 销售管理、HR | 产品面品类问题对应到销售能力；能力结果在月度作战验证 |
| 月度作战雷达 | 本月客户/产品/销售异动？量利拆解？ | 销售一线、运营 | 销售能力到月度结果；月度累计到半年度专项 |
| 半年度专项 | 上半年/下半年整体结果？各维度对比？ | 管理层、财务 | 月度作战累计；visible 由 faces.yaml 人工核定 |

### 2.4 总览面「速览级 vs 明细下沉」设计

| 区块 | 总览面呈现 | 明细下沉目标面 | 引导语 |
|---|---|---|---|
| 产品线/品类毛利率 | Top5 摘要卡 | 产品生命周期面 | 「完整分析详见产品生命周期面」 |
| KA/AA 客户列表 | Top 20 精简列表 | 客户 360 面 | 「点击客户名去客户 360 面下钻」 |
| 产品型号变迁 | 新增/流失数量摘要卡 | 风险与行动面 | 「型号异动详见风险与行动面」 |
| 业务员贡献 | 暂不展示，或仅 Top3 收入卡 | 销售能力面 | 「销售员能力详见销售能力面」 |

### 2.5 叙事线变更说明

- **新增风险与行动面**：插在总览面之后，作为"大局→行动"的桥梁。
- **客户/产品/销售/月度作战顺序不变**：避免用户习惯迁移。
- **半年度专项仍在最后**：按需人工开启展示。

## 3. 风险与行动面内容设计

### 3.1 页面布局

```
┌─────────────────────────────────────────┐
│ ① 上部：当月风险与异常摘要（KPI 卡 +  top 列表） │
├─────────────────────────────────────────┤
│ ② 中部：行动清单（待办/重点关注）              │
├─────────────────────────────────────────┤
│ ③ 下部：三层口径说明体系                      │
└─────────────────────────────────────────┘
```

### 3.2 上部：当月风险与异常摘要

#### 3.2.1 双数据源

| 来源类型 | 文件 | 维护方 | 内容 | 生成规则 |
|---|---|---|---|---|
| 数据驱动风险项 | `output/gold/异常日志.csv` | 系统自动 | 客户级异常 | 异常等级为「高」或「中」 |
| 数据驱动风险项 | `output/gold/负毛利分析.csv` | 系统自动 | 客户×产品负毛利 | 负毛利产品数 > 0 且损失金额 ≥ 阈值 |
| 经营会议跟踪项 | 月度总体文档直接编辑（v4 起） | 人工 | 会议决议、跟踪事项 | 审定环节人工增改；可选速记 `dashboard/meeting_track.md` 在跑批时并入初稿 |

测试版先做「异常日志 + 负毛利分析 + 会议跟踪项」三个源。（v4：三类内容统一汇入月度总体文档 `risk_action_YYYYMM.md` 审定后渲染，见 §3.5。）

#### 3.2.2 会议跟踪项的录入方式（v4 修订）

v4 起，会议跟踪项**直接写在月度总体文档** `risk_action_YYYYMM.md` 的「二、行动清单」表格里（与其他事项同格式同流程）。若平时想随手速记，可维护可选文件 `dashboard/meeting_track.md`，跑批生成初稿时并入总体文档。格式（两者通用）：

```markdown
| 状态 | 跟踪事项 | 负责人 | 期望完成日 | 关联客户/产品 | 备注 |
|---|---|---|---|---|---|
| 跟进中 | 跟进某某科技价格谈判 | 张三 | 2026-07-15 | 某某科技 | 采购反馈待总部批复 |
```

#### 3.2.3 统一候选池

两类来源合并为统一候选池，再经策展规则筛选后写入 `action_items.json`。

| 字段 | 来源 | 示例 |
|---|---|---|
| ID | 规则生成 | `anomaly:某某科技:revenue_drop:202606` / `meeting:20260625:price_negotiation` |
| 来源 | 源表/源文件 | 异常日志 / 负毛利分析 / meeting_track.md |
| 标题 | 源表/人工 | 客户某某科技营收大幅下滑 / 跟进某某科技价格谈判 |
| 风险等级 | 源表/人工 | 高 / 中 / 低 |
| 创建月份 | 当前数据月 | 2026-06 |
| 建议动作 | 源表/人工 | 查看客户 360 / 价格谈判 |
| 关联面 | 规则生成 | 客户 360 / 产品生命周期 / 销售能力 / 月度作战 |

#### 3.2.4 展示策展规则

进入风险与行动面的事项**初稿**必须过以下筛选（v4：以下为初稿生成规则；人工审定环节可推翻任何筛选结果——增、删、改均以审定后的总体文档为准）：

| 规则 | 默认值 | 说明 |
|---|---|---|
| 严重度阈值 | 仅展示「高」「中」等级 | 低风险项不进入展示，保留候选池备查。 |
| 每类 Top-N | 每类最多 10 条 | 异常日志/负毛利/会议跟踪各 Top 10，避免信息过载。 |
| 去重合并 | 同一客户的多条异常合并为 1 条 | 同时触发营收异动和负毛利的客户合并展示。 |
| 已关闭保留期 | 1 个月 | 已关闭事项展示 1 个月后隐藏，保留在历史记录中。 |
| 损失金额阈值 | ≥ 1 万元 | 负毛利损失低于 1 万元的项不进入展示。 |
| 数据源兜底 | 字段缺失/为空时自动跳过 | 若某 gold 表关键字段缺失，该类候选自动不出，避免脏数据。 |

**策展后写入 `action_items.json` 的字段**：

| 字段 | 说明 |
|---|---|
| `display` | 是否展示在 R 面（true/false），用于保留历史但不在当前看板显示。 |
| `display_reason` | 不展示的原因（如「低风险」「超 Top-N」「已关闭超保留期」）。 |

| 卡片 | 指标 | 说明 |

| 当月异常数 | 策展后展示的数据驱动风险项数 | 反映本月需要关注的客户/产品数量 |

#### 3.2.7 事项过多时的降级展示策略

当月候选事项超过阈值时，按以下顺序降级：

1. **优先展示高等级**：先确保所有「高」等级事项展示完。
2. **再展示中等级**：中高等级展示完后，若仍超过单类 Top-N，按损失金额/影响排序取 Top-N。
3. **折叠低优先级**：超出部分收入「展开查看全部」按钮，不默认展示。
4. **会议跟踪项独立计数**：会议跟踪项不受数据驱动风险项 Top-N 限制，单独按状态筛选展示。

### 3.4 下部：三层说明体系

#### 口径文案写作规范（最重要，v4 定稿）

展示层文案只写两层：**简明公式 + 通俗名词说明**。
- ❌ 不写取数出处（哪张表、哪个函数——管理层不关心）
- ❌ 不写判断标准与解读建议（如"掉 3 个点要警惕"——我方阈值未必与管理层一致，避免误导）
- ✅ 公式可以写，但要简明（如 毛利率 = 毛利 ÷ 收入）
- ✅ 名词说明用大家都能理解的大白话（如 ASP = 平均每颗产品的售价）

| 指标 | ❌ 不写 | ✅ 写 |
|---|---|---|
| 毛利率 | 「取自 silver_customer_monthly」/「同比掉3个点要查明原因」 | 「毛利率 = 毛利 ÷ 收入。衡量每元收入的盈利水平。」 |
| ASP | 「源自 pricing 模块」/「连续下滑要警惕价格战」 | 「ASP = 收入 ÷ 发货数量，即平均售价。」 |
| KA+AA 收入占比 | 「客户层级含 KA/AA 的筛选逻辑」/「占比下降说明业务质量变差」 | 「KA+AA 收入占比：KA 与 AA 层级核心客户的收入合计占比。」 |
| RFM | recency/frequency/monetary 打分实现细节 | 「RFM：从最近购买、购买频率、购买金额三个维度衡量客户价值的常用模型。」 |

公式、取数逻辑、技术字段留在 `faces.yaml` 的 `sections[].source` / `sections[].koujing` 供开发查证，**不进展示层**。

#### 三层说明

| 层级 | 位置 | 作用 | 业务语言示例 |
|---|---|---|---|
| 面级口径条 | 每个面顶部折叠面板 | 说明本面内容与口径 | 总览面：「本面展示公司整体经营结果与常用维度摘要。各维度完整明细请跳转对应专面。」 |
| 图表级导读 | 图表标题旁 | 一句话说明图表内容 | KA 经营势能矩阵：「横轴为收入增长率，纵轴为毛利率，每个点是一个 KA 客户。」 |
| 指标级 hover | 指标/缩写悬停 | 简明公式或名词说明 | ASP：「平均售价 = 收入 ÷ 数量。」RFM：「按最近购买、频率、金额三维度的客户价值模型。」 |

**纪律**：口径、阈值变更时，同步更新 `faces.yaml` 的图表导读与 hover 文案。PR 需附带 `faces.yaml` 变更说明，防止说明与实现漂移。

### 3.5 R 面总体文档流程（v4 定稿：人工审定后渲染）

#### 3.5.1 核心模式：一份总体文档 = R 面全部内容

R 面全部内容汇成一份月度总体文档 `dashboard\risk_action_YYYYMM.md`，作为**唯一编辑入口**：

```
月度跑批 → 自动生成总体文档初稿（数据驱动风险项 + 会议跟踪项 + 上月未关闭行动项结转）
        → 人工审定（可增、删、改任何条目——包括数据驱动项；2026-08-24 用户拍板）
        → 双击 bat（或 python run_chain.py --dashboard-only）按固定模板渲染
        → R 面更新（测试期：dashboard_risk_test.html；正式期：并入 dashboard_a.html）
```

- **固定模板与样式**：渲染复用现有面的卡片/表格组件与配色，R 面与 A~F 面视觉风格一致；文档只是内容源，样式不在文档里调。
- **数据驱动项也可人工调整**：初稿由系统按规则生成，但审定环节可改标题/等级/负责人，甚至整条删除——以审定后的文档为准。
- **`action_items.json` 仍是状态持久化层**：渲染时从审定文档解析状态/负责人/备注并更新 json，作为跨月结转基础（json 不是人工编辑对象）。

#### 3.5.2 总体文档格式（固定模板）

```markdown
# 风险与行动 · 2026-06

> 本文件由跑批自动生成初稿，请审定后渲染进看板。增删改随意，以本文件为准。
> 渲染：python run_chain.py --dashboard-only（或双击 2_只生成看板.bat）

## 一、当月风险摘要

| 等级 | 事项 | 客户/产品 | 损失金额(万元) | 建议动作 | 负责人 |
|---|---|---|---|---|---|
| 高 | 客户营收大幅下滑 | 某某科技 | - | 查看客户 360 面 | 张三 |
| 中 | 负毛利产品 4 个 | 某某半导体 | 117.2 | 停止供应/调价 | 李四 |

## 二、行动清单

| 状态 | 事项 | 负责人 | 期望完成日 | 备注 |
|---|---|---|---|---|
| 跟进中 | 跟进某某科技价格谈判 | 张三 | 2026-07-15 | 采购反馈待总部批复 |
| 待处理 | 评估 STI3452HFI 停产影响 | 李四 | 2026-07-10 | 涉及 3 个客户 |

## 三、口径说明（从 faces.yaml 自动带入，勿改）
（面级口径条 / 图表导读 / 术语卡的当月快照）
```

#### 3.5.3 操作流（非程序员三步）

1. **看/改文档**：记事本打开 `dashboard\risk_action_YYYYMM.md`（初稿已生成），直接编辑——删掉不想公开的项、改措辞、补负责人、加会议跟踪项
2. **跑生成**：双击 `2_只生成看板.bat`（或 `python run_chain.py --dashboard-only`），秒级完成
3. **开看板**：刷新测试页（测试期）/ 正式看板（正式期）

#### 3.5.4 状态结转

- **待处理 / 跟进中**：每月跑批自动带入下月文档初稿。
- **已关闭**：在文档中保留 1 个月后不再带入；历史保留在 `action_items.json`。
- **自动关闭**：连续 3 个月未触发且状态为「待处理」的事项自动转为「已关闭」（阈值可配置）。

## 4. faces.yaml 注册表 schema 定稿

### 4.1 文件位置

`sales_analytics_platform/dashboard/faces.yaml`

### 4.2 字段定义

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 面标识，决定 tab 顺序和数据变量前缀。 |
| `name` | 是 | 面显示名称。 |
| `theme` | 是 | 面主题一句话定义。 |
| `enabled` | 是 | `false` 时彻底关闭：不计算、不注入数据、不渲染 tab。 |
| `cadence` | 是 | `monthly` / `quarterly` / `half_year` / `on_demand`。 |
| `visible` | 否 | `false` 时隐藏 tab（可显示灰色占位）。默认 `true`。 |
| `owner` | 否 | 负责业务方。 |
| `icon` | 否 | Font Awesome 图标类名。 |
| `description` | 否 | 面级简短描述。 |
| `compute_stage` | 否 | 关联 `generate_dashboard.py` 进度阶段。 |
| `sections` | 否 | 区块口径说明列表，含 `title/definition/source/koujing/usage/update_note`。 |

**enabled vs visible**
- `enabled=false`：长期禁用，完全消失。
- `enabled=true, visible=false`：计算照常，tab 隐藏或显示占位（如 F 面 non-H1 月份）。

## 5. 插拔与更新节奏机制

### 5.1 总体原则

- **生成期决定**：在 `generate_dashboard.py` 读取 `faces.yaml` 后，决定每个面是否参与计算、是否注入数据。
- **模板最小改动**：模板仍保留 A~F 的固定结构，新增 R 面通过独立测试页先行验证。
- **进度协议不动**：现有 `[STAGE]/[n/m]` 打印语句保留原格式；新增 R 面的进度打印追加到最后一个阶段内部或新增阶段末尾，不破坏 Tauri 壳解析。

### 5.2 生成期挂点设计

`generate_dashboard.py` 当前结构（行号来自当前版本）：

| 阶段 | 行号 | 当前打印 | 对应面 |
|---|---|---|---|
| 加载 | L648-776 | `[1/5] 加载数据...` | 基础数据 |
| KPI | L776-815 | `[2/5] YTD KPI...` | A 面顶部 |
| 月度趋势 | L815-867 | `[3/5] 月度趋势...` | A 面趋势 |
| 饼图+散点 | L867-903 | `[4/5] 饼图+散点...` | A 面图表 |
| 客户列表+B面 | L903-1175 | `[5/5] 客户列表+B面...` | A 面列表 + B 面 |
| D面销售能力 | L1175-1615 | `[6/6] D面 销售能力...` | D 面 |
| E面月度作战雷达 | L1615-1850 | `[7/7] E面 月度作战雷达...` | E 面 |
| F面H1汇总 | L1850-2421 | `[8/8] F面H1汇总...` | F 面 + 部门级次 |
| C面DATA构建 | L2401-2412 | 无单独阶段打印 | C 面 |

#### 四个挂点

| 挂点 | 位置 | 动作 |
|---|---|---|
| 1. 读取 faces.yaml | L648 之后、L776 之前 | 加载配置，解析 `enabled`/`cadence`/`visible`。 |
| 2. 计算阶段判断 | 各 `print("[n/m]...")` 之后 | `if face_enabled("X")` 包裹原计算逻辑，否则注入空数据。 |
| 3. 数据注入判断 | L2344-2384 | 对禁用面的 `js_data.append` 注入空值或占位值。 |
| 4. tab 栏动态生成 | L2420-2472 | 注入 `ENABLED_FACES`/`VISIBLE_FACES`，前端 JS 动态渲染 tab 按钮。 |

核心代码模式（以 F 面为例）：

```python
print("[8/8] F面H1汇总 + 部门级次 + 新品分析...")
if face_enabled("F"):
    # 原 F 面计算逻辑
    ...
else:
    f_h1_kpi = {}; h1_pline_margins = []; ...
    print("  [F面] 本周期未启用，跳过计算")
```

### 5.3 禁用面呈现

| 场景 | 配置 | 呈现 |
|---|---|---|
| 长期禁用 | `enabled=false` | 不生成 tab，不渲染内容。 |
| 平时关闭 | `enabled=true, visible=false` | tab 不渲染（彻底隐藏，无占位）。 |

**F 面**（用户拍板 2026-08-24）：平时 `visible=false` 彻底关闭；半年度复盘期由人工核定临时改 true 开启。原"灰色占位"方案废弃。

### 5.4 缓存兼容性

把 `faces.yaml` 纳入指纹计算（`preagg.json` 缓存键，见 `generate_dashboard.py:L560-646`），确保配置变更后缓存失效、重新生成。

## 7. 三个面的示例口径文案

> 文案风格：朴素业务语言，不营销。用户审后推广到全面。

### 7.1 A 面「总览决策」

**这面看什么**

公司经营总览：整体收入、毛利、ASP、KA/AA 贡献、整体趋势，以及常用维度（产品线、品类、客户层级等）的摘要表现。A 面只给结论和入口，完整明细去 B/C/D/E/R 面。

**关键口径**

- **YTD 收入/毛利**：本年 1 月至最新数据月的累计值，收入按不含税金额计。
- **毛利率 = 毛利 ÷ 收入**。
- **ASP = 收入 ÷ 发货数量**（平均售价）。
- **KA+AA**：层级为 KA 或 AA 的核心大客户群。
- **产品线/品类 Top5**：A 面只展示 Top5 产品线/品类的收入和毛利率摘要，完整列表见产品生命周期面。
- **KA/AA 客户列表**：A 面只展示 Top 20 核心客户精简信息，点击客户名去客户 360 面下钻。
- **产品型号变迁**：A 面只展示新增/流失数量摘要卡，完整异动清单见风险与行动面。

**怎么用**

1. 看顶部 KPI 卡和整体趋势，判断大局。
2. 扫常用维度摘要卡，定位哪个维度异常。
3. 异常点点击「详见 X 面」，跳转到专面下钻。

**更新节奏**

每月刷新。

---

### 7.2 R 面「风险与行动」

**这面看什么**

本月要处理的风险和待办：一部分来自系统自动识别的数据异常，一部分来自经营会议跟踪项。这里只展示经策展后的重点事项，不是全部候选。

**关键口径**

- **数据驱动风险项**：系统按既定规则自动识别的异常（客户营收异动、负毛利产品等），每月跑批生成初稿，人工审定后展示。
- **会议跟踪项**：人工维护的经营会议决议跟踪，编辑总体文档即可更新。
- **展示规则**：只展示审定后的重点事项；同一客户多条异常合并；已关闭事项保留 1 个月后隐藏。
- **状态**：待处理 / 跟进中 / 已关闭。未关闭项跨月保留。

**怎么用**

1. 上部「风险摘要」：扫本月重点异常和损失金额。
2. 中部「行动清单」：分配负责人、改状态、写备注。会议跟踪项直接在这里同步状态。
3. 下部「口径说明」：三层说明体系，面级/图表级/指标级随时查。

**更新节奏**

风险摘要每月刷新；会议跟踪项随 `meeting_track.md` 更新；行动清单状态跨月持久。

---

### 7.3 B 面「客户 360」

**这面看什么**

聚焦单个客户，回答"这个客户最近怎么样、在买什么、有没有风险"。

**关键口径**

- **客户列表**：全部客户的层级、活跃状态、风险等级等属性，支持按层级、活跃状态、风险等级筛选。
- **近 25 个月趋势**：该客户每月的收入、利润、数量，用于看长期走势。
- **品类/品种 Top5**：该客户近 12 个月采购金额最高的品类和型号。
- **新品明细**：标记为新品的产品在该客户中的采购情况。
- **活跃状态**：活跃 / 微量活跃 / 非活跃（按近期采购情况判定）。

**怎么用**

1. 左侧列表找到目标客户（可用搜索/筛选）。
2. 点击客户名，右侧显示该客户近 25 个月趋势、财务汇总、品类构成、Top 品种。
3. 如果发现风险等级高或收入下滑，回到 R 面行动清单建立跟进事项。

**更新节奏**

每月刷新。
