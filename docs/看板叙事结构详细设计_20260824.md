## 2. 叙事线详细设计

### 2.1 新叙事线

**A 总览 → R 风险与行动 → B 客户 → C 产品 → D 销售 → E 月度作战 → F H1 专项**

这条线的逻辑是：先看大局 → 再看这个月要处理什么风险 → 下钻到客户 → 下钻到产品 → 下钻到销售 → 最后看月度执行细节 → H1 专项按需出现。

### 2.2 每面叙事定位

#### A 面「总览决策」

- **主题**：经营总览（总体 + 常用维度速览）。
- **回答的业务问题**：公司这个月整体经营得怎么样？各常用维度（产品线、品类、客户层级等）的摘要表现如何？哪里可能异常需要下钻？
- **主要读者**：管理层、销售负责人。
- **设计原则**：
  - **速览不下沉**：整体 KPI、整体趋势、常用维度摘要卡保留在 A 面。
  - **明细引专面**：任何需要排序、筛选、下钻的完整明细，通过「详见 X 面」引导到 B/C/D/E/R。
- **与下游 R 面的衔接**：A 面摘要卡中的异常信号（如某品类毛利率大幅下滑、某客户层级收入下降），在 R 面展开为具体行动项。

| 面 | 回答的业务问题 | 主要读者 | 上下游衔接 |
|---|---|---|---|
| R 风险与行动 | 本月哪些客户/产品/销售异常？谁跟进？状态？ | 管理层、销售运营 | 承接 A 面异常信号；客户级事项跳转 B 面 |
| B 客户 360 | 这个客户最近怎样？买什么？有风险？ | 客户经理、销售 | R 面风险客户下钻；产品风险跳转 C 面 |
| C 产品生命周期 | 哪些产品在成长/衰退/高风险？ | 产品管理、销售 | B 面产品异常的全市场视角；问题产品对应到 D 面销售 |
| D 销售能力 | 哪个销售员/部门强？客户覆盖和品类热度？ | 销售管理、HR | C 面品类问题对应到销售能力；能力结果在 E 面月度验证 |
| E 月度作战雷达 | 本月客户/产品/销售异动？量利拆解？ | 销售一线、运营 | D 面能力到 E 面结果；E 面累计到 F 面半年复盘 |
| F H1 汇总 | 上半年整体结果？各维度对比？ | 管理层、财务 | E 面月度累计；开关由 faces.yaml 控制 |

### 2.3 A 面「速览级 vs 明细下沉」设计

| 区块 | A 面呈现（速览级） | 明细下沉目标面 | 引导语 |
|---|---|---|---|
| 产品线/品类毛利率 | Top5 产品线/品类毛利率卡 | C 面 | 「完整产品线/品类分析详见 C 面」 |
| KA/AA 客户列表 | Top 20 精简列表 | B 面 | 「点击客户名去 B 面 360 下钻」 |
| 产品型号变迁 | 新增/流失数量摘要卡 | R 面/E 面 | 「型号异动清单详见 R 面行动清单」 |
| 业务员贡献 | 暂不展示，或仅 Top3 收入卡 | D 面 | 「销售员能力详见 D 面」 |

### 2.4 叙事线变更说明

- **新增 R 面**：插在 A 面之后，作为"总览→行动"的桥梁。
- **B/C/D/E 顺序不变**：避免大面积用户习惯迁移。
- **F 面仍在最后**：作为专项复盘，按需出现。

## 3. 新面「风险与行动」内容设计

### 3.1 页面布局

R 面采用三段式布局：

```
┌─────────────────────────────────────────┐
│ ① 上部：当月风险与异常摘要（KPI 卡 +  top 列表） │
├─────────────────────────────────────────┤
│ ② 中部：行动清单（待办/重点关注）              │
├─────────────────────────────────────────┤
│ ③ 下部：各面口径与使用说明                    │
└─────────────────────────────────────────┘
```

### 3.2 上部：当月风险与异常摘要

#### 3.2.1 双数据源

R 面候选事项来自两类来源：

| 来源类型 | 文件 | 维护方 | 内容 | 生成规则 |
|---|---|---|---|---|
| 数据驱动风险项 | `output/gold/异常日志.csv` | 系统自动 | 客户级异常 | 异常等级为「高」或「中」 |
| 数据驱动风险项 | `output/gold/负毛利分析.csv` | 系统自动 | 客户×产品负毛利 | 负毛利产品数 > 0 且损失金额 ≥ 阈值 |
| 经营会议跟踪项 | `dashboard/meeting_track.md` | 人工 | 会议决议、跟踪事项 | 直接读取，按状态过滤 |

测试版先做「异常日志 + 负毛利分析 + meeting_track.md」三个源。

#### 3.2.2 `dashboard/meeting_track.md` 格式示例

```markdown
# 经营会议跟踪项

## 2026-06-25 月度经营会

| 状态 | 跟踪事项 | 负责人 | 期望完成日 | 关联客户/产品 | 备注 |
|---|---|---|---|---|---|
| 跟进中 | 跟进某某科技价格谈判 | 张三 | 2026-07-15 | 某某科技 | 采购反馈待总部批复 |
| 待处理 | 评估 STI3452HFI 停产影响 | 李四 | 2026-07-10 | STI3452HFI | 涉及 3 个客户 |
| 已关闭 | 上月经销商返利核对 | 王五 | - | - | 已完成 |
```

字段说明：
- `状态`：待处理 / 跟进中 / 已关闭。
- `跟踪事项`：一句话描述。
- `负责人`：责任人姓名。
- `期望完成日`：可选，用于到期提醒。
- `关联客户/产品`：可选，用于与数据驱动风险项去重/合并。

#### 3.2.3 统一候选池

两类来源合并为统一候选池，再经策展规则筛选后写入 `action_items.json`。

| 字段 | 来源 | 示例 |
|---|---|---|
| ID | 规则生成 | `anomaly:某某科技:revenue_drop:202606` / `meeting:20260625:price_negotiation` |
| 来源 | 源表/源文件 | 异常日志 / 负毛利分析 / meeting_track.md |
| 标题 | 源表/人工 | 客户某某科技营收大幅下滑 / 跟进某某科技价格谈判 |
| 风险等级 | 源表/人工 | 高 / 中 / 低 |
| 创建月份 | 当前数据月 | 2026-06 |
| 建议动作 | 源表/人工 | 查看 B 面客户 360 / 价格谈判 |
| 关联面 | 规则生成 | B / C / D / E |

#### 3.2.4 展示策展规则

不是全部候选都展示。进入 R 面的事项必须过以下筛选：

| 规则 | 默认值 | 说明 |
|---|---|---|
| 严重度阈值 | 仅展示「高」「中」等级 | 低风险项不进入 R 面，保留在候选池备查。 |
| 每类 Top-N | 每类最多 10 条 | 异常日志 Top 10、负毛利 Top 10、会议跟踪 Top 10，避免信息过载。 |
| 去重合并 | 同一客户的多条异常合并为 1 条 | 如某客户同时触发营收异动和负毛利，合并为 1 条并标注多来源。 |
| 已关闭保留期 | 1 个月 | 已关闭事项在 R 面展示 1 个月后移除，保留在 `action_items.json` 历史记录中。 |
| 损失金额阈值 | ≥ 1 万元 | 负毛利损失低于 1 万元的项不进入展示。 |

**策展后写入 `action_items.json` 的字段**：

| 字段 | 说明 |
|---|---|
| `display` | 是否展示在 R 面（true/false），用于保留历史但不在当前看板显示。 |
| `display_reason` | 不展示的原因（如「低风险」「超 Top-N」「已关闭超保留期」）。 |

#### 3.2.5 KPI 卡设计

| 卡片 | 指标 | 说明 |
|---|---|---|
| 当月异常数 | 策展后展示的数据驱动风险项数 | 反映本月需要关注的客户/产品数量 |
| 高风险异常 | 等级 = 高 的数量 | 需要立即处理 |
| 负毛利损失合计 | 策展后负毛利损失金额求和（万元） | 量化财务影响 |
| 会议跟踪项 | meeting_track.md 中待处理 + 跟进中的数量 | 反映会议决议执行情况 |
| 状态分布 | 待处理 / 跟进中 / 已关闭 | 跟踪进度 |

#### 3.2.6 风险摘要列表字段

| 字段 | 来源 | 示例值 |
|---|---|---|
| 标题 | 源表/人工 | 客户某某科技营收大幅下滑 / 跟进某某科技价格谈判 |
| 来源 | 规则生成 | 异常日志 / 负毛利分析 / 会议跟踪 |
| 风险等级 | 源表/人工 | 高 / 中 / 低 |
| 客户/产品 | 源表/人工 | 某某科技 / STI3452HFI |
| 损失金额（万元） | 负毛利分析 | 117.2 |
| 建议动作 | 源表/人工 | 查看 B 面 / 停止供应 / 价格谈判 |
| 负责人 | 源表/人工 | 张三 |
| 关联面 | 规则生成 | B / C / D / E |

#### 3.2.7 事项过多时的降级展示策略

当月候选事项超过阈值时，按以下顺序降级：

1. **优先展示高等级**：先确保所有「高」等级事项展示完。
2. **再展示中等级**：中高等级展示完后，若仍超过单类 Top-N，按损失金额/影响排序取 Top-N。
3. **折叠低优先级**：超出部分收入「展开查看全部」按钮，不默认展示。
4. **会议跟踪项独立计数**：会议跟踪项不受数据驱动风险项 Top-N 限制，单独按状态筛选展示。

### 3.3 中部：行动清单

#### 3.3.1 事项状态

- **待处理**：系统刚生成，未分配负责人。
- **跟进中**：已分配负责人，正在处理。
- **已关闭**：已处理完成或确认无需处理。

#### 3.3.2 行动清单字段

| 字段 | 类型 | 说明 |
|---|---|---|
| ID | 字符串 | 稳定 ID，格式 `{source}:{customer}:{signature}:{data_month}` |
| 标题 | 字符串 | 一句话描述，如「某某科技负毛利产品 4 个，月损失 117.2 万」 |
| 来源 | 字符串 | 异常日志 / 负毛利分析 / 会议跟踪 |
| 客户/产品 | 字符串 | 关联客户或产品名称 |
| 风险等级 | 字符串 | 高 / 中 / 低（会议跟踪项可人工指定） |
| 创建月份 | 字符串 | 如 2026-06 |
| 状态 | 枚举 | 待处理 / 跟进中 / 已关闭 |
| 负责人 | 字符串 | 可编辑 |
| 备注 | 文本 | 可编辑 |
| 建议动作 | 文本 | 来自源表或人工填写 |
| 触发值 | 数值 | 如损失金额 |
| 关联面 | 字符串 | B / C / D / E，点击跳转 |

#### 3.3.3 候选事项生成规则（测试版）

**规则 1：异常日志 → 客户营收异动**

```
IF 异常等级 IN ("高", "中") THEN
    生成事项：
      标题 = "客户 {客户名称} {异常类型}"
      风险等级 = 异常等级
      建议动作 = "请结合 B 面客户 360 查看该客户近 12 个月趋势"
      关联面 = B
```

**规则 2：负毛利分析 → 负毛利产品处理**

```
IF 负毛利产品数 > 0 AND 负毛利损失金额 >= 10000 THEN
    生成事项：
      标题 = "客户 {客户名称} 有 {负毛利产品数} 个负毛利产品，月损失 {损失金额/10000:.1f} 万"
      风险等级 = 负毛利风险等级（若空则按损失金额分级）
      建议动作 = 源表「建议动作」字段
      关联面 = C
```

**规则 3：meeting_track.md → 会议跟踪项**

```
读取 dashboard/meeting_track.md 中状态 != "已关闭" 的行
    生成事项：
      标题 = 跟踪事项
      来源 = 会议跟踪
      风险等级 = 人工指定（未指定默认"中"）
      负责人 = 表格中的负责人
      建议动作 = 跟踪事项本身
      关联面 = 根据关联客户/产品推断（客户→B，产品→C）
```

### 3.4 下部：三层说明体系

R 面下部不再只是罗列各面口径，而是升级为三层说明体系，让用户按需查看。

#### 三层说明

| 层级 | 位置 | 作用 | 示例 |
|---|---|---|---|
| 面级口径条 | 每个面顶部折叠面板 | 说明这面看什么、关键口径、怎么用、更新节奏 | A 面：「公司经营总览：整体结果 + 常用维度速览」 |
| 图表级导读 | 图表/区块标题旁 | 一句话回答「这张图在看什么」 | A 面 KA 经营势能矩阵：「看 KA 客户增长 vs 毛利，右上角优质、左下角需关注」 |
| 指标级 hover | 指标/缩写悬停 | 解释术语 | ASP：平均售价 = 收入/数量；负毛利：收入低于成本 |

**纪律**：口径、阈值、数据来源变更时，必须同步更新 `faces.yaml` 对应 `sections[].koujing` 和图表导读。PR 需附带 `faces.yaml` 变更说明，防止说明与实现漂移。

### 3.5 人工确认流程与文件格式

### 3.7 跨月结转规则

1. **保留未关闭项**：状态为「待处理」或「跟进中」的事项，跨月保留。
2. **更新触发值**：若同一事项当月仍在触发，更新 `trigger_value`、`suggested_action`、描述，保留业务填写的状态/负责人/备注。
3. **自动关闭**：连续 3 个月未触发且状态为「待处理」的事项，自动转为「已关闭」（阈值可配置）。
4. **业务手动关闭**：状态为「已关闭」的事项不再自动重新打开。

## 4. faces.yaml 注册表 schema 定稿

### 4.1 文件位置

`sales_analytics_platform/dashboard/faces.yaml`

### 4.2 字段定义

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 面标识，决定 tab 顺序和数据变量前缀。 |
| `name` | 是 | 面显示名称。 |
| `theme` | 是 | 面主题一句话定义。 |
| `enabled` | 是 | `false` 时彻底关闭：不计算、不注入数据、不渲染 tab。 |
| `cadence` | 是 | `monthly` / `quarterly` / `half_year` / `on_demand`。 |
| `visible` | 否 | `false` 时隐藏 tab（可显示灰色占位）。默认 `true`。 |
| `owner` | 否 | 负责业务方。 |
| `icon` | 否 | Font Awesome 图标类名。 |
| `description` | 否 | 面级简短描述。 |
| `compute_stage` | 否 | 关联 `generate_dashboard.py` 进度阶段。 |
| `sections` | 否 | 区块口径说明列表，含 `title/definition/source/koujing/usage/update_note`。 |

**enabled vs visible**
- `enabled=false`：长期禁用，完全消失。
- `enabled=true, visible=false`：计算照常，tab 隐藏或显示占位（如 F 面 non-H1 月份）。

## 5. 插拔与更新节奏机制

### 5.1 总体原则

- **生成期决定**：在 `generate_dashboard.py` 读取 `faces.yaml` 后，决定每个面是否参与计算、是否注入数据。
- **模板最小改动**：模板仍保留 A~F 的固定结构，新增 R 面通过独立测试页先行验证。
- **进度协议不动**：现有 `[STAGE]/[n/m]` 打印语句保留原格式；新增 R 面的进度打印追加到最后一个阶段内部或新增阶段末尾，不破坏 Tauri 壳解析。

### 5.2 生成期挂点设计

`generate_dashboard.py` 当前结构（行号来自当前版本）：

## 7. 三个面的示例口径文案

> 文案风格：朴素业务语言，不营销。用户审后推广到全面。

### 7.1 A 面「总览决策」

**这面看什么**

公司经营总览：整体收入、毛利、ASP、KA/AA 贡献、整体趋势，以及常用维度（产品线、品类、客户层级等）的摘要表现。A 面只给结论和入口，完整明细去 B/C/D/E/R 面。

**关键口径**

- **YTD 收入/毛利**：本年 1 月到最新数据月的累计值。收入 = RMB 未税金额，毛利 = 利润列，毛利率 = 毛利 / 收入。
- **ASP**：平均售价 = 收入 / 发货数量。
- **KA+AA**：客户层级含 "KA" 或 "AA" 的核心大客户群。
- **产品线/品类 Top5**：A 面只展示 Top5 产品线/品类的收入和毛利率摘要，完整列表见 C 面。
- **KA/AA 客户列表**：A 面只展示 Top 20 核心客户精简信息，点击客户名去 B 面 360 下钻。
- **产品型号变迁**：A 面只展示新增/流失数量摘要卡，完整异动清单见 R 面。

**怎么用**

1. 看顶部 KPI 卡和整体趋势，判断大局。
2. 扫常用维度摘要卡，定位哪个维度异常。
3. 异常点点击「详见 X 面」，跳转到专面下钻。

**更新节奏**

每月刷新。

### 7.2 R 面「风险与行动」

**这面看什么**

本月要处理的风险和待办：一部分来自系统自动识别的数据异常，一部分来自经营会议跟踪项。这里只展示经策展后的重点事项，不是全部候选。

**关键口径**

- **数据驱动风险项**：来自 `异常日志.csv` 和 `负毛利分析.csv`，自动识别客户营收异动、负毛利产品等。
- **会议跟踪项**：来自 `dashboard/meeting_track.md`，人工维护的经营会议决议。
- **策展规则**：只展示高/中等级事项；每类最多 Top 10；同一客户多条异常合并；已关闭事项保留 1 个月后隐藏。
- **状态**：待处理 / 跟进中 / 已关闭。未关闭项跨月保留。

**怎么用**

1. 上部「风险摘要」：扫本月重点异常和损失金额。
2. 中部「行动清单」：分配负责人、改状态、写备注。会议跟踪项直接在这里同步状态。
3. 下部「口径说明」：三层说明体系，面级/图表级/指标级随时查。

**更新节奏**

风险摘要每月刷新；会议跟踪项随 `meeting_track.md` 更新；行动清单状态跨月持久。

### 7.3 B 面「客户 360」

**这面看什么**

聚焦单个客户，回答"这个客户最近怎么样、在买什么、有没有风险"。

**关键口径**

- **客户列表**：来自 `output/gold/客户全景.csv`，包含层级、活跃状态、风险等级等属性。支持按层级、活跃状态、风险等级筛选。
- **近 25 个月趋势**：该客户每月的收入、利润、数量，用于看长期走势。
- **品类/品种 Top5**：该客户近 12 个月采购金额最高的品类和型号。
- **新品明细**：来自 `silver_cleaned_rows.csv`，标记为新品的产品在该客户中的采购情况。
- **活跃状态**：基于客户全景表判定，包括活跃、微量活跃、非活跃。

**怎么用**

1. 左侧列表找到目标客户（可用搜索/筛选）。
2. 点击客户名，右侧显示该客户近 25 个月趋势、财务汇总、品类构成、Top 品种。
3. 如果发现风险等级高或收入下滑，回到 R 面行动清单建立跟进事项。

**更新节奏**

每月刷新。
