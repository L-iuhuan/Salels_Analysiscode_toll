# 数据契约 · DATA_CONTRACT（销售分析平台）

> 本文档基于 **2026-08-18** 实际运行产物（`output/silver/*.csv` 4 张、`output/gold/*.csv` 30 张）
> 与平台代码逐表核对生成，说明每张表的**用途 / 列清单 / 消费方**，
> 作为批次⓪基线工具链（`scripts/freeze_baseline.py`、`scripts/golden_diff.py`）的对照底稿。
>
> 约定：
> - **必须**：该表正常产出时此列恒有值（nonnull≈100%），且为维度标识或核心度量，漂移对比中视为必检字段；
> - **可选**：存在空值，或为辅助性文本/备注/低填充率字段；
> - **dtype** 为该列经 pandas 读取后的推断类型（object≈文本，float64≈数值，int64≈整数，bool≈布尔）；
> - **消费方** 标注"谁读它"：读方为 `dashboard/generate_dashboard.py`、`processing/cross_reference/run_cross_ref.py`、`processing/run_all.py` 及各处理模块；写方注明来源，便于追溯链路。

---

## 1. 数据分层总览

```
data/ 原始Excel（财务分析-XX月.xlsx，sheet "24-26"）
   │  processing/run_all.py  (stage silver/product/customer/kpi/cross_ref)
   ▼
output/silver/   清洗+月度聚合明细（4 张，含约 19 万行大表）
   │  下游: product_lifecycle / customer_analysis / dashboard
   ▼
output/gold/     各维度汇总指标表（30 张）
   │  下游: dashboard / cross_reference / Excel / BI / 人工分析
   ▼
dashboard/dashboard_a.html（内嵌 JSON 看板，A~F 六面）
```

写入方汇总：
- **silver 4 张**：`processing/run_all.py::stage_silver` → `shared/data_cleaning.monthly_aggregate_double_pass`
- **gold_product_portrait.csv**：`processing/product_lifecycle/run.py`
- **gold_kpi_daily.csv**：`processing/customer_analysis/run_kpi_daily.py`
- **cross_customer_portfolio_health.csv**：`processing/cross_reference/run_cross_ref.py`
- **其余 gold 表**：`processing/customer_analysis/gold.py::generate_gold_tables`（经 `processing/reports/gold_exporter.py::GoldExporter.save` 落盘为 CSV）

## 4. Dashboard 直读原始 Excel 的列

`dashboard/generate_dashboard.py`（L349~393，加载阶段）不读 Silver/Gold 的宽表，而是**直接读取 `data/` 里最新的一份原始 Excel**（sheet **"24-26"**），按列名精准读取后归一为 `rex`（rename 后 `_xxx` 列）。实际读取的列及语义：

| 原始 Excel 列 | 定位方式 | 归一列 | 语义 / 用途 |
|---|---|---|---|
| 发货日期 | 固定列名 | `_d` | 交易日期 → 自动检测最新月份，做 YTD/PYTD/月度过滤（L382、L396~417） |
| RMB 未税金额小计 | 固定列名 | `_rev` | 收入金额（A面 KPI、B/D/E/F 面收入口径）（L383） |
| 利润 | 固定列名 | `_profit` | 毛利（A面 KPI、各面利润口径）（L384） |
| 发货数量 | 固定列名 | `_qty` | 数量（A面、D面销量）（L385） |
| 终端客户简称 | 固定列名 | `_cust` | 客户简称（客户维度去重/计数）（L386） |
| 终端客户名称_客户类别 | 固定列名 | `_tier` | 客户类别/层级 → 筛选 KA/AA 客户（L387、L429~430） |
| 客户订单号 | 固定列名 | — | 订单数（D面订单数 nunique）（L819） |
| 产品线 / 产品品种 | 优先含"产品线"，回退含"品种" | `_prod` | 产品维度（L354~355、L388） |
| 产品品类（新） | 精确匹配，回退 index 66 | `_cat` / `_cat_new` | 品类维度（A/E面品类分析）（L357、L389、L391） |
| 存货名称 | 含"存货名称" | `_item` | A面产品型号变迁（L359、L390） |
| 产品线（新） | 表头 index 24 | — | E面产品线（L367） |
| 是否新品 | 表头 index 28 | `_is_new` | 新品标记（含"是"判定）（L371、L392） |
| 实际业务员 | 表头 index 4 | `_sales` | D面销售员维度（L375、L807） |

说明：
- 表头先以 `nrows=0` 读取（L350），按关键字/列索引**动态定位**列名，再 `usecols=keep_cols` 精准读取（L379），因此**列名随 ERP 导出变化时看板仍可容错**；但若缺少"发货日期/金额/利润/数量"等硬依赖列会直接报错。
- 读取的 sheet 固定为 **"24-26"**；原始 Excel 按 mtime 取 `data/` 里最新的一份（L340~347）。
- 该直读路径与 Silver 层清洗**并行存在**：看板 KPI（`_rev/_profit/_qty` 直接求和）与 Silver/Gold 聚合表是两套口径来源，做基线漂移对比时应留意这一"直读 Excel"事实来源。

## 5. 漂移对比约定（基线工具链）

批次⓪ 基线工具链（`scripts/freeze_baseline.py` + `scripts/golden_diff.py`）对上述表格执行：
- **row_count / columns / schema_hash**：严格相等（行列结构即"硬契约"）；
- **数值列合计**：相对容差 1e-6，近零值绝对容差 1e-6；
- **看板内嵌 JSON 变量**：type+len 严格；
- **看板标量 KPI（点路径）**：数值相对容差 1e-6，字符串/日期严格。

任何表新增/删除/列变更/行数变化/数值合计漂移，都会在漂移报告中按表分组列出。
