## 1. 系统定位与总数据链路

### 1.1 四面一句话定位

| 面 | id | 定位 | 读者 | 消费方式 |
|---|---|---|---|---|
| 总览决策 | A | 经营总览：整体结果 + 常用维度速览（速览不下沉，明细引专面） | 管理层、销售负责人 | rex 现算 |

### 2.1 KPI 九卡（YTD 窗）

窗口：`ytd_start = 当年1月1日`，`ytd_end = 最新数据月末`（derive_periods L243-244，纯函数从 rex 最大日期推导）；上年同期窗 `pytd = 上年1/1 ~ 上年同月末`（L245-246）。

九张卡（template.html L474-484，`kpi-bar` 栅格 9 列）：

| 卡 | id | 口径 |
|---|---|---|
| 本年度收入(YTD) | kpiRev | 当年各月收入求和（万元），副文本=同比 |
| 本年度毛利 | kpiProfit | 当年各月毛利求和，副文本=毛利率 与 同比 pp |
| 本年度成本 | kpiCost | 收入−毛利 |
| 平均售价(ASP) | kpiASP | YTD 收入 ÷ YTD 数量；副文本=同比（YTD ASP 对比）· 环比（**最新月 ASP vs 上一月 ASP**，跨窗） |
| 新品渗透率 | kpiNew | 新品标记=是的收入 ÷ 总收入（YTD），占位符注入 |
| KA+AA YTD收入 | kpiKaaRev | KA+AA 层级收入求和，副文本=占整体% + 客户数 |
| KA+AA YTD毛利 | kpiKaaProfit | KA+AA 毛利求和，副文本=该群毛利率 |
| 广东收入占比 | kpiGdPct | YTD 广东收入 ÷ YTD 总收入（GEO_KPIS） |
| 海外+港澳台占比 | kpiOvsPct | YTD 境外收入 ÷ YTD 总收入，副文本含未识别占比披露 |

**双实现事实**：Python 侧 L1062-1096 对 r26（YTD 帧）/r25（上年同期帧）直接聚合并注入 `%%KPI_R%%` 等占位符（L3413-3420）与日志；模板九卡显示值由前端 `updateKPIs()`（L1900-1990）从 TREND / TREND_TIERS / KAA_REV / E_MONTHLY_KPI / GEO_KPIS / D_KPI 现算覆盖。两者口径一致（月度求和 ≡ 直接求和；前端同比按「相同月数」对齐上年序列，与 pytd 上年同月末语义等价），但属两份实现（登记 8-1）。ASP 环比、KA+AA 客户数（D_KPI.ka_aa_total）只有前端一路。

前端 updateKPIs 逐卡数据源（L1906-1990）：

| 卡 | 前端数据源 | 现算口径 |
|---|---|---|
| kpiRev | TREND.r{当年} | 非空月求和；同比=对去年序列取相同月数求和对比 |
| kpiProfit | TREND.p{当年} | 同上；副文本=毛利率 与 pp 差 |
| kpiCost | TREND.c{当年} | 求和；副文本固定「收入-毛利」 |
| kpiASP | TREND.r + E_MONTHLY_KPI.qty | YTD ASP=收入÷当年各月 qty 求和；同比=vs 去年同月数；环比=当年最后两月的月度 ASP |
| kpiNew | %%NEW_PCT_PURE%% 占位符 | Python 注入（新品收入占比） |
| kpiKaaRev | KAA_REV | 当年各月求和；副文本=占整体% + 客户数（D_KPI.ka_aa_total） |
| kpiGdPct / kpiOvsPct | GEO_KPIS | YTD 占比 + YTD 金额副文本 + 未识别披露 |
| 地域卡缺失 | typeof 守卫 | GEO_KPIS 缺失时跳过、不阻断其余卡 |

Python 侧关键量（L1062-1096）：`ytd_r=r26._rev.sum()`、`kpi_mg=毛利/收入`、`kpi_ry=(ytd_r-lytd_r)/lytd_r`、`kpi_mg_yoy=毛利率差 pp`、`asp_ytd=ytd_r/ytd_q`、`asp_mom=最新月ASP vs 上一月ASP`。KA+AA 子集（L1067-1082）：`_tier.contains("KA|AA")` 命中行求和得 kaaa_yr/yp/sc，占比 `kpi_spt=kaaa_yr/ytd_r`。

### 2.6 geoMap 与 geo_resolver 地址解析

归属口径：按**发货地址**统计、按交易行聚合（同一客户多地址分别计入）；空地址/脏值 → 「未识别」自动披露占比。

解析器 `geo_resolver.resolve_region(address) → (region, sub, abroad)`（三级输出：省级短名或国家/地区、市级或区域、境外布尔）。规则链 11 步（geo_resolver.py L126-190，全部规则在 geo_dict.json，代码零地址词）：

1. FOB 贸易术语特例（FOB深圳机场→深圳，实发地）；
2. 大陆省级：行首全称 → 行首「XX省」→ 任意位置省名（配置序即优先级）；
3. 深圳区名救回（福田区/宝安区…漏写市名 → 广东·深圳市）；
4. 地级市 → 省（行首或含「XX市」）；
5. 台湾（繁体市级 + 邮编正则）；
6. 香港（区域表 + 英文公司形态正则）；
7. 澳门关键词；
8. 韩国（英文/韩文城市表）；
9. 公司名当地址映射表；
10. 其他国家英文国名词表；
11. 其余含 4+ 连续外文字母 → 「海外」兜底；全部未命中 → 「未识别」。

聚合输出（L3005-3177）：`geo_provinces`（近12月各省 r/p/q/mg/custs/share/mom/趋势数组，环比锚=最新月 vs 上一自然月）、`geo_gd_cities`（广东下钻市级）、`geo_abroad`（境外 region×sub 分行 + 末尾「未识别」行）、`geo_top5`/`geo_top5p`（YTD 弹层 Top5 客户/产品含同比）、`geo_kpis`（YTD 广东/境外/未识别占比）。地图 GeoJSON vendored 于 dashboard/geo/（缺失时地图降级提示条，其余地域图表不受影响，L3163-3166）。近12月识别率打印于控制台（L3174-3176），未落盘（登记 8-9）。色阶四档：>50% / 20-50% / 5-20% / <5%；省名标签仅收入 ≥ 地图最大值 8% 的大省显示（faces.yaml 详注）。

省行字段构造（L3064-3078）：`map=short_to_full_province()`（GeoJSON 全称映射，未知原样）、`share=近12月收入/近12月总收入（含海外与未识别，分母零保护 1e-9）`、`mom=最新月 vs 上一自然月（上月为 0 → null）`、`custs` 空客户键剔除后去重。大陆地图排除境外与未识别行（`_ml12`）；广东市级按 `_sub` 空值归「未细分」分组。

## 3. E 面「月度作战雷达」

### 3.1 e_monthly_kpi 逐月 KPI（L2192-2208）

全月份序列（`all_months` 取 rex 全部字符串月键，空日期行防御过滤 L2181），每月：`rev/profit/mg/qty/asp/custs/items` 六指标 + 分层 `KA/AA/KM/MM` 的 `_rev/_custs`。前端六卡（所选月收入/毛利/月均ASP/月均发货量/活跃客户数/首次导入数，template L2830）由该表合成，支持多月份勾选合计。

### 3.2 客户势能矩阵（L2211-2222）

`e_cust_monthly[客户][月] = {r, p, mg, q}`（空客户键剔除）。势能矩阵「同比/环比增长率 vs 毛利率」由前端从该 dict 现算（E_MATRIX_MODE 可切 yoy/mom）。

### 3.3 first_imports 首次大量导入（L2254-2278）

判定：**单订单行 `_qty ≥ 6000` 颗**（单行口径）且 `(客户, 存货名称)` 组合在累积历史集合中未出现过（`all_cust_item_history` 按月累积）。记录 month/cust/item/cat/pline/rev/profit/mg/qty/sales（多业务员顿号拼接）。与 A 面「产品型号变迁」的月聚合 ≥6000 门槛口径不同，勿混用（faces.yaml L35 已声明）。历史边界 = rex 加载窗口（行内注释写「从2024-01」，登记 8-6）。

### 3.4 e_sales_monthly 销售员月度与异动（L2283-2355）

仅当年有交易销售员（`sales_2026_set`）。每人每月：`r/p/q/mg/custs`、新品 `new_r/new_pct`（新品标记=是）、TOP1 客户（按收入 top1_cust/top1_rev/top1_rev_pct 与按利润 top1p_* 双口径）、异动客户列表 `anomalies`（取 |chg| 最大前 3）。

异动判定（L2317-2333）：客户月收入环比 |变化| > 50% 记异动（上月在册）；上月为 0 且本月 >0 记 `is_new`（chg=0，方向↑）。首次导入统计随后按 sales 字段反补进各人各月（L2345-2355）。

### 3.5 客户层级映射与型号变迁汇总（L2357-2399）

- `e_cust_tier`：客户编号 → 首笔交易行的客户类别（前端矩阵分色用）；`e_cust_names` 恒等映射。

### 3.6 量利拆解 e_decomp（L2370-2393；**公式实现在前端 JS**）

Python 只产原料：四维度 `pline 产品线 / ka_cust KA客户 / aa_cust AA客户（排除 KA）/ top_cat Top10品类`（Top10 按全时段收入预计算，避免逐月 TopN 漂移）的逐月 `r/p/q` 三值（维度名/品类名过滤 nan/None/空/未知哨兵）。JS 变量 `E_DECOMP = {dim_key: {label, items: {名称: {月: {r,p,q}}}}}`（L3217）。全部拆解公式在 template.html `eDecompBuild()`（L2964-3023）前端现算：

**基期**：`cur` = 所选各月合计；`prev` = 所选最早月的前一存在月（`eGetPrevMonths`，单月基期，登记 8-5）；同比基期 = 去年同月合计。

**公式（环比列；同比列同构造）**：

```
dR  = (cur.r − prev.r) / 1e4                    # 收入变化（万元）
prevAsp = prev.q > 0 ? prev.r / prev.q : 0      # 上期均价
curAsp  = cur.q  > 0 ? cur.r  / cur.q  : 0
isNew = (prev.q == 0)                           # NEW 语义：上期无销量
dQ  = isNew ? 0 : (cur.q − prev.q) / 1e4        # 销量变化（万颗）
vQ  = isNew ? 0 : dQ × prevAsp                  # 量贡献 = ΔQ × 上期均价
vP  = isNew ? 0 : (curAsp − prevAsp) × prev.q / 1e4   # 价贡献 = ΔASP × 上期销量
dP  = (cur.p − prev.p) / 1e4                    # 毛利变化：单独核算，不参与收入拆解
```

三要点（与 faces.yaml L308-311 详注一致）：

1. **isNew 语义**：上期销量为 0 → vQ=vP=0、环比变化列显示 `NEW`（该项收入全部为增量，不强行拆分）；
2. **残差不摊分**：`dR − vQ − vP = ΔQ × ΔAsp`（交叉项）留存为残差，UI 不单列残差列；
3. **毛利变化单独核算**：dP 独立成列，不属于收入变化组成部分。

**汇总判定**（L3011-3019）：ΣvQ 与 ΣvP 绝对值较大者定「量驱动型/价驱动型」；新品项计数单列。排名列表按 dR 升序（降幅前列）；散点 x=量贡献、y=价贡献、气泡=|dR|；点行进单项 MoM/YoY 瀑布图。同比列的 isNewY 不显示 NEW 标记（登记 8-4）。

渲染时从审定文档行动清单解析：稳定键 = 行内容 sha1 前 8 位（`row:xxxxxxxx`）；字段 status（非枚举值归「待处理」）/owner/due_date/note/created_month=当月/source=总体文档。结转修复：① created_month 保留首次创建月（不随渲染刷新）；② 已关闭项补 closed_month 后与当月项合并存档。action_items.json **不是人工编辑对象**（状态持久化层）。

### 5.8 两级降级（generate_dashboard.py L3279-3313，拍板策略）

1. **一级**：文档缺失（新旧行位置均不存在）或渲染异常 → 调 `build_draft` 自动重建初稿（**绝不覆盖已审定版**——仅在文件不存在时写盘）→ 重试 `build_r_face_inner_html`；
2. **二级**：仍失败 → 降级红色警示横幅（`.rbanner`，复用 --danger token）+ 置 `R_FACE_ERR=1`，模板侧 R tab 按钮显示红色感叹 badge（template L469）。

R 面 md **不入指纹缓存**（两路径均现算，同 C 面毛利率轴「永远现算」模式，fingerprint.py 契约注释）。

## 8. 未核实与登记项

登记规则：代码注释与实现不一致处按实现书写；探索中未逐一打开复核的引用关系、双源配置漂移、设计承诺与实现的脱节，逐条登记如下（编号 8-N 供方案书与说明页引用）。共 12 条。

1. **A 面 KPI 双实现**：Python L1062-1096 聚合与前端 updateKPIs 各算一遍 YTD KPI；`%%KPI_*%%` 占位符注入位置与九卡 id 的对应关系未逐一核实（模板九卡显示值以 JS 现算为准，静态初始值会被覆盖）。ASP 环比与 KA+AA 客户数仅前端一路。
2. **R 面 Top-N 双源**：代码默认 TOP_N_PER_SOURCE=10，faces.yaml 口径卡写 Top12，实际生效靠 risk_templates.yaml top_n=12；yaml 缺失时回退 10，与口径卡文案不符。
3. **R 面通道 3 阈值双源**：代码默认 `min_rev12m=0`（无门槛），faces.yaml 与 risk_templates.yaml 均写 10 万；生效以 yaml 为准，代码默认值构成口径文案漂移风险。
4. **E 面同比列 NEW 缺失**：eDecompBuild 同比列的 isNewY（上年同期无销量）不显示 NEW 标记（模板 L2997 仅环比列有 isNew 分支），vQy/vPy 按 0 显示——是否刻意未证实。
5. **E 面多月基期语义**：勾选多月时 prev = 所选最早月的前一**单月**（eGetPrevMonths），多月合计对单月基期；faces.yaml 未披露该语义。
6. **首次导入「全历史」边界**：累积历史集合以 rex 加载窗口为界；行内注释写「从 2024-01 检查」，实际边界由数据加载范围决定，注释与数据的相符性未验证。
7. **F 面 h1_issues 阈值硬编码**：产品线 −2pp / 部门整体−3pp / 客户 −3pp / 收入>100 万等触发线写死于 generate_dashboard.py L2725-2772，未入 faces.yaml 或配置文件。
8. **R 面对拍解析脆弱性**：load_prev_month_risks 依赖上月 md 表头列名（客户/产品、事项、等级、损失金额、持续）；列被改名后解析静默返回空 → 全部持续列变「新增」，无告警。
9. **geo_resolver 准确率未验证**：近12月识别率仅打印控制台（L3174-3176），未落盘为指标；「未识别」不区分真空地址与解析失败，无独立抽验。
10. **A 面 ASP 卡跨窗副文本**：主值 YTD、环比=最新月 vs 上一月，与九卡其余 YTD 口径不同窗；faces.yaml 仅声明地域双窗口，此卡跨窗未披露。
11. **R 面营收断崖损失额为反推值**：`loss = max(0, prev−rev)`，其中 prev 由 `rev/(1+mom/100)` 从环比反推（L473-474），非源表直接读数；源表无损失口径时作为对拍与排序的近似权重，精确度未标定。
12. **自动关闭规则缺失**：归档设计 §3.5.4 的「连续 3 个月未触发自动关闭」在现行代码无实现（见 §7-6）；长期挂起的待处理事项只能人工关闭。
