## 1. 系统定位与总数据流

### 1.1 业务视角

公司面向 3850+ 终端客户出货，管理层每月面对一组客户分配问题：**资源投给谁、风险盯住谁、谁在失血、代理商盘子怎么分布**。客户分析系统把"每个客户值多少钱、增长潜力多大、风险多高、该做什么动作"压缩成一张每客户一行的全景表（60+ 指标 + 评分 + 评级 + 策略建议），供看板 B 面（客户360）、D 面（销售能力）、A 面（KA/AA）消费。

它服务四类场景：

- **客户分层与资源分配**：5 维评分卡 → 综合价值层级（S/A/B/C）+ 双轴矩阵（明星/潜力/金牛/瘦狗）直接对应"战略扶持 / 维持监控 / 资源培育 / 控制成本"四种态度。
- **风险预警**：风险评级 + 采购中断预警 + 异常检测（营收断崖/异常低价/负毛利）回答"谁正在流失、谁在恶化"。
- **定价治理**：ASP 偏离 / 价格带分布 / 跨客户价差 / 异常低价标记，发现"谁买贵了、谁在侵蚀价格体系"。
- **行动落地**：规则引擎为每个客户生成策略建议（含交叉销售推荐），B 面详情页直接展示。

### 1.2 管道数据流

```
ERP Excel（DSE 加密，快照仓/COM 双通道读取）
    ↓ stage_silver（run_all.py）：ERP_COL_MAP 重命名 → 客户属性合并 → 双通道月度聚合
  Silver 层（4 表：customer_monthly / product_monthly / customer_x_product / cleaned_rows）
    └─→ 客户分析（customer_analysis/run_pipeline.py）
          ├─ calc_customer_portrait()（portrait.py，60+ 指标，向量化实现）
          ├─ generate_gold_tables()（gold.py 编排）：
          │    RFM-π → 行动建议（旧版兜底）→ B2B v2 旅程 → 波动性 → 真实利润
          │    → 帕累托利润分级 → 增长指标 Winsorize → 客户层级 → 5 维评分卡
          │    → 异常检测+库龄 → 负毛利 → 行动建议（升级版替换）→ 集团聚合（禁用）
          │    → 桥接/组合健康度 → v4.16 列精简 → 价格 8 组表 → 销售画像/品类擅长
          │    → 周期经营 4 表 → 研发建议 → 趋势 3 表
          ↓
  Gold 层（客户侧 27 张 CSV，含产品/kpi/cross_ref 共 31 张落盘）→ 看板 B/D/A 面
```

### 1.3 入口

```bash
python run_chain.py                    # 平台全链（silver → product → customer → kpi → cross_ref）
python -m customer_analysis.run_pipeline   # 模块单独运行（processing/ 下）
```

配置唯一真源是 `config/settings_customer.py`（801 行，经 settings.py `import *` 汇入）；`settings.py` 另持有 ERP_COL_MAP / 路径 / 清洗开关等共享配置。

## 2. 客户 ID、层级与渠道口径

### 2.1 客户 ID 口径变更（2026-06-12，重大）

| 项 | 变更前 | 变更后（现行） |
|---|---|---|
| 客户编号来源列 | 代理商/直供名称 | **终端客户简称**（ERP_COL_MAP 映射 → 客户编号） |
| 客户池规模 | 310 个（代理商/直供实体） | **3850+ 终端客户** |
| 分析粒度 | 渠道商视角（一个代理商名下汇聚众多终端） | 终端视角（每家终端工厂独立成行） |

**前因**：按代理商聚合时，同一终端客户经多家代理商拿货会被合并进不同代理商行，终端级的新品接受、品类渗透、流失信号全部不可见；管理层需要终端粒度的客户经营视图。**后果**：客户池从 310 放大到 3850+，评分分布整体位移——综合/风险评级阈值随之在 2026-06-12/13 按新分布重校准（见 §6.4）；代理商视角并未删除，改为看板 B 面"按销售模式"视图承担（YTD 现算口径，见 §12）。**代理 310 vs 终端 3850 双口径的正式定位仍是待拍板事项**。

**空客户编号处理**：`客户编号` 空值统一 fillna("未知客户") 聚合成哨兵桶；看板侧按 M4 口径将"未知客户"从 B 面客户列表剔除（收入归入总盘但不出客户行），统计落数据质量文件。

### 2.2 客户层级（KA/AA/KM/MM）

- **来源**：ERP 明细表 `终端客户名称_客户类别` 列（重命名后为客户类别，原始值如 "KA>1亿"）。
- **映射**（`CUSTOMER_TIER_MAP.mapping`，关键词子串匹配）：KA>1亿→KA（客户自身年营收>1亿）；AA>5000万→AA；KM>1000万→KM（含特殊值 KMM2）；MM<1000万→MM；X/未匹配→未分类。
- **取数链**（`calc_customer_tier`，analysis/scoring.py）：①画像已有"客户层级"列且非空 → 直用；②否则从"客户类别"/"终端客户类别"列关键词映射；③均无 → 未分类。**收入分箱回退已于 2026-05-23 移除**（我方销售额 ≠ 客户自身营收，反推会错分）。
- **客户等级**（A/B/C，另一列）：`build_cust_info` 由客户类别推导（KA/AA→A、KM→B、MM→C），供 Gold 各表 `_inject_tier` 注入。
- 层级反映**客户自身的营收规模**，不是在我方的采购量。

### 2.3 渠道类型推导（含原始列名 gotcha）

`CHANNEL_DERIVE` 现为 source_col 直取模式，三级降级从高到低：

1. **销售模式列直取**：`source_col="销售模式"`，mapping 经销→代理、直销→直供；每客户取首行值（`build_cust_info` 与 `_vec_channel_derive` 同口径）。cust_info 中渠道有效值优先，"未知"/空才落到下级。
2. **交易数据计数推导**（旧模式兜底，`_derive_channel`）：客户编号出现在 **`代理商/直供名称`** 列（原始 ERP 列名）→ 代理；出现在 **`实际终端客户`** 列 → 直供；两边都出现比计数（end_count ≥ buyer_count → 直供）；都不出现 → 未知。
3. **默认"未知"**。

> **Gotcha（顺序不可换）**：旧模式读的是**原始 ERP 列名**（"代理商/直供名称"/"实际终端客户"），这些列不在 ERP_COL_MAP 中、重命名不会动它们；`stage_silver` 的"先读原始数据 → 再重命名"顺序若被调换，旧模式兜底将永远取不到列。另注意：现行 `run_pipeline` 两条路径构造 raw_data 时只保留 `["销售模式", "终端客户名称_客户类别", "实际业务员"]` 三列——**旧模式的两列实际不在保留清单内，兜底在现行链路退化为"未知"**；渠道事实上单源依赖"销售模式"列的填写质量（销售模式填了公司名或留空的行，其客户渠道为"未知"）。

### 2.4 所属区域与业务负责人

- **区域**：设计上三源——客户信息表 sheet 的"所属区域"列 → raw_data"销售部门"列经 `DEPT_REGION_MAP`（T1-T3→华南等 10 条人工维护映射）→ 默认"未知"。**现状：raw_data 三列保留清单不含"销售部门"，客户信息表路径在当前批次未供数，所属区域恒为"未知"**（95 行差异版记载，2026-09-16）。
- **业务负责人**：现行代码有源——`build_cust_info` 取"实际业务员"首值为业务负责人（portrait 兜底路径 `attr_owner` 同源）。与旧差异版"负责人=未知"的记载不一致（该记载可能写于此取数统一前），当前批次实际填充率未跑数验证，登记 §16-9。

### 3.4 缓存与陷阱

- `SKIP_SILVER_IF_EXISTS=True` + 校验和指纹（配置+关键代码+源 Excel 身份）：silver 存在且指纹一致时静默跳过。**改清洗逻辑/ERP_COL_MAP 后必须强制重算**，否则旧缓存继续生效。
- skip_silver 路径的 raw_data 回退"快照优先"（data_warehouse parquet，本地仓 miss 查数据盘仓），无快照才直读 Excel；仅保留 §2.3 所列三列。
- Silver 读写统一指向包根 `output/silver/`、`data/`（批次⑤ 缺陷A修复）；CSV 编码 UTF-8-BOM；customer_x_product 同步双写 parquet（失败仅警告回退 CSV）。

## 4. 客户全景画像（60+ 指标逐组公式）

`calc_customer_portrait()`（portrait.py，批次②车道B向量化，与逐客户版浮点 1e-6 容差等价）输出每客户一行。指标按 12 组组织：

### 4.1 基本信息（_vec_base_info）

渠道类型（§2.3 三级降级）、客户等级（未知兜底）、客户类别（未分类兜底）、所属区域（未知兜底）、业务负责人（实际业务员首值）。客户不在 cust_info 且有 attr 映射时，等级/类别置空 NaN（保留"缺数据"语义而非假默认）。

### 4.2 经营势能（_vec_momentum）

| 指标 | 公式 | 备注 |
|---|---|---|
| 近12月收入/毛利/数量 | Σ rev_sum / profit_clip_sum / qty_sum（近12月窗口） | 毛利率 = 毛利/收入×100（收入≤0→0） |
| 前12月收入 | Σ rev_sum（前12月窗口） | |
| 订单数 | Σ order_count（无订单列→0） | |
| ASP_加权 | 近12月收入 / 近12月数量（数量≤0→0） | |

### 4.3 增长动能组（重点，含窗口回退与钳制）

**收入增长率**（正收入月月均法，三级缩窗）：

```
主窗: p_count≥2 且 p_sum>0（前12月正收入月≥2 且合计>0）
      growth = (近12月正收入月均 - 前12月正收入月均) / 前窗月均
短窗回退: ps_count≥1 且 ps_sum>0 → (近6月均 - 前6-12月均) / 前窗月均
均不满足 → growth = 0
钳制: clip(growth, -1.0, 5.0)   ← 读取 PRODUCT_LIFECYCLE.rev_growth_lower/upper（跨模块借键）
```

> **钳制现状校正**：旧 95 行差异版记载"客户增长率未钳制（极端值如 3085% 可能出现）"——现行 portrait.py（`_vec_momentum` 内增长率钳制段）**已对收入增长率加 [-1,5] 钳制**（与产品生命周期 v2.9 同款）。但 **YoY同比增速未钳制**、画像表中的 增长动量/近6月交易额环比增长率 原值保留（仅评分前 P1-P99 Winsorize，见 §6.2），极端值仍可能出现在这些列——3085% 类极值按列归属核对应落在 YoY/动量类指标。

**YoY同比增速**：近12月均 vs 12-24月前均（要求前窗正收入月≥2 且合计>0，否则 0）。需约 24 月数据，消除季节性。

**连续增长/下滑月数**（状态机）：`v[i] > v[i-1]×(1-5%)` 计增长（5% 容差，growth_streak_tolerance）；`v[i] < v[i-1]` 计下滑；取末尾连续同向段长。零采购月不进序列（silver 无零月行）。

### 4.4 产品覆盖（_vec_product_coverage）

品种总数 = 每客户不重复品种数；品种集中度Top3 = 客户品种收入降序前 3 之和 / 品种总收入（NaN 品种被排除）。

### 4.5 产品线分布（_vec_product_line_distribution）

| 指标 | 公式 | 备注 |
|---|---|---|
| 实际品类数 | nunique(型号_产品品类) | Phase 0 fix：产品一级分类恒=12 无区分度，改细分列 |
| 产品线数 | 收入>0 的产品线（型号_产品线（新），v4.11 起 16 品类）数 | |
| 主导产品线 / 占比 | 收入 idxmax 线 / max(share) | 并列取字典序最小 |
| 产品线HHI | Σ share²（收入占比平方和） | 1=单一依赖 |

### 4.6 采购健康（dimensions 包装 shared.pricing → analysis/pricing）

- 常规平均采购间隔：剔除前 6 个月（purchase_interval_exclude_first_months）后的月均间隔×30.4375 天/月（days_per_month_estimate）。
- 距上次采购天数、采购中断预警：距上次 > 常规间隔×1.5（churn_multiplier）→ 预警。
- Top5集中度/强依赖标记：Top5 品种采购额占比 ≥0.70（concentration_threshold）→ 强依赖。

### 4.7 价格治理

- 价格带分布：品种单价按客户内 P25/P75 分界 → 低价/中价/高价品种收入占比。
- ASP_跌幅%（_vec_asp_comparison）：`clip((ASP_加权 - 全局ASP)/全局ASP × 100, ±100)`。全局 ASP = 近12月全部产品 Σrev/Σqty。截断值 METRIC_CAPS.asp_decline_max_pct=100。

### 4.8 品类接受度

主导品类 / 主导品类占比 / 品类机会标签（品类细分列聚合；实现见 §16 登记项）。

### 4.9 SKU 生命周期

主要SKU阶段 = 客户在采品种的 SKU 生命周期阶段（5 阶段状态机输出）众数，并列取字典序最小；无映射 → 未知。

### 4.10 新品渗透（纯 ERP 标记口径）

`calc_new_product_cohort`：**优先级 1** —— product_monthly 含"新品标记"列（ERP"是否新品"映射）时，近 12 月内任一行为"是"即新品；**优先级 2（回退）** —— 首次销售距今 ≤12 月（new_product_max_months）。输出：新品采购额 / 新品品种数 / 新品采购占比（新品额/总采购额，总为 0→NaN）/ 是否采购新品 / 全市场新品渗透率。**与产品侧双轨不同**（产品侧另有月数/销量模式），与看板 B 面 Top 产品卡口径（ERP 标记+首销月落在近 13 个月内）也不同——三口径并存，勿混用。

### 4.11 机会/风险信号

新品渗透机会、增长动量（来自 calc_opportunity_signals，作为增长动能子指标之一）；品种流失金额占比、近半年营收跌幅（calc_risk_signals）。实现细节未逐行读，登记 §16-2。

### 4.12 毛利率趋势（_vec_margin_trend）

毛利率跌幅% = (近12月毛利率/100 - 前窗毛利率)/前窗毛利率 × 100；前窗毛利率≤0 → 0。注意名称为"跌幅"实为带符号变化率（可为正=改善）。

## 5. RFM-π 评分（渠道隔离）

`score_rfm_pi`（analysis/rfm_pi.py），在 gold.py 编排第一步执行。

### 5.1 维度与打分

| 维度 | 数据列 | 方向 | 默认权重 |
|---|---|---|---|
| R 近度 | 距上次采购天数（整列缺失时填 180） | 越小越好 | 30% |
| F 频次 | 常规平均采购间隔（缺失填 60） | 越小越好 | 20% |
| M 金额 | 近12月毛利（缺失填 0） | 越大越好 | 30% |
| π 新品 | 新品采购占比（缺失填 0） | 越大越好 | 20% |

每维 `pd.qcut(rank(dense), 5)` 五分位打 1-5 分（反向维 labels 翻转）；列缺失或单值 → 全体 3 分；分箱失败 → 3 分。

### 5.2 渠道隔离评分

按渠道类型分组、组内独立五分位 + 渠道特定权重（RFM_PI_WEIGHTS）：**直供 R30/F20/M30/P20；代理四维各 25%**。组内客户数 <5 时回落统一默认权重（打印告警）。**渠道"未知"及其他未配置渠道的客户归入"其余"子集，用统一默认权重在该子集内五分位**——不是不参评，而是与直供/代理分开排名（销售模式未规范填写的客户间互比）。

**为什么隔离**：直销（终端厂商）与代理（分销商）采购行为本质不同——代理客户天然低频大额、终端客户高频小额，混合评分时其中一类会被系统性压到低分位，分层失去意义。

### 5.3 综合分与层级

RFMπ_综合分 = Σ 维分×权重（1.0-5.0）；层级 S≥4.0 / A≥3.5 / B≥2.5 / C（RFM_PI_TIERS）。**注意：v4.16 列精简已把 RFMπ_层级 列从客户全景 Gold 表删除，R/F/M/P_得分与综合分保留**——层级只存在于中间过程，B 面不消费 RFM 字段。

### 10.1 客户旅程（journey/stage_classifier.py，7 阶段）

优先级判定：激活期 > 导入期 > 流失期 > 衰退期 > 成长期 > 成熟期 > 稳定期。

| 阶段 | 判定（CUSTOMER_JOURNEY_THRESHOLDS） |
|---|---|
| 激活期 | 历史最大间隔月 >180 天窗口 且 距上次≤1 月（沉默后回归） |
| 导入期 | 首次交易≤6 月 且 总订单≤3 |
| 流失期 | 距上次>180 天 且 近6月无交易（v4.5：90→180） |
| 衰退期 | 近6月环比跌幅≥20% 且 连续下滑≥2 月 |
| 成长期 | 近6月环比增长≥30% 或 频次激增≥2 倍 |
| 成熟期 | 近12月CV<0.3 且 近6月金额排名前30%（**按渠道分组排名修正**，channel_map 来自画像渠道类型；无渠道映射才全局排名） |
| 稳定期 | 兜底 |

输出列：客户旅程阶段/阶段持续月数/阶段转换次数/首次交易日期/距上次采购天数/近6月交易额环比增长率/近12月交易额CV。历史阶段回溯用乘数 0.9/1.1（跌幅>10%/涨幅>10% 判连续）。**注意：v4.16 已删"客户旅程阶段"列本身**——7 阶段分类在中间过程驱动评分（近6月环比等派生列保留并参与增长动能），B 面显示的是 6 阶段"客户生命周期"（§4.6 同源计算，阈值 CUSTOMER_THRESHOLDS：爬坡环比≥5%、衰退=连续3月低于均线15%）。

### 10.2 采购波动性（behavior/volatility.py）

指标：收入CV（std/mean，均值≤0→999）/最大单月跌幅/零采购月占比（全时间范围零填充缺失月）/趋势R²（线性拟合）。**稳定性等级 v4.5 为加权评分制**（非归档的 AND 逻辑）：

```
cv_score   = 100 if CV<3.0 else 60 if CV<6.0 else 20      （stable/moderate_cv_threshold，v4.5 终端客户宽分位校准）
zero_score = 100 if 零月占比<0.75 else 60 if <0.95 else 20 （⚠ 硬编码，配置键 0.55/0.75 读取后未使用，§16-5）
r2_score   = R²×100
stability  = 0.4×cv_score + 0.3×zero_score + 0.3×r2_score
≥70 高稳定 / ≥40 中等稳定 / 其余 高波动
```

稳定性等级列在评分（效率维/稳定维）后于 v4.16 被删，零采购月占比保留。

### 10.3 真实利润（profitability/true_profit_estimator.py，v4.5 简化）

```
真实利润 = 近12月毛利 - 订单处理成本（订单数×50 元/单；订单数缺失时 = max(1, 收入/5000)）
真实利润率 = 真实利润 / max(收入, 1) × 100
利润等级：≥35% 高利润 / >0 微利 / ≤0 亏损        （Gold 列名"利润率情况"）
```

物流（营收×2%）/售后（退货×30%）/资金占用（应收×6%×DSO/365）三项成本 **v4.5 已删除**——缺真实数据时按营收比例估算对所有客户无区分度、徒增噪声（ESTIMATED_COST 相关键保留未用，待真实成本数据接入后重启）。

### 12.1 双模式与筛选

- **按终端客户**（默认）：搜索 + 层级（KA/AA/KM/MM）+ 状态（活跃/微量活跃/非活跃）+ 风险（极高/高/中/低）筛选；列表默认按近12月收入降序，分批加载。
- **按销售模式**：列表顶部切换"经销/直销"子页签 + 代理商搜索；**YTD 现算口径**（generate_dashboard 从行级明细现聚合）——经销桶按"代理商/直供名称"列聚合为代理商卡片（可展开到终端客户，代理商×客户对口径、客户跨代理商分别列示不去重）；直销桶直接列终端客户；**销售模式填了公司名或留空的行不进本视图**（两组合计小于总盘，差异落数据质量文件）；层级构成环只认 KA/AA/KM/MM 四类，异常层级行不计入（计数落 DQ 文件动态令牌）。

### 12.2 客户详情（下钻）

Gold 属性 + Raw Excel 财务现算拼装：趋势（近12月，行级按客户×月聚合 tail(12)）；YTD/近12/上月/最新月四窗收入毛利毛利率（现算）；品类构成与品种数（近12月品种去重）；Top 产品卡（区间 YTD/近12/近6/近3 四档，趋势为成本+毛利堆积柱）；新品明细（ERP 标记 + YTD + 首销≥窗口 + 品种累计销量≥6000 件过滤）；采购节律（预计下次 = 常规间隔 - 距上次，负值为"已超期N天"）；五维分/综合价值分/层级/双轴/风险/生命周期/策略建议/异常告警全量展示。

### 12.3 与管道口径的差异声明

B 面列表收入/毛利为 **YTD 现算口径**，评分/层级/风险为**画像近12月口径**——同一客户两处数字可不等（与 D 面双口径同构的历史形成，未合并）。品种数两窗口（详情近12月 vs 代理商卡片 YTD）不同属预期（faces.yaml 口径卡已声明）。
