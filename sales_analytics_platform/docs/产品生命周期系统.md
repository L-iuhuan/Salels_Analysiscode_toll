## 1. 系统定位与总数据流

### 1.1 业务视角：这套系统在经营管理中扮演什么角色

一家半导体分销商在售 900 多个产品，管理层每个月面对的是一组资源分配问题：**钱往哪些产品投、哪些产品该准备退场、哪些表面平静的产品其实在失血、新品有没有长起来**。靠人工逐个看报表不可能覆盖，这套系统的价值就是把"每个产品现在值不值得投、风险多大、该做什么动作"压缩成一张快照表，让产品决策从"凭印象"变成"有依据"。

它服务三类使用场景：

- **月度经营复盘**：九宫格画像 + 管理层摘要（投入区/维持区/观察区/退出区）直接对应资源态度——投入区加资源、维持区守住利润、观察区警惕、退出区有序清退。管理层看四区分布就能感知产品组合的健康度变化（比如退出区占比逐月扩大就是预警）。
- **衰退预警**：风险评分回答"哪些产品正在走下坡路、走得多快"。业务上最重要的不是评分本身，而是**主导因子**——同样是 80 分高风险，"增速衰减主导"（需求在消失）和"毛利斜率主导"（利润被侵蚀）的应对动作完全不同：前者查下游需求和大客户订单，后者查成本结构和定价。
- **新品与迭代跟踪**：新品观察池、首次 6K 用时、清仓/偶发隔离，让"新品有没有按预期上量、老品是否已经僵尸化"有量化答案。

设计上的一个核心取舍：**宁可漏报不可误报过多**——大量阈值（分位数参照、爆发截断、脉冲豁免、连续下降加成）都在防"把正常波动判成衰退"，因为误判退出区会直接误杀还在赚钱的产品；反过来，衰退兜底和覆盖规则又保证"真衰退不会被机制性漏掉"。整个评分体系是在这两端之间校准的。

### 1.2 七阶段数据流

产品生命周期系统回答一个问题：**每个产品现在处于什么阶段、赚钱能力如何、衰退风险多大、接下来该怎么处理**。输入是全公司出货明细（银层/行级），输出是每个产品一行的画像快照表（60+ 字段），供 Excel 报告与看板 C 面消费。

七个阶段（run.py `run_analysis` 的 Phase 注释，L266-371）：

```
Phase 1  数据准备      _prepare_data()：类型转换、口径开关、日期过滤、不完整月剔除
Phase 2  新品判定      run_profiling() 内：ERP 标记优先，月数/销量自动兜底
Phase 3  历史参考计算  _compute_reference_groups()：参照组加权均值，多级兜底
Phase 4  画像分类      九宫格：销量动能 × 盈利健康 → 9 画像
Phase 5  风险评分      4 因子加权（v4.0），不可靠因子重加权 + 爆发截断 + 衰退兜底 + 覆盖规则
Phase 6  ETS 预测      _calc_forecast_extras()：3 月预测 + 80%/95% 区间 + 节假日调整 + WMA 兜底
Phase 7  历史画像追踪  t-k 截点重跑画像（多进程），合并变迁轨迹
```

入口：平台全链 `python run_chain.py`（STAGES 注册制）或模块单独运行 `python -m product_lifecycle.run`。配置唯一真源是 `settings_product.py` 的 `PRODUCT_LIFECYCLE` 字典（run.py 内的 `load_config_from_xlsx` 是 v2.8 Excel 配置的兼容死代码，config.xlsx 已不存在——AGENTS.md 明确声明该路径永不使用）。

## 2. 数据准备与清洗（run.py `_prepare_data`，L153-251）

### 2.1 类型与读取

- CSV 路径：`pd.read_csv(encoding="utf-8-sig")`；Excel 路径：`read_excel_auto(sheet_name=0)` + `rename_erp_columns` 列名标准化。
- 产品名称 strip 成字符串；发货日期 `to_datetime(errors='coerce')`；销量/营收/利润 `to_numeric(errors='coerce').fillna(0)`——**数值缺失按 0 处理，不丢行**；订单号 strip。

### 2.2 负销量口径开关（D-2，默认关闭）

```python
if thr.get("_口径_负销量过滤", False):
    df = df[df[qty_col] > 0]
```

**前因**：历史 v2.8 剔除负销量行；平台化时为与生产链（shared.data_cleaning）口径一致改为默认保留——退货/红冲行自然冲减收入，避免剔除后收入虚高。**为什么留开关**：批次③业务门禁（D-2 决策）尚未拍板，保留一键回退到 v2.8 行为的能力。**影响**：默认口径下近 12 月销量可能被退货抵减；若业务最终拍板剔除，改配置即可，无需改代码。

### 2.3 毛利率口径开关（D-1，默认不钳制）

```python
if thr.get("_口径_毛利率钳制", False):
    df['_毛利率'] = (利润/营收).clip(-0.50, 0.75); df['_利润_裁剪'] = _毛利率 × 营收
else:
    df['_毛利率'] = 利润 / 营收(0→NaN); df['_利润_裁剪'] = 原始利润
```

**前因**：v2.8 对行级毛利率做 Winsorization 钳制 [-50%, 75%]，防极端毛利率污染画像；平台批次③预演发现钳制会高估收入 0.50%（全期）/0.58%（YTD），业务拍板 D-1 仅展示层截断、数据层不篡改。**后续全部分析默认用 `_利润_裁剪`**（不钳制时即原始利润），使两条口径路径在代码上同构。

### 2.4 日期下限与不完整月剔除

- `data_start_date = 2020-01-01`：此前数据剔除，日期缺失行剔除。
- **不完整月剔除**（`incomplete_month_threshold_day = 25`）：取最新月份（`df['_月'].max()`）内的最大日期，若 < 25 号则该月数据整体剔除、`latest_month` 回退至上月，并打印警告。**为什么按"该月内最大日期"而不是全局最大日期**：月末最后一笔发生在 25 号前（如春节月提前放假）时，全局最大日期同样 < 25，但若最新月有一笔 28 号的退货冲销，全局最大日期会掩盖"出货数据其实不完整"的事实。基准月回退保证"近 12 月"窗口不含残月。

### 2.5 PIT 截断（r28，run_profiling L986-989）

```python
prod_month = prod_month[prod_month["_月"] <= latest_month]
```

**前因**：历史画像追踪复用全量预聚合表（run.py 传入 prod_month）时，"近 12 月"窗口（`_月 > latest_month-12`）无上界，会把截点之后的月份一并计入——实测 t-12 截点的"近 12 月销量"等于截点前 12 个月起至数据末端的全段。**解决**：在 run_profiling 入口按截点截断。**好处**：历史画像序列严格无未来泄漏（这是后续用画像做任何回测的前提）。

## 3. 预聚合与产品档案（run_profiling 主循环，L967-1193）

### 3.1 产品×月预聚合（L972-984）

```
prod_month = df.groupby([产品名称, _月]).agg(
    qty_sum=销量求和, rev_pos=营收clip(下限0)再取>0部分求和,
    profit_clip_sum=_利润_裁剪求和, [_order_count=订单号nunique])
_avg_price = rev_pos / qty_sum（0→NaN）
```

**营收取正的考量**：rev 列先 `clip(lower=0)` 再对正值求和，使退货月营收不为负，毛利率分母不失真；销量未做此处理（负销量在默认口径下保留，qty_sum 可为负）。

### 3.2 产品档案 prod_info（L997-1068）

每产品一行：首月/末月/活跃月数/日历月龄（`latest_month - first_month + 1`）/近12月销量与营收/参照组（分类列的 first 值）/客户集中度（近12月按客户营收排序：top1_ratio = 第一大客户营收/总营收，top3_ratio = 前三大/总，客户数<3 时 =1.0）/首次6K日期（`销量≥first_6k_threshold(6000)` 的最早日期）。

### 3.3 新品判定双轨（L1058-1068）

- **ERP 标记优先**：存在"新品标记"列时，近 12 月任一行为"是"即新品（`(s=="是").any()`），打印 `[新品判定] 使用ERP标记，新品数: N`。
- **自动兜底**：无标记列时按 `new_product_mode` 二选一——"月数"模式：`日历月龄 < min_history_months(6)`；"销量"模式：`近12月销量 < min_volume(100)`。
- 新品短路输出"新品观察/待观察"画像（L559-594），不参与九宫格、风险评分、参照组。

### 3.4 数据不足分离（L1070-1078）

`日历月龄 < min_record_months(3)` 的产品进入 data_insufficient_list 单独输出，不进入画像主流程。

### 3.5 P-2 预计算包（L1087-1148）

为避免逐产品重复过滤，预聚合 7 个窗口（recent 近12/prior 前12/last3 近3/prior3 前3-6/prior6 前6-12/yoy 12-15 月前/p24 24-36 月前）的 qty/rev/profit/months 字典 + 近 12 月毛利率透视表。`_process_product` 优先从预计算包取数（`p2["has"]`），否则回退到产品月表 pm 现算——两条路径数学等价，预计算仅为性能。

### 3.6 连续下降月数（L1157-1171）

取产品近 13 个月的月销量序列，从最后一个月向前数"本月 < 上月"的连续次数，遇非下降即停。用于 F4 加成与特情说明。

## 4. 单产品指标计算（_process_product，L520-964）

### 4.0 指标体系的业务逻辑

60+ 个指标不是平行堆砌，它们组织成四组递进的业务问题：

1. **规模与动能**（销量/营收/增长率/增速变化/连续下降）——"这个产品在涨还是在跌？涨跌是加速还是见顶？"增长率用月均法加三级缩窗，就是为了让"中途上市的产品"和"老产品"能公平比较趋势方向。
2. **赚钱能力**（毛利率族/自比健康度/他比健康度/斜率）——"它现在赚多少？比自己巅峰差多少？比同类差多少？趋势是在恶化还是改善？"自比健康度回答第一个问题（现在是巅峰的几成），他比回答第二个（在同品类里算好算差），毛利额斜率回答第三个（正在变好还是变坏）。三者交叉才能区分"一直平庸"“突然恶化”“原本很好正在回落"三种完全不同的业务处境。
3. **结构性风险**（客户集中度/订货波动/脉冲/ASP 联合诊断）——"它的收入质量脆弱吗？"top1 客户占比过半意味着一纸调令就能腰斩收入；ASP 与毛利率的联合诊断区分"主动降价换量"和"被动卷入价格战"。
4. **前瞻信号**（增速衰减/连续下降/订货量变化 c6）——"衰退要来了吗？"这三个是领先指标：增速衰减在总收入还没跌时就捕捉到"短期动能弱于全年"的拐点，连续下降月数捕捉趋势的持续性，c6 从大客户订单端交叉验证。

按执行顺序，全部公式如下。

### 4.1 清仓/偶发短路（L532-557）

条件：`日历月龄≥24 且 近24月内有销量月数≤1 且 近12月销量=0` → 画像"清仓/偶发"、摘要"退出区"、评分置空（"暂无评分"）、_margin=NaN、_rev=0。**设计意图**：僵尸产品偶发销售不参与正常周期分析，也避免其异常毛利率污染参照组。

### 4.2 窗口基础量（L596-621）

近12月/前12月的销量、营收、裁剪利润（预计算包或 pm 现算）。

### 4.3 销量增长率——三级缩窗（L623-681）

**主公式（月均法）**：

```
growth = (近12月月均销量 - 前12月月均销量) / 前12月月均销量
月均 = 窗口总量 / 窗口有记录月数
```

**为什么用月均而不是总量比**：窗口内月数不齐（新品中途进入、缺月）时总量比会系统性偏低，月均法对活跃月数归一。

**三级缩窗**（MIN_MONTHS=2）：前 12 月有效月数≥2 且总量>0 → 12 月窗；否则降 6 月窗（近6 vs 前6-12月）；再不足降 3 月窗（近3 vs 前3-6月）；仍不足 → growth=0，窗口标签"无参照"。窗口标签写入 `_growth_window`，非 12 月窗会在特情说明中提示"可能不稳定"。

**增长率钳制**：`growth = max(-1.0, min(growth, 5.0))`，即 [-100%, +500%]；被截断时 `_growth_clamped=True`、质量标记 GC、特情说明注明"实际更高/更深"。**为什么不钳制会失真**：极低基数产品（前 12 月 2 件→本月 100 件）增长率 4900% 会把九宫格纵轴拉爆，钳制后仍落在"加速增长"档，信息不损失。

### 4.4 毛利率族（L683-693）

```
近12月毛利率 = 近12月裁剪利润 / 近12月正营收（分母≤0 时=0）
当月毛利率   = 当月裁剪利润 / 当月正营收（分母≤0 时=None）
毛利率同比变化(pp) = (近12月毛利率 - 前12月毛利率) × 100
```

### 4.5 营收增长率与四判断（L695-711）

```
rev_growth = (近12月月均营收 - 前12月月均营收) / 前12月月均营收（前窗不足2月或≤0 时=0）
钳制 [-1.0, 5.0]
```

营收-毛利综合判断四象限：rev_growth>0 且 毛利率升→**双增**；rev>0 且毛利率降→**增收不增利**；rev≤0 且毛利率升→**减收增利**；双降→**双降**。该判断被九宫格的上下文策略（预警增长分叉）与特情说明（退市复核提示）消费。

### 4.6 帕累托分类（L713-720）

近 12 月营收 ≥100 万（pareto_key_revenue）→"重点产品"；≥10 万（pareto_regular_revenue）→"常规产品"；否则"潜力产品"。**用途**：分层资源分配（重点产品的降本建议、高增长常规品的加投建议，见特情说明 §9）。

### 4.7 首次 6K 追踪（L722-734）

单月销量 ≥6000 件（first_6k_threshold）的最早日期；是否已达 6K；首次 6K 用时（月）= 6K 月份 - 首次发货月 + 1。**业务含义**：6K/月是产品规模化的门槛标记（月度经营分析中"是否已达6K"是新品跟踪信号之一）。

### 4.8 历史参照毛利率——分位数自适应（L736-769）

输入序列：该产品**月度毛利率 > 0** 的月份集合（`profit_clip_sum/rev_pos`，剔除非正）。

```
月龄 < 12（ref_short_age_months）:
    有效月 < 6（ref_robust_min_points）→ 分位数 = 0.50×0.6 = P30
    否则 → P50（ref_short_percentile）
月龄 ≥ 12:
    有效月 ≥ 20（ref_p95_min_months）→ P95（ref_percentile）
    否则 → max(0.90, P50+0.10) = P90（自动降级）
月龄 ≥ 36 → 长期参照 = 最近 24 月（ref_long_months）的 P80（ref_long_percentile）
无有效月 → 参照 = 0
```

**为什么分位数随样本量降级**：P95 在 20 个点以下估计极不稳定（一个极端值即决定结果），短历史降 P50、长历史不足 20 点降 P90，是用"分位水平换稳定性"。**为什么取高分位而非中位**：参照的是产品自己**曾经的好状态**（达到过的盈利水平），自比健康度衡量"现在比巅峰差多少"，用中位数会高估健康。

### 4.9 自比健康度（L771-782）

```
近12月毛利率 < 0        → self_health = 0，标记 _negative_margin
无有效历史毛利率月        → self_health = 0，标记 _no_valid_hist_margin（NH）
否则                     → self_health = 近12月毛利率 / 历史参照毛利率（参照≤0 时=1.0）
```

**含义**：当前毛利率相当于历史峰值的比例——0.6 即"现在只有巅峰期的六成"。

### 4.10 毛利率趋势斜率（L789-831，v4.0 改毛利额斜率）

```
窗口：最近 6 个月的月度毛利额（profit_clip_sum，缺月 NaN，≤0 记 0）
有效月 ≥ 3 → 最小二乘斜率 slope；slope_ratio = -slope / 均值(均值≤0 时=0)
有效月 < 3 → slope_ratio = 0，标记 _slope_data_insufficient（SL）
近6月毛利额最大值 ≤0.001 → _zero_profit（ZP），斜率等级"无利润/异常"
```

**为什么 v4.0 改用毛利额而非毛利率的斜率**：毛利率在零营收月无定义、在低营收月剧烈波动，毛利额斜率对营收规模稳健；**为什么均值归一化（-slope/mean）**：让不同量级产品的斜率可比（月毛利 100 万降 1 万 vs 月毛利 5 万降 1 万，严重程度不同）；**为什么取负号**：毛利下降（负斜率）应映射为正的风险分。输出 `毛利率趋势斜率%/月 = slope_ratio×100`。

### 4.11 增速变化与方向（L833-861）

- 月龄≥24：`前12月增长率 = (前12月均 - 24-36月均)/(24-36月均)`；`增速变化(pp) = (growth - 前12月增长率)×100`；方向=加速/持平/减速。
- 月龄 12-24：无同比基准，增速变化= growth×100，方向按 growth 符号。
- 月龄<12：均置空。

### 4.12 订货波动性 CV 与低量/脉冲豁免（L866-889）

```
近12月销量≤0 → CV=None（_cv_invalid），低量品="是"
月均销量 < 1000（长尾销量阈值）且月数≥6 → 低量品="是"，CV 改用稳健估计：
    CV = MAD / 中位数（绝对中位差/中位数，防自身离群）
活跃月≤4 且 近12月总量>1000 → "脉冲发货"，CV 固定 0.5
其余 → CV = std/mean，低量品="否"
```

**为什么低量品改用 MAD**：传统 CV=std/mean 在低量序列中被单月大单主导，MAD 对离群稳健。**脉冲豁免**：集中备货型产品（活跃月少但总量大）的 CV 无意义，固定 0.5 并在特情说明标注"已豁免"。**注意**：v4.0 中 CV 已不参与风险评分（仅展示与低量标记），`_cv_invalid` 也不再加入质量标记（L345-349 注释）。

### 4.13 增速衰减与同比参照（L891-924）

```
增速衰减(pp) = ((近3月月均 - 前3月月均)/前3月月均 - growth) × 100    （前3月均≤0 时 last3_growth=0）
_yoy_change：月龄≥15 时 = (近3月月均 - 12~15月前月均)/12~15月前月均；否则 None
```

**含义**：短期动能相对全年动能的落差（-20pp 即最近三个月比全年水平减速 20 个百分点）。`_yoy_change` 是同比方向的独立佐证，供 F4 评分矩阵的行分组。

### 4.14 ASP 趋势与联合诊断（L929-953）

```
ASP趋势%/月 = calc_asp_trend(近12月月均价序列)（shared 实现，见 §14 登记项）
方向：>+0.5% → 上升；<-0.5% → 下降；其间 → 平稳
联合诊断（joint_asp_pct=-0.5%/月，joint_margin_pct=-0.3%/月，用 slope_ratio×100 与之比较）：
    ASP降 且 毛利斜率降 → 价格战风险；ASP未降 且 毛利斜率降 → 成本问题
    ASP降 且 毛利斜率未降 → 规模效应；其他 → 正常
```

**判读逻辑**：价格战 = 降价且没换来利润；成本问题 = 没降价利润却缩（成本上升）；规模效应 = 降价但利润稳（量补价）。

## 5. 参照组体系（_compute_reference_groups，L32-99）

### 5.1 参与产品的排除（L35-43）

计算参照组前先剔除：新品观察、清仓/偶发、**已退市**（`_最后发货月 ≤ latest_month - exit_months(12)` 且 `日历月龄 ≥ exit_min_age_months(3)`）。**为什么排除退市品**：退市产品的毛利率分布不代表存活产品的经营基准。

### 5.2 公司加权均值（L55-58）

```
company_avg = Σ(产品近12月毛利率 × 产品近12月营收) / Σ(产品近12月营收)    （仅 _margin 非空且 _rev>0 的产品）
```

**为什么营收加权**：算术平均会把月营收 3 千的小产品与 3 千万的大产品等权，加权均值即"公司整体毛利率"。

### 5.3 分组加权均值（L60-97）

对 ref_priority 中的每个参照列（如"型号_产品品类"）：产品→组值用**众数**映射（同一产品跨月分类不一致时取出现最多的值，缺省"未分类"）；组内加权均值公式同 5.2。每组记录 count（组内有效产品数）。

### 5.4 参照组赋值与兜底链（_score_all_products L134-153）

按 `ref_priority` 顺序（如 `型号_产品品类(≥3)` → `全公司均值`）逐级尝试：组存在且 `count ≥ min_n` → 用该组加权均值，来源标注 `分类: 组值 (n=count)`；各级都不满足 → 公司均值，来源标注"各级参照组均不满足条件"。**他比健康度(pp) = (本产品近12月毛利率 - 参照组加权均值) × 100**（参照≤0 时=0）；同时记录 vs 公司均值(pp)。

## 7. 风险评分函数（shared/risk_scoring.py）

### 7.0 评分体系的业务直觉：为什么是这四个因子、为什么这样配权

四个因子对应衰退的四种病理，权重（F1f 0.10 / F4 0.60 / F5 0.20 / c6 0.10）表达了业务判断上的**信号可信度排序**：

- **F4 增速衰减拿到 60% 权重**，因为"短期动能明显弱于全年水平"是衰退最早、最稳健的信号——需求消失总是先于利润恶化（客户先少买，价格和成本结构才跟着变形）。它用近 3 月 vs 全年月均的落差衡量"拐点"，再叠加同比状态定基调、连续下降月数加成持续性，三层数据互相印证。
- **F5 自比健康度 20%**：利润相对自身巅峰的比例，回答"还剩几成盈利能力"。它排第二是因为利润恶化比需求萎缩晚出现——等到自比健康度跌到 50% 以下，衰退通常已经进行了一段时间，它更像确认信号而非领先信号。
- **F1f 毛利额斜率 10%**：6 个月窗口的趋势方向，是月度噪声最大的指标（单月大单就能扭曲），所以权重最低、且只有三档粗分（10/50/80）。它的价值在"方向"而非"幅度"。
- **c6 大客户订货量变化 10%**：从客户端交叉验证——需求端的自证（产品视角的增速衰减）+客户端的他证（大客户订单骤降）正交互补。权重低是因为覆盖率有限（缺失时零填充重分配）。

**这套评分的业务定位是"预警排序"而非"衰退判定"**：高分含义是"值得人工优先看一眼"，不是"必然衰退"。因此防误报机制（爆发截断、脉冲豁免、低量 MAD）与防漏报机制（衰退兜底、覆盖规则、连续下降加成）的并存不是矛盾，而是分别服务"排序的精确率"和"底线召回率"。

### 7.1 F1f 分桶（L45-49）

```
(0, +∞) → 10 | (-0.008, 0] → 50 | (-∞, -0.008] → 80
zero_profit / slope_insufficient / NaN → 80 或 50（函数入口：zero_profit→80；NaN→50）
```

### 7.2 F4 数据驱动矩阵（L25-42, L88-133）

先行分组（`_classify_yoy_group`）：`_yoy_change` >0.5→high_growth；>0→growing；>-0.1→flat；≤-0.1→shrinking；None→unknown。再列分组（`_classify_decay_group`）：`增速衰减(pp)`>0→accelerating；≥-10→stable；<-10→decelerating；None→unknown。

12 格评分矩阵（分值=风险，越高越危险）：

| yoy\decay | accelerating | stable | decelerating |
|---|---|---|---|
| high_growth | 20 | 10 | 10 |
| growing | 40 | 30 | 20 |
| flat | 70 | 60 | 50 |
| shrinking | 80 | 80 | 70 |

**设计逻辑**（矩阵解读）：行方向（同比状态）是主导——同比萎缩组恒 70-80 分，同比高增组恒 10-20 分；列方向（短期衰减）仅在行内微调 ±10。**为什么这样设计**：v2.9 的"增长率感知"逻辑存在评分反转（增长产品的衰减被评得比萎缩产品更险），v4.0 用经验校准矩阵固化"同比状态定基调、短期衰减做修正"的次序。**连续下降加成**：`+5 分/月`，上限 `+25`，总分封顶 100——月销逐月连跌是独立于窗口比值的持续性信号。

### 7.3 F5 / c6 分桶与复合函数

F5：`(0.70,∞)→10；(0.50,0.70]→40；(0.30,0.50]→70；(-∞,0.30]→70`；hist_margin_invalid 或 NaN→50。c6：`≤-0.5→95；(-0.5,-0.2]→75；(-0.2,0]→50；>0→25`。`compute_composite_v2`（L177-239）是纯函数版复合（与 §6.5 的 DataFrame 版逻辑一致，供单元测试/复用）。

## 8. 九宫格映射与上下文策略（nine_grid.py）

### 8.0 画像的业务语义：从"状态标签"到"管理动作"

九宫格的价值不在于给产品贴标签，而在于**每个格子绑定一个默认的资源配置态度**，让月度产品会议可以直接按格子分池讨论：

- **投入区（成长期/健康扩张）**：需求在涨、利润健康——该争的是产能、备货和销售资源，动作是"加"。健康扩张虽然毛利有侵蚀迹象但动能未衰，继续投的同时盯住毛利率拐点。
- **维持区（现金牛/利润优化）**：量稳利稳——不需要新投入也不该收缩，动作是"守"，把注意力放在防止滑入观察区（毛利率跌破参照组即转预警）。
- **观察区（预警增长/隐性衰退/主动收缩）**：三种病理完全不同——预警增长是"增收不增利"，成本端出了问题，该查成本结构而不是砍资源；隐性衰退最危险，表面量稳但利润已被侵蚀，靠总量报表根本看不见，必须靠自比健康度才能发现；主动收缩是"量跌利升"，可能是主动清退低毛利客户的健康瘦身，业务上要先确认是"主动"再决定是否干预。
- **退出区（夕阳产品/衰退期）**：动作是"有序退"——控制库存、规划替代型号上市时间、安排退市节奏。上下文策略的回升分支（同比 +10pp/+5pp）就是退出区的"缓刑机制"：数据证明利润在回升的，先别退，确认回升可持续性后再定性。

**上下文策略的业务价值**：同一个"衰退期"标签下，"毛利率大幅回升的衰退"和"量利双跌的衰退"该做的动作相反（前者可能是主动瘦身、后者该立即退市）。上下文策略把这个判断前置到系统输出里，避免所有衰退期产品被一刀切清退。

### 8.1 十二组合映射表

12 组合映射表（L108-121）：加速增长×健康=成长期(投入区)；加速×轻度侵蚀=健康扩张(投入区)；加速×严重侵蚀=预警增长(观察区)；稳定扩张×健康=健康扩张；稳定×轻度=现金牛(维持区)；稳定×严重=预警增长；持平×健康=利润优化(维持区)；持平×轻度=现金牛；持平×严重=隐性衰退(观察区)；萎缩×健康=主动收缩(观察区)；萎缩×轻度=夕阳产品(退出区)；萎缩×严重=衰退期(退出区)。组合外→未分类/待观察。

上下文策略（`generate_contextual_strategy`，L27-94）按同一画像细分，全部阈值来自代码：

- **衰退期**：毛利率同比 >10pp → 确认回升可持续性（主动清退低毛利客户则应转"主动收缩"）；回升但 ≤10pp → 观察是否暂缓退市；销量=0 → 确认实质退市、清理库存；量利双跌 → 安排退市。
- **夕阳产品**：同比 >5pp → 控库存暂缓换代；小幅回升 → 规划替代型号上市时间；无回升 → 准备换代。
- **隐性衰退**：有回升 → 观察持续性；无 → 预警（表面稳定实则被侵蚀）。
- **预警增长**：营收-毛利判断="减收增利" → 关注毛利率回升；否则 → 立即查成本结构。

基础策略文本外置于配置 `nine_grid_base_strategies`（11 个画像各一条，业务可直改文案），代码内硬编码同文兜底。
