## 3. 迭代路线图（价值 × 工作量排序）

### P0 · 拍板批（管理层一次评审会可全部处理）

**内容**：C 类 18 条中除 C15/C17 需补充材料外，16 条均为"现状陈述 + 二选一/三选一"结构，可打包成一次评审会议题（预计 1.5-2 小时）。
**为什么最先做**：拍板类不消耗开发量，却直接决定 P1/P2 的范围与方向（如 C3 决定 A1 是否立项、C4 决定 A18 修法、C16 决定评分方向）；拖延只会让双口径/死因子类问题继续累积误解成本。
**工作量**：会议 0.5 天 + 决议整理 0.5 天（更新本清单状态列与三件套"待拍板"章节）。

### P1 · 数据修正批（低成本高确定性，可立即排期）

**内容**：A 类中的纯修复项——**A2 死键、A3 D 面证据死键、A4 波动性死键、A5 反向清单死条目、A8 R 面配置必填化、A9 faces.yaml 三处文案修偏、A10 排序映射、A11 断崖损失额直读、A12 对拍告警、A13 E 面披露补齐、A14 F 面阈值入配置、A15 兜底改必填、A18② 人员错位显式标注**；外加 D3 台账对账。多数改动伴随一次对拍验证（改前改后输出对比）。
**不动生产红线的执行方式**：分支开发 → 预演生成 → golden-diff 对拍（现有 compare 工具 + 现有测试套件）→ 合并。
**工作量**：合计约 **8-12 人日**（12 项 × 平均 0.5-1 人日，A5/A14 需评分对拍略多）。
**依赖**：A1（c6 打通）不在本批——等 C3 拍板；A18① 双口径声明与 C4 联动，文案可先写、拍板后发布。

### P2 · 校准回测批（需立项，按独立小项目排期）

**内容**：B 类 15 条中的数据工作项，按依赖与价值分四组：
- **权重对拍组**（B1/B2/B3）：三套权重各一次可复现推导/敏感性对拍，产出"参数-影响"对照表——是 C8/C9 及后续一切权重调整的前提；
- **回测组**（B4 误报率 / B5 区间覆盖率 / B7 通道命中率矩阵 / B9 残差标定）：全部基于历史数据回放，互相独立可并行；
- **数据质量组**（B8 地址抽验 / B10 激活覆盖统计 / B11 占比漂移监控 / B15 填充率验证）：轻量、可并入月度跑批例行；
- **盘点组**（B12 按需核对 / B13 旅程下游排查 / B14 F 面预演）：随其他批次顺带销项。
**工作量**：权重对拍组约 3×3-5 人日；回测组约 4×3-5 人日；数据质量组约 4×1 人日；合计 **20-30 人日**，可拆四个独立 sprint。

### P3 · 增强批（拍板通过后启动的结构性改造）

**内容**：A1（c6 数据通道打通，L）、A16（区域数据接入，依赖 C6）、A17（评分证据面板）、A18①（双口径合并或对照页，依赖 C4）、C8 实施侧（销售权重配置化迁移，与 D2 注释重写合并做）、C18（品类擅长消费或下线）、D1/D2（归档收口+版本档案机制）、D4（说明页接入看板——方案已成文，见姊妹文档，P0 骨架 1-1.5 人日可先行）。
**工作量**：合计 **15-25 人日**；其中 D4 的 P0/P1 期（骨架+全内容）不依赖任何拍板，可提前插入 P1 批末尾执行。
