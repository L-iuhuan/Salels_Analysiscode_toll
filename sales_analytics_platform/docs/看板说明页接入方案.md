## 1. 跳转可行性评估（核心技术问题）

目标场景：说明页内"自比健康度"条目旁点【去看图 →】，跳到 D 面九维雷达图（dRadar）并高亮。技术路径拆为三段：

### 1a. tab 切换 —— **确定可行**

| 事实 | 代码依据 |
|---|---|
| tab 按钮带 `data-tab` 属性与 `id="btnX"`；现有 A/R/B/C/D/E/F 七个 | template.html L456-463 |
| 点击监听 `document.getElementById('btnA').addEventListener('click',function(){switchTab('A')})` 等 7 条 | template.html L2310-2316 |
| **`switchTab(t)` 为全局函数**（`window.switchTab = switchTab` 已导出） | template.html L2245-2308，导出于 L3435 |
| switchTab 行为：关弹层 → 切按钮/内容 active → 按需懒加载（`TABS._loadLazyData`，非 A/C 面首次）→ 各面首次初始化或 resizeAll | L2246-2307（D 面 L2268-2275 / E 面 L2277-2284 / F 面 L2286-2293 / C 面 L2295-2307） |
| **跨面跳转先例已存在**：`openB(name)`（设 BSEL→切模式→switchTab('B')，L2596）、`fGotoE(name)`（switchTab('E') + setTimeout 200ms 后开抽屉，L3264）、`fGotoETrend`（L3262）——"switchTab + setTimeout 做后置动作"是既定模式 | L2596 / L3262-3264 |

结论：`switchTab('D')` 一行即可完成面切换，无任何改造。

### 1b. 图表定位 —— **可行**（静态容器 id 全部稳定）

从 template.html 提取的**图表容器 id 全清单**（跳转锚点的目标池）：

| 面 | 图表容器 id |
|---|---|
| A | mainBar / pieChart / scatter / kaaaLine / geoMap / geoTopProv / geoAbroad / marginTable（表格）/ saList（客户列表）/ prodChange |
| B | bTrend / bPie / bQty / bAgBar / bAgStack / bAgLine / bAgCat / bAgQty（代理商视图组）/ bpdChart（Top 产品卡）/ bDet（详情容器） |
| C | chart-portrait / chart-risk / chart-pareto / chart-summary / chart-slope / chart-matrix / chart-scatter / chart-sankey / chart-rev-margin / chart-dominance / chart-asp-trend（switchTab 的 C 面分支同样以这 11 个 id 做 resize，L2301） |
| D | dRanking（排名表）/ dRadar（九维雷达）/ dBubble / dTeamTrend / dHeatmap / dCustHeatmap / dWaterfallChart / dProfile（能力档案） |
| E | eMatrix / ePenetration / eImportSales / eImportTable / eDecompRank / eDecompScatter / eDecompWaterfall / eDecompWaterfallYoy |
| F | fDeptRadar / fMarginTable / fProductTable / fCatH1Table / fKaaaTable / fProdTrendRev / fProdTrendCost / fProdTrendASP / fIssues / fNpPenetration |
| R | **无稳定图表级 id**——内容为 md 渲染的动态 HTML（见 1e） |

定位实现：`document.getElementById(chartId).scrollIntoView({behavior:'smooth',block:'center'})`。容器 div 均为静态 HTML（tab-content 骨架在模板中写死，如 tabC 各 chart-* div），**不依赖 ECharts 是否已初始化**——即使图表尚未渲染，容器已有占位高度，滚动目标存在。

### 1c. 图表高亮（可选增强）—— **可行，分两级**

- **CSS 级（P0 即可实现，零风险）**：跳转后给容器加一次性描边动画类（如 `doc-jump-flash`，keyframes 呼吸 2 秒后移除）。不依赖 ECharts。
- **ECharts 级（P2）**：`TABS.ChartRegistry.get(id)`（L855-861：先查显式注册表 `_byId`，兜底 `document.getElementById` + `echarts.getInstanceByDom`）拿到实例后 `dispatchAction({type:'highlight', ...})` / `{type:'showTip'}`。**限制**：highlight/showTip 需要 seriesIndex/dataIndex 等参数，而各图表的 series 结构互不相同——要么按目标图表写少量映射表（每图 1-3 行），要么只做整图 `resize()` + CSS 描边。建议 P2 只对高频跳转目标（dRadar、mainBar、chart-scatter 等个位数图表）做 ECharts 级高亮，其余 CSS 级。

### 1d. 时序与初始化限制（必须处理的三个边界）

1. **首次访问的懒初始化竞争**：D/E/F/C 面图表在首次 switchTab 时经 setTimeout(100-150ms) 才构建（L2268-2307）。路由函数必须在 switchTab 后延迟执行 scroll/highlight（参考 fGotoE 的 200ms；建议 350ms + 一次重试）。滚动本身不受影响（容器已存在，见 1b），仅 ECharts 级高亮受影响。
2. **`.tab-content` 的 `content-visibility:auto; contain-intrinsic-size:auto 800px`**（L130）：非激活 tab `display:none`（L131 `.tab-content{display:none}`，`.active` 才显示）。**顺序必须是先 switchTab 再 scroll**——对 display:none 的元素 scrollIntoView 无效。激活后布局即时可用，content-visibility 不阻碍；已访问过的 tab 滚动位置会被保留，因此每次跳转都要重新 scrollIntoView（不能假设已就位）。
3. **F 面 visible:false（当前状态）**：`_hide_invisible_faces`（generate_dashboard.py L747-762）**只移除 tab 按钮与监听器，`<div id="tabF">` 内容 div 保留在 HTML 中**（F 面计算跳过、注入空值）。直接 switchTab('F') 技术上会激活一个无数据的空面。路由函数必须防御：`document.getElementById('btn'+face)` 不存在（或 faces.yaml visible=false 注入的前端标志）时，降级为提示（"F 面当前关闭，半年度复盘期开启"），不执行跳转。**待实施时验证**：前端如何得知 visible 状态——可在生成时注入一个 `%%VISIBLE_FACES%%` 数组（现无此占位符，属新增）。

### 1e. R 面锚点稳定性 —— **图表级跳转不可行，面级可行**

R 面内容由 `build_r_face_inner_html`（generate_risk_face.py，公共 API）从人工审定的 md 渲染为动态 HTML——**表格与区块无稳定 id**，且内容每月由人工增删改。对 R 面的跳转只能到面级（switchTab('R')），区块级锚点需在渲染器中给固定区块（风险摘要/行动清单）注入 id 后才可用（列为 P2 可选项，改动在 generate_risk_face.py 渲染层，不影响 md 协议）。

### 1f. 结论

> **总体判定：可行（有限制）。**
> - tab 切换（switchTab 全局函数 + 既有跨面跳转先例）与容器定位（静态 id + scrollIntoView）**确定可行**；
> - CSS 级高亮可行；ECharts 级高亮可行但需按图维护参数映射（P2）；
> - **限制三条**：① F 面 visible:false 期间需降级提示；② 首访懒初始化要求跳转动作延迟执行；③ R 面仅面级跳转（md 渲染无稳定锚点）。

## 2. 方案设计

### 2.1 新 tab 定位（第八个按钮，建议 id=X）

| 项 | 设计 | 依据/影响点 |
|---|---|---|
| tab 按钮 | `<button class="tab-btn" data-tab="X" id="btnX">ℹ 说明</button>`，置于 tab-bar 末尾（dataVersion 徽标之前，L463-464 之间） | template.html L456-468 |
| 内容段 | `<div class="tab-content" id="tabX">…</div>`，置于 tabF 之后 | 模板 L723 起 |
| 监听器 | `document.getElementById('btnX').addEventListener('click',function(){switchTab('X')})`，随 L2310-2316 组 | switchTab 无 X 分支也能工作（默认无初始化逻辑），建议加一个空分支或注释说明 |
| faces.yaml 注册 | 新增 face X：enabled:true / visible:true / name:"ℹ 说明" / sections 按总分结构登记 | faces.yaml L12-348 现有六面同构 |
| **生成器两处硬编码清单需同步** | ① `_hide_invisible_faces` 的 `_tab_names` 字典（generate_dashboard.py L750-751）需加 X，否则 X 不参与插拔隐藏机制；② `_FACE_META_CACHE` 的面列表（L3403，现为 A/B/C/D/E/F）需加 X 才能渲染 X 面口径条 | 两处均为小改，**待实施时验证**是否有第三处面遍历（已检索 L732-762、L3403、L3479 三处） |
| 指纹影响 | template.html 与 faces.yaml 均在指纹内（fingerprint.py：template sha256 L97-99、faces.yaml 入 settings 键 L89-92）→ 两者修改使缓存失效、触发一次全量重算（分钟级），属预期行为 | 见 §3 |

### 2.2 总分结构（三层）

```
tabX（ℹ 说明）
├─ ① 总览层（首屏）
│   ├─ 全看板速读表：A/R/B/C/D/E/F 七面一行一卡（定位/回答什么问题/数据口径/刷新节奏）
│   │   ——数据直接取自 faces.yaml 的 theme/description/sections（构建时自动生成，零维护）
│   ├─ 诚实账汇总：四套说明页 25 条欠账 → 按面分组的紧凑表（问题一句话 + 状态 + 链到分面层详情）
│   └─ 待办拍板汇总：14 条待拍板事项表（现状/待决/影响面）——管理层入口
├─ ② 分面层（四套说明页全文）
│   ├─ 每面一节 = 对应《看板说明页_*.md》全文渲染
│   ├─ 折叠面板：默认收起，点击展开（复用 .face-meta 折叠交互模式）
│   ├─ 分面子导航：顶部 btn-toggle 药丸组（总览/产品/销售/客户/总览作战），锚点滚动切换
│   └─ 每个指标/图表条目旁加【去看图 →】跳转链接（见 2.3）
└─ ③ 深度层（四份方案书深度版）
    ├─ 每面一节尾部的"深度阅读"折叠块（默认收起）或独立子页签
    └─ 两方案评估见 2.5-B
```

**三层各自的复用组件**：
- 折叠面板 → 复用 face-meta 的展开/收起交互（`TABS.toggleFaceMeta` / `closeAllFaceMeta`，template.html L1485-1503 的 class 切换模式，样式换皮即可）；
- 分面子导航 → 复用 `.btn-toggle-group` 药丸按钮组（E 面量价四维切换 L698-702、F 面 L743-744 同款）；
- 弹层 → 复用 `TABS.popover`（L1505-1528，chart-guide 的 ❓ 弹层）做术语卡；
- 卡片/表格 → 复用 `.kc`/`.cb`/`.data-table` 现有组件；
- 色彩 → 平台 token（浅色底、白卡、`var(--primary)` 即 #2563EB 系），不引入新色。

### 2.3 跳转链接设计（data-face / data-chart + ~30 行路由函数）

**链接侧**：说明页 md 渲染时，指标/图表条目注入：

```html
<a class="doc-goto" data-face="D" data-chart="dRadar" href="javascript:void(0)">去看图 →</a>
```

锚点目标对照表以 1b 的容器 id 清单为准（构建时校验：data-chart 值必须存在于清单，否则构建警告——防 md 手写错 id）。

**路由函数**（新增，约 30 行，含 F 面防御与懒初始化延迟）：

```js
function docGoto(face, chartId){
  if(!document.getElementById('tab'+face)) return;
  if(!document.getElementById('btn'+face)){          // F 面 visible:false 期：按钮已被服务端移除
    TABS.popover && alert('该页面当前处于关闭状态（半年度专项仅复盘期开启）'); return;
  }
  switchTab(face);                                     // 1a：全局函数，template.html L2245
  setTimeout(function(){
    var el = chartId && document.getElementById(chartId);   // 1b：静态容器 id
    if(el){
      el.scrollIntoView({behavior:'smooth', block:'center'});
      el.classList.add('doc-jump-flash');              // CSS 级高亮（1c 第一级）
      setTimeout(function(){ el.classList.remove('doc-jump-flash'); }, 2000);
    }
    /* P2 可选：ECharts 级高亮
    var c = window.TABS && TABS.ChartRegistry && TABS.ChartRegistry.get(chartId);  // L855-861
    if(c){ try{ c.dispatchAction({type:'highlight'}); }catch(e){} }                  // 按图配参数，见 1c
    */
  }, 350);                                             // 1d-①：避开首访 100-150ms 懒初始化
}
document.querySelectorAll('.doc-goto').forEach(function(a){   // 事件委托亦可
  a.addEventListener('click', function(){ docGoto(a.getAttribute('data-face'), a.getAttribute('data-chart')); });
});
```

配套 CSS 约 20 行（`.doc-joto` 链接样式 + `@keyframes doc-flash` 呼吸描边）。R 面条目只给 `data-face="R"` 不给 data-chart（1e 限制）。

### 2.4 网页风格约束

- 全部复用平台 token 与组件（§2.2 已列），**不新增第三方依赖、不引入构建工具**；
- 说明页 md 的表格 → `.data-table`；标题层级 → 面内 `.subsection-title`；
- 总览层的速读卡可复用 `.kc` 卡栅格（kpi-bar 同款）；
- 移动/窄屏不做专门适配（与主看板现状一致）。

### 2.5 两个关键选型评估

**A. 深度层：外链打开 vs 构建时内嵌折叠**

| 维度 | 外链 docs/*.md 相对链接 | 构建时内嵌折叠（推荐 ✅） |
|---|---|---|
| 单文件自包含 | ✗ 破坏（看板 HTML 拷走后链接失效；md 在浏览器中是下载不是渲染） | ✓ 保持（与全平台"单 HTML 文件交付"一致） |
| 体量 | 零增加 | 四份方案书 ~130KB md → 渲染后约 +300-400KB HTML，相对现有 15-16MB 单文件 **+2~3%，可忽略** |
| 维护 | 两处入口 | 单一事实源（docs/*.md） |
| 体验 | 差（下载/编辑器打开） | 好（折叠面板内直接读） |

**结论：构建时内嵌折叠；外链仅作辅助备注**（"源文件位于 docs/ 目录"）。

**B. 内容注入：构建时 %% 占位符管道（推荐 ✅） vs 静态硬编码**

占位符管道可行性依据——**R 面已走通同款路径**：`%%R_FACE_HTML%%`（generate_dashboard.py L3462）由 md 服务端渲染（generate_risk_face.py 的 md→HTML 渲染器，含表格/emoji/多级节）注入模板。说明页 md 的语法超集是：标题/表格/引用块/粗体/列表——R 面渲染器已覆盖表格与节，需小幅扩展标题与列表解析（估计 100-150 行，或引入 python-markdown——**待实施时验证离线环境是否允许新增依赖，不允许则自研小解析器，复用 R 面表格渲染函数**）。

| 维度 | 构建时注入（推荐） | 静态硬编码进 template |
|---|---|---|
| 单一事实源 | ✓ docs/*.md 唯一维护入口，改后重跑生效 | ✗ 双源，必然漂移（faces.yaml 口径卡漂移已是前车之鉴，见《问题清单》A9） |
| 实施成本 | md 渲染器 + 占位符 + 缓存处理（~1-1.5 人日） | 最低（纯粘贴） |
| 维护成本 | 低 | 高（每次改说明页要同步两处） |

**缓存处理（关键细节）**：`replacements` 会写入 preagg.json 缓存（L3545-3548），而 fingerprint **不包含 docs/*.md**（只含 template/faces.yaml/settings/代码/Excel，fingerprint.py L89-99）——若说明页 HTML 走普通占位符，改 md 后缓存不失效、内容停在旧版。**解法（照抄 R 面模式）**：把说明页占位符列入 L3545-3548 的排除清单（与 `%%R_FACE_HTML%%` 同列），每次生成时实时读 md 渲染——说明页 md 共 ~32KB，解析成本毫秒级，且"改完文档重跑看板立刻生效"与 R 面审定体验一致。

### 2.6 新增占位符与 faces.yaml 草案（实施时落地，此处留设计）

- `%%DOC_OVERVIEW_HTML%%`：总览层（速读表+诚实账汇总+待拍板汇总，速读表部分可从 faces.yaml 自动生成）；
- `%%DOC_FACE_{A,B,C,D,E,R}_HTML%%` 或单占位符内含四面：分面层四节（R 面说明页同样接入，仅无图表锚点）；
- `%%DOC_DEEP_{...}_HTML%%`：深度层折叠块（可并入分面层尾部）；
- `%%VISIBLE_FACES%%`：前端可见面数组（F 面防御用，1d-③）；
- faces.yaml X 面 sections：三个 section（全看板速读/诚实账/待拍板）+ glossary 复用各面术语。

## 3. 风险与红线

| 项 | 论证 |
|---|---|
| **不动生产红线** | 全部改动在分支开发：template.html（+按钮/内容段/监听/路由函数/CSS）、faces.yaml（+X 面）、generate_dashboard.py（+占位符/渲染/~3 处清单同步）、可选 generate_risk_face.py（R 面锚点 id，P2）。合并前预演生成 + 验证 |
| **golden-diff 不受影响** | 新 tab 为**纯增量**：不改任何现有 tab-content 结构、不改任何 JS 数据变量（TREND/B_CUSTS/D_SALES_LIST/GEO_* 等数据块零变化）、不改 KPI 占位符取值逻辑。数据级对拍（现有 compare 工具，docs/perf_eval_20260825/tools/）应零差异；HTML 级 diff 仅新增段落——验收时以"现有 id 集合与既有面字节级不变"为断言 |
| **指纹影响** | template.html + faces.yaml 修改 → sha256 变化 → 缓存指纹失效 → **一次性全量重算**（历史全算耗时分钟级，见批次⑥文档），无数据影响；合并后首次跑批即恢复缓存命中。若按 §2.5-B 方案走 R 面式实时渲染，docs/*.md **不进指纹**——代价是"改 md 不触发缓存失效"，但因占位符已被排除出缓存（每次实读），不存在内容过期问题；唯一残留：改 md 后仍需重新生成 HTML 文件（静态交付物的天然属性，与 R 面一致） |
| **switchTab 兼容** | X 面无图表，switchTab 现有分支结构天然兼容（无 X 分支=不初始化）；`_tabInitialized` 机制不受影响 |
| **md 内容安全** | 说明页为第一方文档，但渲染器仍应转义 HTML 字符（防未来外部素材混入） |
| **回滚** | 单 commit 粒度（骨架/内容/增强分期），任一期出问题 revert 即回到七 tab 现状；不触碰任何数据管道 |

## 5. 结论重述

1. **跳转可行（有限制）**：tab 切换与图表定位确定可行（switchTab 全局函数 template.html L2245/L3435 + 静态容器 id 清单 + scrollIntoView）；ECharts 高亮可行但需按图配参数（P2）；限制三条——F 面关闭期需降级提示、首访懒初始化需延迟执行、R 面仅面级跳转。
2. **注入方案推荐**：构建时 %% 占位符管道 + md 服务端渲染，缓存处理照抄 R 面模式（占位符排除出 preagg 缓存、每次实读）；深度层选构建时内嵌折叠（保持单文件自包含，+2~3% 体量可忽略）；否决静态硬编码（双源必漂移）与外链（破坏单文件交付）。
3. **风险可控**：纯增量改动，golden-diff 数据级零差异可断言；指纹失效仅引发一次预期内全量重算；分支开发+预演验证满足不动生产红线。
