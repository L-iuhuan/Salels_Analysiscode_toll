## 1. 系统定位与总数据链路

### 1.1 业务视角

销售能力系统回答一个问题：**每位销售员的能力结构是什么样的、在同类销售员中处于什么位置**。它不做"按收入排队"的单维排名——单看收入会把"公司分配的大客户"与"自己开拓的市场"混为一谈，也会让管 332 个客户的销售员和管 12 个客户的销售员同尺竞争。系统的输出是每位销售员一行的九维能力画像（每维 0-100 分 + 加权综合分 + 量级/亚组/能力等级），供看板 D 面消费。

设计理念（sales_profiling.py:4-7，v4.13 文件头注释原文）：

- **KA/AA 客户是公司分配 → 不计入能力维度，但计入绝对贡献**——定价博弈力、客户升级力在计算时排除 KA/AA 客户（:30 non_ka，:36，:174，:268），绝对贡献力用全集；
- **销售额代表管理+维系+长期积累 → 纳入绝对贡献力**（v4.13 时权重 20%，v4.14 升至 35%）。

### 1.2 数据链路

```
银层 silver（customer_monthly / customer_x_product）
        │
        ▼
客户画像表 df（customer_analysis 主流程产出，每客户一行：
  近12月收入/毛利/毛利率、收入增长率、首次交易日期、客户层级、
  利润等级、综合价值层级、客户生命周期、客户旅程阶段、
  距上次采购天数、实际品类数、新品采购占比、策略名称 等）
        │
        ├──► b2b_v2.actions.sales_profiling.build_sales_profile(df)
        │        └── 九维评分 + 综合分 + 量级/亚组/能力等级      → gold["销售画像"]      (v4.11)
        ├──► b2b_v2.actions.category_aptitude.build_category_aptitude(df, silver)
        │        └── 销售×产品线 擅长矩阵（5 子维加权）           → gold["品类擅长"]      (v4.15)
        └──► customer_analysis.period_analysis.build_sales_period_performance(silver, df)

                 （gold.py:390-421 装配为三张 Gold 表）

Gold CSV ──► dashboard/generate_dashboard.py D 面（:1725-2163）
                 ├── 6d 读 Gold 销售画像.csv → 九维分/等级/亚组/量级
```

**现算与 Gold 的口径分裂是本系统最重要的结构性事实**：九维能力分与定级来自 Gold 层（画像口径，近 12 月窗口），而 D 面排名表上的 YTD 收入/毛利/同比/环比、气泡图、两张热力图全部由看板从行级明细（rex）当次聚合【现算】——两套数字窗口与口径不同（近 12 月 vs 当年 YTD），同一销售员的"总营收"（Gold）与"ytd_rev"（现算）可以不相等。详见表 §6 与登记项 8-2。

## 2. 九维能力评分（逐维公式）

九维评分的公共结构（全部 `_score_*` 函数一致）：**50 分中性基线 + 各子项偏移量累加，最后截断到 [0, 100]**。50 不是"团队均值"——它是每维的中性起点；真实团队均值由看板另行对 Gold 分数聚合（generate_dashboard.py:1964-1970，仅用于雷达/瀑布对比，不回写评分）。

权重（v4.14，硬编码于 sales_profiling.py:45-47；注释 :44 载明"绝对贡献35%确保销冠不被 per-customer 指标拉低"）：

| 维度 | 权重 | 函数 | 位置 |
|---|---|---|---|
| 绝对贡献力 | 0.35 | `_score_absolute` | :113-135 |
| 客户维系力 | 0.10 | `_score_retention` | :138-156 |
| 品类拓展力 | 0.10 | `_score_category_expand` | :218-241 |
| 客户升级力 | 0.10 | `_score_upgrade` | :261-279 |
| 新客开拓力 | 0.08 | `_score_acquisition` | :189-215 |
| 产品结构优化力 | 0.08 | `_score_mix_improvement` | :282-302 |
| 组合抗风险力 | 0.07 | `_score_diversification` | :99-106 |
| 定价博弈力 | 0.06 | `_score_pricing` | :159-186 |
| 客户激活力 | 0.06 | `_score_activation` | :244-258 |

综合能力分 = Σ(维度分 × 权重)，保留 1 位小数（:48-49；写入行的各维分数也各 round 1 位 :61）。

### 2.1 绝对贡献力（:113-135）

**输入**：近12月收入合计、近12月毛利合计、收入增长率（客户级中位数）。用客户全集（含 KA/AA）。

```
base = 50
营收分 rev_score = clip(log10(总营收) × 20, 20, 100)        # 总营收>0 时生效
score += (rev_score − 50) × 0.5
毛利分 profit_score = clip(log10(总毛利 + 1) × 20, 20, 100)  # 总毛利>0 时生效
score += (profit_score − 50) × 0.3
增长率 avg_growth = median(收入增长率) × 100
score += clip(avg_growth, −20, +50) × 0.2                    # 有非空增长率时生效
截断 [0, 100]
```

**对数刻度（按代码公式）**：log10 里程碑为 100 元=40 分、1000 元=60 分、1 万=80 分、10 万=100 分（封顶）、10 元以下=20 分（保底）。**注意 :119 注释写的锚点（"10万=40分, 100万=60分, 1000万=80分, 1亿=100分"）与公式不符**——按公式任何总营收 ≥10 万的销售员营收分即封顶 100，与注释含义相差四个数量级。本文按代码书写，差异登记于 8-1。

**设计意图（注释载明）**：v4.14 将本维权重升至 35%，防止销冠被 per-customer 型指标（占比类维度）拉低——营收量级是管理+维系+长期积累的合成结果（:6，:44）。

### 2.2 客户维系力（:138-156）

**输入**：近12月收入>0 的客户占比（活跃占比）、首次交易日期早于 24 个月前的客户占比（长期客户）。

```
base = 50；客户总数=0 时直接返回 50
活跃占比 active_pct = count(近12月收入 > 0) / 客户总数 × 100
score += (active_pct − 40) × 0.4          # 40% 活跃为中性点
长期占比 long_pct = count(首次交易日期 < now − 24月) / 客户总数 × 100
score += min(long_pct × 0.3, 20)          # 长期客户贡献封顶 +20
截断 [0, 100]
```

**注意**：长期客户判定用"首次交易日期在 2 年前"近似"存续>24月"（:149 注释原文），依赖画像表首次交易日期列存在（列缺失时跳过该项）。

### 2.3 品类拓展力（:218-241）

**输入**：实际品类数、新品采购占比。

```
base = 50；客户总数=0 时直接返回 50
多品类客户 multi = 客户.实际品类数 ≥ 3
占比项：multi_pct = count(multi)/客户总数 × 100 → score += (multi_pct − 30) × 0.3   # 30% 为中性点（降权）
绝对数奖励：score += min(log10(max(multi_n, 1)) × 20, 30)   # 10人≈20分, 50人≈34→封顶30（:232 注释与公式一致）
新品渗透（列存在时）：
  has_new_pct = count(新品采购占比 > 0)/客户总数 × 100 → score += min(has_new_pct, 30) × 0.3
  avg_new = mean(新品采购占比) → score += min(avg_new × 1.5, 15)
截断 [0, 100]
```

**设计意图（:228-232 注释载明）**：占比项降权 + 绝对数对数奖励"照顾量大销售"——纯占比会让客户基数大的销售员在多品类上天然吃亏。

**前提注**：占比项与绝对数奖励两项共用同一前提——"实际品类数"列存在（:225 `if "实际品类数" in subset.columns` 同时包住两项）；该列缺失时两项同时跳过，本维仅剩新品渗透子项。

### 2.4 定价博弈力（:159-186）

**输入**：负毛利品种数列（列名含"负毛利"且"品种"，取第一个命中列 :167-168）、利润等级（高利润判定排除 KA/AA :174）、低价品占比列（列名含"低价"且"占比" :181）。

```
base = 50；客户总数=0 时直接返回 50
负毛利控制（列存在时）：
  neg_pct = count(负毛利品种数 > 0)/客户总数 × 100
  score += (100 − min(neg_pct × 2, 100)) × 0.2        # 恒非负的衰减奖励：neg_pct=0 → +20，neg_pct≥50% → 0（注释标"降权"）
高利润（non_ka 非空且利润等级列存在时）：
  high_pct = count(利润等级=="高利润")/len(non_ka) × 100
  score += (high_pct − 30) × 0.25                     # 30% 为中性点（降权）
  score += min(log10(max(high_n, 1)) × 15, 25)        # 绝对数奖励（:160 注释：v4.14 加入）
低价品惩罚（列存在时）：
  avg_low = mean(低价占比列)
  score −= min(avg_low, 50) × 0.2
截断 [0, 100]
```

### 2.5 新客开拓力（:189-215）

**输入**：客户生命周期、客户旅程阶段、距上次采购天数、综合价值层级（列均经 `subset.get(..., pd.Series())` 容错，缺失时对应子项按空集计 0）。

```
base = 50；客户总数=0 时直接返回 50
A 真正新客（100% 权重）：
  new_cust = count(客户生命周期 ∈ {导入期, 爬坡期})
  score += (new_cust/客户总数 × 100) × 0.5
B 沉睡唤醒（浅50% | 中30% | 深100%，:203 注释）：
  浅 = count(旅程=="激活期" 且 1≤距上次采购≤365)
  中 = count(旅程=="激活期" 且 366≤距上次采购≤730)
  深 = count(旅程=="激活期" 且 距上次采购>730)
  score += (浅×0.5 + 中×0.3 + 深×1.0)/客户总数 × 100 × 0.5
C 新客质量（综合价值层级列存在且有新客时）：
  quality = 新客中 综合价值层级 ∈ {S,A,B} 的占比 × 100
  score += (quality − 40) × 0.2                       # 40% 为中性点
截断 [0, 100]
```

### 2.6 客户激活力（:244-258）

**输入**：策略名称（含"激活试探"字样匹配）、客户生命周期。

```
base = 50；客户总数=0 时直接返回 50
s6 = 策略名称.str.contains("激活试探")                # 被下发激活试探策略的客户
activated = s6 且 客户生命周期 ∈ {导入期, 爬坡期, 成熟期}
若 s6 总数 > 0：
  rate = activated / s6 × 100
  score += (rate − 20) × 0.5                          # 20% 唤醒率为中性点
截断 [0, 100]
```

**边界**：名下没有被下发激活试探策略的客户（s6=0）时不得分也不扣分，维持 50——即本维实际度量"激活策略的执行收效"，未被策略覆盖的销售员该维信息量为零（对综合分贡献 = 50 × 0.06 中性值）。设计意图未在注释载明。

### 2.7 客户升级力（:261-279，v4.13 修正）

**输入**：综合价值层级（S/A 档），**仅非 KA/AA 客户**（:268）。non_ka 为空时直接返回 50。

```
base = 50
sa_count = count(综合价值层级 ∈ {S, A})
score += min(sa_count × 2.5, 50)                      # 绝对数最多 +50
sa_pct = sa_count / len(non_ka) × 100
score += max(0, (sa_pct − 15) × 1.0)                  # 占比超过 15% 起加分
截断 [0, 100]
```

**设计意图（:262-266 docstring 原文）**：绝对数衡量"培养了多少优质客户"（不受总客户数影响），占比作辅助调节（防止只做大客户忽视中小客户成长）。
**注意**：:275 注释锚点（"0人=30分, 5人=50分, 10人=65分, 20人=80分, 30人=100分"）与公式不符——按公式 0 人=50、5 人=62.5、10 人=75、20 人起绝对数项封顶（+50）。登记于 8-1。

### 2.8 产品结构优化力（:282-302，v4.13 修正）

**输入**：利润等级（**含 KA/AA**）、近12月毛利率。

```
base = 50；客户总数=0 时直接返回 50
高利润客户绝对数（利润等级列存在时）：
  high_n = count(利润等级 == "高利润")
  score += min(log10(max(high_n, 1)) × 30, 40)        # 约 22 人起封顶 +40
毛利率中位数（有非空值时）：
  median_margin = median(近12月毛利率)
  score += min(max(0, (median_margin − 15) × 0.5), 20)  # 毛利率 15% 起计分，封顶 +20
截断 [0, 100]
```

**设计意图（:283-285 docstring 原文）**：高利润客户越多 = 产品结构越偏高端，毛利率中位数作辅助。
**注意**：:291 注释锚点（"1人=30分, 10人=50分, 50人=70分, 100人=90分"）与公式不符——按公式 1 人=+0（50 分）、10 人=+30（80 分）、约 22 人封顶。登记于 8-1。

### 2.9 组合抗风险力（:99-106，v4.14 新增）

**输入**：近12月收入（fillna 0）在名下客户上的分布。

```
total = Σ 客户近12月收入；total ≤ 0 时直接返回 50
hhi = Σ (客户营收/total)²                              # 赫芬达尔指数，0~1
score = (1 − hhi) × 100
截断 [0, 100]
```

**语义**：客户营收集中度越低越稳定。极端情形：单客户垄断（HHI=1）→ 0 分；完全均分（HHHI→1/n）→ 接近 100 分。**这是九维中唯一没有 50 分基线偏移结构的维度**（除零营收兜底外，分数完全由 HHI 决定）。

## 3. 分层定级体系（量级→亚组→百分位→硬保护）

全部规则位于 build_sales_profile :51-93，执行顺序如下：

### 3.1 量级（:52-55）

按名下客户**近12月收入合计**（画像口径，非 YTD）：

| 总营收 | 量级 |
|---|---|
| > 1000 万 | 重量级 |
| > 100 万 且 ≤ 1000 万 | 中量级 |
| ≤ 100 万 | 轻量级 |

### 3.2 亚组（:73-78）

量级内再按**客户总数**分亚组，"同结构比较"（:66 注释：避免 332 客户和 12 客户同尺竞争）：

| 客户总数 | 亚组 |
|---|---|
| > 150 | 批量型 |
| > 50 且 ≤ 150 | 均衡型 |
| ≤ 50 | 大客户型 |

### 3.3 组内百分位定级（:67, :80-89）

比较单元 = 量级 × 亚组（最多 3×3=9 个组）。初值全员 "C级"（:67）。

```
组内人数 < 2 → 全组直接 "B级"（:83-85，小组保底）
rank = 组内 综合能力分.rank(pct=True) × 100    # pandas 默认升序：分最高者 pct 最大
rank ≥ 70          → "A级"
40 ≤ rank < 70     → "B级"
rank < 25          → "D级"
25 ≤ rank < 40     → "C级"（保持初值，:89 未覆盖即 C）
```

**精确口径**：A级=组内前 30%（rank≥70）；B级=[40,70)；C级=[25,40)；D级=末 25%。并列分数取平均秩（pandas 默认）。
**faces.yaml 口径卡差异（:263）**：口径卡写"前30%为A级、40%至70%为B级、70%至75%为C级、其余D级"——A/B 两档与代码一致，**C/D 档错位**（代码 C=[25,40)、D=<25；口径卡的"70-75%为C"方向相反），且口径卡未载明小组保底 B 与硬保护两条规则。文档一律按代码。登记于 8-4。

### 3.4 硬保护（:91-93，最后执行、不被覆盖）

```
总营收 > 8000 万 → 强制 "A级"
总营收 ≤ 0       → 强制 "D级"
```

**执行顺序**：百分位定级先跑完，硬保护最后覆盖（:91 注释"最后执行,不被覆盖"）。业务语义：绝对体量足够大或归零是任何组内相对排名都不能推翻的事实。

### 3.5 输出排序（:95）

`sort_values(["量级", "综合能力分"], ascending=[True, False])`——量级按**中文字符串码位升序**排（实际顺序：中量级→轻量级→重量级），不是业务量级顺序；属实现 quirk，登记于 8-6。

## 4. 配置边界声明

- **settings_customer.py（实测 801 行）中不存在销售九维配置段**——客户评分（体量分/价值贡献等）有配置，销售九维没有。九维全部阈值、系数、权重**硬编码在 sales_profiling.py**：
  - 权重 :45-47；量级线 :53-55；亚组线 :75-77；百分位线 :87-89；硬保护线 :92-93；各维内部全部系数见 §2。
- settings.py:90-91 仅有销售员列名候选（`"sales": ["实际业务员", "业务员", "销售员"]`），与九维无关。
- **改任何权重或阈值都必须改代码**（无配置开关、无回退阀门）。这是与产品生命周期系统（阈值全部集中在 settings_product.py）的显著差异，方案书 §6.1 作为首要欠账论述。

- 五子维权重 30/25/20/15/10（:107-108，文件头 :4-9 载明）；各子维均以**公司级该产品线基准**为参照（毛利率偏离度/均价偏离 :53-58, :73-97）。
