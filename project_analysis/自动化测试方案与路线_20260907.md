# 自动化测试方案与路线（全技术栈梳理）

> 日期：2026-09-07 | 来源：R 面编辑功能迭代（三轮 e2e 返工）中建立的 CDP 实测闭环，及其向全项目技术栈的推广评估
> 定位：**项目测试体系的路线文档**——现状盘点、路线选择依据、各栈推广方案、SOP 模板

---

## 一、事件背景（为什么需要这份文档）

0.3.26 编辑器交付时只有构建级验证（tsc+vite+cargo 全绿），用户实测暴露 8 项交互 bug；连续两轮"构建过但实测失败"后建立 CDP 实测闭环，第五个版本（0.3.28）才收敛。**结论：每个技术栈都需要"真实运行时断言"级验证，构建通过只是语法正确性。**

## 二、本日建立的核心方案：Tauri 壳 UI 的 CDP 实测

### 2.1 技术路线

```
启动链：PowerShell 设 WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9222"
        → npm run tauri dev（cargo PATH 需临时补 puccinialin 工具链）
        → WebView2 开 CDP 调试端口
测试链：agent-browser connect 9222 → snapshot（元素发现）/ click（交互）/ eval（DOM 断言）/ screenshot（视觉凭证）
```

### 2.2 路线选择对比（评估过的替代方案）

| 方案 | 结论 | 原因 |
|---|---|---|
| **CDP + agent-browser（采用）** | ✅ | 真实 WebView 运行时、零侵入被测代码、CLI 可编入任务书让子代理自证 |
| vite dev server 直连浏览器 | ❌ | 前端脱离 Tauri 环境，`invoke()` 全挂（Rust command 不可用），编辑器核心功能无法测 |
| Playwright/Puppeteer | ❌ | 新增重依赖；Tauri 窗口非其管理范围；agent-browser 已覆盖同能力 |
| 纯人工验收 | ❌ | 不可持续（本日返工三轮的教训——人工是最后一道不是唯一一道） |
| WebDriver/Windows UI Automation | ❌ | 只能测原生层，WebView 内 DOM 不可达 |

### 2.3 断言策略（可靠性从高到低）

1. **元素状态断言**（最可靠）：`eval` 读 `classList`/`hidden` 属性/`getComputedStyle().display`——涂色回归用 `rowCls 含 row-c-red`
2. **几何断言**：`getBoundingClientRect()` 尺寸>0=可见；**注意 offsetParent 对 position:fixed 恒 null 的假象**
3. **结构断言**：元素存在性计数（如"格级色点残留=0"）
4. snapshot 文本匹配：**最不可靠**（无障碍树裁剪+中文乱码），仅做元素发现不做判定

### 2.4 已知坑清单（全部实测踩过）

| 坑 | 现象 | 规避 |
|---|---|---|
| PS splatting | `@e16` 被 PowerShell 解析吞参数 | ref 参数必须引号 `"@e16"` |
| 中文匹配 | GBK 控制台中文乱码致正则提取失败 | **一律用 id/CSS 选择器**（#btn-edit-risk），不依赖中文文本 |
| 会话漂移 | `location.reload()` 触发 agent-browser relaunch 自有浏览器→断言全在空白页跑（假失败） | 关键断言前 `agent-browser tab` 确认目标页 |
| 单实例锁 | 安装版在跑→dev 实例启动即退 | 测试前确认唯一实例 |
| 隐藏元素点击 | 常驻 DOM 的隐藏面板被全局选择器命中（.p-red 误中 162 个之一） | 弹出层**懒构建**（打开才生成）从根上消除；测试侧配合断言可见性 |
| CDP 拖拽保真度 | Input.dispatchMouseEvent 跨不过 SortableJS 拖动阈值 | 拖拽类交互交真人鼠标终验，自动化只验实例挂载/handle 存在 |
| BOM 陷阱 | Set-Content UTF8 写配置→JSON 解析炸 | `[IO.File]::WriteAllText` + `UTF8Encoding($false)` |

## 三、各技术栈自动化测试现状与推广方案

| 技术栈 | 现有水位 | 本日新增 | 推广方案 | 优先级 |
|---|---|---|---|---|
| **Python 流水线**（silver/gold/看板计算） | pytest **147 用例** + golden_diff 零漂移门禁 + 五门禁体系 | +33 协议往返用例 | 成熟，维持；月度跑批 SOP 已固化 | — |
| **壳前端 TS**（编辑器/界面） | 仅 tsc 类型检查 | **CDP 实测闭环（本方案）** | 固化为 SOP（§四）；后续 UI 迭代强制走 | ✅ 已建立 |
| **壳 Rust 侧**（commands/状态机） | cargo check（编译级），零测试用例 | — | **补 cargo test**：valid_month/路径解析/watchdog 超时/risk_err_envelope 等纯函数单测；状态机转换表测试 | 中（下迭代） |
| **看板 HTML 产物**（template.html 交互） | check_js_syntax + check_js_runtime（Node vm 冒烟，**加载期无错**级别） | — | **CDP 深化**：`agent-browser open file:///...html` 直开产物测真实交互（B 面钻取/经销商视图切换/图表联动/翻页）——比 vm 冒烟深一层，可直接复用本方案工具链 | **高（推荐下一个做）** |
| **发布链**（publish/版本检测） | 人工+复读验证 | 发版命令固定形态 | publish 后自动断言 app-version.txt（一行脚本可入 CI） | 低（简单） |
| **性能** | perf_smoke 门禁（<600s/<180s） | — | 维持；UI 侧可加打开耗时断言 | 低 |

## 四、SOP 固化：UI 返工任务书模板（教训 T1 的机制化）

```
1. 任务书必含：现状+根因线索+【实测命令模板】（connect 9222 → 操作 → eval 断言）
2. 完成判据：断言输出贴进返回报告（构建过≠完成，断言过=完成）
3. 编排者独立复核：复现同一断言（双通道）
4. 视觉类：observer 截图提证据 → designer 设计+实施+自证截图 → 编排者复核 → 用户终验
5. 发版：版本 bump + 三参数 publish + app-version.txt 复读
```
