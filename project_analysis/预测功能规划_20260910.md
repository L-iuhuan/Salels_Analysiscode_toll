## 二、议会裁决（含红队修正后的最终方案）

**核心裁决（议会 2:1）**：quarterly 为经营预测唯一生产口径；平台 ETS 定位月度短期趋势指示灯（渲染点亮但不作经营口径）；beta 席的 bake-off 擂台赛保留为 Phase 3 ETS 升位通道——既守住"回测可辩护性优先"，又不锁死 ETS 上行。

**红队修正（9 处全部采纳）**：
1. 复跑必须显式 `--data` 指向当月文件（默认文件名是冻结快照，原样复跑第一步就会失败）
2. 对拍闸门分双指标：收入 <2% + 利润独立阈值（利润是残差，收入闸门拦不住利润漂移；或先只切收入口径）
3. **砍掉 Phase 1 的 A/R 面季度预测区块**——季桶与自然月两套数字同板打架，且违背"需求先行"原则
4. 触发条件可度量化：复盘文档加固定小节记录预测引用
5. SOP 不另立文档——quarterly→unified 串行调用直接挂进 run_chain 命令序列，失败整链告警
6. quarterly→unified 必须串行重跑（vintage 一致性）
7. 方法锁定=验证既有锁定模式+定义 WAPE 阈值（代码已存在，勿重复造轮子）
8. ETS 渲染前对 forecast 输出值加显式上下界断言（防 1e+157 复发）
9. 全量回测实测 5-10 分钟/锁定模式 1-2 分钟——算力不是问题，纪律才是

## 三、修正后路线图

**Phase 1 · 快赢（预估 1-2 天）**
- ① quarterly 带当月 `--data` 复跑成功（补断档）→ 串行重跑 unified → vintage 一致
- ② ETS forecast 字段最小化渲染点亮（含输出值钳制断言）
- ④ quarterly→unified 挂进 run_chain 跑批序列（失败告警）
- ⑤ utils 三件套删除（git 留档）+ README 漂移修复（unified=system）
- 验收：两线产出可复现且进跑批序列；看板出现月度趋势指示（带口径标注）

**Phase 2 · 数据源切换（对拍闸门后，预估 2-3 天）**
- ⑥ silver vs 原始口径差异量化报告（收入+利润双指标）→ 用户拍板阈值
- ⑦ 过闸后 quarterly 改读 silver parquet（Excel 留季度对账快照）
- ⑧ 方法锁定落地（验证既有锁定模式+WAPE 恶化阈值定义）

**Phase 3 · 深化（触发后）**
- ⑨ 独立预测面：硬触发=嵌入数字连续两期在复盘文档被引用（固定小节记录）
- ⑩ ETS bake-off：quarterly WAPE 赛场打分，胜则升位月度主口径

## 四、用户拍板点（5 项）

1. 对拍闸门：收入 <2% 是否认可？利润差异阈值给多少（或 Phase 2 先只切收入口径）？
2. ETS 指示灯定位是否接受（Phase 1 只渲染月度趋势，不进经营口径）？
3. 独立预测面：认可"连续两期被引用"触发条件，还是跳过独立面常住嵌入？
4. 预算周期对齐：季度滚动桶 vs 自然季度边界（财务口径）？
5. 双轨过渡接受度：Phase 1-2 期间 quarterly（经营口径）+ETS（指示灯）并存。

## 五、风险台账

- R1 复跑环境风险：依赖/路径变化（缓解：显式传参+首跑验证）
- R2 口径信任风险：对拍不过则 Phase 2 延期（闸门存在的意义）
- R3 单人纪律风险：跑批挂载后仍需人工确认（缓解：整链告警）
- R4 ETS 稀疏长尾：指示灯渲染已加钳制；bake-off 前不上经营口径
- R5 **方法准确率（用户 2026-09-10 核心修正，优先级最高）**：预测功能没用起来的根因=准确率不高——资产多≠方法对。**方法筛选与验证先行**（多轮回测与评估，筛选出真正可用的方法组合），消费激活后置。原 Phase 1"复产+渲染点亮"路线作废重排，本规划待产品生命周期改完后按此原则重新展开
