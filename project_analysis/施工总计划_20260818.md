## 二、加速与存储方案裁决

| 方案 | 裁决 | 落位 | 依据 |
|---|---|---|---|
| 看板预聚合（output/dashboard/*.json） | ✅ 最值得 | ③起步、④a 收口 | 消除看板 80% 重算（1031s 的主因：6 面循环过滤 170–185s + C 面 15–20s）→ 看板 30–50s / only 10–20s |
| 指纹分级缓存 + --dashboard-only 真跳过 | ✅ 值得 | ③ | 开发测试高频场景的核心收益 |
| CSV+Parquet 双写 | ✅ 值得 | ② | parquet 落盘 0.77s vs csv 8.15s、体积 15MB vs 172MB；CSV 保留供人检查 |
| avg_price / 画像 / 交叉销售 / 热点循环向量化 | ✅ 值得 | ①② | 低风险等价变换 |
| DuckDB 预聚合表 | ⚠️ ③再评估 | ③ | JSON 预聚合若已达标则不引入；引入则便携 Python 包须同步 |
| 增量 ETL | ❌ 不做 | — | 数据量小、每月全量、退货红冲使真增量不可靠 |
| Polars 替代 pandas | ❌ 不做 | — | 迁移风险大、收益对 20 万行有限（报告 §5.3 同判） |
