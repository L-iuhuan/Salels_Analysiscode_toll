## 一、需求与决策轨迹（用户拍板链）

1. R 面内容编辑入口进壳（非程序员零命令行）
2. 表单化/填空编辑（非裸 md），格式风险归零；保留源码模式逃生门
3. KPI 卡：**一行最多 8 个、用户自由增减卡片数量、自适应宽度、完全填充左右边距、超出换行**；默认 4 张派生卡（自动跟随表格计算）+ 每卡人工覆盖开关 + 新增自定义卡
4. 表格全能力：全单元格可编辑（含初稿数据，配恢复初稿值）、增删行、**增删列**、行排序（拖拽+上下移）
5. 语义标色：单元格/行级色板（emoji 前缀编码：🔴紧急 🟠关注 🟢好转 ⚪备注）
6. 保存前校验：必填/数值/日期行级标错
7. 列头悬停说明复用 faces.yaml 口径（单一真源）
8. 保存 = Python 单一真源组装 md → 自动 --dashboard-only 秒级重渲染 → 看板即所见

## 二、架构：单一真源三端同构

```
┌ 壳编辑器（TS 表单） ── JSON ⇄ ── Python generate_risk_face（--export-json / --import-json）
│                                      │
│                                      ├── md 解析/组装（唯一真源，渲染同解析器）
│                                      └── 渲染 build_r_face_inner_html（动态列+卡片数组+emoji 映射）
└ md 文件（output\dashboard\risk_action_YYYYMM.md）= 持久化格式
```

**决策依据**：TS/Python 两套 md 解析器必然漂移（W4 时代竖线清洗崩溃的同源风险）；编辑器只与 JSON 打交道，往返一致性由 Python 单一真源保障。

## 三、md schema v2 设计

### 3.1 分区结构（向后兼容：旧 md 无新节时按默认处理）

```markdown
# 风险与行动 · YYYY-MM
> 头部元信息（只读，跑批生成）

## 〇、KPI 卡片                      ← 新增节（缺省时=4 张派生卡，不落盘）
| 标题 | 数值 | 副文本 | 级别 | 来源 |
|---|---|---|---|---|
| 高风险事件数 | 12 | 请立即处理 | 红色 | 派生 |
| 专项提示 | 331.0万 | 领导要求展示 | 橙色 | 自定义 |

## 一、当月风险摘要                  ← 表头驱动动态列（列可增删）
| 等级 | 事项 | 客户/产品 | ... |          ← 列名/列数由 md 表头决定
## 二、行动清单                      ← 同款动态列
## 三、口径说明（勿改）               ← 锁定
```

### 3.2 语义色编码：emoji 前缀

- 单元格值首部 `🔴/🟠/🟢/⚪`（均为单码点无变体选择符依赖：U+1F534/U+1F7E0/U+1F7E2/U+26AA）
- 行级色：行首列（第一列）emoji 同时驱动该行淡色底
- 渲染端映射：emoji → 色类（红/橙/绿/灰 token，复用看板警示色体系）→ 去 emoji 显示文字
- 容错：未知 emoji 原样显示；无前缀=默认样式。**emoji 非 md 特殊字符，不触碰竖线/换行规则**（与既有全角｜清洗正交）
- 编辑器：选单元格→色板按钮→前缀增删；读取时解析首 emoji 回显色状态

### 3.3 KPI 派生卡与覆盖

- 派生卡（来源=派生）：数值由风险表统计现算（高风险数/中风险数/负毛利合计/第 4 卡既有逻辑）
- 覆盖开关：来源改"派生覆盖"时数值列人工填写，渲染取人工值
- 自定义卡（来源=自定义）：全字段人工
- **初稿生成（--force-draft / 兜底重建）不落 KPI 节**——保持派生默认，人工编辑过后才落盘该节

## 四、渲染端设计

1. **KPI grid**：`grid-template-columns: repeat(min(n,8), 1fr)`（Python 计算卡数注入；n≤8 每卡 1/n 宽度填满整行，>8 固定 8 列换行）；gap/最小宽度沿用现有 kpi-bar 体系
2. **动态列表格**：表头数组驱动渲染（列名/列宽自适应），替代固定 7 列；列对齐规则：数值列右对齐（按表头名白名单：金额/数量/合计）
3. **emoji 映射表**：渲染层一处常量（emoji→CSS 类），编辑器与 export-json 共享同一映射（JSON 附带图例）
4. R 面 HTML 维持"永远现算"模式（不入 preagg——r24 既有设计），动态列/卡片不触碰指纹缓存链

## 五、Python 侧改动清单（generate_risk_face.py）

1. 解析器扩展：KPI 节解析（缺省容错）/ 动态列表格解析 / emoji 前缀剥离与样式映射
2. `--export-json`：md → 结构化 JSON（分区+表格行列数组+样式标记+faces.yaml 口径注入+初稿快照供"恢复初稿值"）
3. `--import-json`：JSON → md 组装（竖线清洗/emoji 编码/动态列表头语法生成，往返逐字节稳定）
4. 渲染 `build_r_face_inner_html`：动态列/KPI 数组 grid/emoji 色类
5. 单测：往返一致性（md→json→md 不变式）/ 旧版 md 兼容解析 / emoji 容错

## 八、风险与开放问题（议会审查重点）

| # | 风险点 | 当前设计 | 待挑战 |
|---|---|---|---|
| R1 | 往返一致性破坏（编辑操作序列导致 md 累积畸变） | 单一真源+不变式单测 | 序列组合是否有漏网（删列后样式映射/序号错位等） |
| R2 | emoji 编码边界（组合字符/复制粘贴带 VS16/Windows 输入法） | 限定 4 个单码点 emoji+未知原样显示 | 渲染剥离正则是否会把文字误剥（首字符匹配严格性） |
| R3 | 动态列与既有表格渲染样式冲突（宽表溢出/列对齐） | 表头驱动+数值列白名单右对齐 | 超多列（>10）时移动端/窄窗表现 |
| R4 | KPI 覆盖与派生并存的双真源嫌疑 | 来源字段显式区分+初稿不落盘 | 用户改表后忘取消覆盖导致数值滞后的运营风险 |
| R5 | 壳编辑器规模膨胀（原生 TS 手写表格组件复杂度） | 参照既有弹层表格先例 | 拖拽排序/列操作的原生实现是否该引入轻量库 |
| R6 | md 头部"增删改随意"承诺 vs 表单化约束（自由段落在哪放） | 单元格长文本承载叙述 | 是否需要补自由段落区（## 备注） |

## 九、议会审查结论与设计修订（v3.1 定稿，2026-09-07）

> 三席（alpha 架构 / beta UX / gamma 实现）+ council 综合。共识：方向正确，**P0×8 落地前不得施工**；布局分歧已裁决。

### 9.1 P0 修订（并入施工，8 项）

| # | 修订 | 设计要点 |
|---|---|---|
| P0-1 | 显式月份上下文 | Rust 命令显式传 `month`；编辑器顶部月份选择器（列出 output\dashboard\ 现存 md 月份+当前数据月）；默认=当前数据月 |
| P0-2 | 头部时间戳往返不变 | 头部元信息只读**逐字节回写**（import 不重生成头部）；不变式单测归一化时间戳字段后比对 |
| P0-3 | KPI 双真源治理 | export-json 每卡附 `derived_value` 与 `stale` 标志（覆盖值≠现算值时 true）；编辑器与看板覆盖卡显示"人工值，不随表更新"角标 |
| P0-4 | 长文本单元格 | 点击格弹**宽幅编辑抽屉**；多条建议按全角｜自动拆行为列表逐条编辑、保存回拼；含换行拒绝并提示（或转 `<br>` 约定） |
| P0-5 | 核心列保护 | "等级""状态"列禁删禁改名（编辑器置灰+说明）；渲染端列名特判（tag 色/派生统计）在核心列缺失时降级为普通列并在口径条提示 |
| P0-6 | 传输通道 | export/import JSON 强制 **stdin 管道**（Windows 命令行 32K 上限规避）+ 临时文件兜底；错误回传=stderr+exit code+JSON error envelope |
| P0-7 | emoji 语义顺序 | 解析层**先剥离 emoji 再语义匹配**（r[0]=="高"/STATUS_ORDER 等判断在剥离后执行，剥离色值另存行/格 style）；剥离正则锚定 `^\s*(🔴\|🟠\|🟢\|⚪)\uFE0F?\s*`（⚪ 兼容 VS16），先全角｜清洗后剥离；行级色=首列单元格内容级 emoji（非位置级），JSON 侧显式 `style.row_color` 字段，转换仅在 Python 单一真源内发生 |
| P0-8 | 表格组件依赖 | 引 **SortableJS（~40KB，零框架依赖）** 管拖拽排序；其余原生 TS 手写；"零新依赖"目标对工期与稳定性让位（壳 npm 依赖+1，登记台账） |

### 9.2 P1 修订（应采，8 项）

保存链路完整化（mtime 并发校验+保存中 loading/防重入+失败明确报错+未保存关闭拦截+成功后看板跳 R 面定位）；`--force-draft` 覆盖人工结构需二次确认+备份文件；action_items 回写改**稳定键**（首行内容 hash 或显式 id 字段）+结转改显式命令；补 `## 备注` 自由段落节（`_md_cell` 不触碰该节）；import 行列**矩形性校验**显式报错；源码逃生门保存时裸｜全角化容错；KPI grid `n=0` 隐藏整条 kpi-bar；emoji 剥离顺序单测。

### 9.3 P2（缓办登记，4 项）

数值列类型元数据（先以值正则 `^-?[\d,.]+%?万?$` 判右对齐）；派生 KPI 预览快照随 export 附（P0-3 的 derived_value 已覆盖大半）；初稿快照存法；增列防呆默认名/删列撤销栈。

### 9.4 布局冲突裁决（council）

用户需求"一行最多 8 个+完全填充"vs 议员 auto-fit 建议——**裁决：正常态 `grid-template-columns: repeat(8,1fr)` 固定 8 列满排**（卡数 n≤8 时每卡 1/8 宽，>8 换行）；窄容器（编辑器预览悬浮窗）降级 `auto-fit minmax(120px,1fr)`；`.kc` 卡补 `min-width:0`+文本 ellipsis 防溢出。

### 9.5 JSON 协议契约（export-json / import-json 数据结构，两侧施工唯一依据）

```json
{
  "month": "202608",
  "mtime": 1694064000.0,
  "header_raw": "（头部元信息原文，import 时逐字节回写）",
  "kpi_cards": [
    {"title": "高风险事件数", "value": "12", "sub": "请立即处理",
     "level": "red", "source": "derived|override|custom",
     "derived_value": "12", "stale": false}
  ],
  "risk_table": {
    "columns": ["等级", "事项", "客户/产品"],
    "col_meta": [{"name": "等级", "locked": true}],
    "rows": [
      {"cells": [{"text": "客户采购中断", "color": "none"}],
       "style": {"row_color": "red"}}
    ]
  },
  "action_table": {"…同构…": ""},
  "notes_section": "自由段落文本（## 备注 节）",
  "caliber_raw": "（口径区原文，锁定逐字节回写）",
  "derived_snapshot": {"n_high": 0, "n_mid": 0, "loss_sum": 0.0},
  "legend": {"red": "紧急", "orange": "关注", "green": "好转", "gray": "备注"}
}
```

约定：`color/level/row_color ∈ {red, orange, green, gray, none}`（Python 端与 🔴🟠🟢⚪ 映射，md 落盘为 emoji 前缀，JSON 层为语义枚举）；错误 envelope `{"ok": false, "err": "...", "stage": "parse|import|render"}`。
