## W1 快照仓（存储设计）**——优先级已升为「高」（2026-08-24 实测后修订）**

### 实测证据（2026-08-24，`C:\Users\910373\Downloads\财务分析-7月（8.1）.xlsx`，224.8MB / 199,687 行 × 71 列）

| 路径 | 结果 | 含义 |
|---|---|---|
| 文件加密状态 | **已被 DSE 加密**（头 `00 00 5b 00`） | 用户流程属实：核对加工后文件被加密 |
| calamine / openpyxl 直读 | **不支持加密文件** | 现役 `read_excel_auto()` 只有 calamine>openpyxl 两条路径，**无任何加密兜底** |
| Excel COM 解密读 | 打开 47.9s + 读值 14.4s = **62.3s/次** | 每次跑批的"解密税" |
| parquet 快照读 | **1.2-1.6s**（既有实测） | 快照仓方案的跑批读速 |

**关键结论**：现役流水线对加密 Excel **会直接报错崩溃**（calamine/openpyxl 都读不了非 ZIP 头文件）。下月（7月数据）跑批若无 W1 或兜底，**现在就会失败**。W1 从"风险隔离"升级为"下月跑批的前置条件"。

### 设计决策

- **ingest 时机**：月度流程改为——ERP Excel 放入 `data\` → 人工核对加工完成 → **跑 `scripts\ingest_snapshot.py`** → 之后才允许任何人用 Excel 打开/保存原文件（加密与否跑批都不再关心）。
- **快照落点**：`sales_analytics_platform\data_warehouse\YYYYMM\erp_snapshot.parquet` + `manifest.json`（源文件名/mtime/行数/列名哈希/关键合计校验值/ingest 时间/是否经 COM 解密路径）。
- **明文保证**：Python 写 parquet，DSE 不拦截（非白名单进程）；快照永远明文。
- **读侧**：`run_all` silver 构建优先读快照（manifest 校验通过），否则回退现状直读 `data\*.xlsx`；若 Excel 已被 DSE 加密且无快照 → **明确中文报错**引导先跑 ingest（不走静默 COM 慢路径，避免每次跑批付解密税）。
- **目录约定**：`data_warehouse\` 加入宪法目录表（数据产物，gitignore）；publish 脚本排除（共享盘客户端不需要快照仓）。
- **ingest 容错**：源 Excel 已被加密时，ingest 走 COM 解密读取（实测 62.3s/次）——解密税只在 ingest 时付一次；明文窗口 ingest 用 calamine（~25s）。
- **兜底加固**：`read_excel_auto()` 增加加密检测（文件头非 `PK\x03\x04`）→ 明确中文报错引导跑 ingest（不静默改 COM 慢路径，避免每次跑批付 62s 税）。

### 验收

1. 快照行数/关键列合计与源 Excel 对账一致（ingest 打印对账表）。
2. 用加密副本实测：有快照时跑批正常；无快照且 Excel 加密时按设计报错。
3. 全量跑 golden_diff 零漂移。

## W4 新面「行动与说明」测试版（人工确认后写入）

### 面结构（2026-08-24 用户修订：异常与风险并入本面，命名「风险与行动」）

- **上部：风险与异常摘要**——当月异常/风险要点（来自 gold 异常/风险表，测试版先接 1-2 个源），每条可转为行动项
- **中部：行动清单**（待办/重点关注）——事项带状态（待处理/跟进中/已关闭）+ 负责人 + 备注
- **下部：口径与使用说明**——各面定义/口径/数据源/更新节奏（从 faces.yaml 渲染）

### 测试版核心流程（不能自动推，确认后写入）

```
每月跑批 → generate 阶段把候选事项（来自 gold 异常/风险表，测试版先接 1-2 个源）
         写入暂存文件 dashboard\行动清单_候选_YYYYMM.md（含格式说明）
         → 人工编辑确认（勾选/修改/删除，直接在 md 文件里改）
         → 确认后的事项存 dashboard\action_items.json（入版本库，跨月跟踪状态）
         → 下次生成看板时，只有"已确认"的事项写入 HTML
测试期新面输出到独立测试页（或 --with-action-face 开关），不并入正式 dashboard_a.html；
评审通过后再并入正式看板。
```

### 范围控制（测试版）

- 候选数据源先接 1-2 个（建议：异常日志 + 客户预警），格式跑通再扩
- 口径说明先写 3 个面示例（W3 产出），用户审后补全
- 跨月状态结转：上月"待处理/跟进中"自动带入本月候选，已关闭不带入

### 验收

- 候选→人工确认→写入流程端到端跑通；**未确认项绝不出现**在输出里
- 测试期正式看板 dashboard_a.html 逐字节不变（golden_diff 零漂移）
- [STAGE] 协议不动
