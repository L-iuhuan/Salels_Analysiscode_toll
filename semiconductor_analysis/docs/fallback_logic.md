## 1. 渠道类型推导（三级降级）

| 项        | 值                                                    |
| -------- | ---------------------------------------------------- |
| **用途**   | 确定客户是"代理"还是"直供"渠道                                    |
| **使用位置** | `portrait.py:_derive_channel()` + `masters.py` CRM映射 |
| **数据来源** | ERP交易数据 + CRM终端客户表                                   |
| **严重度**  | 高 — RFM-π评分依赖渠道隔离                                    |

### 取数优先级

```
Primary: CRM"代理商/直供"列 → 直接取值
          来源: 所有的终端客户.xlsx col 2 "代理商/直供"
          预期覆盖率: 123/189 (65.1%)
              ↓ 如果CRM未匹配或为空
Fallback 1: 交易数据推导
            逻辑: 客户ID出现在"代理商/直供名称"列 → 代理
                  客户ID出现在"实际终端客户"列 → 直供
                  同时出现在两列 → 次数比较，多者胜出
            来源: ERP"所有的出货明细"原始列
            预期覆盖率: ~80%
              ↓ 如果交易数据也无法判定
Fallback 2: 默认"未知"
```

### 补充建议

* CRM覆盖率可通过补充终端客户主数据提升至95%+

* 交易推导逻辑依赖ERP始终包含"代理商/直供名称"和"实际终端客户"列

* **当前状态**: Fallback 1已实现并测试通过，覆盖率从0%提升至189/189

## 2. 客户层级映射

| 项        | 值                                                                                   |
| -------- | ----------------------------------------------------------------------------------- |
| **用途**   | 客户自身营收规模分级: KA/AA/KM/MM（非我方采购量）                                                     |
| **使用位置** | `customer_master.py:enrich_customer_portrait()` → `scoring.py:calc_customer_tier()` |
| **数据来源** | CRM"客户类别"字段（标注客户自身年营收规模）                                                            |

### 取数优先级

```
Primary: CRM"客户类别"字段
          来源: 所有的终端客户.xlsx col 4 "客户类别"
          原始值: "KA>1亿", "AA>5000万", "KM>1000万", "MM<1000万"
          映射方式: 关键词匹配（如"KA"出现在字符串中→KA）
          预期覆盖率: ~60%（取决于CRM数据完整性）
              ↓ CRM未匹配或无客户类别字段
Default: "未分类"
```

### 重要说明

**【已移除】收入分箱回退 — 2026-05-23**

之前版本有"近12月收入"分箱回退，逻辑上存在问题：

* "近12月收入"是**我方对该客户的销售额**，不是客户自身总营收

* 客户自身年营收>1亿（KA级），从我方采购可能仅200万

* 用采购额反推客户规模会错误地将KA客户归入KM或MM档

因此：

* 客户层级完全依赖CRM"客户类别"字段

* CRM未匹配的客户 → "未分类"，不做推测

* 提升覆盖率的正确路径：补充CRM终端客户主数据

### 补充建议

* 当前CRM匹配率\~60%，补充终端客户数据可提升

* 不推荐用任何交易数据推测客户层级

## 3. 收入增长率计算（二级降级）

| 项        | 值                             |
| -------- | ----------------------------- |
| **用途**   | 计算客户收入增长趋势，用于增长动能评分           |
| **使用位置** | `portrait.py:_dim_momentum()` |
| **数据来源** | `customer_monthly` 月度收入聚合     |

### 计算逻辑

```
Primary: 近12月均收入 vs 前12月均收入
          条件: 前12月至少有2个月有正收入
          方法: (近12月均值 - 前12月均值) / 前12月均值
              ↓ 条件不满足（新客户/数据不足）
Fallback: 近6月均收入 vs 前6月均收入
          条件: 前6月至少有1个月有正收入
          方法: (近6月均值 - 前6月均值) / 前6月均值
              ↓ 条件不满足（全新客户）
默认值: 0（无增长信号）
```

### 补充建议

* 短窗口(6月)对季节性波动更敏感，可能高估/低估实际增长率

* 当数据积累至24个月以上后，可增加YoY同比增速作为主指标

* **当前状态**: Fallback已实现，未触发短窗口的客户数待统计

## 6. 评分维度子指标缺失（加权跳过）

| 项        | 值                               |
| -------- | ------------------------------- |
| **用途**   | 当子指标字段在DataFrame中不存在时的处理        |
| **使用位置** | `scoring.py:_score_dimension()` |
| **严重度**  | 中 — 单一指标缺失不阻断评分                 |

### 逻辑

```
对SCORE_SUB_WEIGHTS中的每个子指标:
  if 指标列不在DataFrame中:
      跳过该指标（不报错）
      总权重和 weight_sum 不包含该指标权重
  if 指标列存在但全为空:
      Min-Max归一化返回默认值50
最终: 总分 = sum(指标分 × 权重) / weight_sum（剩余权重重归一化）
```

### 补充建议

* 如果某个维度所有子指标都缺失，该维度评分为0

* 监控维度中缺失指标的数量，缺失超过50%应告警

* **当前状态**: 正常工作中，随数据完善各字段逐渐齐全

## 7. Min-Max归一化零变异回退

| 项        | 值                           |
| -------- | --------------------------- |
| **用途**   | 当指标值无变异（全相同）时无法归一化          |
| **使用位置** | `scoring.py:_minmax_norm()` |

### 逻辑

```
if s.max() > s.min():
    return (s - s.min()) / (s.max() - s.min()) * 100
else:
    # 所有值相等，无变异
    return pd.Series(50.0, index=s.index)  # 返回50分
```

### 补充建议

* 零变异通常意味着该指标在当前数据集中完全无区分力

* 需要判断是数据质量问题还是该指标确实无意义

* **当前状态**: 部分子指标（如近12月毛利率P50=54.6%）区分力本身有限

## 12. RFM-π渠道隔离回退

