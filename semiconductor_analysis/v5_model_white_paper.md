## 1. 背景与动机

### 1.1 原始问题

半导体产品的量价数据呈现明显的生命周期特征：导入 → 增长 → 成熟 → 衰退 → 退出。原始项目试图通过多因子规则模型对产品进行风险评分，但因以下问题导致效果远低于预期：

1. **规则过多依赖直觉**：因子权重、阈值由人工设定，缺乏数据验证
2. **标签定义不合理**：使用"是否在 T+24 个月内完全无销量"这个二值标签，忽略了销量暴跌 90% 但未完全退出的"灰色地带"产品
3. **验证方式有数据泄露**：K-fold 交叉验证中，同产品的不同时间点可能同时出现在训练集和测试集，夸大模型表现
4. **没有客户维度信息**：完全忽视"不同客户的采购行为差异"这个信号
5. **评分分辨率极低**：阶梯函数只有 4-5 个档位（10/40/50/70/90），无法区分细微差别

### 1.2 数据背景

- **数据来源**：ERP 导出产品-客户-月度明细数据
- **时间范围**：2020 年 ~ 2026 年 4 月
- **数据结构**：每行是 (产品, 客户, 月份) 的聚合销量和金额
- **最终面板**：1,857 条产品-时间点记录，覆盖 361 个独立产品
- **时间点选择**：每 ~5 个月一个评估节点，共 7 个时间点（2022-02 ~ 2024-08）

### 1.3 目标重定义

将问题从"这个产品会不会死？"（二值分类）改为**"这个产品在未来 12 个月的衰退程度有多严重？"**（连续回归）。

这种重新定义的优点：
- 不需要等产品完全退出才能标记为"衰退"——销量跌一半也算衰退
- 减轻右删失影响——2024-08 时间点的产品即使没完全退出，只要已经开始萎缩就有标签
- 业务上更实用——知道"会死 50%"比知道"可能会死"更有操作价值

## 2. 探索过程：从 v1 到 v5

### 2.1 v1-v2 规则模型

**原始模型 (risk_scoring.py v2.9)** — 5 因子阶梯函数 + 加权平均

| 因子 | 权重 | 打分方式 |
|:----|:----:|:---------|
| 毛利率趋势斜率 | 20% | if-else 分档: 10/20/50/80 |
| 订货波动性 CV | 10% | if-else 分档: 10/40/65/85 |
| 增速衰减 | 20% | 增长率感知分支: 10~80 |
| 自比健康度 SH | 35% | if-else 分档: 10/40/70/90 |
| ASP 趋势 | 15% | 联合毛利率判断: 10~80 |

综合分 = `w1*s1 + w3*s3 + w4*s4 + w_sh*s_sh + w6*s6`（范围 10~90）

**调优结果**：在 params_full.json 中，最优参数组合的 precision 仅 28.6%，recall 仅 4.3%。意味着：
- 模型几乎只标注了"最确定会死"的产品（极保守）
- 大量正在衰退的产品完全被漏掉
- 而这 28% 的 precision 可能还有 K-fold 数据泄露带来的虚高

### 2.2 v3 LR 模型

**v3 (risk_scoring_v3.py)** — 3 因子 Logistic Regression 连续评分

- 移除冗余特征（margin_slope, CV, ASP）→ 精简为 3 个产品级特征
- 从阶梯函数改为 Logistic Regression 连续输出
- 公式: `score = 100 / (1 + exp(-(intercept + w1*growth + w2*depth + w3*health)))`
- 系数: intercept=-2.16, w_growth=-0.40, w_depth=3.76, w_health=-0.93
- ROC-AUC ≈ 0.76（walk-forward），比阶梯函数有提升但天花板明显
- 局限：LR 只能建模线性关系，且仍使用二值标签

### 2.3 v4 探索客户特征

**v4 — 产品 3 因子 + 客户特征** — Logistic Regression 二值分类

- 新增客户特征：cust_rev_hhi（收入集中度）、cust_churn_rate（客户流失率）
- 在完整数据上 ROC-AUC=0.90（全样本），但严格时间切分测试 AUC=0.80

**关键发现**：
- **HHI 确实有用**：产品3+HHI 测试 AUC=0.89，远高于产品3 单独的 AUC=0.80
- **但 churn_rate 是噪音**：时间切分下训练 AUC=0.80 测试 AUC=0.64 → 分布不稳定
- **HHI 不是产品成熟度的代理变量**：HHI vs tenure 的 Pearson r=-0.065，几乎不相关
- **时间切分与全样本 AUC 差异巨大**（0.89 vs 0.80），说明存在数据泄露问题
- 差异的 bootstrap 95%CI: [0.027, 0.114]，v4 优于 v3 的概率 100%

### 2.4 v5 全面重构

决定重构 v5 的原因：

| 问题 | v4 中 | v5 方案 |
|:----|:------|:--------|
| 标签是二值 | 丢失信息 | 连续衰退严重度 [0,1] |
| 验证不严格 | 全样本 AUC vs 时间切分差距大 | Walk-forward 面板验证 |
| 模型是线性 LR | 无法捕捉交互 | RandomForest |
| 客户特征不够充分 | 仅 HHI+churn | 6 个客户特征 |
| 单客户产品没区分 | 混在一起 | 新增 is_single_customer + n_customers_log |

## 3. 目标变量定义与计算方法

### 3.1 定义

`decline_severity`（衰退严重度）= **1 - min(未来 12 月平均月销量 / 过去 12 月平均月销量, 1)**

### 3.2 计算公式

```
severity = 1.0 - min(future_12m_avg / past_12m_avg, 1.0)
```

其中：
- `past_12m_avg` = 时间点 T 之前 12 个月内（不含 T 当月）该产品的月均销量
- `future_12m_avg` = 时间点 T 之后 12 个月内该产品的月均销量
- 当 past_avg > 0 且 future_avg >= 0 时，正常计算
- 如果 past_avg <= 0 且 future_avg > 0，则视为增长，severity=0
- 如果两者都 ≤ 0，则视为完全死亡，severity=1

### 3.3 含义

| severity 值 | 含义 |
|:----------:|:-----|
| 0.0 | 持平或增长（未来 12 月 ≥ 过去 12 月） |
| 0.3 | 未来销量比过去下降 30% |
| 0.5 | 未来销量腰斩 |
| 0.8 | 未来销量仅为过去的 20% |
| 1.0 | 完全退出 |

### 3.4 与原始二值标签的区别

原始定义：`will_decline = 产品在未来 24 个月内完全无销量（连续 12 个月无订单）`

```
原始标签             连续标签
                     
会死→ [1]           1.0 ← 完全死亡
                         0.8 ← 销量跌80%
                        0.5 ← 腰斩
                        0.3 ← 跌30%
不会死→ [0]          0.0 ← 持平/增长
```

**关键改进**：原始标签把 severity=0.8 的产品和 severity=0.0 的产品都归为"不会死"，丢失了 80% 的信息。连续标签保留了完整的衰退幅度。

## 4. 特征工程：变量定义与计算方法

### 4.1 产品级特征

#### 4.1.1 growth_rate（增长率）

**定义**：最近 12 个月与之前 12 个月的月均销量变化率。

**计算公式**：
```
recent_avg = sum(近12月销量) / 近12月有数据的月数
prior_avg  = sum(前12月销量) / 前12月有数据的月数

growth = clip((recent_avg - prior_avg) / prior_avg, -1.0, 5.0)
```

**取值范围**：[-1.0, 5.0]
- 负值 = 下降；正值 = 上升
- 0.0 = 持平
- -1.0 = 完全消失（截断下限）
- 5.0 = 暴涨 5 倍（截断上限，防止极端 outlier）

**Python 代码逻辑**：
```python
recent = pm_prod[pm_prod.index > (tp - 12)]
prior  = pm_prod[(pm_prod.index <= (tp - 12)) & (pm_prod.index > (tp - 24))]
if len(prior) >= 2 and prior["qty_sum"].sum() > 0 and len(recent) > 0:
    recent_avg = recent["qty_sum"].sum() / len(recent)
    prior_avg  = prior["qty_sum"].sum() / len(prior)
    growth = max(-1.0, min(5.0, (recent_avg - prior_avg) / prior_avg))
else:
    growth = 0.0
```

#### 4.1.2 decline_depth（衰退深度）

**定义**：当前月均销量相对于历史峰值的跌幅。

**计算公式**：
```
peak_qty     = max(产品在该时间点之前所有月份的销量)
recent_3m_avg = 最近3个月的月均销量（如果有数据）
decline_depth = max(0, (peak_qty - recent_3m_avg) / peak_qty)
```

**取值范围**：[0.0, 1.0]
- 0.0 = 正处于历史峰值附近（未衰退）
- 0.5 = 从峰值下跌了一半
- 0.9 = 从峰值暴跌 90%
- 1.0 = 完全无销量

**为什么用 3 个月平均而不是单月**：平滑季节性波动，避免某个月特别低就误判为衰退。

**Python 代码逻辑**：
```python
peak_qty = pm_prod["qty_sum"].max()
if peak_qty > 0:
    recent_3m = pm_prod[pm_prod.index > (tp - 3)]
    recent_3m_avg = recent_3m["qty_sum"].mean() if len(recent_3m) > 0 else 0
    decline_depth = max(0.0, (peak_qty - recent_3m_avg) / peak_qty)
else:
    decline_depth = 1.0
```

#### 4.1.3 self_health（自比健康度）

**定义**：近 12 月的月均销量相对于产品全历史月均销量的比率。

**计算公式**：
```
recent_12m_avg = sum(近12月销量) / 近12月有数据的月数
all_avg       = sum(产品全历史销量) / 全历史有数据的月数

self_health = min(recent_12m_avg / max(all_avg, 1), 2.0)
```

**取值范围**：[0.0, 2.0]
- 1.0 = 当前水平和历史平均持平
- 0.5 = 当前水平只有历史平均的一半 → 不健康
- 2.0 = 当前水平是历史平均的两倍 → 超健康（截断上限）
- 0.0 = 极不健康

**与 decline_depth 的区别**：
- decline_depth 回答"从最好跌了多少"
- self_health 回答"比历史平均是强还是弱"
- 一个产品可能 decline_depth 很高（从 100 跌到 30，跌了 70%），但 self_health 仍然 >1（历史平均才 20，现在 30 比平均高）

### 4.2 客户级特征

**核心思路**：产品级信号是"所有客户的混合"，可能掩盖个体客户的流失行为。客户级特征通过**按收入加权聚合**，放大重要客户的变化信号。

#### 原始数据准备

首先需要每个 (产品, 客户, 月份) 的明细：
```python
cust_prod_month = df.groupby([产品名, 客户编号, "_月"]).agg(
    qty_sum=(销量, "sum"),
    rev_pos=(营收, lambda x: x[x > 0].sum()),  # 只计正营收
).reset_index()
```

#### 4.2.1 n_customers（客户数）和 n_customers_log

**定义**：最近 12 个月内为这个产品下过单的唯一客户数量。

**计算公式**：
```
active_custs = unique(客户编号 满足: 产品=当前产品 AND 时间>=(T-12) AND 时间<=T)
n_customers  = len(active_custs)
n_customers_log = log(1 + n_customers)
```

**含义**：
- 客户数量本身有预测力——单客户产品的退出概率远高于多客户产品
- 对数变换压缩差异：1 到 10 的变化比 100 到 110 重要得多
- 单客户产品占比 ~30%，其中约一半会衰退

#### 4.2.2 cust_rev_hhi（客户收入集中度，赫芬达尔指数/Herfindahl-Hirschman Index）

**定义**：各客户收入占比的平方和，衡量客户集中度。

**计算公式**：
```
总营收   = sum(各客户近12月营收正部分)
各客户占比 = 该客户营收 / 总营收
HHI       = sum(各客户占比^2)
```

**取值范围**：[0, 1]
- HHI=1.0 = 只有一个客户（或一个客户占 >99%）
- HHI=0.5 = 两个客户各占 50%
- HHI=0.3 = 三个客户各占 33%
- HHI 越低 = 客户越分散

**为什么重要**：
- 单客户产品（HHI=1.0）的退化风险最高
- HHI 本身对二值（是否会完全退出）预测的 AUC=0.86，是第二强的单特征
- **但 HHI 对"衰退严重度"（连续值）的预测力很弱**（重要性仅 1.2%）——它回答的是"一旦衰退会不会死透"，不是"会不会衰退"

**Python 代码逻辑**：
```python
rev_shares = cf["revenue"].values / total_rev
cust_rev_hhi = float((rev_shares ** 2).sum())
```

#### 4.2.3 cust_top1_share（第一大客户收入占比）

**定义**：收入最高的客户占总收入的比例。

```
cust_top1_share = max(rev_shares)
```

**取值范围**：[0, 1]
- 0.8 = 最大客户占 80% 收入 → 极高依赖风险
- 该客户一旦流失，产品收入会暴跌

#### 4.2.4 cust_churn_rate（客户流失率，收入加权）

**定义**：最近 12 个月内已"沉默"（≥3 个月未下单）的客户中，按收入占比加权计算的流失比例。

**计算公式**：
```
对每个客户:
  距离上次下单月数 = T - 该客户的最后一次下单月份
  该客户是否流失 = 距离上次下单月数 >= 3

cust_churn_rate = sum(各客户收入占比 × 该客户是否流失)
```

**为什么是收入加权**：一个大客户流失比 10 个小客户流失更严重。

**注意**：v4 测试中发现 churn_rate 的分布在不同时间点不稳定（train AUC=0.80, test AUC=0.64），但在 v5 的 RandomForest 中通过与其他特征的交互仍然有效（重要性 3.2%）。

#### 4.2.5 avg_cust_tenure（客户平均合作时长，收入加权）

**定义**：客户的第一个订单月份到当前时间点的时长，按收入加权平均。

```
对每个客户:
  tenure = (T - 该客户首次下单月份) 的月数 + 1

avg_cust_tenure = sum(各客户收入占比 × 该客户 tenure)
```

**取值范围**：原则上 ≈[1, 120] 个月
- 时长越高表示客户关系越稳定
- 新客户 + 高收入占比 → 高风险（可能是一次性大单）

#### 4.2.6 is_single_customer（是否单客户产品）

**定义**：该产品是否只有 1 个客户（或 HHI≥0.99）。

```
is_single_customer = 1 if (n_customers <= 1 or cust_rev_hhi >= 0.99) else 0
```

**为什么单独成为一个特征**：单客户产品的行为模式完全不同——生命周期完全绑定于这一个客户。在数据中：
- 单客户产品占总体的 30%
- 单客户产品本身的 AUC=0.770（对是否严重衰退）
- 但由于和 n_customers_log 高度相关，在特征重要性中几乎为 0（0.02%）——被 log 吸收了

### 4.3 特征汇总表

| 特征名 | 类型 | 范围 | 含义 | 原始计算输入 |
|:-------|:---:|:----:|:-----|:------------|
| growth_rate | 产品 | [-1, 5] | 增长率 | 近12月均销量 / 前12月均销量 - 1 |
| decline_depth | 产品 | [0, 1] | 从峰值跌幅 | (峰值 - 近3月均) / 峰值 |
| self_health | 产品 | [0, 2] | 相对历史均值健康度 | 近12月均 / 全历史均 |
| cust_rev_hhi | 客户 | [0, 1] | 客户集中度 | sum(各客户收入占比²) |
| cust_top1_share | 客户 | [0, 1] | 最大客户占比 | max(各客户收入占比) |
| cust_churn_rate | 客户 | [0, 1] | 流失率(收入加权) | 加权距离上次下单≥3月占比 |
| avg_cust_tenure | 客户 | [0, ~120] | 平均合作月数(收入加权) | 加权客户历史时长 |
| is_single_customer | 客户 | 0/1 | 是否单客户 | n_customers ≤ 1 |
| n_customers_log | 客户 | [0, ~6] | 客户数(对数) | log(1 + n_customers) |

## 5. 模型原理：RandomForest 回归

### 5.1 为什么选择 RandomForest

在探索阶段尝试了多个模型：

| 模型 | 优势 | 劣势 |
|:----|:----|:-----|
| Logistic Regression | 可解释性好，训练快 | 只能捕捉线性关系，需要手动做特征交叉 |
| 阶梯函数(原始) | 完全可解释 | 离散化丢失信息，人工调参主观 |
| **RandomForest** | **自动捕捉非线性 + 特征交互，无需归一化** | 可解释性低于 LR，模型文件较大 |

**最终选择 RandomForest 的原因**：
1. decline_depth 和 growth_rate 的关系是高度非线性的（高深度+负增长=确定衰退，但高深度+正增长≠）
2. 客户特征的交互复杂（单客户 + 高 HHI + 高 churn 的复合效应不能简单用加法建模）
3. 无需做大量特征工程预处理

### 5.2 参数配置

```python
RandomForestRegressor(
    n_estimators=500,      # 树的数量：500棵（越多精度越高，但边际递减）
    max_depth=8,           # 限制树的最大深度为8层（防止过拟合）
    min_samples_leaf=10,   # 叶节点最少10个样本（防止极端单点分割）
    random_state=42,       # 固定随机种子，保证结果可复现
    n_jobs=-1,             # 使用所有CPU核心并行训练
)
```

**参数选择逻辑**：
- `max_depth=8`：数据只有 1,857 行 9 个特征，深度 8 已足够。更深则容易记住单个时间点的噪音模式
- `min_samples_leaf=10`：平均每个叶节点覆盖至少 10 个产品-时间点，保证统计稳定性
- `n_estimators=500`：在 200~500 之间 R² 提升约 2%，500 以上几乎没变化

### 5.3 数据取值映射与裁剪规则

模型对输入特征的取值有明确的裁剪规则（防止 NaN、Inf、极端值破坏预测）：

| 特征 | 裁剪范围 | NaN/Inf 默认值 | 业务含义 |
|:-----|:--------:|:--------------:|:---------|
| growth_rate | [-1.0, 5.0] | 0.0 | 增长率不可能低于-100%(完全消失)或高于500%(极端暴涨) |
| decline_depth | [0.0, 1.0] | 0.5 | 深度始终在0~1之间；无数据时默认中间值 |
| self_health | [0.0, 2.0] | 0.5 | 健康度上限2倍均值；无数据时默认中间值 |
| cust_rev_hhi | [0.0, 1.0] | 0.0 | HHI天然在0~1之间 |
| cust_top1_share | [0.0, 1.0] | 0.0 | 占比天然在0~1之间 |
| cust_churn_rate | [0.0, 1.0] | 0.0 | 流失率天然在0~1之间 |
| avg_cust_tenure | [0.0, 120.0] | 0.0 | 合作时长不超过10年 |
| is_single_customer | {0, 1} | 0 | 布尔值，默认非单客户 |
| n_customers_log | [0.0, 6.0] | 0.0 | log(1+0)=0, log(1+400)≈6.0 |

**预测输出裁剪**：`pred = clip(pred, 0, 1)` — 确保输出值在 [0, 1] 范围内。

## 6. 验证方案：Walk-forward 面板验证

### 6.1 为什么不是 K-fold

| 验证方式 | 优点 | 缺点 |
|:---------|:---:|:-----|
| **K-fold CV** | 常用，方差小 | ❌ **同产品不同时间点跨训练/测试** → 数据泄露，高估 AUC |
| 时间切分 | 简单时间前推 | ❌ 只有一个测试集，结果不稳定 |
| **面板 Walk-forward** | ✅ 严格时间前推 + 每步独立测试集 | 方差略大但最诚实 |

**面板 Walk-forward 的具体问题**：如果使用标准 K-fold，产品 A 在 2022-02 的样本可能在训练集、2022-08 的样本在测试集，但模型实际上"见过"了 A 的早期行为，对于同一个产品，预测后期比预测全新产品要容易得多。Walk-forward 强制使用前 N 个时间点训练、预测第 N+1 个，杜绝所有未来信息。

### 6.2 验证流程

```
时间点:   P1      P2      P3      P4      P5      P6      P7
       2022-02  2022-08  2023-02  2023-08  2024-02  2024-08  2025-02(预留)
                  ↓
Step 1: [P1]    → [P2]   训练: P1, 测试: P2
Step 2: [P1+P2] → [P3]  训练: P1-P2, 测试: P3
Step 3: [P1+P2+P3] → [P4]  ...
Step 4: [P1-P4] → [P5]
Step 5: [P1-P5] → [P6]
...
```

每个 step 都是严格时间前推：**测试集的时间一定在训练集之后**。

### 6.3 时间点与面板结构

| 参数 | 值 |
|:----|:----|
| 起始时间点 | 2022-02 |
| 末尾时间点 | 2024-08 |
| 时间间隔 | ~5 个月 |
| 时间点数量 | 7 个 |
| 每个时间点产品数 | ~265 个（不等，随时间增加） |
| 面板总行数 | 1,857 |
| 独立产品数 | 361 |
| 评估窗口 | 未来 12 个月 |
| 最低产品月龄 | 24 个月 |
| 最低产品销量 | 50,000 |

**产品过滤条件**：
1. 在时间点 T 之前至少有 3 个月的数据（保证有历史）
2. 到时间点 T 时产品月龄 ≥ 24 个月（避免导入期噪音）
3. 全历史总销量 ≥ 50,000（排除边缘小产品）

## 7. 模型表现与结论

### 7.1 最终性能指标

| 指标 | 全量训练 | Walk-forward 均值 |
|:----|:--------:|:----------------:|
| **R²** | 0.671 | 0.559 |
| **MAE** | 0.170 | 0.181 |
| **RMSE** | 0.242 | - |
| **Spearman ρ** | 0.728 | - |
| **AUC (severity>0.5)** | 0.910 | 0.882 |

- R²=0.671 意味着模型解释了 67.1% 的衰退严重度方差
- MAE=0.170 意味着平均预测误差约 17 个百分点（比如实际=0.50，预测≈0.33~0.67）
- Spearman=0.728 意味着排序能力强——高风险的确实排在前面
- walk-forward AUC=0.882 是"诚实"值（去除了数据泄露）

### 7.2 特征重要性

| 排名 | 特征 | 重要性 | 累计 | 类别 |
|:---:|:-----|:-----:|:----:|:---:|
| 1 | **decline_depth** | **74.70%** | 74.7% | 产品级 |
| 2 | self_health | 7.47% | 82.2% | 产品级 |
| 3 | n_customers_log | 4.26% | 86.4% | 客户级 |
| 4 | growth_rate | 3.31% | 89.7% | 产品级 |
| 5 | cust_churn_rate | 3.21% | 93.0% | 客户级 |
| 6 | cust_top1_share | 3.10% | 96.1% | 客户级 |
| 7 | avg_cust_tenure | 2.73% | 98.8% | 客户级 |
| 8 | cust_rev_hhi | 1.20% | 100.0% | 客户级 |
| 9 | is_single_customer | 0.02% | 100.0% | 客户级 |

**三个核心洞察**：

1. **decline_depth 占据 75%**：模型本质上是"过去衰退越深 → 未来衰退越严重"的延续性检测器。这个特征回答的是"从峰值跌了多少"，而结果变量（severity）回答的是"未来会不会继续跌"。两者高度相关说明：**一旦产品开始从峰值衰退，这种趋势很可能延续**。

2. **客户特征合计 ~15%**：远低于预期。v4 中 HHI 的 AUC=0.86 是因为当时用的是"是否会完全退出"这个二值标签。在连续标签下，客户特征对"衰退深度"的预测力有限。

3. **is_single_customer 几乎为 0**：因为与 n_customers_log 完全线性相关，信息被 log 吸收了。

### 7.3 风险分布

```
          预测严重度    实际严重度
P 5         0.030       0.000
P 10        0.044       0.000
P 25        0.087       0.000    ← 25% 产品被模型认为几乎无风险
P 50        0.198       0.063    ← 中位产品模型给~0.2，实际~0.06
P 75        0.586       0.913    ← 前25%高风险产品模型准确
P 90        0.917       1.000    ← 前10%模型非常确定
P 95        0.917       1.000
P 99        0.917       1.000
```

**解读**：
- 模型在低分区域系统性**高估**风险（预测中位 0.198 vs 实际中位 0.063）
- 在高分区域非常准确（P75+ 预测分和实际分差距在 0.1 以内）
- P90 以上的预测值聚集在 0.917，说明模型对"极度濒死"产品的置信度有上限

**预测 vs 实际交叉表**（阈值 0.1/0.25/0.5 划分）：

```
预测↓ 实际→         低      中低     中高      高    合计
低风险(<0.1)       476      43      22       2     543  ← 只漏了2个严重
中低风险(0.1-0.25)  339      66      70      44     519
中高风险(0.25-0.5)  102      17      47     118     284
高风险(>0.5)        52       5      11     443     511  ← 443/511=87%精确
```

**关键问题**：426 个健康产品（低+中低）被预测为中高风险以上 → **误报集中在健康产品被高估**。

### 7.4 阈值选择与业务权衡

#### 各阈值表现

| 阈值 | 报警比例 | Precision | Recall | F1 | 误报率 |
|:---:|:-------:|:---------:|:-----:|:--:|:-----:|
| >0.10 | 70.8% | 46.0% | 99.7% | 0.630 | 56.7% |
| >0.20 | 49.9% | 62.7% | 95.7% | 0.758 | 27.6% |
| >0.30 | 37.8% | 76.8% | 88.8% | 0.824 | 13.0% |
| >0.35 | 34.2% | 80.9% | 84.7% | 0.828 | 9.7% |
| >0.40 | 30.6% | 84.0% | 78.6% | 0.812 | 7.3% |
| >0.50 | 27.5% | 86.7% | 73.0% | 0.792 | 5.4% |

#### 推荐阈值：>0.35

选择逻辑：F1 最高点（0.828），此时：
- **报警比例**: 34.2%（635/1857）
- **Precision**: 80.9%（报警的产品中 80.9% 确实会严重衰退）
- **Recall**: 84.7%（会严重衰退的产品中 84.7% 被模型抓住）
- **误报率**: 9.7%（所有不会严重衰退的产品中 9.7% 被误报警）

#### 业务权衡指南

| 如果目标 | 推荐阈值 | 代价 |
|:---------|:-------:|:-----|
| 尽量减少漏报（不能放走任何衰退产品） | >0.20 | 误报率 27.6%，需要投入更多精力甄别 |
| 平衡（推荐） | >0.35 | 误报率 9.7%，漏报率 15.3% |
| 尽量少误报（资源有限，只关注最确定的） | >0.50 | 漏报率 27%——会漏掉超过 1/4 的衰退 |

### 7.5 提前预警能力

#### 核心问题

> 模型是否能在产品**还没有明显衰退迹象时就提前发现**哪些会衰退？

#### 测试方法

1. 取 T 时刻 severity < 0.3 的产品（"健康"产品）
2. 用模型在 T 时刻打分
3. 看 T 时刻得分 > 0.35 的产品中，有多少在 T+1 时刻真的衰退了

#### 结果

| 指标 | 值 |
|:----|:--:|
| 健康产品中触发预警数 | 78 |
| 其中确实在下一时间点衰退的 | 15 |
| **提前预警精度** | **19.2%** |
| 健康产品总数 | ~968 |
| 触发率 | ~8% |

**结论：提前预警能力弱（r≈0.25）**。

模型无法可靠地在产品衰退之前就发现它。当产品看起来健康（severity<0.3）时，客户特征和产品特征都无法有效区分"哪个健康产品会下滑"。**客户特征的价值主要体现在"确认衰退"而非"预测衰退"**。

## 8. 与原始 v2.9 模型的对比

### 8.1 方法论对比

| 维度 | 原始 v2.9 (risk_scoring.py) | v5 (RandomForest) |
|:----|:---------------------------|:------------------|
| **建模方式** | 规则型阶梯函数（if-else 分档） | 数据驱动的随机森林回归 |
| **评分范围** | 离散值 10/20/40/50/70/80/90 | 连续值 [0, 1] |
| **特征数量** | 5 个（斜率/CV/衰减/SH/ASP） | 9 个（3产品+6客户） |
| **客户维度** | ❌ 无 | ✅ 6 个客户特征 |
| **标签** | 二值（是否"高风险"） | 连续（衰退严重度） |
| **调优方式** | 人工调阈值 + 网格搜索 | RandomForest 自动学习 |
| **验证** | K-fold CV（数据泄露） | Walk-forward 面板验证 |
| **解释性** | 每个因子的得分 | 特征重要性 + 触发原因 |
| **模型文件** | 阈值 JSON（~1KB） | pickle 模型（~3.5MB） |

### 8.2 修正的问题

1. **Ground Truth 标签对齐 Bug**：原始 pipeline 中，`compute_all_labels()` 在所有产品上计算标签，但后续只将 filter 过的产品子集 attach 回去。修复：确保使用的每一个样本都有一致的特征-标签对。

2. **Look-ahead 偏差**（最严重的 bug）：客户特征计算时，原始代码使用了时间点之后的数据来计算"距上次下单月数"等指标。例如：T=2024-02 计算 churn_rate 时用了截至 2024-08 的数据，等于看到了未来。修复：所有客户特征计算明确限制为 `<= T`。

3. **右删失 bias 识别**：2024-08 时间点的标签系统性偏低（只有 20 个月观察窗口，不足以判定"是否完全退出"），导致部分深度衰退产品被标记为"未衰退"。修复：连续标签缓解了这个问题（severity 不需要等到完全退出），但在 2024-08 点仍然可能低估。

4. **验证方式不严格**：K-fold CV 中同产品不同时间的样本跨训练/测试集。修复：Walk-forward 面板验证。

### 8.3 提高的方面

| 指标 | 原始 v2.9（最优调参） | v5（阈值>0.35） |
|:----|:--------------------:|:--------------:|
| **Precision** | 28.6% | **80.9%** |
| **Recall** | 4.3% | **84.7%** |
| **F1** | ~0.075 | **0.828** |
| **评分分辨率** | 5 档 | 连续 0~1 |
| **误报率** | ~71.4% | **9.7%** |
| **可操作性** | 只能给出分数 | 输出具体触发原因 |

**注意**：以上对比在不同标签定义上进行的——原始模型的目标是"50 分以上即为风险"，v5 的目标是"衰退严重度>0.5"。两者不完全等价，但数量级差距说明根本性改进。

## 10. 局限性与风险

### 10.1 已知局限

1. **decline_depth 主导（75%）**：模型本质上是延续性检测，不是真正的预测模型。对新产品（无历史峰值，decline_depth=0）会严重低估风险。

2. **提前预警能力弱**：无法在产品健康时可靠发现未来会衰退的产品。模型回答的是"这个产品目前在衰退中，会多严重？"而不是"哪个健康产品会开始衰退？"

3. **单客户产品不可预测**：单客户产品（占 30%）的衰退完全取决于这个客户的行为，而客户的采购决策受市场、合约等多因素影响，难以用历史数据预测。

4. **右删失未完全解决**：2024-08 点的标签可能仍被低估。如果业务继续运行，半年后回刷数据会发现部分"未衰退"产品最终也衰退了。

5. **面板样本不独立**：同产品在不同时间点的样本存在自相关（AR-1 结构）。虽然 Walk-forward 避免了未来信息，但不同时间点的产品关联会导致标准误差被低估。

### 10.2 部署风险

1. **模型解释性**：业务方习惯了"50 分以上高风险"的简单规则，改为 0~1 连续值需要沟通成本。建议在评分旁边附带 `get_risk_triggers()` 的输出。

2. **阈值需要业务对齐**：推荐的 0.35 阈值基于 F1 优化，实际应用时可能需要调整。建议：
   - 第一阶段：**并行运行新/旧模型**，输出两套结果对比
   - 第二阶段：**差异分析**——v5 报警但旧模型不报的，逐一核查
   - 第三阶段：**确定业务可接受的误报率**后，锁定阈值

3. **模型需要定期重训**：
   - 6 个月/次重新跑 `redesign_v5.py` 更新 `v5_rf_model.pkl`
   - 原因是行业和市场环境变化会导致特征-衰退的关系变化
   - 非参数模型（RF）不会遗忘旧数据，但需要新数据来适应新模式

4. **数据质量要求**：
   - 客户编号不能是脏数据（"0"、""、"NaN"等），否则客户特征计算错误
   - 产品名称必须一致（同一产品的名称不能在不同月份有变化）
   - `原数据中 ~1.2% 的客户编号是疑似脏数据`，需要 ETL 时清洗

### 10.3 未来改进方向

1. **转为早预警模型**：将目标改为 "T+1 时间点的 severity > 0.5" 的二值分类，重新训练。v5 的旁路测试显示客户特征在分类任务中重要性可达 35%。

2. **新产品的风险估计**：针对月龄 <24 个月的新产品，建立单独的小样本模型（或启发式规则），不依赖 decline_depth。

3. **引入外部数据**：半导体行业的景气度指数、下游需求预测、客户财务健康度（如果可用）。

4. **时间序列结构**：当前模型把每个时间点视为独立样本。更好的方式是用 LSTM/Transformer 直接建模序列结构，但需要更多数据点。
