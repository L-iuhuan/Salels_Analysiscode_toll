# 实验 0.0.6: 层级准入诊断

## 元信息
- 日期: 2026-06-12
- 数据版本: output/silver/silver_cleaned_rows.csv (329,644行, 2020-01至2026-05)
- 前置实验: 0.2 基线锁定 ✅, 0.3 生命周期对齐 ✅
- 方案版本: v1.4补丁

## 实验假设
不同产品线适合不同预测层级。在进入Phase 1实验前，必须明确每条产品线在哪些层级上有足够的数据支撑，避免在稀疏/无效层级上浪费计算资源或产生误导性结果。

## 实验设计

### 层级启用规则

| 层级 | 启用条件 |
|---|---|
| 产品线×季度 | 默认启用 |
| 产品线×月度 | 最近36个月有效月份≥18，零月份占比<60% |
| 品类×月度 | 产品线内品类数≥2，至少2个品类有≥6个有效月份，品类缺失率低，品类不跨产品线 |
| SKU×月度 | 有效月数≥6或非零月数≥4的SKU数≥3，头部SKU覆盖销售额≥70% |
| 产品×客户 | 头部客户/SKU组合有效月数≥6 |
| 客户层级 | 2024+缺失率=0，仅使用终端客户名称_客户类别，禁止客户分析系统评分 |

### 数据来源
- silver_cleaned_rows.csv
- 字段: 发货日期, 型号_产品线（新）, 型号_产品品类, 存货编码, 终端客户名称_客户类别, 出货总金额

### 注意事项
- `产品系列`和`存货名称`列在silver层被删除，使用`型号_产品品类`作为品类键，`存货编码`作为SKU键
- 客户层级仅检查2024+缺失率，不检查全历史

## 关键发现

1. **品类层可用性最低**: 仅53%产品线可用，主要原因是小产品线品类数不足或品类过稀疏
2. **SKU层可用性中等**: 76%产品线可用，4条线SKU过少
3. **客户层级全部可用**: 2024+数据完整，可用于当前预测
4. **PMIC是唯一严重受限线**: 仅2个层级可用，月度/品类/SKU/产品×客户全部不可用
5. **A类产品线层级选择最丰富**: 6条A类线中5条全部层级可用

## 结论

层级准入诊断完成。17条产品线均有明确的层级白名单，可作为Phase 1实验1.0的输入范围。建议：
- 实验1.0只对准入表标记为可用的层级运行
- PMIC作为特殊线单独处理
- 品类层仅对9条可用线运行
- 客户层级使用2024+数据
