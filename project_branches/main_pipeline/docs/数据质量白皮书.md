## 1. 数据规范说明

### 1.1 数据来源

系统接受单一 Excel 文件（`.xlsx`）作为输入，通常来自 ERP 系统的"所有的出货明细"导出。文件放置于 `data/` 目录下，系统自动检测并加载。

### 1.2 必填列

下列列必须在 Excel 中存在，否则系统无法运行：

| 列名                                  | 数据类型 | 说明           | 值范围/样例                      |
| ----------------------------------- | ---- | ------------ | --------------------------- |
| `客户编号`（或 ERP 原列名 `代理商/直供名称`）        | 文本   | 客户唯一标识       | 如 `CUST001`、`深圳市XX电子有限公司`   |
| `产品品种`（或 ERP 原列名 `存货名称`）            | 文本   | 产品 SKU/型号级标识 | 如 `LM358DR`、`STM32F103C8T6` |
| `数量`（或 ERP 原列名 `发货数量`）              | 数值   | 发货数量（含正负）    | 整数，正数=出货，负数=退货              |
| `金额(RMB未税)`（或 ERP 原列名 `RMB 未税金额小计`） | 数值   | 未税金额（人民币）    | ≥0，单位：元                     |
| `发货日期`（或 ERP 原列名 `发货日期`）            | 日期   | 发货日期         | `YYYY-MM-DD` 格式             |

### 1.3 可选列（强烈建议提供）

| 列名                         | 数据类型  | 说明     | 价值                 |
| -------------------------- | ----- | ------ | ------------------ |
| `利润`（或 ERP 原列名 `利润`）       | 数值    | 未税利润   | ⭐ 客户评分、真实利润估算的核心输入 |
| `成本`（或 ERP 原列名 `成本`）       | 数值    | 未税成本   | ⭐ 毛利率计算的备用来源       |
| `单价`（或 ERP 原列名 `未税单价`）     | 数值    | 单一单位价格 | ⭐ 价格离散度、定价建议分析     |
| `产品一级分类`（或 ERP 原列名 `产品线`）  | 文本    | 产品大类   | 品类分析、产品生命周期分析      |
| `产品二级分类`（或 ERP 原列名 `产品系列`） | 文本    | 产品细分系列 | 品类深度分析             |
| `是否新品`（或 ERP 原列名 `是否新品`）   | 布尔/文本 | 新品标记   | 新品渗透率、客户新品接受度分析    |
| `渠道类型`                     | 文本    | 直销/代理  | 渠道差异化评分、权重分配       |
| `客户等级`                     | 文本    | 客户等级   | 客户分层分析             |

### 1.4 可选工作表：客户信息表

如果 Excel 中包含名为 `客户信息表` 的工作表，系统会读取以下列：

| 列名      | 说明            | 样例                 |
| ------- | ------------- | ------------------ |
| `客户编号`  | 与主表 `客户编号` 对应 | `CUST001`          |
| `渠道类型`  | 直销/代理         | `直供` / `代理`        |
| `客户等级`  | 客户等级          | `A` / `B` / `C`    |
| `所属区域`  | 销售区域          | `华南` / `华东` / `华北` |
| `业务负责人` | 负责该客户的销售      | `张三`               |

> **注意**: 如果缺少此工作表，渠道类型将通过交易数据规则推导（三级降级策略：客户信息表 → 交易数据推导 → 未知），客户等级和区域信息无法获取，影响渠道差异化分析和客户分层分析。

### 1.5 数据规范一览

| 规范项       | 要求                                    |
| --------- | ------------------------------------- |
| 文件格式      | `.xlsx`（Excel Open XML 格式）            |
| 文件数量      | `data/` 目录下 **仅放置一个** `.xlsx` 文件      |
| 编码（CSV输出） | UTF-8 with BOM（`utf-8-sig`）           |
| 工作表名称     | 主表无要求（自动检测第一个包含数据的表），客户信息表固定为 `客户信息表` |
| 表格结构      | 第一行为列标题，后续为数据行                        |
| 日期格式      | `YYYY-MM-DD` 或 Excel 日期序列值            |
| 空值表示      | 留空单元格，不要写 `NULL` / `N/A` / `-`        |

## 2. 数据交付前检查清单

准备 Excel 文件时，请逐项核对以下事项：

### 2.1 基础检查

* [ ] `data/` 目录下 **只有一个** `.xlsx` 文件（多个文件会导致系统不确定用哪个）

* [ ] Excel 文件不是正在编辑或损坏的状态（可以正常打开）

* [ ] 第一行是列标题，没有合并单元格

* [ ] 没有冻结窗格或分组折叠（不影响读取但可能导致误解）

### 2.2 列完整性

* [ ] **5个必填列**全部存在且列名完全匹配

* [ ] `利润` 列存在（强烈推荐，否则无法进行客户价值评分和真实利润分析）

* [ ] `产品一级分类` / `产品二级分类` 列存在（支持品类分析）

* [ ] `是否新品` 列存在（支持新品渗透分析）

* [ ] 存在 `客户信息表` 工作表（支持渠道识别和客户分层）

### 2.3 数据值检查

* [ ] `数量` 列：数值正常，无异常大/小值

* [ ] `金额(RMB未税)` 列：**没有金额为0但数量为正的行**（样品单未标记）

* [ ] `利润` 列：确认亏损记录的含义——是真实亏损还是数据录入错误？

* [ ] `发货日期`：日期格式统一，没有未来的日期，没有早于预期起始日期的数据

* [ ] 所有文本列（客户编号、产品品种等）：**没有前导/尾部空格**，**没有连续多个空格**

* [ ] 所有列名：**没有前导/尾部空格**，**没有多余空格**

### 2.4 高级检查

* [ ] `利润` 和 `金额` 的比值（毛利率）没有极端值（超出 -50%\~+75% 的毛利率应核实）

* [ ] `产品等级` / `产品结构` 等字段（如果存在）填充率 > 50%（否则系统无法使用）

* [ ] 确认所有退货记录（数量为负的行）的金额和利润是否已正确冲减

* [ ] 确认 ERP 列名未因系统升级/版本变更而改变

### 2.5 文件交付确认

* [ ] 文件名包含数据时间范围，如 `出货明细_2024Q1.xlsx`

* [ ] **不要**在 `data/` 目录中放置历史版本的备份文件

* [ ] **不要**在 `data/` 目录中放置其他无关的 Excel 文件

* [ ] 如果 ERP 列名与历史版本不同，请同步通知技术团队更新 `ERP_COL_MAP` 配置

## 3. 常见问题与修复方案

### 3.1 金额为零但数量为正 — 样品单未标记

**现象**: 数量 > 0，但 `金额(RMB未税)` = 0。\
**实际数据占比**: 约 0.36% 的行。\
**原因**: 免费样品发货时录入数量但不录入金额，且未标记为样品单。

**影响**:

* 拉低客户平均单价

* 干扰毛利率计算（金额为0时分母为零）

* 样品费用未被正确归类，影响成本分析

**解决方案**:

| 优先级 | 措施                         | 责任方    |
| --- | -------------------------- | ------ |
| ★★★ | 在 ERP 中为样品出库增加"样品单"标志字段    | ERP 运维 |
| ★★☆ | 导出前手动筛选零金额行，补充标记           | 数据提供方  |
| ★☆☆ | 系统侧已实现自动识别和标记（Z分数法），但准确性有限 | 系统侧已处理 |

### 3.2 正数量负利润 — 亏损交易无解释

**现象**: 数量 > 0，利润 < 0。\
**实际数据占比**: 约 5.52% 的行（样本中 2761/50000 行），涉及亏损总额约 465 万元。\
**原因**: 可能是真实亏损（低价竞争、清库存），也可能是数据录入错误（成本核算不准、利润计算有误）。

**影响**:

* 严重影响客户评分（利润是核心维度）

* 导致特定客户/产品出现异常低甚至为负的毛利率

* 真实利润估算会大幅偏离

**解决方案**:

| 优先级 | 措施                           | 责任方    |
| --- | ---------------------------- | ------ |
| ★★★ | 与财务/销售确认亏损记录的真实性             | 数据提供方  |
| ★★☆ | 在 ERP 导出时增加"亏损原因"备注字段        | ERP 运维 |
| ★★☆ | 区分"策略性亏损"（如开拓市场）和"录入错误"      | 数据提供方  |
| ★☆☆ | 系统侧毛利率钳制在 -50%\~+75%，减少极端值影响 | 系统侧已处理 |

### 3.3 毛利率超过 75% — 疑似样品或价格异常

**现象**: 毛利率 > 75%（毛利率 = 利润 ÷ 金额）。\
**实际数据占比**: 约 1.55% 的行（774/50000 行）。\
**原因**: 可能是样品单（成本极低或为零）、测试单、或价格录入异常。

**影响**:

* 拉高客户/产品的平均毛利率，导致业绩虚高

* 干扰定价建议（基于市场中位价计算）

* 影响产品生命周期阶段的判断

**解决方案**:

| 优先级 | 措施                             | 责任方    |
| --- | ------------------------------ | ------ |
| ★★★ | 核实此类交易的性质，确认是否为正常销售            | 数据提供方  |
| ★★☆ | 样品/测试单在导出前标记清楚                 | 数据提供方  |
| ★☆☆ | 系统侧已做毛利率 Winsorization 钳制到 75% | 系统侧已处理 |

### 3.4 文本列中存在多余空格

**现象**: 客户名称、产品名称等字段有前导空格、尾部空格或连续多个空格。\
**实际数据占比**: 72 行有前导/尾部空格，40 行有连续多个空格。\
**原因**: Excel 输入不规范、ERP 文本字段未做 trim、数据从其他系统迁移残留。

**影响**:

* 导致同一个客户/产品被识别为两个不同实体（如 `"华为"` 和 `" 华为"`）

* 客户合并分析出错，采购频次和金额统计偏小

* 报表中出现"重复"客户

**解决方案**:

| 优先级 | 措施                            | 责任方    |
| --- | ----------------------------- | ------ |
| ★★★ | 导出前在 ERP 中清理文本字段，使用 TRIM 函数处理 | 数据提供方  |
| ★★☆ | 切换 ERP 版本后核对客户主数据的空格情况        | 数据提供方  |
| ★☆☆ | 系统侧清洗时会自动 strip 空格和合并连续空格     | 系统侧已处理 |

> **注意**: 系统侧虽会清理，但**在 ERP 源头解决**才是根本。源头解决后，客户编号与 CRM 系统的匹配会更准确。

### 3.5 关键列大面积为空

**现象**: 某些列绝大部分行没有数据。\
**实际数据示例**:

| 列名             | 空值率   | 判定       |
| -------------- | ----- | -------- |
| `产品等级`         | 93.9% | ⚠️ 基本不可用 |
| `产品结构`         | 100%  | ❌ 完全不可用  |
| `客户等级`（来自 CRM） | 85.5% | ⚠️ 基本不可用 |

**原因**: ERP 中未启用这些字段、CRM 与 ERP 未打通、导出时未包含相关列。

**影响**:

* 产品等级：产品生命周期分析无法按等级分层

* 产品结构：无法区分成品/半成品/原材料

* 客户等级：客户分层分析缺失 CRM 维度的输入

**解决方案**:

| 优先级 | 措施                          | 责任方        |
| --- | --------------------------- | ---------- |
| ★★★ | 确认 ERP 中哪些字段有数据，选择有实质内容的列导出 | 数据提供方      |
| ★★☆ | 如果 ERP 中确实没有这些数据，考虑从 CRM 补充 | 数据提供方 + IT |
| ★☆☆ | 系统侧会自动跳过空值率 > 90% 的列，不影响主流程 | 系统侧已处理     |

### 3.6 客户信息表缺失

**现象**: Excel 文件中没有 `客户信息表` 工作表。\
**实际数据情况**: 常见问题，约一半的数据交付缺失此表。\
**原因**: 数据提供方未意识到需要此表，或 CRM 数据无法导出。

**影响**:

* `渠道类型` 通过交易数据规则推导（三级降级策略回退到第2层）

* `客户等级`、`所属区域`、`业务负责人` 无法获取

* 渠道差异化评分无法进行（使用代理模式默认权重）

* 客户分层分析缺少区域维度

**解决方案**:

| 优先级 | 措施                                               | 责任方    |
| --- | ------------------------------------------------ | ------ |
| ★★★ | 在 Excel 中增加 `客户信息表` 工作表                          | 数据提供方  |
| ★★★ | 确保 `客户编号` 列与主表一致（可多对一）                           | 数据提供方  |
| ★★☆ | 如 CRM 无法导出，手动整理关键字段（至少包含渠道类型）                    | 数据提供方  |
| ★☆☆ | 系统侧使用三级降级策略推导渠道：①客户信息表 ②交易数据规则推导 ③未知（准确率 70-80%） | 系统侧已处理 |

### 3.7 ERP 列名变更

**现象**: 由于 ERP 系统升级、版本切换或用户自定义设置变更，导出文件的列名与预期不同。\
**原因**: `_derive_channel` 函数使用硬编码的原始 ERP 列名（如 `"代理商/直供名称"`、`"实际终端客户"`），列名变化会导致该函数返回空值。

**影响**:

* 渠道推导失败，所有客户渠道类型变为空

* 系统可能检测不到错误（静默失败）

* 客户评分中渠道权重分配使用默认值（代理模式权重）

**解决方案**:

| 优先级 | 措施                                                          | 责任方    |
| --- | ----------------------------------------------------------- | ------ |
| ★★★ | ERP 导出前检查列名是否与历史版本一致                                        | 数据提供方  |
| ★★★ | 列名有变化时，**必须**通知技术团队更新 `config/settings.py` 中的 `ERP_COL_MAP` | 数据提供方  |
| ★☆☆ | 系统侧未来可增加列名校验和自动告警                                           | 系统侧规划中 |

### 3.8 多个 Excel 文件导致加载混乱

**现象**: `data/` 目录下存在多个 `.xlsx` 文件。\
**原因**: 历史数据备份未清理、同一个目录放了多期数据、测试文件和正式文件混放。\
**后果**:

| 组件                            | 选择策略              | 可能选错     |
| ----------------------------- | ----------------- | -------- |
| 主管道（`run_all.py`）             | 按文件名**字母序**选择第一个  | 可能选了旧文件  |
| 测试框架（`test/run_all_tests.py`） | 按文件名**字母序**选择最后一个 | 可能选了备份文件 |

**解决方案**:

| 优先级 | 措施                                          | 责任方   |
| --- | ------------------------------------------- | ----- |
| ★★★ | `data/` 目录下仅保留**一个**当前要分析的 `.xlsx` 文件       | 数据提供方 |
| ★★☆ | 历史数据移至其他目录（如 `data/archive/`）               | 数据提供方 |
| ★☆☆ | 使用 `--data` / `--file` 参数显式指定文件路径（但依赖命令行操作） | 系统侧可选 |

## 5. 数据质量规则引擎

系统在数据处理过程中自动执行以下质量规则。了解这些规则有助于理解数据为何"变了"。

### 5.1 清洗规则（自动执行）

| 规则                    | 触发条件         | 处理方式              | 可配置参数                |
| --------------------- | ------------ | ----------------- | -------------------- |
| 毛利率 Winsorization（下限） | 毛利率 < -50%   | 钳制到 -50%          | `winsor_lower`       |
| 毛利率 Winsorization（上限） | 毛利率 > 75%    | 钳制到 75%           | `winsor_upper`       |
| 样品单标记                 | 金额为零但数量为正    | 标记为"疑似样品单"        | `sample_z_threshold` |
| 文本空格清理                | 文本列有前导/尾部空格  | 自动 `strip()` 去除   | 固定执行                 |
| 连续空格合并                | 文本列有 2+ 连续空格 | 合并为 1 个空格         | 固定执行                 |
| 空值列跳过                 | 列空值率 > 90%   | 自动从分析中排除          | 固定执行                 |
| 日期格式标准化               | 各种日期格式       | 统一转为 `YYYY-MM-DD` | 固定执行                 |
| 编码处理                  | CSV 输出       | 写入 UTF-8 with BOM | 固定执行                 |

### 5.2 校验规则（执行并报告）

| 校验项      | 检测内容         | 严重程度  | 后续处理         |
| -------- | ------------ | ----- | ------------ |
| 必填列存在性   | 5个必填列是否存在    | 🔴 错误 | 缺少必填列则终止流程   |
| 列数据类型    | 数值列是否可转为数字   | 🔴 错误 | 转换失败的行被剔除    |
| 数量正负号    | 数量为负是否对应退货   | 🟡 警告 | 保留记录，影响计算    |
| 金额-利润一致性 | 金额为0时利润是否也为0 | 🟡 警告 | 保留记录，标记关注    |
| 客户编号规范性  | 客户编号是否含特殊字符  | 🟡 警告 | 自动清理，记录变更    |
| 日期合理性    | 是否在未来/过于久远   | 🟡 警告 | 超出分析窗口的行被过滤  |
| 重复行检测    | 完全相同的行是否存在   | 🟡 警告 | 保留第一条，其余标记重复 |
| 客户信息表一致性 | 客户编号是否与主表匹配  | 🟡 警告 | 无法匹配的客户信息丢弃  |

### 5.3 渠道类型推导规则（三级降级策略）

当客户信息表缺失或其中渠道类型列为空时，系统采用三级降级策略推导渠道类型（优先级从高到低）：

**第1层 — 客户信息表渠道类型列（最优先）**
如果 Excel 中包含 `客户信息表` 工作表且其中有 `渠道类型` 列，则直接使用该列的值。

**第2层 — 交易数据规则推导**
使用 `_derive_channel` 函数分析交易数据中的原始 ERP 列名（`"代理商/直供名称"`、`"实际终端客户"`）：

* 客户编号只出现在 `"代理商/直供名称"` 列 → 渠道类型 = "代理"

* 客户编号只出现在 `"实际终端客户"` 列 → 渠道类型 = "直供"

* 同时出现在两列 → 比较出现次数，终端出现次数 ≥ 代理出现次数则为"直供"，否则为"代理"

* 两列均无此客户编号 → 进入第3层

**第3层 — 未知（所有条件不满足时）**
所有条件不满足时，渠道类型标记为 `"未知"`。

> ⚠️ **局限**: 第2层推导准确率约 70-80%，部分直供客户因 ERP 中未填写"实际终端客户"列会被误判为代理。提供客户信息表（第1层）可提升准确率至 99%。

## 6. 质量问题对分析输出的影响

了解每个数据质量问题如何传导到最终的分析报告，帮助您判断优先级。

### 6.1 影响传导矩阵

| 数据问题        | → 影响中间数据 | → 影响最终输出                              |
| ----------- | -------- | ------------------------------------- |
| 利润为负未核实     | 客户毛利率偏低  | ⭐ **客户评分偏差**：利润维度的分值偏低，可能错误地将优质客户评为低分 |
| <br />      | 产品毛利率异常  | ⭐ **定价建议偏差**：基于中位价的提价/降价建议不准确         |
| <br />      | 真实利润估算偏小 | ⭐ **企业规划决策**：基于真实利润的资源配置可能出错          |
| 样品单未标记      | 零金额行参与计算 | ⭐ **平均单价偏低**：客户和产品的平均价格偏低             |
| <br />      | 毛利率无法计算  | ⭐ **毛利率统计失真**：分母为零时被排除，样本有偏           |
| 文本列空格       | 同一实体被拆分  | ⭐ **客户数量虚增**：同一客户显示为多个                |
| <br />      | 聚合分析偏小   | ⭐ **采购频次/金额统计偏低**：子集数据不完整             |
| 客户信息表缺失     | 渠道未知     | ⭐ **评分权重错误**：RFM-π 权重使用代理默认值而非真实的直供权重 |
| <br />      | 无区域信息    | ⭐ **区域分析缺失**：无法按区域统计客户分布              |
| 产品等级/结构空    | 产品无法分层   | ⭐ **产品生命周期分析受限**：无法按等级分层分析            |
| 列名变更        | 系统读取失败   | ❌ **系统中断**：列映射失败，建议终止流程并更新配置          |
| 多个 Excel 文件 | 系统加载错误文件 | ❌ **分析结果完全错误**：基于错误数据得出误导性结论          |

### 6.2 严重性分级

| 严重程度      | 导致结果         | 典型问题                   |
| --------- | ------------ | ---------------------- |
| 🔴 **严重** | 分析结论完全错误     | 多个 Excel 文件、列名变更、必填列缺失 |
| 🟠 **高**  | 核心指标偏差 > 10% | 利润大面积异常、客户信息表缺失        |
| 🟡 **中**  | 部分分析维度失效     | 产品等级空置、样品单未标记          |
| 🟢 **低**  | < 5% 的微小偏差   | 少量文本空格、少量零值金额          |

## 7. 数据提供最佳实践

### 7.1 数据准备流程

```
每月/每季度数据导出
        │
        ▼
  步骤1: 确认 ERP 列名与上次一致
        │
        ▼
  步骤2: 从 ERP 导出"所有的出货明细"
        │
        ▼
  步骤3: 从 CRM 导出客户信息表（含渠道/等级/区域）
        │
        ▼
  步骤4: 将客户信息表作为独立工作表放入同一个 Excel 文件
        │
        ▼
  步骤5: 执行"数据交付前检查清单"（见第2章）
        │
        ▼
  步骤6: 将文件放入 data/ 目录（确保仅有这一个 .xlsx 文件）
```

### 7.2 关键实操建议

#### ① 利润数据务必核实

利润是客户评分和定价建议的核心输入。对于亏损交易（利润为负）：

* **建议做法**: 导出前与财务/销售确认亏损原因

* **可操作性分类**:

  * **策略性亏损**: 开拓市场、打入新客户的低价策略 → 保留，分析时会识别为"战略性投入"

  * **清库存亏损**: 处理呆滞库存 → 保留，产品生命周期分析会标记为衰退期

  * **数据错误**: 成本核算有误、价格录入错误 → **必须修正后再导出**

* **判断方法**: 如果某客户/产品的亏损集中在特定时段且毛利率波动剧烈，疑似数据错误可能性大

#### ② 客户信息表优先提供

提供 `客户信息表` 工作表是**投入产出比最高**的提升措施：

| 项目    | 无客户信息表                 | 有客户信息表               |
| ----- | ---------------------- | -------------------- |
| 渠道类型  | 三级降级策略：交易数据推导（准确率 70%） | 精确匹配 CRM 数据（准确率 99%） |
| 客户等级  | 不可用（评分缺失此维度）           | CRM 等级直接映射           |
| 区域分析  | 不可用                    | 可按华南/华东/华北等区域分析      |
| 业务负责人 | 不可用                    | 可按销售个人统计业绩           |

**客户信息表格式要求**:

```
客户编号 | 渠道类型 | 客户等级 | 所属区域 | 业务负责人
C001    | 直供     | A       | 华南     | 张三
C002    | 代理     | B       | 华东     | 李四
```

#### ③ 样品单独做标记

如果 ERP 中有"样品单"字段，导出时务必包含该列。如果没有：

* 在 ERP 中为样品出库增设标记功能

* 或导出后手动补充标记

* 最不济：系统会自动识别，但会有误判

#### ④ 控制 data/ 目录的洁净度

```
✅ 正确:
  data/
  └── 出货明细_2026Q1.xlsx

❌ 错误:
  data/
  ├── 出货明细_2026Q1.xlsx
  ├── 出货明细_2025Q4.xlsx      ← 备份文件未清理
  ├── 测试数据.xlsx              ← 无关文件
  └── 客户信息表_旧版.xlsx        ← 无关文件
```

#### ⑤ 列名变更时及时通知

ERP 升级或版本切换后，导出列名可能变化。**在切换后的第一次数据交付时**，请：

1. 对比新旧版本的列名差异
2. 将差异列表同步给技术团队
3. 技术团队更新 `config/settings.py` 中的 `ERP_COL_MAP`
4. 数据提供方按新列名导出数据

#### ⑥ 定期检查数据健康度

建议每次数据交付前，在 Excel 中快速自查：

```excel
# 快速检查公式（在 Excel 中执行）
=COUNTBLANK(A:A)              → 检查某列空值数
=SUMIF(B:B,">0",C:C)         → 计算数量>0但金额为0的行
=SUMIF(D:D,"<0",B:B)          → 利润为负的记录数
=IF(LEFT(A2,1)=" ","有前导空格","")  → 检查前导空格
```

### 7.3 不同场景的数据优先级

| 分析场景    | 最关键的列           | 备选方案          |
| ------- | --------------- | ------------- |
| 客户价值评分  | 金额、利润、客户编号      | 无利润时系统用金额代理   |
| 客户生命周期  | 发货日期、金额、客户编号    | —             |
| 产品生命周期  | 产品品种、数量、金额、发货日期 | —             |
| 定价建议    | 单价、金额、利润、产品品种   | 无单价时金额/数量推导   |
| 新品分析    | 是否新品、金额、客户编号    | 无可用的自动备选      |
| 区域/渠道分析 | 客户信息表、客户编号      | 无渠道信息表时使用规则推导 |
| 集团聚合分析  | 客户编号、金额、利润      | —             |

### 7.4 数据版本命名规范

建议使用以下命名格式，便于识别和管理：

```
{数据源}_{时间范围}_{版本}.xlsx
```

**示例**:

* `出货明细_2026Q1_v1.xlsx` — 2026年第一季度数据（第一版）

* `出货明细_202601-202604.xlsx` — 2026年1月至4月数据

* `出货明细_2026年5月更新.xlsx` — 2026年5月最新导出

**注意**: 放置到 `data/` 时，确保只需一个文件，删除旧的备份。
