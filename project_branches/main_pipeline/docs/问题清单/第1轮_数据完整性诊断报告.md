## 5. 降级/回退链路分析

### 降级路径1：渠道类型推导
```
原始Excel无"客户信息表" → CRM渠道字段缺失
  ↓
交易数据推导(代理商/直供名称 vs 实际终端客户)
  ↓
匹配失败的客户 → 渠道类型="未知"
  ↓
RFM-π评分中"未知"渠道使用默认权重(代理等权)
```

### 降级路径2：新品判定
```
"是否新品"列缺失/全空 → is_new自动计算
  ↓
按首次销售月≤12月判定
  ↓
如果数据起始点偏移则引入误判
```

### 降级路径3：产品风险评分
```
产品历史数据<3个月 → 跳过斜率计算
  ↓
斜率/CV/衰减/健康/ASP → 全部NaN
  ↓
综合风险评分缺失 → 产品无风险评级
  ↓
后续9宫格策略 → 这些产品降级到"观察"类
```

## 7. 待深挖线索（下一轮）

1. **客户分析start_date=2024-01-01**：这是否为有意为之（仅分析近2年活跃客户）还是疏忽？如果是有意的，"growth_window_months=12"要求12个月对比窗口，2024-01至今2026-04共28个月，足够。但会丢失客户早期行为模式。

2. **161个无风险评分产品**的具体特征：是新品（数据不足）还是退市产品？分析这些产品的时间分布、阶段分布。

3. **负利润交易的行业合理性**：5.52%的亏损交易比例在半导体行业是否正常？这些是否对应特定产品线、特定客户、特定时间段？

4. **渠道推导精度**：仅靠交易数据推导渠道（代理商/直供名称 列）的准确率如何？与"所有的终端客户.xlsx"(2.7MB)交叉验证。

5. **产品画像中20.3%缺失率是否为正常水平**：这些缺失产品是否集中在特定品类？是否导致数据偏离？

6. **"是否新品"列的真实覆盖率**：需从原始Excel读取该列的空值率，判断自动计算的触发频率。

7. **Config一致性深度检查**：product_lifecycle和customer_analysis的阈值是否存在相互矛盾（如新品月数：6 vs 12）。

8. **产品一级分类在cross_reference中的可用性**：目前传递到customer_x_product表，但空值率待确认。
