# 通用数据科学分析技能 — DS³ 框架

> **设计目标**：在任何数据分析任务中，遵循"理解需求→解构数据→提出假设→辩证验证→解释提炼→分层交付"的工作流，输出专业且通俗的分析结论。

## 触发条件

当用户请求以下类型的任务时，自动加载此技能：

- "帮我分析一下这些数据"
- "优化这个评分/决策模型"
- "看看XX和YY之间有没有关系"
- "这个结论数据上靠得住吗"
- 任何涉及**统计检验、相关性分析、显著性判断、模型优化、评分卡设计**的任务

---

## 核心思维模式（必须内化）

### 三大原则

1. **先问为什么，再算怎么做**：没搞清楚业务目标就动手分析，9成概率在浪费时间。
2. **不证明"正确"，只证伪"不成立"**：统计的意义在于排除巧合，不是给拍脑袋找证据。对每个发现，同时寻找反驳它的信号。
3. **显著 ≠ 有价值**：p<0.01 不代表这个发现对业务有用。问自己："这个结论能让人做出之前不会做的决策吗？"

### 辩证检查点（每个阶段结束时自检）

- 有没有我忽略了的重要变量？
- 如果结论是反的，数据能不能同样支持？
- 换一个子样本，结论还在吗？
- 这个发现是"显然"的（换个人也能猜到），还是"非显然"的（需要数据才能发现）？

## 阶段 0：需求拷问与数据校准

### 不可跳过
此阶段如果跳过，后续所有分析都可能方向错误。宁可多花时间在这里，也不要后期返工。

### AI 必须主动提出的问题

**① 业务目标澄清**
- 这个分析最终要预测/反映/判断的真实业务结果是什么？
  - *例：客户是否会复购？供应商是否准时？订单利润是否达标？产品是否进入衰退？*
- 这个目标在数据中对应哪一列？值的含义是什么？（0/1？连续值？分档？）
- 结论的使用者是谁？（做战略决策的高管？做日常运营的经理？写代码的工程师？）

**② 现有模型/规则定义**（如果有）
- 请给出当前评分/判断模型的计算逻辑（文字、Excel公式、Python代码、SQL均可）
- 模型中用到了哪些原始数据列？各自代表什么业务含义？
- 如果有权重和分层阈值，请一并提供。

**③ 数据基本情况**
- 数据表大致多少行、多少列？时间跨度？粒度？（一行=一次交易/一个客户/一天？）
- 是否有已知的缺失、异常、或数据采集方式变更？

**④ 评价标准**
- 怎样算"分析成功"？AUC提升多少？分类准确率提高？还是发现一个可用的业务洞见？
- 有没有必须保留的业务约束？（例：某个因子权重不能为负、分层不能超过5档）

**⑤ 期望的输出形式**
- 需要最终生成新公式、新权重，还是只要分析报告和建议？
- 是否要求可执行代码（Python/SQL）？
- 输出需要多通俗？（给CEO看 vs 给数据团队看）

### AI 必须做的事
- **用自己的话复述一遍理解**，让用户确认是否正确
- 如果数据路径、列名、目标定义有任何模糊，**不猜测，直接追问**
- 给出本次分析的**范围声明**："本次分析将聚焦____，不包括____"

## 阶段 1：数据探索与因子复现

### AI 必须做的事
1. **读取数据**，报告基本统计：
   - 行列数、时间范围、缺失比例
   - 各列的数据类型、取值范围
   - 目标变量的分布（分类问题：正负样本比例；回归问题：均值/方差/偏度）

2. **按用户提供的公式计算每个因子**（如果有现有模型）
   - 确保计算结果与用户预期一致
   - 自动检测并报告：
     - 因子缺失率（>20% 标 ⚠️，>50% 标 ❌）
     - 异常值（如除零、负值不合理、极端值）
     - 因子之间的相关性矩阵（若两个因子 |r|>0.8，标注为"高度冗余"）

3. **输出"数据健康检查报告"**，用直观符号表示：
   - ✅ 正常
   - ⚠️ 需关注（如缺失 10-20%）
   - ❌ 严重问题（如缺失 >50%、计算逻辑有误）

### 必须输出的人话
- "你的数据有15275条记录，时间从2020年1月到2025年6月。其中29.7%的产品出现了衰退（正样本），这个比例适中，模型有足够的信号学习。"
- "你的五个因子中，毛利率斜率和订货CV相关性只有0.04，说明它们测量的是完全不同的东西，组合使用是有价值的；但毛利率斜率和ASP趋势相关性0.68，可能部分重叠。"

---

## 阶段 2：候选因子生成

### AI 必须做的事
**仅当用户要求优化/改进模型时执行。** 如果用户只是要理解现状，跳过此阶段。

对用户模型中的每个业务维度，尝试生成变体（每族不超过10个，避免过度挖掘）：

| 原始指标 | 可能的变体 |
|----------|-----------|
| 增长率 | 近3月/近6月/近12月增长率、环比、同比、对数增长率 |
| 利润率 | 绝对值、历史分位、标准差、趋势斜率 |
| 波动性 | 标准差、变异系数(CV)、最大/最小比值、极差 |
| 频率 | 零值占比、连续非零次数、最后一次出现距今 |
| 集中度 | Top1/Top3占比、HHI指数、客户数量变化、流失率 |
| 趋势 | 线性回归斜率、移动平均、指数平滑、二阶导数(加速度) |

### 命名规范
所有变体使用标准命名：`{原始因子名}__{变体描述}`，如 `margin__3m_ma` 表示"毛利率3月移动平均"。

### 必须输出的人话
- "基于你的'增长率'指标，我生成了5个变体：近3月增长、近6月增长、增速变化（近期减远期）、连续增长月数、增长稳定性（标准差）。接下来我会逐个测试它们与目标的关系。"

---

## 阶段 3：因子有效性筛选（辩证验证）

### 这是整个框架的核心——区分"表面有效"和"真正有用"

### AI 必须做的事

**① 单因子区分度测试**
- 分类问题：计算每个候选因子的 AUC / KS / 信息值(IV)
- 回归问题：计算 Pearson/Spearman 相关系数
- 对每个因子做 **统计检验**（t检验、Mann-Whitney、χ²等，看数据类型）
- 报告 p 值

**② 多重检验校正**
- 如果一次测试 N 个因子，**必须做 FDR 校正**（Benjamini-Hochberg）
- 只保留校正后仍显著的因子
- 向用户解释："因为你一次测试了15个假设，约有15×5%=0.75个会是纯运气通过的。用了FDR校正后，我们只保留了9个真正有效的。"

**③ 正交性检查**（这步很多人跳过，但它是最重要的）
- 计算每个候选因子与**现有模型得分**的相关性
- 如果 |r|>0.3：该因子与现有模型高度重叠，增加它不会带来新信息
- 如果 |r|<0.1：该因子测量的是现有模型完全没覆盖的新维度——这才是最有价值的发现
- **优先推荐低相关 + 高区分度的因子**

**④ 增量测试**
- 用简单模型（逻辑回归/线性回归）测试：加入该因子后，验证集 AUC/R² 有多少提升？
- 提升 < 0.005 的因子，即使"显著"，也不推荐加入

### 必须输出的人话
- "毛利率斜率的 AUC 是 0.58，看起来还行，但它在 p=0.003 显著且与现有模型相关系数高达 0.68——这不是新发现，现有模型已经捕捉了这个信号。"
- "连续下跌月数 AUC 是 0.54，与现有模型相关系数只有 0.03——这才是真正的增量价值。它测量的是'跌了多久'，而现有模型只测量'跌了多少'，两者几乎正交。"
- "客户集中度 AUC 也是 0.54，但与现有模型相关系数 0.20，意味着 20% 的信息已经存在于现有评分中，增量价值有限。建议不优先采用。"

### ⚠️ 不要做的事情
- 不要同时丢几百个因子进模型"看谁活下来"——这叫 p-hacking
- 不要报告"p<0.05 的都用"——多重比较下这是错误的
- 不要只看显著性不看效应量——p<0.001 但效应量 0.1%，在业务上没有意义

## 阶段 4：权重与分层优化

### AI 必须做的事

**权重优化**
- 用筛选后的因子训练简单可解释模型（逻辑回归 / 线性回归 / 有序回归）
- 用验证集（时间序列数据用 TimeSeriesSplit）评估新旧权重表现
- 只有验证集 AUC/R² 明显提升（>0.01），才建议修改权重
- 若有业务约束（如某因子权重不能为负），在优化中强制执行

**分层合理性检验**
- 检验相邻档位（如"中风险 vs 高风险"）在真实目标上是否有显著差异
- 使用非参数检验（Mann-Whitney 或 Welch's t-test）
- 对两两比较做 **Bonferroni 校正**（因为同时做了多组比较）
- 若某两档无显著差异 → 建议合并
- 若某档内部差异很大 → 建议拆分

### 必须输出的人话
- "你的'中风险'和'高风险'档位，实际衰退率分别是12%和14%，统计检验 p=0.23——没有足够证据区分它们。建议合并成一个'需关注'档，减少执行困惑。"
- "优化后权重：增速衰减从0.20升到0.38——说明你的业务中，'增速是否在恶化'比'毛利率是否在降'更值得关注。"
- "ASP趋势权重降到0.01——不是因为价格不重要，而是因为在这个数据中，价格信号大多已被毛利率斜率捕获了。"

---

## 阶段 5：最终交付

### AI 必须两部分都输出

**【给业务同事看的一页纸】**

必须包含：
1. **一句话总结**：优化后模型预计能____（例：区分力提升 2.3%、多识别 150 个高风险产品）
2. **改了什么，为什么**：最多 3 条（例："新增了连续下跌月数，因为同样跌 20% 但跌了 4 个月的产品风险比只跌 1 个月的高 3 倍"）
3. **新规则（用中文描述）**：公式 + 分层逻辑
4. **什么情况下模型可能不准**：坦诚说明局限（例："该模型未考虑季节性因素，春节前后的数据波动可能被误判"）
5. **建议的下一步**：做什么、谁来做、什么时候

**【给技术人员/代码使用的附录】**

必须包含：
1. 详细统计表（AUC对比、各因子p值、置信区间、效应量）
2. 可直接复制的模型定义（Python/SQL/Excel公式）
3. 验证方法说明（用了什么交叉验证、多少折、什么指标）
4. 本次分析的局限（数据覆盖范围、未考虑的变量、样本量限制）
5. 建议的监控指标和重训练触发条件

## 工具与技能要求

### 必须掌握的统计方法
| 场景 | 方法 |
|------|------|
| 二分类区分度 | AUC-ROC、KS统计量、信息值(IV) |
| 连续变量关联 | Pearson相关系数、Spearman秩相关 |
| 组间均值差异 | t检验（方差齐性用Welch's）、Mann-Whitney U |
| 多重检验校正 | FDR（Benjamini-Hochberg）用于因子筛选；Bonferroni用于两两比较 |
| 参数优化 | Optuna / GridSearch + TimeSeriesSplit CV |
| 概率校准 | Isotonic Regression / Platt Scaling |
| 稳健性 | Monte Carlo参数扰动、情景压力测试 |
| 正交性 | 皮尔逊相关矩阵 + 增量AUC测试 |

### 必须掌握的基本原则
| 原则 | 含义 |
|------|------|
| 时间序列泄漏 | 绝对不能用未来信息预测过去。CV必须时间感知。 |
| 类不平衡 | 正样本<20%时必须报告并处理（SMOTE/加权/阈值调优） |
| p-hacking | 多重假设检验必须校正，不能"测到显著就用" |
| 过拟合 | 训练集AUC远高于验证集→模型记了噪音（>0.05差即报警） |
| 辛普森悖论 | 聚合后相关方向可能与分组相反，注意检查 |
| 协变量位移 | 数据分布变了模型还适用吗？定期监控PSI |

## 使用示例

**场景**：用户说"帮我看看这些供应商数据，有什么方法能预测谁可能延期交货"

AI（加载技能后）的回应模式：

> **阶段 0 启动**：在开始分析之前，我需要确认几件事：
>
> 1. "延期交货"在你的业务中具体怎么定义？是超过承诺日期 1 天就算，还是超过 3 天？
> 2. 这个结果在数据中有没有对应的列？
> 3. 你手上有什么数据？给我一个大概的描述（什么粒度、哪些字段、多久的历史）。
>
> 请先回答这些，然后我可以设计具体分析方案。
