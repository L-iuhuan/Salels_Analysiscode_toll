## 1. 当前问题

### 1.1 业务痛点

| 问题 | 表现 |
|------|------|
| 生命周期凭感觉 | 无法量化回答"这个产品在什么阶段" |
| 增长假象 | 销量在涨但利润在跌，但传统分析只看销量 |
| 反应滞后 | 等到量利双跌才行动，已经晚了 |
| 管理粗放 | 所有产品统一管理，缺乏差异化策略 |

### 1.2 方案目标

1. **标准化打标**：每个产品自动获得生命周期画像标签
2. **早期预警**：在"量增利减"阶段就发出警报
3. **行动指引**：不同画像的产品给予不同类型的建议
4. **可解释**：所有结论可追溯到原始数据，业务团队能理解

## 2. 数据源与口径说明

### 2.1 数据范围

| 项目 | 说明 |
|------|------|
| 数据源 | ERP销售出货明细表（发货单+型号的行级数据） |
| 时间跨度 | 建议 $\geq$ 3年 |
| 关键字段 | 存货名称、产品品类/小类、发货日期、发货数量、出货总金额、利润 |
| 辅助字段 | 客户简称、细分市场、产品系列、产品类别 |

### 2.2 产品粒度定义

**分析基本单元：存货名称（料号/型号）**

| 层级 | 用途 |
|------|------|
| 存货名称 | **核心分析单元**，每个产品一行 |
| 产品系列 | 次选参照组 |
| 产品品类 | 主选参照组（技术规格相似的产品） |
| 产品小类 | 可选精细参照组（产品极度相似，含改版/升级/迁移） |

### 2.3 时间窗口定义

每次分析取数据截止日（如2026年3月）为基准，**按月刷新快照**：

| 窗口 | 定义 | 用途 |
|------|------|------|
| 近12月 | 数据截止日前推12个月 | 当前状态判断 |
| 前12月 | 近12月再前推12个月 | 增长率计算的分母期 |
| 全历史 | 产品首次出货至截止日 | 历史峰值、寿命计算 |

**重要说明**：每份报表不是给源数据每行打标签，而是**按月聚合成产品级快照表**。每月输出一张表，每行一个产品，标注该产品在当前时间窗口下的生命周期画像。下个月窗口前移，画像自动更新，支持**画像迁移追踪**（上个月成长期→这个月是否滑到预警增长）。

### 2.4 数据清洗规则

#### 负销量过滤
在所有分析开始前，直接剔除销量 $< 0$ 的记录（退货/红冲），从物理层面避免退货造成的比率失真。

#### 毛利率 Winsorization（钳制）
对剔除退货后的正常发货明细，按以下规则进行钳制处理：

$$
\text{毛利率}_{\text{清洗}} =
\begin{cases}
-50\%, & \text{原始毛利率} < -50\% \quad \text{（限制极端成本录入错误）} \\[2pt]
\text{原始毛利率}, & -50\% \leq \text{原始毛利率} \leq 75\% \quad \text{（保留真实的业务亏损与盈利）} \\[2pt]
75\%, & \text{原始毛利率} > 75\% \quad \text{（成本记账异常/样品单）}
\end{cases}
$$

**钳制边界依据：**
- **下限 -50%**：允许真实亏损进入月度汇总（如果当月一单赚一单亏，汇总毛利率会被拉低，真实反映产品当月盈利能力）。同时设定 -50% 的下限以防止 ERP 成本多输一个零等录入错误导致模型崩溃。
- **上限 75%**：行业最高毛利率水平约55~60%，75%留有余量。超过此值的月份基本是样品单或成本未记账。

> **注**：v2.9 版本仅进行行级毛利率Winsorization钳制 [-50%, 75%]，不进行月度汇总后的二次钳制。月度汇总层残留极端值的影响通过以下机制缓解：
> 1. 趋势斜率计算使用至少 3 个有效数据点（`slope_min_data_points`），不足时标记为"数据不足"
> 2. 历史参照毛利率使用 P90/P95 等高分位数，天然过滤极端值
> 3. 自比健康度使用 P95 参照而非单月峰值，对偶发异常不敏感

#### 最低数据要求

| 历史长度 | 处理方式 |
|---------|---------|
| $\geq$ 6个月 | 参与完整分析（含增长率计算和画像判定） |
| 3~5个月 | 仅标注"新品观察"，不给出生命周期画像 |
| $<$ 3个月 | 仅记录在案，不参与分析 |

>仅分析 config.xlsx 中设定的 数据起始日期 之后的数据，之前的记录将被忽略，以减少远古异常数据的影响。当前默认值为 2020-01-01
>**新品判定优先级**：源数据包含ERP“是否新品”字段时优先使用该标记（近12月内有任一行标记为“是”即为新品观察）；仅当无该字段时，才回退至 config.xlsx 中配置的“月数”或“销量”模式。
>负销量过滤：发货数量为负的记录会被视为退货红冲，从分析中剔除。
>低量品处理：当月均销量低于 长尾销量阈值（默认1000）且数据点 ≥ 6个月时，订货波动性(CV)改用 MAD/中位数 计算，避免低基数下标准差失真。

#### 特殊业态过滤：清仓/偶发（僵尸产品复活）判定
在进行生命周期指标计算前，系统会识别因偶尔清仓而导致数据失真的“僵尸复活”产品。
- **判定条件**：产品上市总日历月龄 $\ge 24$ 个月，且在最近的 $24$ 个月内，实际有发货记录的月份数 $\le 2$ 个月。
- **处理方式**：该类产品直接被打上“清仓/偶发”画像，不参与正常的九宫格定位和风险评分，也不进入参照组的大盘均值计算中，避免其突然的清仓销量导致增长率虚高（分母为0导致增速假象）。

## 3. 核心分析框架：二维九宫格

### 3.1 框架原理

放弃传统的"一维综合得分→分类"的加权方法，改用**二维交叉定位**，原因：

1. **加权分掩盖矛盾**：一个产品销量增长高分、利润下滑低分，加权后居中，分不清它是什么病
2. **二维矩阵直接揭示矛盾**：横轴纵轴的不同组合天然对应不同业务状态
3. **行动建议更精准**：每种组合有明确的业务含义和应对策略

### 3.2 坐标轴定义

```
                 纵轴：销量动能
                  ▲
     加速增长      │
  ────────────────┤
     稳定扩张      │
  ────────────────┼───────────────►  横轴：盈利健康
       持平        │
  ────────────────┤                 健康    轻度侵蚀   严重侵蚀
     萎缩         │
                  │
```

#### 纵轴：销量动能

| 增长率范围 | 动能等级 | 简写标签 |
|-----------|--------|--------|
| $>$ 15% | 加速增长 | 量增 |
| 0% $\sim$ 15% | 稳定扩张 | 量增 |
| $-10\%$ $\sim$ 0% | 持平 | 量稳 |
| $\leq$ $-10\%$ | 萎缩 | 量跌 |

**增长率分界线的依据：**
- **15%**：行业年均增长约5~10%，$>$15%代表显著高于均值，属于加速增长
- **0%**：增长/萎缩的天然分界
- **$-10\%$**：正常业务波动通常在$\pm$10%以内，超出此范围的下降属于结构性萎缩

#### 横轴：盈利健康

产品相对于自身历史高点和参照组均值的毛利率表现，决定其盈利健康等级：

| 自比健康度 | 他比健康度 | 健康等级 | 简写标签 |
|-----------|----------|--------|--------|
| $\geq$ 70% | $\geq$ 参照组均值（即 $\geq$ 0pp） | 健康 | 利稳 |
| $\geq$ 50% | 低于参照组均值但差值 $<$ 10pp | 轻度侵蚀 | 利稳 |
| $<$ 50% | 或 低于参照组均值 $\geq$ 10pp | 严重侵蚀 | 利跌 |

> **注**：严重侵蚀是"或"逻辑——自比<$50%**或**他比$<$-10pp 任一触发即判定为利跌。轻度侵蚀的完整代码逻辑为：自比$\geq$50% 且 他比$\geq$-10pp（含自比[50%,70%)但他比$\geq$0pp的边缘情况——此时自比未达健康线但高于参照组均值，仍归入轻度侵蚀作为保守判断）。

**双重参照的必要性：**

| 场景 | 自比 | 他比 | 诊断 |
|------|------|------|------|
| 行业性下行 | 侵蚀 | 与参照组均值持平 | 行业价格战，大家都跌 |
| 产品自身问题 | 侵蚀 | **低于参照组均值** | 只有这个产品在跌 |
| 先天低毛利 | 健康 | 低于参照组均值 | 从上市起就低毛利，非衰退 |

### 3.3 九宫格矩阵

|          |  健康 |         轻度侵蚀 |       严重侵蚀 |
|----------|-------|-----------------|---------------|
| 加速增长 | 🟢 成长期 | 🔵 健康扩张 | ⚠️ 预警增长 |
| 稳定扩张 | 🔵 健康扩张 | 🟡 现金牛 | ⚠️ 预警增长 |
| 持平     | 🔵 利润优化 | 🟡 现金牛 | ⚠️ 隐性衰退 |
| 萎缩     | 🔄 主动收缩 | 🟠 夕阳产品 | 🔴 衰退期 |


**各格子的业务含义：**

| 格子 | 含义 | 特征描述 |
|------|------|---------|
| 🟢 **成长期** | 量利齐升 | 市场接受度提高，定价能力强，毛利率稳定 |
| 🔵 **健康扩张** | 量增长，利稳定 | 规模扩大但盈利未恶化 |
| 🟡 **现金牛** | 量稳利稳 | 市场格局固化，稳定收割 |
| ⚠️ **预警增长** | 量增但利跌 | **最危险的信号**：销量掩盖利润流失 |
| ⚠️ **隐性衰退** | 量稳但利跌 | 表面稳定实际正在恶化 |
| 🔄 **主动收缩** | 量跌但利升 | 可能是主动清退低毛利客户，好策略 |
| 🟠 **夕阳产品** | 量跌利稳 | 需求消退，利润尚可 |
| 🔴 **衰退期** | 量利双跌 | 需安排退市或换代 |

### 3.4 管理层摘要（四区简化标签）

为便于管理层快速扫读，在九宫格画像标签之外，额外提供一个更简洁的"管理层摘要"，将所有产品归入五个粗粒度分类，每类对应明确的管理动作：

| 管理层摘要 | 包含的九宫格画像 | 含义与管理方向 |
|-----------|----------------|--------------|
| 🟢 **投入区** | 成长期、健康扩张 | 产品处于上升通道，值得主动投入资源。可加大产能、拓展客户、稳固定价 |
| 🔵 **维持区** | 现金牛、利润优化 | 产品格局已稳定或处于优化阶段，应保持现状，重点监控利润率、控制成本 |
| 🟡 **观察区** | 预警增长、隐性衰退、主动收缩 | 产品出现"量增利跌"或"量稳利跌"等矛盾信号，需要深入诊断，可能需干预。其中主动收缩需确认是否为主观策略 |
| 🔴 **退出区** | 夕阳产品、衰退期 、清仓/偶发| 产品已进入需求消退阶段，应准备换代或安排退市时间表、清理库存或已彻底死亡仅偶尔售后发货|
| ⚪ **待观察** | 新品观察 | 数据积累不足尚无法判定，持续跟踪，暂不参与完整画像分析 |

**映射关系说明：**

管理层摘要与九宫格画像的对应关系是固定的，由程序中的 `classify_9grid_full` 函数统一控制。具体对应如下：
成长期 → 投入区
健康扩张 → 投入区
现金牛 → 维持区
利润优化 → 维持区
预警增长 → 观察区
隐性衰退 → 观察区
主动收缩 → 观察区
夕阳产品 → 退出区
衰退期 → 退出区
新品观察 → 待观察

>输出文件中"管理层摘要"列直接展示此四区标签，与"当前画像"列并排显示，方便管理层在不深入理解九宫格细节的情况下快速做出决策。

**数据质量标记系统：**
每行产品附带一个"数据质量标记"列，用缩写标记数据异常，方便快速过滤：

| 标记 | 含义 | 触发条件 |
|------|------|---------|
| ZP | 零利润 | 近12月毛利率全为0或负数 |
| NM | 负毛利率 | 近12月毛利率为负 |
| SL | 斜率数据不足 | 有效毛利率数据点 < 3 |
| CV | CV无效 | 近12月无发货记录 |
| AS | ASP数据不足 | ASP有效数据点 < 3 或ASP均值≤0 |
| GC | 增长率截断 | 增长率达截断上限/下限 |
| ZS | 零销量 | 近12月销量=0（非新品/清仓） |
| NH | 无历史参照 | 历史无正毛利率月份 |

若无异常则显示"全部可靠"。

## 4. 指标计算公式全集

### 4.1 基础指标

#### 4.1.1 当前毛利率（滚动12月）

$$
\text{当前毛利率} = \frac{\displaystyle\sum \text{近12月利润}}{\displaystyle\sum \text{近12月出货总金额}}
$$

- 采用滚动12月合计而非单月值
- **不需要月均法的原因**：毛利率的计算在同一个时间窗口内完成（分子分母均来自近12月），不存在"窗口月份数不一致"的问题。增长率需要月均法是因为它要比较两个不同的时间窗口（近12月 vs 前12月），如果前后窗口数据的月份数不同，直接比较总量会失真。毛利率不存在跨窗口比较，分子分母天然来自同一组数据，因此直接使用总量即可
- 先对逐行毛利率做Winsorization（极值）处理后汇总。在每行交易层面做钳制 [-50%, 75%]，异常交易在源头被处理，后续所有聚合（包括12月汇总毛利率）均使用清洗后的数据

#### 4.1.2 历史基准毛利率

$$
\text{历史基准毛利率} = 
\begin{cases}
P_{30}(\text{所有月份毛利率}), & \text{日历月龄} < 12 \text{ 且月度数据点} < 6 \\[4pt]
P_{50}(\text{所有月份毛利率}), & \text{日历月龄} < 12 \text{ 且月度数据点} \geq 6 \\[4pt]
P_{90}(\text{所有月份毛利率}), & \text{月度数据点} < 20 \\[4pt]
P_{95}(\text{所有月份毛利率}), & \text{月度数据点} \geq 20
\end{cases}
$$

- 使用95分位值$P_{95}$而非单月最大值
- 原因：单月峰值可能是异常值（特殊大单/成本调整），95分位更稳定
- 月度数据点不足20个时，P95 退化为接近最大值（29.2%的产品 P95≈Max），因此自动降为 P90，保持足够的参照高度同时避免虚高
- 短月龄产品（<12个月）使用中位数 P50，最稳健，当短月龄产品数据极度匮乏（<6个点）时，采用P30更为稳健，避免偶然极值使参照虚高
- **长周期产品**（月龄 ≥ 36个月）：取最近24个月的毛利率，使用 P80（略低于P95），避免过于久远的历史峰值（如疫情前的高毛利）作为不切实际的比较基准。由 config 参数 `长周期参照月数`（默认24）和 `长周期参照分位数`（默认0.80）控制
- 所有阈值在 config.xlsx 中可配置：`P95最少有效月数`（默认20）、`短月龄阈值`（默认12）、`短月龄参照分位数`（默认0.50）、`稳健参照最少数据点`（默认6）

#### 4.1.3 参照组加权平均毛利率

$$
\text{参照组加权均值} = \frac{\displaystyle\sum_{i \in \text{参照组}} (\text{营收}_i \times \text{毛利率}_i)}{\displaystyle\sum_{i \in \text{参照组}} \text{营收}_i}
$$

- 用营收加权而非简单平均
- 原因：小产品高毛利会扭曲参照值（营收10万的80%毛利率不该与营收1000万的50%毛利率等权）
- 参照组兜底顺序由 config.xlsx 中的"参照组优先级"工作表或 settings.py 中的 `ref_priority` 定义，支持多级兜底。**默认链路**：`型号_产品品类`（参照组最低产品数≥3）$\to$ `产品二级分类`（≥3）$\to$ 全公司均值

**参照组样本清洗逻辑：**
在计算任何参照组均值（含全公司均值）时，系统会自动排除以下两类产品：
1. **新品观察期产品**：处于导入期，毛利波动极大，不具有参照意义。
2. **已退市产品**：存在清仓大甩卖现象，毛利率异常低，会拉低大盘健康线。
   
### 4.2 销量动能指标

#### 4.2.1 销量增长率（月均法）

$$
\text{增长率} = \frac{\text{近12月月均销量} - \text{前12月月均销量}}{\text{前12月月均销量}}
$$

其中：

$$
\text{近12月月均销量} = \frac{\text{近12月总销量}}{\text{近12月有销售数据的月数}}
$$

$$
\text{前12月月均销量} = \frac{\text{前12月总销量}}{\text{前12月有销售数据的月数}}
$$

- 分子分母均为发货数量
- **采用月均法而非总量法的原因**：部分产品在某个窗口内只有部分月份有销售数据（如刚上市的产品在前12月窗口只有5个月数据）。如果直接用总量比——5个月的总量 vs 12个月的总量——增长率会虚高。月均法消除窗口月份数不一致的影响，确保同口径对比。
- **窗口自动缩短机制：** 如果产品上市时间不足以支撑“近12月 vs 前12月”的对比（即前12月窗口无发货记录），系统会自动依次尝试缩小对比窗口至 **6个月**（近6月 vs 前6月）或 **3个月**（近3月 vs 前3月）。发生缩窗时，诊断卡的特情说明会自动提示“历史不足12月，增长率基于X月窗口，可能不稳定”。
- 前后窗口各至少有1个月有数据即可计算。如果某窗口完全无数据，增长率为0
- 截断范围：$[-100\%, +500\%]$

#### 4.2.2 增速变化（二阶指标，辅助用）

> ⚠️ **单位说明**：增速变化用百分点（pp）表示，非百分比。例如增长率从+20%变为+15%，增速变化 = -5pp。

$$
\text{增速变化} = \text{近12月增长率} - \text{前12月增长率}
$$

- 正数：增长在加速；负数：增长在减速
- 用于预警信号，不直接参与九宫格定位

### 4.3 盈利健康指标

#### 4.3.1 自比健康度

$$
\text{自比健康度} = \frac{\text{当前毛利率}}{\text{历史95分位毛利率}} \times 100\%
$$

- 衡量产品相对于自身历史峰值的盈利水平
- $<$ 50%：严重侵蚀（从峰值跌了一半以上）
- 50% $\sim$ 70%：轻度侵蚀
- $\geq$ 70%：健康
- 零利润/无历史盈利的特殊处理：当产品历史上没有任何月份毛利率 >0 时，自比健康度设为0%，盈利健康直接判定为“严重侵蚀”。同时，该产品的毛利率趋势斜率会被标记为“无利润/异常”，并在风险评分中赋予高风险分。

#### 4.3.2 他比健康度

$$
\text{他比健康度} = \text{当前毛利率} - \text{品类加权均值} \quad (\text{单位：百分点})
$$

- 正数：高于品类均值
- 负数：低于品类均值

### 4.4 营收动能指标（v2.8新增）

#### 4.4.1 营收增长率

采用与销量增长率相同的月均法：

$$
\text{营收增长率} = \frac{\text{近12月月均营收} - \text{前12月月均营收}}{\text{前12月月均营收}}
$$

#### 4.4.2 营收-毛利综合判断

结合营收增长率与毛利率变化，分为四类：

| 判断 | 条件 | 含义 |
|------|------|------|
| 双增 | 营收↑ 且 毛利率↑ | 量利齐升，健康状态 |
| 增收不增利 | 营收↑ 但 毛利率↓ | 以价换量，需关注 |
| 减收增利 | 营收↓ 但 毛利率↑ | 主动收缩或产品升级 |
| 双降 | 营收↓ 且 毛利率↓ | 量利齐跌，需干预 |

### 4.5 ASP趋势分析（v2.8新增）

#### 4.5.1 ASP趋势斜率

$$
\text{ASP趋势} = \frac{\text{线性回归斜率}}{\text{ASP均值}} \quad (\text{比率/月})
$$

用近12月月均价（rev_pos / qty_sum）对月份序号做一元线性回归，再除以均值得到相对变化率。

#### 4.5.2 ASP-毛利率联合诊断

| ASP趋势 | 毛利率趋势 | 诊断结论 |
|---------|-----------|---------|
| ↓ | ↓ | 价格战风险（最危险） |
| → | ↓ | 成本问题 |
| ↓ | → | 规模效应（正常） |
| → | → | 正常 |

### 4.6 首次6K追踪（v2.8新增）

**6K** = 单笔发货数量 ≥ 6000。追踪产品从首次出货到首次达到6K大单的月数，衡量产品起量速度。

### 4.7 帕累托分类（v2.8新增）

基于近12月营收将产品分为三类（阈值从 config.xlsx 的 `pareto_key_revenue`/`pareto_regular_revenue` 读取，默认单位万元）：

| 分类 | 默认标准（可配置） | 特情处理 |
|------|------------------|---------|
| 重点产品 | ≥ 100万 | 自动追加降本迭代建议，计算降本1%的毛利率杠杆 |
| 常规产品 | 10万~100万 | 增长率 > 100% 时提示加大投入 |
| 潜力产品 | < 10万 | 无特情 |

### 4.8 未来风险预测指标（5因子模型，v2.9回归精简）

> v2.6~v2.7 使用5因子（斜率+集中度+CV+衰减+历史对照），v2.8扩展为6因子（新增ASP，下调斜率权重），v2.9回归为5因子：移除客户集中度（CM，因49%产品标记为HL无区分度）和同类历史对照（HL，因退市样本不足大量取兜底分50），新增自比健康度（SH）作为替代盈利因子。权重基于 config.xlsx 读取，合计=1.00，不可靠因子自动置零归一化。

#### 因子1：毛利率趋势斜率（权重20%）

$$
\text{斜率} = \frac{n\sum(xy) - \sum x \sum y}{n\sum(x^2) - (\sum x)^2}
$$

其中：
- $x$ = 月份序号（1, 2, 3, ..., 12）
- $y$ = 对应月份的Winsorized毛利率
- $n$ = 12（近12个月）

**风险判定：**

| 斜率值 | 风险得分 | 含义 |
|--------|---------|------|
| $\geq 0\%$/月 | 10分 | 稳定/提升 |
| $0 \sim -0.3\%$/月 | 20分 | 轻度下降 |
| $-0.3\% \sim -0.8\%$/月 | 50分 | 明显侵蚀，需关注 |
| $< -0.8\%$/月 | 80分 | 快速恶化，立即预警 |
| 无利润/异常（近12月毛利率全为0或负数） | 80分 | 一票否决，直接极高风险 |

> 阈值从 config.xlsx 读取（斜率_低分阈值%/月=0, 斜率_中分阈值%/月=-0.3, 斜率_高分阈值%/月=-0.8）。zero_profit=True 时直接返回80分，无视斜率值。

#### 因子3（原序号）：订货波动性 CV（权重10%）

时间范围：**近12月**（月度数据）

$$
\text{CV} = \frac{\text{近12月月销量标准差}}{\text{近12月月销量均值}}
$$

**风险判定（v2.9 阈值放宽至 0.5/1.0/1.5）：**

| CV范围 | 风险得分 |
|--------|---------|
| $<$ 0.5 | 10分（低） |
| 0.5 $\sim$ 1.0 | 40分（中低） |
| 1.0 $\sim$ 1.5 | 65分（中高） |
| $\geq$ 1.5 | 85分（高） |

**B端脉冲式发货豁免机制：**
对于长尾低量产品（月均销量 < 长尾销量阈值，默认1000），系统改用 MAD/中位数 替代传统标准差，以防基数过低导致CV失真。此外，针对 B 端业务常见的"季度大客集中采购"的健康产品：
- **脉冲判定条件**：近12月活跃月份 $\le 4$ 个月，但近12月总销量 $\ge$ 长尾销量阈值。
- **处理方式**：固定赋值 CV=0.5，特情标记"脉冲发货"，避免优质大客户被误杀。

#### 因子4：增速衰减 v4（权重20%）

$$
\text{近3月增长率} = \frac{\text{最后3个月销量} - \text{前3个月销量}}{\text{前3个月销量}}
$$

$$
\text{增速衰减} = \text{近3月增长率} - \text{近12月增长率} \quad (\text{单位：百分点})
$$

**增长率感知风险判定（v4算法）：**

同样的衰减值，在不同增长率下含义完全不同。v4 使用"增长率感知三叉戟"：

| 增长率区间 | 衰减条件 | 风险得分 |
|-----------|---------|---------|
| **高速增长** (>50%) | 自然减速，衰减≤0pp | 10分 |
| | 轻度减速，衰减 0~-10pp | 30分 |
| | 深度减速，衰减<-10pp | 50分（上限） |
| **已萎缩** (≤-10%) | 近3月仍在下跌 | 80分 |
| | 减速放缓，衰减≤0pp | 70分 |
| | 基本止跌，衰减 0~-10pp | 60分 |
| | 反弹中，衰减≥-10pp | 50分 |
| **正常区间** | 近3月同比下跌>10% | 80分 |
| | 衰减<-10pp | 70分 |
| | 衰减<0pp | 50分 |
| | 衰减≥0pp | 20分 |

**代码实现中的阈值常量（固定值，不来自config）：**

- `GROWTH_RAPID = 0.5`：增长率 > 50% 进入高速增长分支（`yoy_change` 为 ratio 形式）
- `GROWTH_SHRUNK = -0.10`：增长率 ≤ -10% 进入已萎缩分支
- `DECAY_RAPID_HIGH = 10(pp)`：高速增长分支的"明显加速"阈值（decay_val 正值=近期加速）
- `DECAY_RECOVER_HIGH = 10(pp)`：萎缩分支的"明显恢复"阈值（decay_val 正值=开始恢复）

**阈值参数（来自config.xlsx）：**

- `decay_yoy_high = -0.10`：正常区间中近3月同比低于 -10% 触发 80 分
- `decay_mid_pp = 0`：正常/高速分支中衰减/加速方向的零界点
- `decay_high_pp = -10`：正常分支中深度衰减阈值，萎缩分支中加速恶化阈值

> **上限保护**：近12月增长率>100% 且 增速衰减<-100pp 时，因子4最高50分。但若最后3月同比已转为实际下跌（`_yoy_change ≤ 0`），解除上限保护并标记`_decay_cap_removed=True`，特情提示"增速衰减因子未享受上限保护"。

#### 因子5（原序号）：自比健康度 SH（权重35%，v2.9新增）

$$
\text{自比健康度} = \frac{\text{当前毛利率}}{\text{历史参照毛利率}} \times 100\%
$$

**风险判定：健康度越低，风险越高：**

| 自比健康度 | 风险得分 | 含义 |
|-----------|---------|------|
| $\geq$ 70% | 10分 | 接近历史峰值，健康 |
| 50%~70% | 40分 | 轻度下降，需关注 |
| 30%~50% | 70分 | 明显恶化，高风险 |
| $<$ 30% | 90分 | 极度恶化，极高风险 |
| NaN/无历史参照 | 50分（兜底） | 数据不足，等效中性 |

> 阈值从 config.xlsx 读取（健康度_低分阈值%=70, 健康度_中分阈值%=50, 健康度_高分阈值%=30, 健康度_默认分值=50）。`health_pct` 以小数形式输入（如 0.70 表示 70%），函数内部自动乘以 100 转为百分数与阈值比较。

#### 因子6（原序号）：ASP趋势（权重15%）

$$
\text{ASP斜率} = \text{近12月ASP线性回归斜率} / \text{ASP均值} \quad (\text{比率/月})
$$

**风险判定（与毛利率趋势联合判定）：**

| ASP斜率 | 毛利率趋势 | 风险得分 |
|---------|-----------|---------|
| ≥ 0%/月 | — | 10分（低） |
| > -0.5%/月 | 毛利率斜率 > -0.3%/月 | 20分（低） |
| > -0.5%/月 | 毛利率斜率 ≤ -0.3%/月 | 50分（中，ASP微降+毛利率同步恶化） |
| ≤ -1.0%/月 | 毛利率斜率 > -0.3%/月 | 20分（低，ASP下降但毛利率稳定） |
| ≤ -1.0%/月 | 毛利率斜率 ≤ -0.3%/月 | 50分（中） |
| ≤ -1.0%/月 | — | 80分（高） |

> **联合判定逻辑**：ASP单独下降不一定代表风险——若毛利率稳定，降价可能是主动策略或成本同步下降。仅当ASP下降伴随毛利率同步恶化时，才是真正的价格战风险信号。

#### 综合风险得分（5因子加权）

$$
\text{风险得分} = S_1 \times w_1 + S_3 \times w_3 + S_4 \times w_4 + S_{SH} \times w_{SH} + S_6 \times w_6
$$

其中权重 $w$ 从 config.xlsx 读取，默认值：$w_1=20\%$（斜率）, $w_3=10\%$（CV）, $w_4=20\%$（衰减）, $w_{SH}=35\%$（自比健康度）, $w_6=15\%$（ASP）。不可靠因子权重自动置零后归一化。

**风险底线保护**：当产品画像为"衰退期"且（毛利率≤0 或 近12月销量≤0）时，非自比健康度部分的加权平均分强制 ≥ 50 分（默认值，由 `衰退期_最低风险分` 控制）。

**总分映射：**

| 综合得分 | 风险等级 | 行动频率 |
|---------|---------|---------|
| 0~25 | 🟢 低风险 | 季度跟踪 |
| 25~50 | 🟡 中风险 | 月度跟踪 |
| 50~75 | 🔶 高风险 | 双周跟踪，加入预警清单 |
| >75 | 🔴 极高风险 | 周度跟踪，准备决策 |

> 总分映射阈值从 config.xlsx 读取（总风险_低风险上限=25, 总风险_中风险上限=50, 总风险_高风险上限=75）。

#### 风险主导因子

> 基于归一化后的实际权重计算各因子加权贡献（`S_i × w_i`），取贡献最大者。即使某因子因数据不可靠被权重清零，也不会被错误地标注为"风险主导因子"。

## 5. 未来6月衰退风险预测模型

### 5.1 模型定位

- **不是精确概率预测**，而是**多信号预警评分系统**
- 输出"风险等级"而非精确百分比
- 目的是在"量增利减"阶段就拉响警报，而非等量利双跌才事后诸葛亮

### 5.2 5因子评分一览（v2.9精简）

| 序号 | 因子名称 | v2.9权重 | v2.8原权重 | v2.7原权重 | 数据来源 | 时间范围 |
|------|---------|----------|-----------|-----------|---------|---------|
| ① | 毛利率趋势斜率 | **20%** | 20% | 35% | 近12月月度毛利率 | 近12月 |
| ③ | 订货波动性(CV) | **10%** | 15% | 15% | 月发货数量 | 近12月 |
| ④ | 增速衰减 | **20%** | 25% | 20% | 月发货数量 | 近3月 vs 近12月 |
| ⑤ | 自比健康度（**v2.9新增**） | **35%** | — | — | 当前毛利率/历史参照毛利率 | 近12月 vs 全历史 |
| ⑥ | ASP趋势 | **15%** | 20% | — | 近12月月均ASP | 近12月 |

> v2.9 从风险因子中移除客户集中度（CM，原权重15%）和同类历史对照（HL，原权重5%），新增自比健康度（SH，权重35%）。
> **注意：CM 虽不再作为风险因子，但客户集中度数据（前1大/前3大占比）仍保留在输出列和特情说明触发条件中，作为参考指标。**
> CV 阈值从 0.3/0.7/1.0 放宽至 0.5/1.0/1.5 以适应 B 端脉冲发货特征。

### 5.3 因子可靠性判定与动态权重

在实际数据中，某些风险因子可能因信息缺失而无从计算。若继续让这些"不可靠"的因子以原始权重参与加权，一个猜测出来的兜底分会稀释其余有数据支撑的信号，导致综合风险得分失真。因此，系统在计算综合得分前，会自动识别每个因子的"可靠性"并进行动态权重调整。

**可靠性判定规则（v2.9 5因子）：**

| 因子 | 不可靠/异常条件 | 兜底/惩罚得分 |
|------|-----------|---------|
| ① 毛利率趋势斜率 | 有效月度毛利率数据点少于 3 个 | 50（数据不足，等效中性） |
| | **近12月最高毛利率仍 $\leq 0\%$（持续亏损/无利润）** | **80（极高风险，一票否决）** |
| ③ 订货波动性(CV) | 近12月总销量为 0（产品无发货记录） | 85 |
| ④ 增速衰减 | **始终可靠**（无不可靠情况） | — |
| ⑤ 自比健康度(SH) | 历史无有效毛利率参照（从未有过正毛利率月份） | 50（默认分，等效中性） |
| ⑥ ASP趋势 | ASP数据不足（有效数据点<3 或 ASP均值≤0） | 50（数据不足，等效中性） |

**动态权重归一化算法：**

1. 读取 config.xlsx 中配置的原始权重：$w_1$=20%(斜率), $w_3$=10%(CV), $w_4$=20%(衰减), $w_{SH}$=35%(自比健康度), $w_6$=15%(ASP)
2. 对每个不可靠因子，将其权重临时置零（`w[idx] = 0`）
3. 计算剩余可靠因子的权重总和 $\text{sum} = \sum w_i$
4. 若 $\text{sum} > 0$，则每个因子新权重 = $w_i / \text{sum}$（归一化）
5. 使用新的权重计算综合风险得分

**影响与示例：**

- 当斜率数据不足时，其20%权重被清零，其余因子权重按比例放大（如自比健康度从35%升至约43.75%），综合得分更多地反映盈利健康和ASP等有实际数据的信号。
- 当多个因子同时不可靠（如新品 + 无ASP数据 + 无历史毛利率参照），可靠因子可能仅剩增速衰减和CV，此时风险得分完全由这些证据最充分的因子决定，避免了大量兜底分叠加带来的"得分平均化"问题。

**风险主导因子的计算：**

风险主导因子基于归一化后的实际权重计算各因子的加权贡献（$S_i \times w_i$），取贡献最大者。即使某因子因数据不可靠被权重清零，也不会被错误地标注为"风险主导因子"。

> **注意：** 各因子的原始得分仍保留在输出列中（如"因子5得分(自比健康度)"），用户可结合"风险主导因子"字段和特情说明，判断哪些因子的不可靠性影响了综合评估结果。


### 5.4 退市产品定义（保留用于参照组清洗，不再用于风险评分）

> v2.9 已移除同类历史对照因子。退市产品的检测逻辑保留用于参照组均值计算的样本清洗（排除已退市产品避免拉低大盘均值），但不再参与风险评分。

退市产品定义为：

$$
\text{退市产品} = \text{最后发货距今} \geq N \text{个月} \cap \text{总月龄} \geq M \text{个月}
$$

其中 $N$（退市判定月数，默认12）和 $M$（退市最少历史月数，默认3）均在 config.xlsx 的阈值参数中可调。

**参照组寿命中位数计算：**

$$
\text{参照组寿命中位数} = \text{Median}(\{\text{参照组内退市产品的寿命}\})
$$

其中每个退市产品的寿命 = 最后发货月 - 首次发货月（月数）。

**保留原因**：在计算参照组加权平均毛利率时，系统会自动排除已退市产品，避免其清仓甩卖导致的毛利率异常低值拉低参照组健康线。

### 5.5 坐标轴可视化

九宫格可直接映射到二维散点图坐标轴上：

- **纵轴**：销量增长率（%），范围 $[-50\%, +200\%]$
- **横轴**：盈利健康度（自比健康度%），范围 $[0\%, 100\%]$
- **气泡大小**：产品营收或利润
- **气泡颜色**：九宫格画像（共11种，含 新品观察 和 清仓/偶发）

完整生命周期迁移路径（含新品和清仓分支）：

```
🟢 成长期 → 🔵 健康扩张 → 🟡 现金牛 → ⚠️ 隐性衰退 → 🔴 衰退期
                            ↘ ⚠️ 预警增长 ↗
⚪ 新品观察 → ↴
                🟢 成长期（正常起量）
                🔴 直接进入预警增长/衰退（上市即衰退）
🔴 衰退期 → 🟤 清仓/偶发（彻底退市后仅偶发订单）
```

此路径可通过月度画像迁移的 Sankey（桑基图）图追踪。输出文件包含 Top100 产品的迁移桑基图。

### 5.6 后续扩展：品类/客户内产品迁移

当客户在同一产品小类内从产品X切换采购到产品Y时：

- 产品X的衰退可能只是被Y替代，而非市场萎缩
- 可引入 **替代关系识别**：跟踪客户在小类内的采购比例变化
- 输出：产品快照表中增加`替代型号`和`替代类型`（升级/降级/平替）字段

### 5.7 模型局限

1. 无法预测市场黑天鹅（政策变化、技术替代）
2. 纯需求端预测，未纳入供给端（产能、供应链）变量
3. 权重需在实际运行后根据误报率调整
4. 自比健康度(SH)基于历史毛利率 P95，对于从未达到过健康毛利率的产品，其"历史参照值"本身偏低，可能低估衰退风险

| — | 无任何条件触发 | `暂无异常信号` | 兜底 |

**排序逻辑：**

- **P0（最严重信号）**：零销量、亏损、零利润、无历史参照、参照组不足——使用 `insert(0)` 插入到列表最前方，确保第一时间被看到。
- **P1（具体风险信号）**：增速衰减、客户集中度、毛利率趋势、健康度跌破阈值——直接反映产品核心问题，按逻辑顺序追加。
- **P2（指标可用性）**：数据不足、波动性无法评估——提示数据质量局限。
- **P3（业务建议）**：重点产品降本杠杆、高增长投入提示、价格战风险—— actionable 的业务信号。
- **P4（一致性检查）**：画像矛盾复核、策略一致性、衰退回升复核——避免输出矛盾结论。

**v2.9 修复的关键语义矛盾：**

1. **零销量+毛利率比较**：零销量时跳过"跌破历史参照值一半"和"低于参照组均值"的生成，避免"存量=0却说跌破一半"的矛盾。
2. **202画像矛盾（成长期/健康扩张+近期下滑）**：当`_decay_cap_removed=True` 且画像为成长期/健康扩张时，使用"需综合判断"替代技术性说明。
3. **70语义矛盾（衰退期+毛利率回升）**：衰退期且毛利率同比回升 >5pp 时，提示复核画像是否为主动收缩。
4. **65亏损遗漏**：补充衰退期中`_negative_margin` 未触发的场景：衰退期且近12月毛利率<0时仍输出"当前处于亏损状态"。

**示例输出：**

对于一个毛利率快速恶化、自比健康度极低、但零销量的衰退期产品：

> 近12月无发货记录，当前画像与毛利率基于零销量推断，毛利率无实际意义；同类参照组不足，他比健康度仅供参考；增长动能正在衰减；客户集中度过高，存在单点崩塌风险

对于一个使用了6月窗口的新兴常规产品且高增长：

> 历史不足12月，增长率基于6月窗口，可能不稳定；高增长常规产品，建议加大投入抢占市场

当产品没有触发任何异常条件时，特情说明显示为"暂无异常信号"。

## 7. 分类替代方案说明

### 7.1 参照组层级选择

| 选项 | 适用场景 | 优缺点 |
|------|---------|--------|
| **产品小类** | **推荐首选** | 同类产品聚合，含改版/升级/迁移关系，技术规格和成本结构极度相似；需评估可用性 |
| 产品品类 | 主选参照组 | 技术规格相似，样本量充足 |
| 产品系列 | 兜底选项 | 组内差异较大，仅当更细粒度不足时使用 |

### 7.2 产品小类的可行性评估方法

如果数据中包含产品小类（同类产品的聚合，含同一型号的改版、升级、迁移关系），可按以下方法验证其是否适合做参照组：

**评估步骤：**

```
步骤1：计算产品小类内的毛利率方差
  组内方差 = Σ(产品毛利率 - 小类均值)² / (产品数 - 1)

步骤2：对比产品小类 vs 产品品类的组内一致性
  如果 产品小类的平均组内标准差 < 产品品类的平均组内标准差
  → 说明产品小类内部更一致，更适合做参照组

步骤3：检查覆盖率
  统计产品小类中「产品数 ≥ 3」的小类占比
  如果 ≤ 50% → 太多小类样本不足，需要用产品品类做主参照
  如果 > 70% → 产品小类可以作为主参照组

步骤4：兜底方案落地
  基于步骤3的结果，选择主参照组，配置兜底链路
```

### 7.3 兜底逻辑

**推荐链路（产品小类优先）：**

```
产品小类 ≥ 3个产品 → 用小类加权均值
产品小类 < 3个产品 → 回退到产品品类加权均值
产品品类 < 3个产品 → 用全公司加权均值
```

**备选链路（产品品类优先）：**

```
产品品类 ≥ 3个产品 → 用品类加权均值
产品品类 < 3个产品 → 回退到产品系列加权均值
产品系列 < 3个产品 → 用全公司加权均值
```

### 7.4 分类标准可替换性说明

所有参照组相关的计算（加权均值、自比/他比健康度）不依赖固定的分类层级，只需替换分组字段即可迁移：

```
产品小类  ↔  产品品类  ↔  产品系列  ↔  全公司
```

用户可根据数据质量和业务理解，选择任一链路。差异仅在于参照组的精细程度和样本量。

## 8. 行动建议体系

### 8.1 九宫格通用策略

| 画像 | 通用策略 |
|------|---------|
| 🟢 **成长期** | **加大投入** — 扩产能、拓客户、稳定定价 |
| 🔵 **健康扩张** | **维持投入** — 跟踪利润率变化，预防"量增利减" |
| 🔵 **利润优化** | **优化结构** — 销量平稳但利润偏低，聚焦成本优化与产品组合调整 |
| 🟡 **现金牛** | **稳定收割** — 控制成本，减少营销投入，最大化现金流 |
| ⚠️ **预警增长** | **成本审计** — 逐客户/逐订单分析毛利率，查清跌因 |
| ⚠️ **隐性衰退** | **利润修复** — 提价/优化产品组合，止损行动 |
| 🔄 **主动收缩** | **保持策略** — 确认是主动收缩，评估何时彻底退出 |
| 🟠 **夕阳产品** | **准备换代** — 控制库存，规划替代型号上市时间 |
| 🔴 **衰退期** | **安排退市** — 制定退市时间表，清理库存 |

### 8.2 具体型号特情分析

每个诊断卡在通用策略的基础上，增加针对该产品实际情况的个性化建议：

1. **触发条件**：哪一项指标触发了当前画像的判断
2. **可行动切入点**：是针对客户、成本、定价、还是库存
3. **时间建议**：短期（1个月）、中期（3-6个月）、长期（12个月）

| 隐患 | 影响 | 缓解措施 |
|------|------|---------|
| 成本记账不准 | 毛利率失真 | Winsorization钳制 + 95分位替代单月峰值 |
| 退货/负发货冲抵 | 销量和利润被低估 | 按产品层面聚合而非订单层面分析 |
| 产品分类混乱 | 参照组偏差 | 多级兜底 + 提供替代分类方案 |
| 历史数据不足 | 退市产品少（旧因子5历史对照失效） | v2.9已移除该因子，不再依赖退市产品样本量 |
| 客户字段缺失 | 客户集中度因子失效 | v2.9已移除客户集中度因子，不再依赖客户数据 |

### 10.2 模型层面的隐患

| 隐患 | 说明 |
|------|------|
| 无法预测黑天鹅 | 新竞争对手、技术替代、政策变化无法从历史数据中预测 |
| 纯需求侧模型 | 未考虑产能、供应链、原材料价格等供给侧变量 |
| 新品类无历史对照 | 全新品类的寿命和衰退模式未知，因子5无法启用 |
| 阈值依赖经验 | 增长率和CV的分界值基于行业经验，需在实际运行中校准 |

### 10.3 操作层面的隐患

| 隐患 | 说明 |
|------|------|
| 误报率 | 部分健康产品可能被标记为预警，需要人工复核 |
| 漏报率 | 一些产品可能在没有任何预警信号的情况下突然衰退 |
| 数据刷新时效 | 建议月度刷新，但决策层可能希望更快的信号 |
| 习惯阻力 | 业务团队可能不信任量化诊断，倾向"感觉"做判断 |

## 12. 阶段测试方法论

> 详见《客户量化评估方案》第15章"阶段测试方法论"，此处仅记录产品生命周期的专属测试要点。

### 12.1 批量变更测试流程

每次批次变更遵循三阶段测试：

| 阶段 | 内容 | 耗时 |
|------|------|------|
| Phase 1 | 加载源数据 → Silver层构建（共享管道） | ~200s（137MB数据） |
| Phase 2 | 加载中间件 → `run_profiling` 验证 → 诊断CSV | ~40s |
| Phase 3 | 生成可视化图表 → 测试报告 | ~10s |

### 12.2 产品专属检查点

| 检查项 | 验证方法 | 通过标准 |
|--------|---------|---------|
| 新品判定日志 | 检查打印输出含 "使用ERP标记" 或 "无ERP标记，使用自动计算" | 日志出现 |
| 新品观察占比 | `result_df['当前画像']=='新品观察'` 占比 | 5%~25% 合理区间 |
| 画像分布完整性 | 11种画像是否全部出现 | 无0值画像 |
| 性能基线 | `run_profiling` 耗时 | < 120s |
